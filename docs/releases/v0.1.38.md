# Arslan 0.1.38 — reliability foundations

This release strengthens execution safety and durable work. It is not a claim
that agent quality has reached 8/10; live model comparisons remain unmeasured.

## Changes

- Python execution no longer retries outside its sandbox. On macOS, a
  default-deny filesystem/network policy limits access to the runtime, per-call
  workspace and staged references. Unsupported platforms refuse this path.
- The packaged app includes a locked standalone computation runtime with NumPy,
  pandas and Matplotlib. Missing runtime fails closed, with no first-run package
  installation or implicit Homebrew dependency.
- Host answers have durable Runs, cancellation, partial-output checkpoints,
  traces and persisted artifacts. Python files survive temporary workspace cleanup
  and can be downloaded through authenticated endpoints.
- Child work shares request, tool, wall-time, token, output and artifact budgets.
  Versioned task recipes support dependencies, 1–4 parallel steps, explicit
  approvals and manual recovery that reuses completed steps.
- Startup rejects unauthenticated non-loopback HTTP/WebSocket clients. MCP child
  processes receive restricted environments rather than all parent secrets.
- Backup/restore validates synthetic-tested snapshots, paths, checksums and
  database integrity, and restores only into a new directory.
- Gemini native tool schemas, function calls, responses and thought signatures
  now round-trip through mock-wire acceptance tests.
- Memory context caps account for CJK text. Exact-vector retrieval scans bounded
  batches; a 100k-row synthetic test retained identical top-20 ranking with much
  lower peak process memory. This is not a semantic recall result.
- The optional browser panel previews public HTTPS pages with scripts disabled,
  a validating proxy, explicit setup, cancellation and stored snapshot/image
  artifacts. It is not an autonomous interactive browser or a kernel network jail.
- Graph loading/error/empty states are explicit, chart code loads on demand,
  and coverage explanations can be expanded without crowding the empty view.
- Thirty deterministic engineering contracts and source-derived capability
  inventories make verification and implementation limits reproducible.

## Important boundaries

Confirmed shell commands and user-connected MCP servers are not covered by the
Python filesystem sandbox. Application budgets are not exact currency ceilings.
Recovery is explicit, not exactly-once replay of arbitrary external effects.
Real provider quality, human judge calibration, physical microphone/Bluetooth
behavior and Linux desktop support remain unverified. A Linux-only `glib` alert
is documented in [dependency status](../DEPENDENCY_STATUS.md), not suppressed.

Before installing, preserve your encryption secret and a backup of application
data. See [reliability contracts](../RELIABILITY.md), [evaluation boundaries](../EVALUATION.md)
and the [implementation ledger](../IMPLEMENTATION_2026-09-14.md).

The release workflow produces a draft only after signing, notarization and
fresh-install acceptance. Publishing the draft enables automatic updates for
installed copies and remains a separate maintainer action.
