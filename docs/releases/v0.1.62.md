## Arslan 0.1.62 — long commands finish, fewer "needs your check", MCP tools can't break a chat

A fix release on top of 0.1.61. Nothing new to learn; things that went wrong stop going wrong.

**Long commands run to their own limit.** A terminal command now runs as long as it asked for (2 minutes by default, at most 10), instead of being cut off after 20 seconds. It never runs past what the reply has left: near the end, a command gets the time that remains, minus a margin for the answer. When a time limit stops a command, Arslan still sees what it printed so far and is told the limit stopped it. A command that floods its output keeps its beginning and its end; the middle is dropped and Arslan is told how much.

**"Needs your check" only when something may really have happened.** A task now ends with "needs your check" only when an action may have left a trace outside your Mac and Arslan cannot tell whether it did.
- A command that only reads (`ls`, `git status`, `grep`, `find` without `-delete` or `-exec`) never asks you to check, even when it is stopped.
- An action that never ran no longer asks you to check: a card you declined, a Hands step refused before it reached an app, a command that had no time left to start.
- A command stopped by its own time limit inside the workspace sandbox counts as not done, and can be run again.
- A background task that saved its file, and whose check confirms the file, finishes as done even when it ran out of steps afterwards. Chat replies still pause in that case; that changes in 0.1.63.

**An MCP tool can no longer break every chat.** A server whose tool descriptions a provider refuses (0.1.61: Anthropic refused some and DeepSeek others, and then every message failed) now works.
- Arslan reshapes MCP tool descriptions into a form Anthropic, OpenAI-compatible providers and Gemini all accept, before sending them.
- If a provider still refuses one, that tool is left out for the rest of the reply and the reply goes on. If the refusal names no tool, or a second one is refused, all MCP tools are left out for that reply. Arslan remembers a refused tool for that model until it restarts.
- Built-in tools are sent exactly as before.

**AppleScript and Shortcuts in the terminal ask every time.** `osascript` and `shortcuts run` in a terminal command now ask every time, with only "This time" to choose, however they are written:
- directly, with a path (`/usr/bin/osascript`), or through `command`, `exec` or `xargs`;
- an earlier "Always" or "In this conversation" for them no longer applies.

Not yet asked (examples only, not a complete list): a script that calls osascript itself (for example `python3 script.py`), `$(which osascript)`, and `open "shortcuts://…"`. 0.1.63 blocks these inside the sandbox.

**Writing files never follows a link out of your working folder.** Writing or editing through a link that points outside the working folder is refused. Writing to a file that has a second name elsewhere (a hard link) replaces the file in the working folder and leaves the other name as it was. New files are never executable; an existing file keeps its permissions. Writing a file now needs write permission on its folder, and the file's owner, access lists (ACLs) and Finder tags do not carry over to the rewritten file.

**Corrections to 0.1.61's notes:**
- 0.1.61 said "Every AppleScript still asks every time". That holds for Hands' AppleScript tool. In the terminal, which spellings ask is listed above (0.1.62).
- 0.1.61 planned "fewer command cards" for 0.1.62. They come in 0.1.63.

**Known limits:**
- Inside the sandbox, a command Arslan does not recognise as outbound and that is killed at its time limit may be run again.
- A reply's own time limit can still shorten a long command near its end.
- If every MCP tool is left out, MCP is unavailable for that reply; after a restart, the first message meets a refused tool once more before it is left out.
- Chat replies that ran out of steps after saving a file still pause.
