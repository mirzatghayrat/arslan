## Arslan 0.1.64 — asks only when it matters, commands run in a sandbox, side chats, sub-sessions

Arslan 0.1.64 fixes the thing 0.1.63 had to work around: it asks before a command only when the command is risky, and it runs commands inside a sandbox that has no network except through Arslan's own proxy. Around that come permission modes per conversation, side chats, sub-sessions, quick questions from the iPhone, a new Progress page and many smaller fixes.

### Permissions and modes

**Arslan asks only when a command is risky again.** "Ask only when risky" is the default again. If you never chose a setting, you move back to it; if you are on asking before every command, including anyone 0.1.63's one-time switch moved there, you stay on "Ask every step" until you change it. Either way Arslan tells you once, with the way to switch. The gaps in how commands were judged, which 0.1.63 listed under Known limits, are closed: a delete after changing folder in the same command is judged against the folder it really runs in, a wipe started through `find -exec` or `xargs` is refused, and a command hidden in another command's option (for example `rsync -e`) is treated as unreadable: inside the sandbox it runs offline with no card, outside it asks. While the sandbox isn't running, the working folder is your whole home folder, or Arslan can't save a checkpoint of the folder, "Ask only when risky" asks every step for now, and says why.

**Permission modes, per conversation.** Next to the input box you pick how much Arslan may do in this conversation: Plan, Ask every step, Ask only when risky, or Full access. Settings › What Arslan may do keeps only the mode for new conversations. Start, in Plan, goes back to the mode you were in. Sub-sessions inherit a mode and never widen it. The iPhone and the Island can't change a mode. Even in Full access, money, sending, sites, shortcuts, files that run later, git, other apps' data, the network and the hard rules still ask or stay blocked, and so does installing a capability.

**Remembered answers.** A new "Remembered answers" section at the end of Settings › What Arslan may do lists what you told Arslan to remember ("Always", "In this conversation") and lets you take each one back. The old command rules are deleted. "This time only" is still never remembered.

**Scheduled tasks run commands again.** A scheduled run now runs the commands that wouldn't need your OK, inside the sandbox, in Arslan's own working folder. Anything that would need your OK is refused and listed under its task on the Scheduled page, instead of skipping every command as in 0.1.63. Tasks set up before this update, or after reading outside content, run their commands offline; with "Ask every step", scheduled runs run none.

**Cards say what they are for.** A confirmation card's heading names the action and what it leads to, in your language (which app Arslan will click in, or that an MCP tool can delete data), then what it touches and the risk, with the command folded below. More deploy and publish commands ask first (Render, `gcloud app deploy`, Pulumi, EAS, Fastlane and several package publishers), writing a secret to a deploy service asks every time, and cloud-storage uploads ask first. Hands refuses a paste only when a password field may really be taking input.

### Sandbox and network protection

**Commands run in a default-deny sandbox.** Terminal commands, Python and MCP servers now share one default-deny base, each with its own preset. Other apps' private data (Mail, Messages, Photos, password managers and the like) is closed, with an "allow once" card where a task needs it. Other agents' config and sign-ins, backups and cloud-tool credentials (rclone, s3cmd, gsutil) are closed inside the sandbox. The sandbox refuses writes to files that run later: git hooks and config, editor tasks, agent and package settings, LaunchAgents and login items. CI files are written as usual; a push card lists the CI files it would change and names the real destination.

**Network only through Arslan's proxy.** Online commands and MCP servers reach the network only through a local proxy that judges each site. A site that appeared only in outside content (a web page, an attachment) is refused. When the proxy refuses, the model is told it was a sandbox stop and why.

**Sites list.** Settings › What Arslan may do lists the sites commands may reach, under the sandbox switch. A pre-flight card names a site a command wants before it runs, when only outside content named it, and after a refusal a card can let commands in this conversation reach that site.

**"Outside content" is tracked more tightly.** Things that came from outside are marked wherever they travel: attachment and OCR text, background-job results, a failed outside call, tasks a restart resumed, and replies brought back from a side chat. A skill, an imported file or a pasted memory with hidden bidi or tag characters is blocked; other invisible characters are marked, and Arslan says how many.

**Hard rules, written down.** One written set of hard rules, each with a test. A command that tries to wipe through `find -exec` or `xargs`, or that is driven through stdin, is refused or asked about.

**Images and the main window.** Web images in Markdown show as chips instead of loading by themselves, and the main window can only load from Arslan itself.

**Smaller sandbox changes.** An allowed delete outside the working folder goes to the Trash. A sandboxed command that fails because of the sandbox says so, so the model does not blame the script. System-certificate checks and trusted local devices have their own settings.

### Side chats

Select text in a reply and choose "Start a side chat". A panel opens on the right with its own tabs. It reads the main conversation up to that point, can use only five read-only tools, takes the main conversation's mode and outside-content mark, and writes no memory. "Bring back to main" only fills the main input box and names the side chat it came from. Deleted side chats stay gone.

### Sub-sessions

Arslan can hand part of a job to a sub-session: a real conversation that runs in the background and reports back with a summary. A sub-session can start one more layer below it, and no deeper. Each one writes only in its own folder and reads the whole workspace. It appears as a tree under its conversation in the sidebar and on the project page, can be stopped and deleted, and is never a top-level job; if the Mac restarts mid-run, the conversation that started it is told. The old `delegate_work` helper and the three "professional methods" are gone. A sub-session's stop works even when its commander has already finished.

### Phone and iPhone

- **Quick questions.** Ask a short question from the iPhone; it answers with four read-only tools and, if you continue it, becomes a normal chat that learns from then on. This replaces Remote.
- **More of the Mac on the phone.** Overview and per-conversation details reach the iPhone; the privacy page says exactly what the Mac sends.
- **Sub-sessions on the phone** are view-only; the server refuses writes into one.
- **Install cards on the phone.** A capability install card from a phone turn reaches the iPhone to view; only a no counts from there, and the reason you give reaches the model.
- **Pairing is faster** (the Mac checks every 2 s while a code is open), and a turn offers each file once, in its last version.
- **Push only what needs you.** Nothing Arslan merely notices pops a notification; quiet hours hush approval cards. "Done" still notifies, and the Mac says when something waits for you to look at.
- **Sidebar on both:** newest first under date sections (Today, Yesterday, Previous 7 days...).

### Progress, Scheduled and the workbench

- **Progress leads with what waits on you**, then a time axis with a bar per run, an inspector beside the list with the run's steps, changes and diagnosis, and cost by model. The run drawer and fleet radar are gone.
- **The Inbox is gone.** What waits on you is one number on Progress, with a row that says why. Learned practices take effect directly, and "about you" memories take effect when you are present and the conversation is clean; the rest wait in Memory under "To sort".
- **A Scheduled page** with its own sidebar entry and dot. A fire keeps its run; a task paused on a deleted conversation says so.
- **"Done, not seen"** shows in the sidebar, and a project row shows its most urgent state.
- **Acceptance sheet.** Background jobs and sub-sessions end with a sheet of what was done and what to look at.
- **The right-hand workbench** is a fixed row (Overview, Working folder, Progress, Browser, then side chats). Overview shows a turn's changes with undo, a side-by-side line diff of a changed text file, and, for a git working folder, the branch, PRs and files.
- **The morning brief is removed.**

### Sidebar and chat window

- Sidebar: pin a conversation, drag it onto a project, collapse it with ⌃⌘S, rename from the sidebar or header, search titles (sub-sessions included) and message text with ⌘K.
- Code blocks have a header, syntax highlighting and a copy chip; formulas, nested lists, task checkboxes and tables render as on the iPhone; a long reply streams without dropping frames.
- The chat input wraps and grows. The model chip shows what the next turn really runs on. "Add model" asks for the key first, then lists the provider's live models. Closing the window from full screen no longer leaves a black screen.

### Memory and rules

- Memory writes merge by meaning, use your language, never guess gender, and keep one-off task state out of "about you".
- Arslan reads a folder's rules (`AGENTS.md`, else `CLAUDE.md`) into each turn. After the same correction twice in one folder, the practice it learned applies to that folder only, and Memory says where each practice applies. Arslan never writes a rules file.
- Import memories you paste from ChatGPT or Claude (listed before anything is stored). What you ask Arslan to remember reaches your cloud model.

### MCP, skills and plugins

- **Capabilities is one list** (built in, skills, connections) with a details sheet. The discovery centre, the Skill Forge page and the curator are removed; "create skill" is a card.
- **Install cards say what was fetched, scanned and pinned**: one commit, one lock, license and organization shown, and a package-vulnerability check (OSV) on every locked package. A skill that tells you to download something and run it is blocked.
- **Pinned connections.** A connection is pinned to the tools its first test listed; a change stops it until you accept. Hand-added `npx` and `uvx` packages are pinned to one exact version or refused with a reason. A stdio program that exits early is a closed connection, and removing a server removes its stored sign-in.
- **One-click list** for registry servers, now including GitHub's remote MCP server. A remote server that asks you to sign in is no longer a failed install. Secrets in a connection's address or arguments can move to an encrypted store.
- **Plugins** install as one group of skills and connections, in a Plugins group with search. **Import from Claude Code and Codex**: MCP servers, skills and plugins, from a sheet in Capabilities; skills also read and export from `~/.agents/skills`. A plugin's hooks are shown on its install card, each with its own switch; this version runs none of them.
- **Verify**: a project's smoke test run once in the sandbox.

### Models and replies

- Every role follows the conversation's model, else the primary; task routing is removed. For new setups the Anthropic default is Claude Sonnet 5.5 (`claude-sonnet-5-5`); existing setups keep their model. OpenAI-compatible and Gemini keys use each model's documented output cap.
- A failed model call names its call, provider and model, and offers "switch this chat and retry". Terminal commands see the PATH your shell setup defines. A stopped run is never silent: it says whether the chat cap, wall clock or step count ended it, and a job ended by the hard limit says what was done, blocked and left.
- Replies follow a warmer style in chat and four rules for task reports. When blocked, Arslan guides you instead of stopping.
- The dollar limit per task has an off switch; the step and token limits still hold.

### Reliability fixes

- Several races and hangs fixed in the Bridge, MCP closing, process cleanup and turn cancelling; a step left open when a run stops no longer spins forever.
- Sending you a file no longer needs a tool search first, so a reply can't stop halfway with the file unsent.
- A reply that would freeze the window to parse shows as written. Dragging the panel divider no longer selects text; Ctrl+K deletes to the end of the line again.
- Every provider gets each tool under a name it accepts.
- Dependency updates (vite, Tauri updater, Pillow, pypdf, PyJWT, urllib3 and others) for known advisories.
- Plus test, bench, CI and internal-cleanup fixes.

### Removed

The expert-era code and tables (routes, spawns, scoring, the equip popover and former-experts page, expert-scope memory writes), the capability discovery tables, Project learned gate-advancing and its stats, the Cua Driver engine files, the any-declared network mode and the old command profile, `delegate_work`, and the rollback switches for K7, K8a and K9.

What the upgrade changes in your data:
- The experts you made become skills, switched off until you turn them on; a secret found in one is removed, and the skill says so. Knowledge an expert kept to itself moves into one "Former expert notes" collection. Unfinished expert tasks are cancelled.
- Expert-scope memories move to your global memory with their ids kept. None is put in use without your yes: each waits as a proposal, and the restricted ones (secret, never-use or empty) are quarantined. Nothing is deleted.
- The old one-to-one expert chats and their feedback are dropped without an export; the backup taken before the upgrade keeps them until it is pruned.
- The old "don't ask again" command rules, task routing settings and the professional-methods tables are removed.

Arslan's product code is 36,291 lines larger than in 0.1.63 (52,531 added, 16,240 removed in `server/`, `arslan/` and `web/src/`, tests and translations not counted).

**Docs.** SECURITY.md and docs/ARCHITECTURE.md are rewritten to match 0.1.64.

### Goal mode, off by default

Type `/goal` and what you want done. Arslan drafts the checks that say when it is finished, and you confirm them. It then keeps working in rounds until the checks pass, or until it stops and tells you why: no progress, the budget, a check it can't judge, or a protected file that changed. Your own `check:` lines are run by Arslan itself. Goal mode stays off until you turn it on in Settings › Advanced.

### Known limits

- **Goal mode can't yet judge a check like "changed only X, everything else unchanged".** When a goal has such a check, it stops and asks you to look instead of deciding. A fix is planned for 0.1.65.
- **A goal's judgement checks, the ones Arslan judges by reading a file rather than by running a command, can be wrong in either direction.** In our test, the judge failed a correct file five rounds in a row, which stopped the goal, and in another run it passed a file with a wrong total. Checks that run a command, such as your own `check:` lines, aren't affected. If a judgement result looks wrong, look at the file yourself.
- **A goal's check that reveals its tests in stages is replayed by Arslan at most 12 times.** A check that reveals its tests in k stages needs k+2 runs, so one with more than about 10 stages can't settle and the goal stops for you to look.
- **When the files a goal's check writes add up to more than 64 MB, the goal stops for you to look** instead of checking them on its own.
- **The model sometimes writes out a command and asks in the chat before running it.** Reply with a short confirmation and it goes ahead. A fix is planned first after 0.1.64.
- **If a script fails partway and the model then finishes the job, Arslan asks you to check the result.** Part of the work may already have been done before the failure, so Arslan won't mark it complete on its own, to avoid doing something twice.
- **An AppleScript that contains comments (lines starting with `--`) stays in the sandbox even after you approve it, and can fail there.** Arslan's reply tells the model why, and the model retries without the comments. Common Reminders and Calendar actions are planned to get their own tools in 0.1.65.
- **A quick ask from the iPhone can search and recall, but can't act on your Mac.** For a screenshot, a file, or anything that runs on the Mac, start a new conversation from the iPhone's sidebar, or ask on the Mac; the quick ask's reply says so.
- **The sandbox, measured on a real Mac (2026-11-15, Claude Sonnet 5.5, 4 tasks, 24 runs).** In the default "Ask only when risky" mode, no command card was shown, and no run needed a card to leave the sandbox (0 of 24). The sandbox stopped 1 of 149 commands. The same tasks under "Ask every step" showed 86 cards in 12 runs.
- **This release had no smoke-test sitting on a real Mac.** Problems found in daily use go into point releases.
