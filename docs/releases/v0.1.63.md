## Arslan 0.1.63 — change course mid-reply, answers as they are written, undo a turn

Arslan does more of a task in one reply, shows its answer as it writes it, lets you add a message while it works, and can take a turn back. Two safety changes come first, because they change what you see.

**Arslan asks before every new command, for now.** Every terminal command shows you a card first, unless you choose otherwise. This applies to everyone, including anyone who had chosen "Ask only for risky commands" before: on the first start of 0.1.63 that choice is switched once, and a choice you make afterwards is kept. The reason: Arslan's judgement of which commands are harmless enough to run without asking has known gaps, which 0.1.64 closes. A command you allowed "In this conversation" runs again in that conversation without asking, so the setting reads "every new command". The cost is more cards: in our pre-release test (27 runs on DeepSeek), asking before every new command showed 51 command cards, against 4 with "Ask only for risky commands". To switch back: Settings › What Arslan may do › Terminal › When to ask › "Ask only for risky commands". Choosing it first tells you what it misses in this version (see Known limits) and asks you to confirm. Beside it, a note says its judgement is completed in 0.1.64, and one sentence says where to undo a turn; the chat shows one line while it is on. If you were on "Ask only for risky commands" before 0.1.63, by your choice or because it was the default, Arslan tells you once, the first time you open it after the upgrade: that it now asks before every command, why, and how to switch back.

**Scheduled tasks don't run commands in this version.** A step that needs a command is skipped and listed in your Inbox, whatever you allowed before ("Always", "In this conversation", "Ask only for risky commands"). A scheduled task is told this before it starts. It can still look things up, save files in Arslan's own folder, and call MCP tools the server marks read-only.

**Change course while Arslan works.** Type a message while a reply is running (in the Mac window, on the iPhone, or with hold-to-talk) and it reaches that reply at its next step, instead of waiting for the reply to end. The steps not started yet are skipped and the reply reads your message first; the window says it was added. A reply already writing its final answer has no step left, so your message runs right after it.

**Answers appear as they are written.** With DeepSeek and other OpenAI-compatible providers, Claude and Gemini, the reply streams in as the model writes it. Checks that used to hold the answer back now add a correction after it when needed. If a stream fails halfway, Arslan keeps what you already saw and says the reply was interrupted, rather than starting again.

**Several reads at once.** When the model asks for several reads in a row (web pages, searches and MCP reads), up to four run at the same time. Each result stays paired with the call that asked for it.

**Undo this turn.** Before a turn first changes your working folder, Arslan saves a checkpoint. "Undo this turn" puts the files back and takes the turn out of the conversation.

**Files reach you, not just their path.** When you ask for a file (a screenshot, chart, export or document), Arslan attaches it to its answer: a file card in the Mac window, and the file itself on your iPhone.

**Search uses your model's own search first.** A Claude conversation searches with Anthropic's own web search; a conversation with a local model uses no cloud search. Tavily or SearXNG can be the only search or a backup. When a search service blocks Arslan, it says so instead of returning nothing.

**Fewer tools in every request.** Tools you rarely use, and MCP tools, are no longer sent with every request; Arslan finds and uses them when a task needs them.

**MCP tools are asked about according to what they do.** A tool its server marks read-only runs without a card; one marked destructive asks every time; the rest ask once per conversation. A call whose arguments are too long to show on a card is refused, never cut.

**A dollar limit per task, on by default.** Each chat reply and each background task stops at $2 of model spend (it starts wrapping up at about two thirds). Change it in Settings › Background › Dollar limit per task. Only models with a known price count.

**Long work stays in the chat.** Arslan no longer pushes long work into the background or answers with a single sentence; background work is the same work done elsewhere, when you or the model choose it. After ten minutes a reply tells you it is still working.

**Hands in a chat reply.** A chat reply can now take as many Hands steps as the task needs, in more than one app, and Stop stops it; a risky step still asks every time. An app named with `.app` or a full path is judged as the same app, so one you never allowed stays refused however it is written.

**The desktop app's server is locked down.** It always needs its access token, accepts no other website as a caller, and ignores settings inherited from the environment that launched it. The access token no longer appears in the server log.

**Smaller changes.**
- Conversation titles come from your first message, written by the conversation's own model.
- A task whose check could not run no longer ends as "needs your check" when the work is done.
- A step that cannot be written to a background task's record is refused on its own; the task goes on.
- Arslan ships two skills of its own (a designed HTML report and the skill creator); skills you imported with the same names as retired ones are no longer removed.
- Tasks started by the old experts, before 0.1.44, are continued by Arslan when you resume them.
- An attachment's text is kept up to 40,000 characters (was 12,000). When it is longer, Arslan is told how long it was and, when the message says where the file is saved, to read the rest there.

**Removed.** The expert-era code that no reply could reach any more (creating experts, their templates and engine), the evolution and curation machinery, the research review, and the conversation menu's "Distill". Arslan's product code is 12,514 lines smaller than in 0.1.62 (11,586 added, 24,100 removed in `server/`, `arslan/` and `web/src/`, tests and translations not counted).

**For developers (source runs only).** `ARSLAN_ALLOWED_HOSTS` and `ARSLAN_ALLOWED_ORIGINS` refuse to start with any entry containing `*` (including `*.example.com` and `localhost:*`), and the origins refuse `null`. Name each host and origin in full. The desktop app ignores both variables.

**Moved to 0.1.64.**
- "Fewer command cards", planned for 0.1.62 and then 0.1.63, is not in 0.1.63: the fix to how commands are judged (S2a-3) moved to 0.1.64, and until then every new command asks, as above.
- The page that lists and undoes your remembered answers (S6), the allowed-folders setting (S4b) and the one mode setting (S5, with "Full access") move to 0.1.64. When "Full access" comes, it still asks before: a payment; installing a capability; sending or submitting anything outward (mail, messages, uploads, `git push`, forms); a deletion outside what checkpoints can undo. Commands Arslan never runs stay refused, and "this time only" answers are never remembered, in any mode.

**Known limits.**
- With "Ask only for risky commands" on, a delete written after changing folder in the same command (for example `cd folder && rm file`) is treated as inside the working folder, so it can run without a card even when that folder is somewhere else, and "Undo this turn" only brings back files in the working folder. 0.1.64 fixes this. Under the default, every new command asks first.
- After deleting files in your working folder, Arslan may say they can't be recovered. Usually they can: open ⋯ under that reply, choose "Undo this turn…", then "Undo files", and the files come back as they were before the turn. The undo box says when a file was left out of the copy, or when nothing was saved (for example, a folder too big to copy).
- A message you add in the Mac window during a reply shows on your iPhone from the next reply on, and the iPhone keeps saying "Queued behind the current turn" after its own message was added.
- A scheduled task that needs a command skips that step every time in this version.
- While several reads run together, the window shows their steps only when the group finishes; Stop works throughout.

**Where our pre-release test fell short.** Before release we run the same nine tasks three times each, on DeepSeek and on Claude, with "Ask only for risky commands" on, as in earlier rounds. Two of our own bars were missed:
- **T11 (find another way after a refused delete), on Claude: 0 of 3, down from 3 of 3 in 0.1.62.** Under "Ask only for risky commands", a delete inside the working folder runs without a card on purpose, because "Undo this turn" can bring the files back; the task expects a card. Claude changed into the working folder and deleted by name, so no card came and the files were deleted. DeepSeek deleted by full path, got a card, was refused and moved the files to the Trash: 3 of 3. Under the default, every new command asks first.
- **T8 (three follow-up edits to one document): DeepSeek 1 of 3, Claude 0 of 3.** In every failed run the edits were right but one: the checker wants the second section cut below 60% of its length, and the task only asks to make it shorter. We kept the checker as it is. Claude Code, on the same checker: 1 of 3.
