## Item 1

- First run: **failed**, for two reasons in the code.
  - The fact extractor filed "answer briefly, conclusion first" as a *practice*, not a fact about the user,
    so memory got nothing.
  - The lesson capture that took it was refused: work scheduled after the answer inherited the finished
    turn's checkpoint, so its model calls failed with `task_attempt_stale`. Unit tests stub the judge and never
    saw it.
- After the fixes: conversation 1 saved "用户希望回答简短、先给结论，再用要点列出理由。" as active (noticed from the user's
  words). Conversation 2 answered "结论先行，然后要点列理由；整体要简短…这是你之前确认过的偏好" with no tool call: the
  preference came from the memory block.

## Item 3

Run 1 asks to *try* AppleScript first, because left alone the model usually goes to EventKit straight away (3/3 in
the P3 round), which would show nothing about learning. On this Mac, Reminders refuses Apple Events from the bench's
process and allows EventKit.

| Round | Run 1 (AppleScript first) | Lesson learned | Run 2 (normal prompt) | Counters after run 2 |
| --- | --- | --- | --- | --- |
| b | osascript refused (-10004) → Swift/EventKit, 4 calls, 118 s, check 3/3 | detour, active | EventKit first, 18 calls, 145 s, check 3/3 | recalled 1, followed 1, succeeded 1 |
| c | osascript refused → Swift/EventKit, 2 calls, 76 s, check 3/3 | quirk of this Mac, active | EventKit first, 7 calls, 113 s, check 3/3 | recalled 1, followed 1, succeeded 1 |

- Round c's lesson: "用 osascript 直接控制「提醒事项」时遇到权限错误（privilege violation） → 改用 EventKit（如 Swift 脚本）
  请求日历/提醒事项权限后再操作，比 AppleScript 更稳。"
- What works: the lesson is captured automatically from the turn's own trace and judged worth keeping. It takes
  effect at once (the turn read nothing from outside), is recalled into the next turn's status block, and the
  judge records that it was followed and the turn went well. Run 2 never tried AppleScript.
- What did not show: speed. A refused `osascript` costs one quick call, so following the lesson can save at most
  that. Run 2's extra calls came from writing, editing and re-checking its own script, which varies more from run
  to run than the saving.
  - In round b part of it was a bench artefact: `swift` printed a cache error because the sandbox allowed only
    `$TMPDIR`, and the bench sets its own. Fixed: macOS's per-user folder is now writable too.
- A fair speed test is "run 2 with the lesson vs run 2 without it", over several runs, on a task where the model
  does not already prefer the working route. Not run.

## Fixes these runs found (in 0.1.52)

1. After-turn learning runs in the background-maintenance context, with the turn's memory permissions
   (`lessons.later`).
2. The judge asks with thinking off (official DeepSeek) and the decisions made after the answer get 15 s; with
   2 s a thinking model almost never answered.
3. The extractor keeps the look of answers (length, tone, format) as a fact about the user.
4. The command sandbox also allows macOS's per-user folder (`/var/folders/..`) when `$TMPDIR` points elsewhere.
5. A detour's error reads both error and stderr; Apple Events "privilege violation (-10004)" marks a quirk.
