# 0.1.48 – 0.1.50 plan: remove experts, real capabilities, accounts through Arslan's own browser

Written 2026-09-30 after 0.1.47. Facts below were checked in code or at the source.

## Facts

- Experts ("spawns") touch 161 backend files, 93 frontend files and ~700 test
  files, and are tied into scheduled tasks, run records and database tables.
- The "App Store Connect" and "Local image generation" cards in Connections are
  placeholders: their capability endpoints return every capability `false`. They
  are not a key vault and do nothing.
- Arslan's own browser (0.1.45) already runs with a persistent profile
  (`server/services/agent_browser.py`, `--user-data-dir`), so a site the user logs
  into there stays logged in. There is no way for the user to open it to log in,
  and watches do not use it.
- Seed skills already include research, competitive-analysis, sector-overview,
  idea-generation, arxiv, blogwatcher. They are instructions without the tools and
  data to act on them, which is why they feel useless.
- Skill sources, licences checked at the source:
  - `anthropics/financial-services`: Apache-2.0, 112 skills; most are institutional
    (investment banking, PE, fund admin). Personal-use candidates: competitive
    analysis, sector overview, comps, DCF, earnings analysis, morning note.
  - `anthropics/skills`: per-skill licences. skill-creator, mcp-builder,
    webapp-testing, frontend-design are Apache-2.0. **docx / pdf / pptx / xlsx are
    "all rights reserved": they must not be bundled.** Document output has to be
    built on open libraries (openpyxl, python-pptx, python-docx, pypdf).
  - `K-Dense-AI/scientific-agent-skills`: MIT, 168 skills (science/biomed).

## 0.1.48 — experts out (step two)

Stop and remove, in this order, so each step is shippable:
1. Surfaces: the Former-experts tab, expert chat routes in the UI, the two
   placeholder Connections cards, the dead settings (spawn synthesis mode,
   auto-evolution + max dispatches, learn per-spawn preferences) via a
   retired-fields contract (reads ignore them, writes refuse them, tests say so).
2. Background: evolution watcher/loop, per-spawn distill, staffing/dispatch.
3. Code and tests that only served those.
Kept on purpose: database tables and rows (no data deletion), the scheduled-task
`spawn_id` column (existing tasks already run as Arslan), migrations.

## 0.1.49 — accounts through Arslan's own browser; watches that can log in

- "Sign in to a site": opens Arslan's own browser window; the user logs in
  themselves. Arslan never sees or stores a password. Sessions persist in its
  profile; a list shows signed-in sites with Sign out (clears that site's cookies).
- This is how the frontier agents do it (the user takes over to log in); a vault of
  social-media passwords for the agent to type is not built: it would put
  passwords in reach of the model and trips most platforms' automation rules.
- Watches gain "use my signed-in browser" for pages behind a login (read only).
- Acting on those sites (post, reply, buy) stays per-action confirmed, as in 0.1.45.
- API keys and tokens move to the macOS Keychain.
- More watch sources through connectors: RSS/feeds, email (IMAP or Gmail MCP),
  calendar, GitHub notifications.

## 0.1.50 — capability packs instead of experts

Each pack = skills + the tools and data they need + one real task it must pass
before it ships.
- Deep research: multi-source, citations checked (existing research review).
- Personal finance and markets: Apache skills above + free data (SEC EDGAR filings,
  public price data) + spreadsheet output.
- Documents: xlsx / pptx / docx / pdf authoring on open libraries.
- Science (optional pack): K-Dense MIT skills.
