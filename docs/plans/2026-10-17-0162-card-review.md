## 3. 开工前必须改：技术缺口（按卡）

严重度：**高** = 照卡做会出错或留安全 / 成本口子；**中** = 会漏情形或返工。

### F1 命令时限
- **中：** 外层等待最长约 615 秒，可聊天回合剩下的时间可能比这短，回合自己的超时会先到（`arslan/execution_budget.py:317`），命令被杀、没有输出。**改：** 时限取「回合剩余时间 − 余量」，和 `delegate_work` 的做法一样（`tool_loop.py:1270`）。
- **低：** 后台 worker 也走这条路（`task_workers.py:150`），加一条测试；读输出时给缓冲设上限。

### F2「结果不明」链
- **高：** 「结果不明」这个标记只认「是不是只读」：`local_write` 和 `external_write` 一样会触发（`task_service.py:305`、`:332`）。所以第 ① 处必须把读命令判成 `read`，判成 `local_write` 没有用。
  - 还有一个副作用：`local_write` 失败会被记成「失败」（`task_repository.py:454-455`），重复执行的保护就放行了。
  - **改：** 被停止或被信号杀掉的、出了沙箱的命令，仍按「未知」处理；补一条「能不能重跑」的测试。
- **中：** 往外发数据的命令有几种写法认不出来。**亲核：** `curl --request=POST …`、`gh api … -f …` 现在都判成 `run`。HTTPie 的 `http POST` 也是（子任务测，我没复核）。这几种写法都要进测试，并在 S2a 里归到「对外」那一类。
- **中：** 第 ④ 处（存过交付物就不挂起）只看了「有没有成功写过文件」，可能把预算用完时只写了一半的任务判成成功。**改：** 以验收检查通过为条件。

### F3 MCP schema
- **中：** OpenAI 也拒绝顶层 `anyOf`，所以三家都要做顶层合并；还要处理 `$ref` / `$defs`、`type: [..., "null"]`、`$schema`。
- **中：** 从报错里认出是哪个工具时，要按供应商最终发出去的 payload 计序号：Anthropic 会跳过没有名字的工具，Gemini 按 `functionDeclarations` 计。
- **中：** 只重试一次的话，一个服务器有两个坏工具，这一轮照样失败。**改：** 再失败就去掉全部 MCP 工具。排除要对本轮后面的每一步都生效，`wired_keys` 也要一起去掉。坏工具清单按「模型、工具、schema 哈希」在进程里记住，参照 `_REFUSES_IMAGES` 的做法。

### F4a 终端 osascript 只给「这一次」
- **高（亲核）：** 下面几种写法今天判成 `run`，**一张卡都不出**，比 R2 的「能被总是允许」更严重：
  - `/usr/bin/osascript -e …`
  - `command osascript …`
  - `… | xargs osascript`
  - `/usr/bin/shortcuts run …`

  **改：** 认命令名时，要认带路径的写法、`command`、`xargs`，并补齐这几种写法的测试。**这一条进热修版。**
- **高：** 脚本里调用 osascript（例如 `python3 x.py`）照样不出卡，而沙箱是 `(allow default)`，Apple Events 能直接发出去。
  - **改：** 这一条放在 S2a 修（见下）。
  - v0.1.61 发布说明的更正**不能**写成「终端里的 AppleScript 现在都会问」，只能写清楚哪些写法会问。

### F4b 写文件不跟随符号链接
- **中：** `os.open` 默认的权限是 0o777，新文件会带上可执行位。**改：** 传 0o666。
- **中：** 工作区里一个**硬链接**指向 `~/.zshrc`，`resolve()` 和 `O_NOFOLLOW` 都拦不住。**改：** `st_nlink > 1` 时拒绝，或者先写临时文件再用 `os.replace` 换上。
- **中：** 检查完路径之后才建上级目录，中间有空档。**改：** 用 macOS 11+ 的 `O_NOFOLLOW_ANY`，或者建好目录后再解析一次路径。

### FR 发热修版
- **高：** F1、F2、F3 都改 `tool_loop.py`，K1、K3、K4、K8 会把这个文件大改。如果热修提交先合进 main，再挑回 v0.1.61，就会冲突，或者发出一个没人测过的组合。
  - **改：** F 线从 v0.1.61 拉出 `release/0.1.62` 分支，在上面开发，合了再把这个分支合回 main。热修版发布前，`tool_loop.py`、`task_service.py` 不接别的 PR。K 线反正要等 M1B（A4），不损失时间。
- **中：** 每张卡都会重新生成 `CAPABILITY_INVENTORY.md`，挑提交时每次都冲突。**改：** 冲突时随便取一边，最后统一重新生成一次。

### K1 原生工具协议
- **高（亲核）：** 现在解析 Claude 的回复，只留文字和 `tool_use`（`anthropic_provider.py:412-422`），思考块和签名都丢了。可 Claude 5.x 默认会思考，Opus 5.5 和 Fable 还关不掉（`:45-56`）。
  - 原生协议要求把思考块原样带回去。不带，就是 400。
  - **改：** 解析时保留 thinking 块和签名，在 trajectory 的 continuation 里传回去；补上「有思考 + 有工具」的往返测试。
- **高（亲核）：** Anthropic 的 `chat()` 不接受 `tool_choice` 参数（`anthropic_provider.py:289-295`），Gemini 也一样；可 `adapter.chat_trajectory` 会传它，直接 TypeError。
  - **改：** 强制收尾那一步，Anthropic 发 `{"type":"none"}`，Gemini 用模式 NONE。
- **中：** 状态块现在是追加在最后一条消息上的。原生模式下，最后一条消息就是 `tool_result`，状态块会被当成工具输出（不可信）。**改：** 在所有 `tool_result` 之后，单独加一个文本块。
- **量级：** 实际约 +300 行，不是 +150。

### K2 跨轮上下文
- **中：** 新增的「工具摘要」消息，卡里没列全读取方：`server/api/phone.py:126`（非用户的角色一律当助手消息发给 iPhone）、`server/api/runs.py:128`、`conversation_search.py:72`。

### K3 提示词布局与缓存
- **中：** 「系统 + 最后 3 条消息」这种放法，下一轮命中不了上一轮历史的缓存。**改：** 断点放在三处：系统和工具的末尾、之前历史的末尾、滚动的尾部，共不超过 4 个。1 小时的断点要排在 5 分钟的前面。

- **中：** K7 的按需工具会改动工具前缀。两张卡要先约定：工具只追加、顺序固定。
