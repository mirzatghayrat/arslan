## 4. 合并顺序（两种情况，等 #432）

**情况 A：#432 不采纳，照 10-22 的顺序。**

```
M64（随时）
SBX ──→ S2a-3（Codex 审 rebase 后的头）──→ CAP ──→ SUB
  └──→ ACM ──→ INB、STY
Q1：Bridge 帧点头后随时，但和 SUB 共用迁移，Q1 先合
C7c、F5b-2、C5b：空档里合
```

**情况 B：#432 采纳（三层 + 模式），且同意第 3 条「不跑陌生代码的不等沙箱」。**

```
M64（随时）
Q1、STY、INB 的非安全部分、C7c、F5b-2、C5b：先做，不等 SBX
硬规则整理 ──→ 分类器（先量漏放和误拦）──→ 模式（S5 扩写）──→ ACM
SBX ──→ CAP 里跑陌生代码的部分（verify、插件脚本）──→ SUB
```

- 两种情况里，**跑陌生代码的**（CAP 的 verify 和插件脚本、SUB）都排在 SBX 后面。
- **INB 的第 6、7 条**（学到的做法、记忆直接生效）碰安全面，单独一个 PR、最先做，按 effort=max 写和审，不管哪种情况（②Main 审 #433 时定的拆法）。
