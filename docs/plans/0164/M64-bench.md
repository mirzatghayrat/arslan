## 目标

用户 10-27 定的两条（`docs/plans/0162/README.md` §8「代码相关能力至少追平 Hermes」），加上 SUB 卡要的一道题：

1. **代码审查题：** 给一个埋了已知 bug 的 PR，数抓出几个。先出 3 题，不同语言，每题埋几个已知 bug。用户说过：Arslan 审得好、自己有信心，就让它做这类活；这批数据就是用来判断这件事的。
2. **「对 Hermes」的门槛：** 同样的题，Arslan 三次全过的题数不少于 Hermes，只比两边都能跑的那批题。v0.1.63 只比同题时 Arslan 少 1 题（`R63-verdict.md` §5.1），所以 v0.1.64 至少要再多过 1 题。
3. **拆分派汇总题（SUB 卡要的）：** 一个要分几块做的项目题，看 DeepSeek 当总指挥能不能拆好；同时测反面：一步就能做完的请求不开子会话。

## 改哪些文件

- `scripts/kernel_bench/prompts.json`：加三道代码审查题、一道拆分派汇总题、一道「一步就能做完」的反面题。
- `scripts/kernel_bench/check_t13.py` 起：每道题一个检查脚本（照 `check_t*.py` 的写法）。
  - 代码审查题：埋的每个 bug 有一个标识（文件、行、类型）；检查回复里点到了几个，记「抓到 / 埋了」和「误报数」（指出了不存在的问题）。
  - 拆分派汇总题：记开了几个子会话、汇总有没有覆盖每一块、花费、服务商回了几次 429。
  - 反面题：开了子会话就算不过。
- `scripts/kernel_bench/fixture_t13.py` 起：造题用的小仓库（每题一个，生成在跑分的临时目录里，不放真项目的代码）。
- `scripts/kernel_bench/runner.py`：
  - `UNSUPPORTED`（`:84-87`）给新题登记谁不能跑（例如拆分派汇总题在 SUB 合并前对 Arslan 也记不支持）；
  - 「同题比」的统计：只算两边都支持的题，和旧的「不支持记 0」并列输出，R64 用前者。
- `scripts/kernel_bench/report.py`：报告里加「同题三次全过」一栏，和代码审查的「抓到 / 埋了 / 误报」。
- **Codex 作参考线：** 用用户的 Plus 跑代码审查题（不另花 API 的钱），只当参考，不进门槛；它用的是自己的模型，和 DeepSeek 上的两组不是同一个比法。Codex 怎么接进 runner 先不做：第一轮由用户在自己的 Codex 里贴题、把回复存成文件，⓪Plan 用同一个检查脚本打分。

## 不许碰

- 已有题（T1–T12）的题面和检查脚本：改了旧基线就不能比。
- 代理的上限：只在现有上限内跑，不调高；快到上限就停下，写进早报。
- 跑分结果的存放：长跑前挪到持久目录（`/tmp` 下的结果重启就没了，10-23 丢过一次）。

## 怎么做（要点）

1. 先造三道代码审查题的小仓库和埋的 bug，写检查脚本，用一个「全抓到」和一个「一个都没抓到」的假回复验证检查脚本能分开两种情况。
2. 在 main 上用 DeepSeek 跑一次 Arslan 和 Claude Code，各三遍，得到 v0.1.64 开工时的基线。
3. 「同题比」那一栏，用 v0.1.63 R63 那一轮的原始结果重算一遍，确认和 `R63-verdict.md` §5.1 的「少 1 题」对得上。原始结果要是已经丢了，就在 main 上用 DeepSeek 重跑 Arslan 和 Hermes 的全套。
4. 拆分派汇总题和反面题先出、先用假回复验证检查脚本；SUB 合并后再真跑。

## 验收

- 检查脚本对假回复能分开「全抓到」和「全没抓到」；对反面题能分开「开了子会话」和「没开」。
- 基线跑完，报告里有三栏：旧算法、同题三次全过、代码审查的抓到 / 埋了 / 误报。
- 花费写进早报（按 run 的 usd_peak 加总）。

## 量级

脚本约 +400 行（三个小仓库的生成器、四个检查脚本、runner 和 report 的统计）；不碰产品代码。

## 风险与回退

- **风险：** 埋的 bug 太明显或太偏，分数说明不了「审得好不好」。每道题至少一个要读懂上下文才能发现的 bug，⓪Plan 出题后请 ②Main 看一遍题面（不看答案）。
- **风险：** 检查脚本靠关键词匹配，模型换个说法就漏判。每个 bug 的标识用文件加行号范围，再加一个人工复核的抽样。
- **回退：** 只加了新题和新统计，旧题不变，回退就是删掉新题。

## 开工前要用户定的

- Codex 的参考线第一轮用「用户贴题、存回复」的办法，可以吗（不用给 Codex 接任何东西）。
- 三道代码审查题用哪三种语言：⓪Plan 建议 Python、TypeScript、Swift（Arslan 自己的三种语言）。
