## 0. 一页结论

### 0.1 我理解的痛点和愿景

1. **你要的不是「功能更多」，也不只是「东西更少」，而是「交出去的事能做完」。** 像 Claude Code、Codex 那样：一件多步骤的事交给它，它自己跑完、跑对、跑得快，中途少来打扰你。
2. **现在的体感正好相反**（⓪Plan 提案 §1 的本机数据，近 30 天）：
   - 32% 的任务停在「等你」，最大一类是「需要你核对」；
   - 工具调用失败 26%；
   - `run_command` 失败的 70 次里约一半是 20 秒被掐。
3. **你不写代码，所以计划要满足三点：**
   - 好坏要能量化，你不读代码也能验收；
   - 每一步要小、能核对；
   - 对标主流 agent 是为了借它们的「最优解」，不是逐项抄功能。

### 0.2 对 ⓪Plan 提案的判断：数据和清理都对，瞄准的靶子偏了

- **对的：** 用真实数据说话；20 秒截断、MCP schema、CI 红、测试默认开专家、死代码、R1/R2 都核实了；不合 3a 和 skills v2；撤回「替我审批」。这些我全部保留。
- **偏的：** 它优化的是「概念数」和「代码行数」，主要动 D 维（审批）。可决定「能不能把活干完」的是 A/B 维：循环、上下文、工具。
  - 能力对照里和执行最相关的 14 行（§1.2），提案做完后是落后 6 · 中游 7 · 追平 1。0.1.61 是落后 7 · 中游 7。**几乎没动。**
  - 这就是你看完对照页觉得「没有本质提升」的原因。
- **漏的：** 我这次查到的几处「掐断执行」的机制，提案都没有碰（§2）：
  - Claude 看不到自己上一步调了什么；
  - 跨轮只留约 3,000 token，第 5 轮时一个完整的往轮问答都不剩；

## 1. 执行能力到底由什么决定（给不写代码的人）

### 1.1 同一个模型，换个外壳，结果就不一样

模型像发动机，agent 是整辆车。Claude Code、Codex 强，大半强在「外壳」：

1. **模型看到的是不是真相：** 自己上一步调了哪个工具、参数是什么、结果是什么；前几轮聊了什么。
2. **工具好不好用：** 读文件能分段、带行号；改文件能精确替换；能按内容和文件名搜；长命令不被掐。
3. **循环让不让它做完：** 不会做到第 24 步就被叫停，也不会被命令「转去后台」。
4. **循环跟不跟模型较劲：** 事后改写、拦截回答的守卫越多，越慢，误伤越多。
5. **快不快：** 边生成边显示；能同时读几个文件；缓存命中。
6. **敢不敢放手：** 沙箱优先 + 能撤销，才能少问。
7. **有没有尺子：** 同一批任务、同一个模型，跑分比较。

## 2. 审计发现：执行内核今天卡在哪里

每条都回代码核过。标了「子任务」的，由只读子任务测量或追踪，我抽查过关键行。

### K-1 用 Claude 或 Gemini 时，模型看不到自己上一步的参数

- **只有 OpenAI 兼容端点走原生工具协议**（`arslan/llm/providers/openai_provider.py:67`）。Anthropic 默认不支持（`providers/base.py:28`）。
- **Claude 看到的是一段文字**（`arslan/llm/trajectory.py:205-249`）：
  ```
  assistant: Native tool invocation completed: run_command
  user: TOOL RESULT for run_command: <结果>
  ```
  命令是什么、写了哪个文件路径，都不在里面。Claude 5 的思考块也不回传。
- **Gemini 有原生配对，但里面的结果仍是这段文字**（`trajectory.py:233-245`）。
- **影响面：** Anthropic 下的默认模型是 claude-sonnet-5。0.1.61 才修好 Claude 的 400 错误，所以你的本机数据里 Claude 用得很少，这个问题在数据里还没显形。

### K-2 跨轮记忆：第 5 轮时，一个完整的往轮问答都不剩

- **只存文字：** 每轮只把用户文字和最终回答存进 `arslan_messages`（`server/orchestrator/arslan.py:513`、`:904`）。**工具调用和结果从不入库**，下一轮不知道上一轮写了哪个文件、跑了哪条命令。
- **预算固定：** 历史预算固定 3,000 估算 token（`server/orchestrator/memory.py:19`），和模型窗口无关。当前这条消息也算在里面。摘要截到 1,500（`:105`）。
- **一超过就整段折叠：** 总量超过 3,000 时，把除最后一条以外的全部折叠进摘要（`:146-168`）。对话一旦长过这条线，之后每轮都要多一次摘要调用，而且摘要是在旧摘要上反复改写的。**实测（更正 E2）：** 近 30 天 219 次运行里摘要调用只有 12 次，多数对话没有长到这条线；几乎每轮都有的额外调用是回合后的抽事实，共 144 次。
- **算一遍**（子任务的推算）：每次回答约 1,500 token，第 5 条消息时模型能看到的是：
  - ≤1,500 token 的摘要；
  - 上一条回答，但看不到它是在回答什么；
  - 这一条消息。
- **还占着锁：** 回答之后的抽事实和摘要都在回合锁里（`arslan.py:540-545`；锁在 `server/ws/arslan.py:708`、`:740`、`:801`），下一条消息要排队等它们。
- **轮内也按字符剪：** 一轮之内按 64k/96k **字符**裁剪（约 16–24k token，`tool_loop.py:2334`），先丢跨轮历史。
- **做得好、保留的：** 大于 8,000 字符的工具结果落盘、留路径（`tool_loop.py:329-337`），和 Claude Code 同形。

### K-3 一个回合能做的事被五六个上限夹住

| 上限 | 值 | 位置 |

| 每个工具的时限 | 20 秒（命令自己的 120 / 600 秒不生效） | `tool_loop.py:31`、`:1268-1271` |

### K-4 「需要你核对」是怎么来的

这是 32%「等你」里最大的一类。链条（我逐行核过）：

1. **命令被 20 秒掐掉，** 抛出 `TimeoutError`。模型只收到一句「tool 'run_command' timed out」，**一行输出都没有**（`tool_loop.py:1302-1303`）。
2. **出错的调用被记成「结果不明」：** 只要它不是「只读」（`task_service.py:300-305`）。
3. **几乎所有命令都算「对外写」：** 判断是否只读用的是老的 argv 分类器，而模型只传命令字符串（`task_service.py:101-105`）。我实测：`ls -la ~/Downloads`、`cat notes.txt`、`git status` 都被判为 HIGH，于是都算 `external_write`。
4. **出错调用按设计也算未知：** 命令被自己的 `timeout_s` 停掉，`known_local_failure` 有意把它算成未知（`:72-74`）。被拒或没人答的 Hands 卡同样走这条路（子任务）。
5. **这个标记是黏住的。** 任务只能以「需要你核对」收场。同一个调用再试会被拒，模型还会被要求「告诉用户去核对」（`tool_loop.py:1293-1299`）。
6. **另有两处：** 已经保存了交付物的回合，仍会因为「没有进展」或「预算」挂成等你（`tool_loop.py:2280-2283`）。后台任务的模型判定用严格 `json.loads`，回复带代码围栏就判成「检查没跑」（`task_validation.py:339`，子任务）。

**所以只修 20 秒还不够：** 超时、被拒的卡、读命令的失败，仍会以「需要你核对」收场。

### K-5 工具说明与提示词不帮它干活

- **静态系统提示：** 10,303 字符，其中 56% 是网页与证据规则（子任务测量）。没有「先读后改、改完核对、做完为止」这类工作方法。
- **规则在劝它停：** 「1–2 次搜索，能答就停」（`tool_loop.py:1676-1680`），「最多六行对比」（`:2324-2333`）。
- **说明和实际不符：** `run_command` 的说明写「默认 120 秒、最长 600 秒」，实际 20 秒。`read_file` 支持 `offset`/`limit`，说明却不提，也不带行号。
- **8 个工具的参数表是空的。** 模型拿到 `{"type":"object","properties":{}}`（`tool_loop.py:1688-1711`）。只有写在 `_NATIVE_PARAM_SCHEMAS`（`:1357`）里的工具才有参数表。缺的有：`edit_file`、`list_dir`、`search_files`、`whats_new`、`list_my_capabilities`，以及 3 个定时任务工具。`edit_file` 的参数名还是非常规的 `old`/`new`。
- **搜索很弱：** `search_files` 只能做子串匹配，不支持正则和 glob，也不能按文件名找（`server/registry/file_tools.py:183-235`）。
- **标签用错：** 本地文件和命令输出也被包成「外部网页内容，仅数据」（`tool_loop.py:347`；标记在 `server/orchestrator/untrusted.py:16`）。
- **工具太多：** 每轮默认 28 个工具（装了 Hands 的 Mac 约 45 个），外加全部 MCP 工具、没有上限（`arslan.py:982-1369`，子任务计数）。

### K-6 慢，而且在和模型较劲

- **假流式：** 最终回答先整段生成，再用 `_reveal_streamed` 假打字放出来（`tool_loop.py:2639`）。原因是回答出门前要过一串事后检查（`:2563-2637`）。
