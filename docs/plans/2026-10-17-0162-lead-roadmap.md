## 0. 一页结论

### 0.1 能不能做到

**设计上能做到，但要三个版本。** 一版做完，范围会大到重演 0.1.61 那种无法审查的 PR。

| 版本 | 执行相关 14 行 | 其余 37 行 | 主题 |
|---|---|---|---|
| 0.1.61 | 落后 7 · 中游 7 | 落后 8 · 中游 17 · 追平 8 · 领先 3 | — |
| **v0.1.63** | **追平 10 · 领先 4** | 落后 6 · 中游 14 · 追平 13 · 领先 3 | 执行内核（v0.1.63 计划，按 §5 调整后） |
| **v0.1.64** | **领先 14** | 落后 3 · 中游 5 · 追平 24 · 领先 4 | 执行领先 + 其余一半追平 |
| **v0.1.65** | **领先 14** | **追平 32 · 领先 4** | 其余全部追平 |

- 「其余 37 行」里有 1 行是终端界面（TUI），不在产品定位内，始终记为「—」（§3）。
- v0.1.65 之后合计：**领先 18 · 追平 32 · 落后 0 · 中游 0**。

### 0.2 为什么可行

- **同一个模型，换外壳差 11–21 分。** Terminal-Bench 2.0 上：
  - Opus 4.6，最好的外壳 76.4，Claude Code 58.0；
  - GPT-5.3-Codex，78.4 对 64.7；
  - Haiku 4.5，35.5 对 13.9（§8 [tb2]）。
  外壳是执行力的主要变量之一，而且 Claude Code 并不总在前面。
- **领先外壳靠的都是可以搬的工程做法，不靠私有模型：**
  - 原生工具协议；
  - 输出设上限；
  - 首轮给环境快照；
  - 完成前过核对清单；
  - 长命令转后台；
  - 工具按需加载；
  - 先遮蔽旧输出再摘要。
  （§8 [kira] [metaharness] [droid] [tooluse] [complexity]）
- **极简往往更强。** 第三方 30 题测试（DeepSeek V4 Flash）里，最简的 pi 得 20/30 排第一，Hermes 15/30（§8 [composio]，第三方数据）。Meta-Harness 的搜索里，改提示词的候选全都退步。这和 v0.1.63 计划「先删挡路的东西」是同一个方向。
- **Arslan 有别家没有的条件：**
  - 它就在你的 Mac 上：APFS 瞬间复制、操作 App、Mac 睡眠续跑；
  - 一张卡、一条消息流能同时到窗口、灵动岛、iPhone、语音。
  - 14 行里有 10 行的领先设计用到了这些条件（§2 每行的「独有优势」）。

### 0.3 不能承诺的

- **对照表上的「领先」只是设计判断。** 真正说「执行领先」，要在公开基准上、用同一个模型、同一套环境，分数最高，而且置信区间不重叠（差距小于约 3 分都算噪声，§6）。
- **最难赢的一场：** 终端编程题上，对最新的 Claude Code + 最新 Claude 模型。
  - Terminal-Bench 2.1 上，Opus 4.7 配 Claude Code 是 68.9，中立外壳 Terminus 2 是 66.1；
  - Terminal-Bench 4.0 的第一名就是 Claude Code + Opus 5.5。
  - 那里的目标是追平。
- **最现实的领先战场：** Mac 日常任务（文件 + App + 命令 + 多轮），也就是 MacAgentBench 这类题。那里的第一名目前是 OpenClaw + Opus 4.6，pass@1 73.7%，论文说领先主要来自它的技能库（§8 [macagentbench]）。

### 0.4 榜单怎么看

**这份榜单按经过 OpenRouter 的 token 量排名，反映的是用量和啰嗦程度，不是质量：**

- 直连官方 API 的用量看不到（Claude Code 的大部分用量大概如此，推断）；
- 输入重、缓存差的 agent 排名反而靠前。

**前 20 名里有执行参考价值的：** Hermes Agent、Claude Code、Kilo Code、Cline、pi、Codex、omp、OpenClaw、OpenHands、Cursor、Zed（ACP 协议）、Letta（记忆）、Command Code（参数修复、口味学习）、Portkey（模型网关）。

**没有参考价值的：** Lemonade（Roblox）、GDevelop（游戏引擎）、Proto Agent（ERP）、CodeGPT（文档太薄）。ZCode 只有宣传页，Strix 是安全测试工具，只看沙箱做法。

### 0.5 需要你拍板的（详见 §7）

1. 接受「三个版本到位」的节奏，而不是全压在 v0.1.63？
2. v0.1.63 范围按 §5 扩大（流式、插话、检查点、缓存提到必须），发版会晚一些，接受吗？
3. 「AI 审批员」这一行要追平，就得在 v0.1.65 做一个窄版（默认关）。这和 v0.1.63 撤回「替我审批」不矛盾，但要你确认方向。
4. 公开基准私下跑（Terminal-Bench 2.1 + MacAgentBench）的费用和 Mac 虚拟机，要你同意。

## 2. 执行相关 14 行：领先做法逐行

信心：**高** = 只用已证实的做法，Arslan 现有代码就在手边；**中** = 要组合多家做法，或者依赖还没跑过的 Mac 特性。

### L1 agent 循环（中游 → v0.1.63 追平 → v0.1.64 领先，信心：中）

- **领先做法：** 一个循环跑聊天、后台、定时、iPhone，不再分两档规矩；事件按「对话 → 回合 → 条目」写成只追加的日志，同一份事件驱动窗口、灵动岛、iPhone 和外部编辑器（ACP）；每一步先记「打算做什么」再执行，Mac 睡眠或崩溃后只重放标为安全的步骤；首轮带一份环境快照（系统、可用命令、文件夹概况），收尾前过一遍完成核对清单。
- **借鉴自：** Codex app-server（Thread→Turn→Item）；OpenHands 只追加事件日志；Pi Durable 意图日志；Zed ACP；Meta-Harness / Droid 环境快照；Terminus-KIRA 完成核对清单。
- **Arslan 独有的优势：** 一张卡多端可答，已经是领先形状；Mac 睡眠或崩溃后接着跑，五家对标对象里没有（pi 有类似做法）。
- **哪一版、多大：** v0.1.63 K4 统一规矩；v0.1.64 拆出约 300 行的薄循环 + ACP 服务端（官方 Python SDK）。量级 L。
- **怎么证明：** 睡眠/崩溃后续跑测试；Zed 能驱动 Arslan。

### L2 工具调用（中游 → v0.1.63 追平 → v0.1.64 领先，信心：高）

- **领先做法：** 所有供应商走原生协议；常驻工具只留核心几个，其余（Hands 各 App、MCP、技能）按需检索加载；执行前校验参数并自动修复常见错误；每家供应商的 schema 规整。
- **借鉴自：** pi 极简工具；Codex 工具分直接 / 延迟 / 隐藏；Hermes BM25 工具检索；Cursor 只列 MCP 名字（−46.9% token）；Command Code 只修坏字段的参数修复；Anthropic Tool Search（Opus 4.5 从 79.5% 到 88.1%）。
- **Arslan 独有的优势：** Hands 的 App 工具天然适合按需加载。
- **哪一版、多大：** v0.1.63 K1、K5、K7；v0.1.64 内置工具也按需加载 + 参数修复。量级 M。
- **怎么证明：** 每次请求工具说明 ≤12k 字符；无效参数类失败接近 0。

### L3 并行工具调用（落后 → v0.1.63 追平 → v0.1.64 领先，信心：高）

- **领先做法：** 默认并行，单个工具可声明必须串行（Hands 点按、写入）；结果按原顺序记录；流式里一个只读调用块一结束就开跑，不等整条回复。
- **借鉴自：** Codex 读写锁 + 取消的调用也补结果；pi 默认并行 + 串行标记；Hermes 线程池；Cline 默认并行。
- **Arslan 独有的优势：** Mac 上读多个 App 窗口也能并行。
- **哪一版、多大：** v0.1.63 K9（升为必须）；v0.1.64 边流式边执行。量级 S–M。
- **怎么证明：** 读 3 个网页/文件的题用时下降 ≥40%（公开研究显示并行主要省时间，不提高成功率）。

### L4 流式输出（落后 → v0.1.63 追平 → v0.1.64 领先，信心：中）

- **领先做法：** 真流式；命令输出、工具进度也实时流出；同一条流同时到窗口、灵动岛、iPhone；守卫改为事后更正。
- **借鉴自：** Anthropic/OpenAI 流式协议；Cline 实时命令输出；Zed 流式编辑。
- **Arslan 独有的优势：** iPhone 已能接收 stream_chunk，真流式后多端自动受益。
- **哪一版、多大：** v0.1.63 K8（升为必须）；v0.1.64 工具进度流到灵动岛和 iPhone。量级 M。
- **怎么证明：** 首字延迟接近模型首字；iPhone 上同样逐字出现。

### L5 中断与插话（中游 → v0.1.63 领先 → v0.1.64 领先，信心：高）

- **领先做法：** 打字、iPhone、灵动岛、按住说话都能插话；插话在下一个工具边界送达，还没开始的工具给一个「已跳过」结果（历史保持合法）；排队消息可改顺序、可撤；再按一次就中断。
- **借鉴自：** Codex turn/steer（带回合号防串）；Claude Code 回合中消息在本批工具后送达、Ctrl+Enter 把手头的事转后台；OpenClaw 跳过未开始的工具；Cursor send now。
- **Arslan 独有的优势：** 别家只有一个界面；Arslan 有窗口、灵动岛、iPhone、语音四个入口，且已有排队机制。（更正 E12：灵动岛今天没有输入、语音走窗口的输入框，v0.1.63 能插话的是窗口、iPhone、按住说话；灵动岛输入挪到 v0.1.64。）
- **哪一版、多大：** v0.1.63 K9：在现有排队上加「工具边界注入」。量级 S。
- **怎么证明：** 任务进行中从 iPhone 改方向，它在下一步就照做。

### L6 命令执行超时（落后 → v0.1.63 追平 → v0.1.64 领先，信心：高）

- **领先做法：** 命令跑过约 10 秒自动转后台而不是被杀，返回进程号和日志文件；一个进程工具可以看输出（只看头尾）、等某句话出现、输入、结束；监视有期限、到期自动续；命令结束时唤醒对话，并推到灵动岛和 iPhone。
- **借鉴自：** Claude Code 超时转后台 + Monitor；Codex PTY 会话 + write_stdin + 1 MiB 头尾缓冲；OpenClaw yieldMs + notifyOnExit；Hermes notify_on_complete；Command Code monitor_command。
- **Arslan 独有的优势：** 命令跑完通知到手机，别家只在终端里。
- **哪一版、多大：** v0.1.62 F1（120/600 秒 + 超时给输出；原写 0.1.61.1，见 v0.1.63 计划更正 E1 和 U1）；v0.1.64 后台进程 + 进程工具 + 通知。量级 M。
- **怎么证明：** 一题跑 5 分钟构建，期间还能聊别的，结束自动接着做。

### L7 停止条件（中游 → v0.1.63 追平 → v0.1.64 领先，信心：中）

- **领先做法：** 一个停止策略（步数、墙钟、无进展）+ 卡住检测（同一动作和结果 4 次、同一错误 3 次）+ 美元上限；「目标模式」：给一个完成条件，独立的小模型逐条核对证据，判完成 / 继续 / 受阻；同一个阻碍连续 3 轮才算受阻；可加一条必须通过的检查命令。
- **借鉴自：** Codex goal（逐条核证据、3 轮才判受阻、token 预算）；Claude Code /goal（无工具的小模型判定）；Hermes 检查命令；OpenHands 卡住检测；Kilo goal_report。
- **Arslan 独有的优势：** Arslan 已有「验收标准」和校验代码，直接改造成目标模式；目标进度显示在灵动岛。
- **哪一版、多大：** v0.1.63 K4；v0.1.64 目标模式。量级 M。
- **怎么证明：** 目标题（如「把 20 个发票整理好并核对总额」）一次跑到完成。

### L8 上下文压缩（落后 → v0.1.63 追平 → v0.1.64 领先，信心：中）

- **领先做法：** 按供应商返回的真实 token 和窗口比例触发；先免费修剪（旧工具输出换成占位）再摘要；摘要是固定结构（目标、进度、决定、动过的文件、下一步），原地更新；保留最近几轮原文；压缩前先静默存记忆；溢出时压缩后重试一次；支持的供应商用服务端压缩。
- **借鉴自：** JetBrains 研究：先遮蔽旧工具输出，成本约减半、成功率不降；Hermes 50% 触发；Kilo 锚定摘要；Claude Code 压缩后重新注入规矩、计划和最近文件；OpenClaw 压缩前存记忆；Anthropic/OpenAI 服务端压缩。
- **Arslan 独有的优势：** 每轮的工具摘要跨轮保存（K2），iPhone 回来接着聊也不断片。
- **哪一版、多大：** v0.1.63 K2（含修剪 + 结构化摘要）；v0.1.64 存记忆 + 服务端压缩。量级 M。
- **怎么证明：** 20 轮长对话里还记得第 2 轮写的文件；摘要调用次数下降。

### L9 token 预算（中游 → v0.1.63 领先 → v0.1.64 领先，信心：高）

- **领先做法：** 以真实用量为准；上下文环可点开看各部分占比（系统、工具、记忆、历史、工具结果）；每轮花费；可设每任务美元上限；模型自己也能查剩余上下文。
- **借鉴自：** Cursor 上下文环明细；Claude Code /context；Codex 剩余上下文工具；Hermes 以真实用量为锚。
- **Arslan 独有的优势：** Arslan 已有用量浮窗和上下文环（0.1.58），补明细即可。
- **哪一版、多大：** v0.1.63 K4 + 一个界面小改。量级 S。
- **怎么证明：** 环里的数字和账单一致。

   - 现在公开榜不接受新提交，所以先私下跑、公开轨迹。
2. **Mac 日常任务（公开）：**
   - 跑 MacAgentBench（676 题、25 个 App，约 60% 界面 + 命令行混合），同一模型对比 OpenClaw；
   - 另跑 MacArena 的 Mac 原生子集；
   - 要 Apple Silicon 虚拟机。
3. **私有题库：** 从本机周报（v0.1.63 计划 M2）里的真实失败挑 50–150 道。v0.1.63 没有这张卡，放到 v0.1.64 做（任务卡审查 §5）。
   - 包括：原生 App、权限对话框、多 App 流程、该问 / 该拒的情形；
   - 按最终状态判分；
   - 留一部分不参与调优，防止过拟合。
4. **公平规则：**
   - 固定模型版本、推理档位、供应商（OpenRouter 上关掉自动换供应商）、虚拟机配置；
   - 跨几天跑；
   - 报置信区间、Pass^k、成本、token、用时；
   - 差距小于约 3 分算噪声（Anthropic 实测：沙箱资源设置单独就能让分数差 6 分）。
5. **怎么说：** 只按「哪个模型、哪个基准」说领先，例如「Claude Sonnet 5 上，MacAgentBench 第一」。不说笼统的「全面领先」。
6. **一次只改一处：** 每个 K 线 PR 按「环境快照 → 输出上限 → 遮蔽窗口 → 编辑格式 → 完成清单 → 计划工具 → 并行」这类阶梯做消融，读轨迹，不只看分数。

**时间：** 第 1、3 项在 v0.1.63 的 M1 里开始；第 2 项要虚拟机，放 v0.1.64。
