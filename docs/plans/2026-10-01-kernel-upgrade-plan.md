# Arslan 执行内核升级计划：在你的真实任务上达到并超过 Hermes

状态：**计划，待你点头后按阶段执行。** 日期 2026-10-01。
依据：内核对比小样（`2026-10-01-kernel-bakeoff-sample-results.md`）、对 Arslan 代码的逐项核对（下文带文件:行号），以及《深入理解 AI Agent：设计原理与工程实践》（李博杰，Apache-2.0，github.com/bojieli/ai-agent-book）第 1–7、9 章。

## 0. 「达到 Hermes」怎么算——先定尺子

不用感觉判断，用同一把尺：

- **任务集**：T1–T6（提醒事项、岗位表格、财报表格、盯登录页面、整理下载、手机发消息），之后按你的真实任务扩充。
- **可靠性用 Pass^3**：每件任务连跑 3 次、**3 次都过**才算过（书第 7 章：只成功一次说明「能做到」，连续成功才说明「靠得住」）。
- **同模型对照**：Arslan 与 Hermes 同用 `deepseek-v4-pro`，goose 作第二参照。
- **指标**：Pass^3、实付花费、模型调用跨度（用时）、调用次数、失实次数（声称做完实际没做 = 一票否决）、越界次数（一票否决）、打扰次数（确认卡数量）。
- **目标线**：
  - 稳：每个任务族 Pass^3 ≥ Hermes；失实与越界为 0。
  - 快：用时 ≤ Hermes × 1.1。
  - 便宜：花费 ≤ Hermes。
  - 安全：达到 DeepSeek Harness 的姿态——每条命令在系统沙盒里跑，越界必须你在窗口里点。
- **诚实边界**：只承诺「在你的任务 + 回归集上」达到/超过；「全面比 Hermes 稳」没人能凭一个用户的数据证明，不承诺。

## 2. 分阶段计划

每阶段结束都跑同一把尺（第 4 节），**用数据决定下一步**，不堆改动。每项都带验收标准；改动按书里的做法「一次只改一个变量」、用配对比较。

### P0 尺子入库（约 1 天）——先把测量做对

1. 把对比用的夹具、检查器、计量代理、驱动整理进仓库 `scripts/kernel_bench/`（不含任何 key；外部参赛者的安装步骤写成脚本+说明）。
2. 修驱动：心跳不再重置空闲计时；所有终止状态（完成/失败/等待用户/取消）都结束本场。
3. Pass^k 运行器 + 配对报告（逐任务谁过谁不过、花费、调用跨度、失实/越界）。
4. 每场保存「中立格式」轨迹（书第 5 章），用于失败归因和以后的回归。

验收：重放小样得到与已发布结果一致的分数；驱动对 5 种终止状态各有测试。

### P1 执行层「稳」（约 3–5 天）——这是追上 Hermes 的主战场

1. **原生工具协议（D1，最关键）**：OpenAI 兼容通道改为标准的 assistant `tool_calls` + `role: tool` 结果（带 `tool_call_id`），**原样回传 `reasoning_content`**（DeepSeek / Kimi / GLM 同协议）；外部内容仍在 tool 结果里按数据包裹。内部轨迹存中立格式，渲染时按厂商转换。
   - 预期收益：每步不再从零思考 → 输出 token、用时、重复劳动都下降；这也很可能是 T5 回复冲到 8192 的主因之一。
   - 风险：`tool_loop.py` 是 1700+ 行的核心文件，改动面大 → 先补「轨迹形状」测试，再改，再用 P0 的尺子对照。
2. **输出预算与截断（D2）**：按模型目录给输出上限（思考模型默认放宽，DeepSeek 上限 384K）；`finish_reason == "length"`：第一次静默提高上限重发，仍截断则让模型从断点续写；**被截断的工具调用参数绝不执行**，改为要求「分批做」。
3. **故障分类与恢复（D3）**：可重试（429/5xx/超时/连接断/流式卡死）→ 指数退避+抖动、尊重 Retry-After；不可重试（参数错/权限/模型不存在）→ 不重试、改输入；后台辅助调用（标题、事实提取）失败直接放弃、不挤占主链路；每条恢复路径有熔断上限；错误路径上禁止再触发会调模型的副作用（防「死亡螺旋」）；最终报错必须带真实原因 + 已尝试的恢复动作。
4. **工具错误变成模型输入**：未知工具、参数校验失败带约束提示、可修复的畸形参数先程序修复；与已有的指纹检测衔接（在状态栏提示「此调用已第 N 次」，而不是只在最后暂停）。
5. **长输出落盘（D4）**：头尾进上下文，完整输出存 `~/Arslan/.arslan/outputs/…`，结果里写明路径。

验收：
- T5 Pass^3 通过；T1–T6 全部无空错误消息。
- 故障注入测试全过：429、500、超时、**流式卡死**、在「思考中/正文中/工具参数中」三处截断——每种都能恢复或给出带原因的报错。
- 与 P0 基线配对比较：调用次数、输出 token、用时不升反降。

### P2 上下文工程「快、便宜」（约 2–4 天）

1. **状态栏（D6）**：把时间、工作文件夹、后台作业、工具调用计数、TODO 进度从系统提示词移到末尾追加的 `<agent_status>` 消息；系统提示词跨轮字节不变。书中实验：状态栏能把思考 token 和延迟压低约一个数量级，小模型准确率接近大模型。
2. **TODO 工具**：多步骤任务先列清单、逐项更新（书中数据：迭代 21 → 15 次，少遗漏子任务）。
3. **工具描述审计**：每个工具写清「何时用」「做不到什么」，带 1–5 个真实调用示例（书中数据：准确率约 72% → 90%）。
4. **分层压缩**：大工具结果存盘只留预览（替换后冻结，保证缓存）、噪声直接删、全量压缩配熔断；多页网页阅读这类重活可在子上下文里做完只回传结论（先测量再决定是否启用）。

验收：缓存命中率（同轮内、跨轮）有明确提升并记录；T1–T6 上调用次数与花费 ≤ Hermes。

### P3 安全姿态达到 DeepSeek Harness（约 3–5 天）

1. **命令沙盒（D5）**：`run_command` 默认在 macOS 沙盒里跑——可写：工作文件夹 + 临时目录；不可读：`~/.ssh`、钥匙串、Arslan 自己的密钥与数据库；越界时弹卡「这次允许在沙盒外运行」，只能你在窗口里点。复用现有沙盒包装代码（`server/services/code_sandbox.py`）。
   - 诚实说明：macOS 沙盒管得住文件，**管不住「只连某台主机」**（此前实测过），网络出口不靠它承诺。
   - 处理「工具自带沙盒、无法嵌套」的情况（小样里 DeepSeek Harness 就是这样被卡住的）。
2. **证据与指令隔离**：网页、文件、工具输出及其摘要一律是数据；写进长期记忆前要过同等审查（书第 5 章：持久记忆是攻击放大器）。
3. **对外不可逆动作**：保留「先预览、你点确认、再执行」，有条件的加幂等键，失败不盲目重试。

验收：沙盒逃逸测试在 macOS CI 上真跑（写工作区外、读 ~/.ssh、读钥匙串均被拒）；T1–T6 仍全过；记录确认卡数量（打扰不能明显上升）。

### P4 记忆与技能——超过 Hermes 的部分（约 1–2 周，可与 0.1.50 合并）

- 记忆：有界的「关于你」+「Arslan 笔记」两份可直接编辑的文本 + 历史对话全文检索（返回原文而不是摘要）+ 只追加的事实记录（Mem0 v3 思路），第二大脑收进高级视图。
- 技能：复杂任务、从错误中恢复、你纠正过之后，后台提议新建/修补 Skill，经你批准才生效；Curator 定期整理、可回滚。
- 评测：书第 3 章三层记忆评测（基础回忆、多会话检索、主动服务）。

### P5 触达——T6（约 3–5 天）

- 接一个手机渠道（建议 Telegram 机器人起步）：你发消息 → 结构化事件 → Arslan 在家里的 Mac 上干活 → 结果和通知回到手机；确认仍只在窗口里点（或只允许低风险动作远程执行，待定，届时请你拍板）。

## 4. 测量流程与费用

- 每轮对照：6 个任务 × 3 次 × 2 家（Arslan、Hermes）= 36 场；goose 只在需要第二参照时加跑。
- 费用（DeepSeek 今日价，v4-pro）：每轮约 $2–5（非高峰），高峰约 $4–10；计量代理每场、每家、总额三层上限，到顶自动拒绝。
- 计划共 3–4 轮（P1 后、P2 后、P3 后、发版前）→ 总计约 $8–20；每轮开跑前告诉你上限。
- 尽量在非高峰跑（北京时间工作日 09–12、14–18 点是高峰）。

## 5. 决策门（换不换内核）

沿用已约定的规则：P1 完成并跑完 T1–T6 × 3 后，如果 Arslan 仍有 **3 类以上**不同的执行层问题是 Hermes 没有、需要我们逐个补的，就认真转向 Hermes（或把 Hermes 的对应模块整块搬进来）。否则继续本计划。

## 6. 风险

- D1 改动面大：先补测试、小步提交、每步对照，可随时回退到旧协议（保留开关，书第 7 章：每个主要特性可独立关闭）。
- 样本仍小：6 个任务 × 3 次只能说明「在你的任务上」，报告里写清。
- 外部参赛者版本变化：每轮记录版本号；Hermes 每周发版，必要时固定版本。
