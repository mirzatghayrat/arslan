# 0.1.61 PR 1 — the web behind a fake-IP proxy: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** `web_search`, `web_extract` and the agent browser work again on a Mac whose proxy uses
fake-IP DNS (every name → `198.18.0.0/15`), while every private, local and mixed answer stays
refused.

**Architecture:**
- **The rule.** `net_pin._resolve_pinned` learns one narrow exception. A **name** whose IPv4 answers
  all lie in `198.18.0.0/15` passes when either holds:
  - a proxy carries the request (the proxy resolves the name; our process never connects to the
    fake address);
  - the system DNS itself is fake-IP (a public canary name also resolves there; this is TUN mode).
- **The tunnel.** The agent browser's tunnel (`browser_proxy.PublicTunnel`) chains through the
  system proxy **by name** when one is set, instead of dialling the address itself.
- **The error text.** `categorize()` names the guard's own refusal, so search errors stop saying
  "unexpected error".

**Tech Stack:** Python 3.11, httpx, asyncio streams, pytest (`asyncio_mode = "auto"`).

**Spec:** `docs/specs/2026-10-11-0161-smooth.md` §0.3 (evidence) and §E (E1–E4). Approved by the
user 2026-10-11.

## Global Constraints

- Allow-lists, never deny-lists, for network boundaries. The predicate stays `not is_global`. The
  fake-IP exception is one network (`198.18.0.0/15`), only for names, and only under the two
  conditions above.
- **Resolve once.** The target name is looked up once per hop. The canary (`example.com`) is looked
  up **only** when every IPv4 answer is already fake, so ordinary requests never pay for it.
- `allow_host` (a SearXNG address a human typed in Settings) keeps its exemption unchanged. That
  includes local names such as `searx.lan`.
- Both callers (`web_extract` and search) must keep agreeing:
  `tests/server/test_pinning_is_the_same_on_both_paths.py`.
- Tests are hermetic.
  - The developer Mac has a system proxy (`127.0.0.1:7899`) and fake-IP DNS. Every test patches
    `net_pin.getproxies` and `socket.getaddrinfo`.
  - Nothing may reach the real proxy or the real network.
- Before pushing: `.venv/bin/ruff check server tests` is clean (line length 100), `gitleaks dir`
  on the changed files is clean, and the full suite runs as CI runs it
  (`uv sync --frozen --extra dev --extra server --extra ocr`, then `.venv/bin/python -m pytest -q`).
- Do not edit the vendored Hermes files.

## Deviations from the approved spec (flag to the user, asynchronously)

1. **§E1 says "every answer lies in the fake-IP range"; this plan checks every *IPv4* answer.**
   - In fake-IP mode, mihomo with IPv6 enabled also returns an AAAA record (real, or fake ULA).
     Requiring it to be fake would keep the web dead on those setups.
   - Nothing connects to the IPv6 answers here: the fake IPv4 is pinned, or the proxy resolves the
     name itself.
2. **§E1 says the canary "is checked once every 10 minutes"; this plan asks it on demand.**
   - The canary is consulted only after an answer was already fake. The OS caches the lookup.
   - Without a module cache, no state leaks between tests or between a proxy switching on and off.

## Review Focus

These are the five inputs the spec implies but its happy path doesn't exercise. Each has a test in
the owning task.

1. **Dual-stack answers.** A fake A record together with a real or ULA AAAA record (Clash/mihomo
   with IPv6). Expected: allowed, pinned to the fake IPv4. IPv6 answers are ignored in fake mode,
   because nothing connects to them. → Task 1, `test_fake_v4_with_v6_answers_pins_the_fake_v4`.
2. **A fake answer mixed with a private IPv4.** Expected: refused. → Task 1,
   `test_real_private_and_mixed_answers_stay_refused_through_a_proxy`.
3. **The canary on ordinary lookups.** Running it would add a DNS lookup to every request and blur
   "resolve once". Expected: it is never asked for a public answer. → Task 1,
   `test_the_canary_is_asked_only_for_fake_answers`.
4. **A system proxy the tunnel cannot speak to** (`socks5://`, `https://`). Expected: no chaining,
   the direct path as today. → Task 2, `test_only_http_proxies_are_chained`.
5. **The developer Mac's real system proxy leaking into the browser-tunnel tests.** It would make
   them dial `127.0.0.1:7899`. Expected: an autouse fixture keeps them hermetic. → Task 2, Step 1.

```python
#: RFC 2544's benchmarking block. No real host lives here; fake-IP DNS (Clash, Surge,
#: Stash, sing-box, Shadowrocket) hands these out so the proxy can map them back to names.
_FAKE_IP_NET = ipaddress.ip_network("198.18.0.0/15")
#: A public name whose answer says whether the system DNS is fake-IP. IANA's, stable.
_FAKE_IP_CANARY = "example.com"
#: Names that are never on the public internet, whatever a resolver answers for them.
_LOCAL_SUFFIXES = (".localhost", ".local", ".lan", ".internal", ".intranet", ".home.arpa",
                   ".corp")


def _is_local_name(host: str) -> bool:
    name = host.lower().rstrip(".")
    return name == "localhost" or name.endswith(_LOCAL_SUFFIXES)


def _is_ip_literal(host: str) -> bool:
    try:
        ipaddress.ip_address(host.strip("[]"))
    except ValueError:
        return False
    return True


def _all_fake_v4(ips: list) -> bool:
    """Every IPv4 answer lies in the fake-IP block. IPv6 answers are ignored: in fake mode
    nothing connects to them (we pin the IPv4, or the proxy resolves the name itself)."""
    v4 = [ip for ip in ips if ip.version == 4]
    return bool(v4) and all(ip in _FAKE_IP_NET for ip in v4)


def _fake_ip_dns() -> bool:
    """Is this Mac's DNS fake-IP (a TUN-mode proxy)? Asked only after an answer was already
    fake, so an ordinary lookup never pays for a second one."""
    try:
        infos = socket.getaddrinfo(_FAKE_IP_CANARY, 443, type=socket.SOCK_STREAM)
    except OSError:
        return False
    return _all_fake_v4([ipaddress.ip_address(info[4][0]) for info in infos])
```

```python
async def _upstream(record: list, reply: bytes = b"HTTP/1.1 200 Connection established\r\n\r\n"):
    """A stand-in for the user's proxy: records the CONNECT it got, answers `reply`, and on
    200 echoes the first tunnelled bytes back."""
    async def handle(reader, writer):
        try:
            record.append(await reader.readuntil(b"\r\n\r\n"))
            writer.write(reply)
            await writer.drain()
            if reply.startswith(b"HTTP/1.1 200"):
                writer.write(await reader.read(100))
                await writer.drain()
        finally:
            writer.close()
```

```python
def _upstream_proxy(host: str) -> tuple[str, int] | None:
    """The system or environment HTTPS proxy to chain through, as (host, port). Only plain
    http:// proxies speak CONNECT the way this tunnel does; anything else (socks, https)
    keeps the direct path."""
    proxies = net_pin.getproxies()
    if not proxies:
        return None
    raw = proxies.get("https") or proxies.get("all")
    if not raw or net_pin.proxy_bypass(host):
        return None
    parsed = urlsplit(raw if "://" in raw else f"http://{raw}")
    if parsed.scheme != "http" or not parsed.hostname:
        return None
    return parsed.hostname, parsed.port or 80
```
