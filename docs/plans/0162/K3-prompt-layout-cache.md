## 目标

系统提示只放静态内容，每轮都变的内容挪到本轮用户消息开头，让缓存命中。本地工具输出不再被标成「外部网页内容」（0.1.62 计划 K-5、K-6）。

## 改哪些文件

- `server/orchestrator/arslan.py`
  - `:383-390`：把 `volatile`（事实、摘要、知识库、MCP 状态、回复语言、当前时间）拼成一个上下文块，放进本轮用户消息开头。
  - 删 `_team_roster()` 的两处调用（`:726`、`:759`；定义在 `:416`），结果没被使用。
- `arslan/llm/cached_system.py:31`：系统提示保持字节级不变。
- `arslan/llm/providers/anthropic_provider.py:175-204`：4 个滚动断点（系统 + 最后 3 条消息）。TTL：人在聊天用 1 小时，后台任务用 5 分钟。1 小时 TTL 的写法，按当时的官方文档确认（本卡未核）。
- 工具列表按名字排序（`server/orchestrator/tool_loop.py:1713` 的 `_native_tool_schemas`）。
- `server/orchestrator/tool_loop.py:347` 与 `server/orchestrator/untrusted.py:16-38`
  - 本地文件和命令输出换成「工具输出，仅数据」标记；网页内容保留现有标记。
  - 两种标记都走同一个去伪造逻辑（`_strip_injection`）。
- 网页用量浮窗显示缓存命中率（找到 0.1.58 的用量组件再改）。6 种语言的新文案按冲突协议加。
- 测试：两轮之间事实、时间、语言都变时，系统提示字节不变；注入测试照旧通过。

## 不许碰

- 历史预算与压缩（K2 已做）；工具按需加载（K7）。

## 怎么做（要点）

1. 先写「缓存前缀不变」的断言测试，确认今天会失败。
2. 挪 `volatile`，让测试通过。
3. 再加断点和 TTL，用 M1 的多步题看 `cache_read`。

## 验收

- 断言测试在 CI；注入测试全过。
- **M1（贴在 PR 里）：** 多步题里 Anthropic 的 `cache_read` 占输入 ≥60%；各题成功率不差于 K2 之后；贴每题成本对比。

## 量级

产品代码约 ±120 行，外加前端一个小改动和 6 种语言的文案。

## 风险与回退

- **风险：** 上下文块放进用户消息后，模型对「当前时间、回复语言」的遵守可能变化。用 M1 的语言题和时间题看。
- **回退：** 断点和 TTL 改动可以单独回退；布局改动回退要整 PR revert。
