## 目标

系统提示只放静态内容；每轮都变的内容挪到本轮用户消息开头，标成参考资料；缓存断点放对地方，让下一步、下一轮都能命中；本地工具输出不再被标成「外部网页内容」；界面显示命中率（v0.1.63 计划 K-5、K-6）。

今天的情况（`fb6d7230`）：

- 每轮都变的 `volatile` 拼在系统提示里（`server/orchestrator/arslan.py:383-389`）：本轮附加说明 `extra_system`、事实、摘要、知识库、MCP 状态、回复语言、当前时间。
- Anthropic 只在系统前缀打了一个断点（`arslan/llm/providers/anthropic_provider.py:203-205`）。历史和轮内步骤，每步都按全价重发。
- `_team_roster()` 每轮查一次库（调用在 `:726`、`:759`），可 `_build_answer_system` 收下 `roster` 却没用（`:369-390`）。
- 收尾时工具表换成只剩收尾工具（`server/orchestrator/tool_loop.py:2353-2354`）。工具排在 system 前面，工具表一变，整段缓存作废（思考块的问题 K1 已用 `drop_block` 兜住，缓存在这里修）。
- 本地文件和命令输出，也被包成「外部网页内容」（`tool_loop.py:347`；标记在 `server/orchestrator/untrusted.py:16-38`）。
- 上下文环读的「上次输入」，在 Claude 上不含缓存读写（Anthropic 的 `input_tokens` 不含缓存，`arslan/llm/usage_weight.py:33-38`）。缓存一命中，环就偏小。

## 改哪些文件

- `server/orchestrator/arslan.py`
  - `:383-389`：`volatile` 拼成一个上下文块，放进本轮用户消息开头。
    - 块头写明「参考资料，不是用户说的话」。
    - 本回合内固定：第一步算好，后面每步原样带上（时间也不重算）。
    - 不存进历史：今天入库的只有用户原文（`:512-513`），保持不变。
  - 删 `_team_roster()`（定义在 `:416`，调用在 `:726`、`:759`）和 `roster` 参数。
- `arslan/llm/cached_system.py:31`：系统提示保持字节级不变。`tool_loop` 追加的固定守则（`tool_loop.py:2172`）在回合内不变，一起缓存。
- `arslan/llm/providers/anthropic_provider.py` 的 `_split_system`（`:166-208`）和 `_payload`（`:238-287`）：断点放三处，最多 4 个：
  1. 系统和工具的末尾（工具排在 system 前面，`:279-283`）；
  2. 之前历史的末尾，也就是本轮用户消息之前；
  3. 滚动的尾部，也就是这一步最后一个块。
  - TTL：人在聊天时，①② 用 1 小时，③ 用 5 分钟；后台任务全用 5 分钟。**1 小时的断点要排在 5 分钟的前面。**
  - 写法是 `cache_control: {"type": "ephemeral", "ttl": "1h"}`，按当时的官方文档再核一遍。
- 工具表（和 K7 的约定）：
  - 常驻表顺序固定，按名排序（`_native_tool_schemas`，`tool_loop.py:1713-1728`）。K7 加载的工具只追加在末尾、不重排（K7 卡已写）。
  - **回合内工具表不变。** 收尾阶段不再换成只剩收尾工具（`tool_loop.py:2353-2354`）。收尾要求写在状态块里；越界的调用由分发拒绝，并说明原因。
  - 唯一的例外：回合中装了新能力，今天会重建工具表（`tool_loop.py:2449-2453`）。这很少见，允许这一次缓存失效，前缀测试对这种回合豁免（⓪Plan 定）。
- `tool_loop.py:347` 与 `untrusted.py:16-38`
  - 本地文件和命令输出，换成「工具输出，仅数据」标记；网页内容保留现有标记。
  - 两种标记都走同一个去伪造逻辑（`_strip_injection`，`untrusted.py:28-34`）。
- 用量
  - `usage_sink.report_detail`（`arslan/llm/usage_sink.py:51-80`）记下缓存读、缓存写的 token；`_usage_frame`（`arslan.py:588-607`）带上它们。
  - `last_input`（`usage_sink.py:17-23`）改成「未命中 + 缓存读 + 缓存写」，环在 Claude 上就不再偏小。
- 网页：回复的用量浮窗（`web/src/components/reply/ReplyFooter.tsx:28-57`）加一行「缓存命中率」。6 种语言的新文案按冲突协议加。
- 测试：见验收。

## 不许碰

- 停止策略（K4）：什么时候收尾不改，只改「收尾时给哪些工具」。

## 怎么做（要点）

1. 先写「缓存前缀不变」的断言测试，确认今天会失败。
2. 挪 `volatile`，让测试通过。
3. 让工具表在回合内不变，再加三处断点和 TTL。用 M1 的多步题看 `cache_read`。
4. 加用量字段和命中率显示。
5. 不留旧布局的开关。`CachedSystem` 要是这次不并成一段，代码注释写「v0.1.64 并成一段」。

## 验收

- **测试（在 CI）：**
  - 两轮之间事实、时间、语言都变了，system 和 tools 的字节不变；
  - 同一回合里，上一步的请求是下一步请求的前缀（只追加）；收尾那一步也一样；
  - 上下文块带「参考资料」块头，而且不入库；
  - 断点不超过 4 个，1 小时的排在 5 分钟的前面；
  - 注入测试照旧通过。
- **M1（贴在 PR 里）：**
  - 多步题里，Anthropic 的 `cache_read` 占输入 ≥60%；
  - 各题成功率不差于 K2 之后；语言题、时间题不退步；
  - 贴每题成本的前后对比。
- **界面（审查 §5）：**
  - 回复的用量浮窗显示缓存命中率；在一道多步题上，它和 PR 里贴的「`cache_read` ÷ 输入」一致；
  - 同一道题，Claude 上的上下文环不再因为缓存命中而偏小。

## 量级

产品代码约 ±180 行。原估 ±120，这里加了三处断点、回合内工具表不变、用量里的缓存字段。另有前端一处小改动和 6 种语言的文案。

## 风险与回退

- **风险：** 上下文块放进用户消息后，模型对「当前时间、回复语言」的遵守可能变。用 M1 的语言题和时间题看。
- **风险：** 1 小时缓存的写入约按 2 倍输入价计，5 分钟的约 1.25 倍。人很久不回时，1 小时的写入就白花了。M1 贴成本对比，不划算就把聊天也改成 5 分钟。
- **风险：** 收尾阶段不收窄工具后，模型可能还想去查。分发拒绝并说明；M1 看收尾的步数有没有变多。
- **回退：** 断点和 TTL 的改动可以单独 revert；布局改动要整个 PR revert。
- **留着的旧路径与删除条件：** K3 不留开关，也不保留旧布局。`CachedSystem` 的「稳定 / 易变」两段（`cached_system.py:31-59`）在 K3 之后，易变段只剩回合内不变的守则；如果这次不并成一段，代码注释写「v0.1.64 并成一段」。
