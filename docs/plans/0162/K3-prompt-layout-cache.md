## 更正与实施记录

- **两个前提问题（⓪Plan 2026-10-20 定）：**
  - **工具表跨轮：** 按名排序（本卡原文，K7 的「只追加在末尾」靠它），`escalate` 排最后。**不按对话冻结**：MCP 服务器连上、Hands 连上、`propose_capability` 装好的能力，都要在当前对话里看得见。技能索引留在工具表里：① 同时缓存工具表和 system，挪进 system 尾部没有好处，挪进本轮参考块反而每轮第一步都不缓存。工具表只在环境变时变（Hands、浏览器、MCP 就绪、技能增删开关、读文件和工作区设置），每次算 ① 一次未命中。
  - **历史跨轮不是字节稳定的（K2 的遮盖和截断）：** 接受，量出来再说。遮盖只在越过 4 轮那条线的回答带 `<turn_tools>` 时改字节，不带工具的回合不受影响；历史预算满了以后，最旧的消息每轮被截掉，直到压缩把它折进摘要，这期间 ② 每轮都不命中。M1 报跨轮的 `cache_read`，以及 ② 的未命中率（分「遮盖」和「截断」两种原因）。未命中率高，才在 K2 卡上跟进「按 4 轮一块遮盖」。
- **TTL 只发给认得的端点（⓪Plan 定）：** `ttl: "1h"` 只发给 `_clears_server_side()` 为真的端点，也就是 Anthropic 官方主机，或者白名单里的直通代理（和 K1b 的服务端清理同一道门）。其他走 Anthropic 协议的端点照旧只发普通的 `{"type": "ephemeral"}`。再加一道：`param_heal` 能丢掉被拒的 `ttl`（从每个标记里），重发，记下来，运行记录里记一次 `cache_ttl_off`。
- **断点怎么放（实施）：** `tool_loop` 用 `trajectory.request()` 标出本轮的请求，Anthropic 的 `build_trajectory_messages` 据此记下历史最后一块的位置；`_payload` 只在原生请求上打三处标记（`_mark_cache`），打在复制出来的块上，轨迹里原样保存的块（回放的思考块）不会被写进去。思考块和空文本块不能带标记，往前找能带的那一块。旧协议的请求不变。
- **聊天用 1 小时、后台用 5 分钟：** `request_policy.prompt_cache(long=...)`。聊天回合进入 `long=True`；后台任务显式进入 `long=False`，因为它可能是在聊天回合里启动的，会继承上下文。
- **回合内工具表的例外（各算一次未命中，前缀测试对这种回合豁免）：** 回合中装了新能力；provider 拒了某个 MCP 工具的 schema（0.1.62 F3）；重试时的 `relax()`。
- **收尾不再收窄工具表：** 状态块写「仍能用的工具：…；其他调用会被拒绝」，越界的调用由分发拒绝并说明原因（原有的 `code: "wrap_up"`）。
- **本地工具输出的标记：** 关键字用 `ARSLAN_TOOL_OUTPUT`（带前缀，免得误伤代码里正常出现的 `TOOL_OUTPUT`）。网页、浏览器、MCP、联网的命令仍用 `EXTERNAL_WEB_CONTENT`。两个关键字在两种框里都会被去伪造。`GUARD_NOTE` 加了一句说明这种框。「本回合读过外部内容」的判断照旧按工具来（`counts_as_external`），不看框，所以联网前要确认、学到的做法不立即生效这些规则都不受影响。
- **K1 回滚 golden：** 只因为 `GUARD_NOTE` 这一句而变（⓪Plan 同意：回滚要保的是 v0.1.62 的线上格式，没变）。测试用 sha256 钉住「去掉这一句就等于 v0.1.62 录下的那份」。
- **记忆证据（K3 引出的修正）：** 记忆从 system 挪进了本轮参考块，记忆收据数「请求次数」时原来只看 system 字段，会数不到。现在也认请求开头的参考块（`personal_context._turn_reference`），只认开在用户消息最前面、最新的那一块，用户自己话里引用的块不算。
- **`_team_roster` 删了：** 每轮查一次库，结果从来没用上。
- **量级：** 产品代码约 +350 / −120 行，网页 +11 / −3。比估的 ±180 多：收尾的状态说明、记忆证据的修正、四家用量的缓存字段归一、注释。
- **留着的旧路径：** `CachedSystem` 的两段，**v0.1.64 并成一段**（代码注释里写了）。K3 没有开关，不保留旧布局。

## 目标

系统提示只放静态内容；每轮都变的内容挪到本轮用户消息开头，标成参考资料；缓存断点放对地方，让下一步、下一轮都能命中；本地工具输出不再被标成「外部网页内容」；界面显示命中率（v0.1.63 计划 K-5、K-6）。

今天的情况（`fb6d7230`）：

- 每轮都变的 `volatile` 拼在系统提示里（`server/orchestrator/arslan.py:383-389`）：本轮附加说明 `extra_system`、事实、摘要、知识库、MCP 状态、回复语言、当前时间。
- Anthropic 只在系统前缀打了一个断点（`arslan/llm/providers/anthropic_provider.py:203-205`）。历史和轮内步骤，每步都按全价重发。
- `_team_roster()` 每轮查一次库（调用在 `:726`、`:759`），可 `_build_answer_system` 收下 `roster` 却没用（`:369-390`）。
- 收尾时工具表换成只剩收尾工具（`server/orchestrator/tool_loop.py:2353-2354`）。工具排在 system 前面，工具表一变，整段缓存作废（思考块的问题 K1 已用 `drop_block` 兜住，缓存在这里修）。
- 本地文件和命令输出，也被包成「外部网页内容」（`tool_loop.py:347`；标记在 `server/orchestrator/untrusted.py:16-38`）。
- 上下文环读的「上次输入」，在 Claude 上不含缓存读写（Anthropic 的 `input_tokens` 不含缓存，`arslan/llm/usage_weight.py:33-38`）。缓存一命中，环就偏小。

  - 断点不超过 4 个，1 小时的排在 5 分钟的前面；

  - 各题成功率不差于 K2 之后；语言题、时间题不退步；
  - 贴每题成本的前后对比。

  - 回复的用量浮窗显示缓存命中率；在一道多步题上，它和 PR 里贴的「`cache_read` ÷ 输入」一致；

## 风险与回退

- **风险：** 上下文块放进用户消息后，模型对「当前时间、回复语言」的遵守可能变。用 M1 的语言题和时间题看。
- **风险：** 1 小时缓存的写入约按 2 倍输入价计，5 分钟的约 1.25 倍。人很久不回时，1 小时的写入就白花了。M1 贴成本对比，不划算就把聊天也改成 5 分钟。
- **风险：** 收尾阶段不收窄工具后，模型可能还想去查。分发拒绝并说明；M1 看收尾的步数有没有变多。
- **回退：** 断点和 TTL 的改动可以单独 revert；布局改动要整个 PR revert。
- **留着的旧路径与删除条件：** K3 不留开关，也不保留旧布局。`CachedSystem` 的「稳定 / 易变」两段（`cached_system.py:31-59`）在 K3 之后，易变段只剩回合内不变的守则；如果这次不并成一段，代码注释写「v0.1.64 并成一段」。
