## 目标

下一轮知道上一轮做了什么、动了哪些文件；历史长度按模型窗口算，不再固定 3,000；回合后的抽事实和压缩不再挡住下一条消息（0.1.62 计划 K-2）。

## 改哪些文件

- `server/orchestrator/memory.py`
  - `:19` 的 `_DEFAULT_TOKEN_BUDGET = 3000` 改为模型窗口的一定比例。窗口从 `server/services/model_catalog.py`（`context_window`，`:63-68`）取；取不到时用保守默认值。
  - `:100-170`：只在约 75% 时压缩一次，并保留最近 N 轮原文。
  - 先把旧工具输出换成占位（免费），不够再摘要。
  - 摘要用固定结构（目标、进度、决定、动过的文件、下一步），原地更新。
- `server/services/memory_history.py`：`eligible_messages` 纳入新的 `role="tool_digest"`。
- `server/orchestrator/arslan.py`
  - `:513`、`:904` 旁边，在回合结束时写一条工具摘要：工具名、关键参数、结果前约 500 字或落盘路径。
  - `:540-545` 的 `turn_facts.capture` 和 `memory.maybe_compact` 挪到回合锁外（锁在 `server/ws/arslan.py:266-268`，调用点 `:708`、`:740`、`:801`）。
- 显示与外发要把 `tool_digest` 滤掉：网页消息列表、`server/api/conversations.py`，以及 iPhone 读历史的 `server/services/phone_reads.py`。这是 Bridge 契约，帧格式不变，只是不发这类行。
- 测试：见验收。

## 不许碰

- Bridge 帧格式；记忆 v2 的长期记忆存储（C2a 只删 v1 死分支）。
- 提示词布局（K3）。

## 怎么做（要点）

1. 先写测试：窗口 200k 的模型和窗口 32k 的模型，进提示词的历史上限不同。
2. 工具摘要在回合结束时由 `tool_trace` 生成，一个回合一条。
3. 锁外的抽事实和压缩：回合返回后排一个后台任务；下一轮组装历史时读已提交的状态，不等它。
4. 先遮蔽、后摘要：参考领先路线 L8 和 JetBrains 研究。

## 验收

- **测试：**
  - 历史上限随窗口变化；
  - 压缩只在约 75% 时触发一次，最近 N 轮保留原文；
  - 下一轮的提示词里有上一轮的工具摘要；
  - 第二条消息不等抽事实结束就开始；
  - `tool_digest` 不出现在网页、API 和 iPhone 的消息列表里。
- **M1（贴在 PR 里）：** 三轮追问题 3/3；其余题不差于 K1 之后。
- **M2（装上后 7 天）：** 回合后的调用不再挡住下一条消息。

## 量级

产品代码约 +200 / −100 行。

## 风险与回退

- **风险：** 大窗口模型的 token 成本上升。给历史上限加封顶（例如窗口的一半，且不超过一个固定值），数值在 PR 里写明。
- **风险：** 锁外任务和下一轮并发写摘要。用每个对话一把小锁，只保护摘要写入，或用版本号丢弃过时结果。
- **回退：** 一个设置切回旧预算；工具摘要写入可单独关掉。
