## 用户定的方向（2026-10-20，原话整理）

1. **这一轮所用模型自带的搜索：** D5，再加 OpenAI、Gemini。
2. **Arslan 自己的浏览器搜索：** 复用 agent_browser 的托管 Chromium，参考 GitHub 上 kuraneko1/chrome-web-mcp 的做法。
   - 后台运行；首次安装时在后台把 Chromium 装好；
   - 多个搜索引擎依次换，被验证拦了就冷却、换下一家；控制节奏；
   - 结果抽成「标题、链接、摘要」；
   - 全部被拦才报「搜索被拦」，并提供打开窗口手动验证；
   - 它取代现在直接抓 DuckDuckGo 网页的那一档。
3. **用户自己配的 key：** D5 的 only / backup。
4. **官方免 key 接口**（Parallel 搜索 MCP、Firecrawl 免 key 档）：默认关，首次问一次同意，本地模型的对话不走，上线前核对条款。

第②层要先量：在 bench 上，DeepSeek 关掉自带搜索、只用第②层，跑 T2、T3，看被拦率和通过数。

## 顺序（⓪Plan 的读法，和 D5 的规矩合在一起）

| 设置 | 顺序 |
|---|---|
| 没选搜索服务 | ① → ② → ④（④ 只在用户同意过、且这一轮不是本地模型时） |
| 选了服务，「作备选」 | ① → ③ |
| 选了服务，「只用它」 | ③ |

- **②不放在③前面，选了服务就不走②和④。** 这是 D5 里 ③Hands 提的规矩：用户选了一家搜索服务，查询就不该再发给用户没选的地方。第②层会把查询发给公开搜索引擎，第④层发给 Parallel、Firecrawl，都算「没选的地方」。
- 用户的原话是 ①②③④ 的顺序。我的读法是：四层是「没选服务」时的自动顺序，③的两种用法照 D5。**你要是想让「作备选」也走②，告诉我，改这一行就行。**
- 本地模型的对话：①不用（D5 的规矩），④不走（用户定的），②照用。②就是本机浏览器去公开搜索引擎，和今天抓 DuckDuckGo 是同一类去处。
  - **但默认第一家是 Google**（③Hands 审卡指出）：今天本地对话的搜索只去 DuckDuckGo，以后会先去 Google。是加一个「搜索引擎」设置，还是本地对话默认 DuckDuckGo 打头，由用户定，见「风险」。
- 临时对话（`task_context.is_temporary`）不走④。

## 第①层：这一轮模型自带的搜索（D5 再加 OpenAI、Gemini）

规矩全照 D5：
- 按这一轮的 adapter 选，本地模型不用；
- 只在官方 host 上用；
- 一小轮专门的搜索请求，结果只从结构化的块里取；
- 用量计进预算；
- `max_uses` 或同类上限封顶 1–2 次。

| 家 | 怎么调（⓪Plan 2026-10-20 读官方文档） | 结果从哪取 | 价钱 |
|---|---|---|---|
| Anthropic | D5 | `web_search_tool_result` | D5 |
| OpenAI | Responses API 的 `{"type": "web_search"}`（`web_search_preview` 是旧的）；Chat Completions 只能用专门的搜索模型 `gpt-5-search-api`（`gpt-4o-search-preview` 已在 2026-07-23 下线） | `web_search_call` 和 `url_citation`；加 `include: ["web_search_call.action.sources"]` 拿全部来源 | 每 1000 次 $10，另计搜到内容的 token |
| Gemini | generateContent 的 `tools[].googleSearch`；新的 Interactions API 是 `{"type": "google_search"}` | `groundingMetadata.groundingChunks[].web{uri, title}` | Gemini 3 以上按查询计，每月 5000 次免费，之后每 1000 次 $14 |

- **Gemini 要先过条款**（2026-03-23 版）。条款要求：
  - 搜索结果要连同 Google 的「搜索建议」（`searchEntryPoint`）一起显示；
  - 只能用在「你自己拥有并运营的应用」里；
  - 不能缓存结果、不能拿去训练。

  Arslan 会把工具结果存进对话记录和 `tool_outputs/`，这可能就算缓存。**上线前核对；做不到就不做 Gemini 这一档**，Gemini 用户落到第②层。
- OpenAI 的条款要求引用可点击；Arslan 的搜索结果本来就带链接，开工时核对一遍。
- **门只认官方地址**（③Hands 审卡）：OpenAI 只认 `api.openai.com`，Gemini 只认 `generativelanguage.googleapis.com`。Azure、OpenRouter 和别的兼容端点不用这一档。
- Gemini 的 `searchEntryPoint` 是一段 HTML，只能放进沙箱化的 iframe 里显示；做不到就不做 Gemini 这一档。
- 每家都写测试，覆盖三种情况：结构化结果、没有结果块、错误对象。门也照 D5 写测试。

## 第②层：Arslan 自己的浏览器搜索（取代直接抓 DuckDuckGo）

**参考：** kuraneko1/chrome-web-mcp（MIT 许可，⓪Plan 读的是 `dba1ff62cd`，2026-10-15）。它的 README 说历史会被 force-push。借代码时：
- 钉住这个 SHA；
- 在第三方声明里保留 MIT 的版权行。

**照它做的：**
- **搜索引擎轮换：** 默认顺序 Google（`udm=14` 的纯网页结果）→ DuckDuckGo HTML → Brave → Bing。第一家拿到可用结果就停。
- **认人机验证：** 查页面上的验证表单，以及 Google 的 `/sorry` 路径。表单包括：
  - `form[action*="/sorry"]`、`#captcha-form`、`#challenge-form`、`form[action*="challenge"]`；
  - reCAPTCHA 和 challenge 的 iframe。

  再配上「unusual traffic」「not a robot」「captcha」这类字眼。
- **冷却：** 被拦一次冷却 5 分钟，连续被拦翻倍，最多 30 分钟。下一次在这家成功就清零。
  - chrome-web-mcp 只对 Google 真跳过；**这里每一家都真跳过。**
  - 冷却状态存在数据目录里，重启不丢。
- **节奏：**
  - 同一时间只跑一个搜索；
  - 两次搜索之间随机隔 1.0–2.5 秒；
  - 每家每小时最多 60 次，用完这家就跳过。
- **抽结果：** 每家一组选择器，抽成「标题、链接、摘要」，把 DuckDuckGo 和 Bing 的跳转链接还原成真链接。provider 记成 `browser:<引擎>`，标 `best_effort`。

**和它不一样的（⓪Plan 定）：**
- **不注入「伪装成真人」的脚本，不伪造浏览器指纹。** chrome-web-mcp 会注入 stealth 脚本。这里被拦就老实冷却、换下一家；全拦了就请用户自己去验证，不去绕开网站的人机验证。
- **用自己的搜索专用资料夹**（`<data>/search_browser/profile`），长期保留，验证过的 cookie 能留下来。**不用 agent_browser 那个用户登录过的资料夹**，搜索记录不进用户的 Google 账号。
- 网络照走 `browser_proxy.PublicTunnel`（只连公网），和 agent_browser 一样。
- **以下几条是 ③Hands 审卡加的：**
  - **平时在后台跑，不开窗口**（`--headless=new`）。只有「打开窗口手动验证」那一次开可见窗口，而且只在用户点了按钮以后开，不抢焦点。
  - **资料夹锁紧：** 不下载、只开 http(s)、不装扩展。搜索结果照 `web_search` 今天的做法，算外部内容。
  - **验证窗口上写明「这里不要登录」。** 设置里加「清除搜索浏览器数据」按钮：长期保留的 cookie 会把所有搜索串在一起。
  - **模型没有任何办法打开验证窗口，** 只有用户点按钮。
  - **备份不带它：** `search_browser` 不进 `backup.ASSET_DIRS`。
  - 借代码时回源核对 chrome-web-mcp 仓库里的 LICENSE 文件，不只看 GitHub 的许可证字段。

**后台安装（用户定的：首次安装时在后台装好）：**
- **今天的情况：** 托管运行时第一次用到浏览器时才装，约 1–2 分钟（`hands_tools._run_setting_up_once`，0.1.48）。它只装了 headless shell（`playwright install chromium --only-shell`），而且**要求用户的 Mac 上有 node 和 npm**（`managed_browser.status` 的 `node_required`）。
- **要改的：**
  1. 首次运行时在后台开始装，设置 › 高级里显示进度和大小。
  2. 装完整的 Chromium，不只是 headless shell。「打开窗口手动验证」要一个能开窗口的浏览器；chrome-web-mcp 也说老式 headless 更容易被认成机器人。
  3. 去掉对用户自己装的 node 的依赖，否则大部分用户这一层根本用不上。怎么去由 ②Main 开工时定，比如用 Playwright 自带的 driver，或者随 App 带一个 node。
- **装不上**（没网、磁盘不够）：这一层不可用，设置里写原因，搜索顺序跳过它。

**全部被拦时：**
- 报 `search_blocked`，逐家写「被拦 / 冷却中，还剩几分钟」。
- 回答里给一个「打开窗口手动验证」的按钮：在同一个搜索资料夹里开一个可见窗口，停在被拦那家的页面上。用户点完验证、关掉窗口，再搜一次。
- 只在 Mac 的 Arslan 窗口里有这个按钮。手机上只说「搜索被拦，回到 Mac 上验证」。

## 第④层：官方免 key 接口（默认关）

| 服务 | 接口 | 限额 | 条款里要核的（⓪Plan 2026-10-20 读到的） |
|---|---|---|---|
| Parallel 搜索 MCP | `https://search.parallel.ai/mcp`（Streamable HTTP），不要 key、不要账号 | 没公布具体数字；匿名时强制 `fast` 模式，每次输出约 2.5 万字符 | 客户条款 §4(b) 写着可以拿客户内容训练模型，FAQ 却说不用客户数据训练；匿名免费使用受哪份条款管不清楚；隐私政策没写保存多久 |
| Firecrawl 免 key 档 | `POST https://api.firecrawl.dev/v2/search`，或 MCP `https://mcp.firecrawl.dev/v2/mcp` | 按 IP 按天限，具体数字没公布；超了回 429 | 服务条款（2026-10-07）§5.d.1 禁止未经授权的商业用途；§8.d 要你授予它对提交内容的永久免费许可；隐私政策没有零保留承诺，也没提训练 |

- 默认关。**每一家分开问一次同意**（③Hands 审卡）：写明会把搜索词发给这一家、对方条款的要点。以后不再问，设置里可以随时撤回。
- 本地模型的对话、临时对话都不走这一层。
- 被限流（429）、被拦，照 D5 的规矩报，不报「没有结果」。
- **上线前核对条款是硬门槛**：
  - 上表的问题要有书面答案，比如问对方，或者等条款更新；
  - 核对的结论写进 PR；
  - 哪一家过不了就不上哪一家。

## 第 0 步：先量第②层（用户要求）

- **做法：**
  - 先做一个最小的第②层：只有引擎轮换、认验证、冷却、节奏、抽结果，不做界面和后台安装。
  - 加一个只给 bench 用的开关，关掉第①层、只用第②层。这个开关是环境变量，不进设置页；本卡做完就删，删除条件写进代码注释。
  - 在 bench 上用 DeepSeek 跑 T2、T3，各 3 次，每格全新实例。
- **记录：**
  - 每次搜索用了哪家、有没有被拦、有没有在冷却；
  - 每家的被拦率（被拦次数 / 尝试次数），全部被拦的次数；
  - T2、T3 的通过数和花费。
- **对照：** 同一构建、开着 DeepSeek 自带搜索的 T2、T3（K3 的 `k3-ds` 是 2/3、2/3），以及 Hermes（3/3、3/3）。
- **要注意：** bench 是短时间里连着搜，比一个人平时用要密得多，算是最坏情况。被拦率要分开写「一格里的第几次搜索被拦」。
- **⓪Plan 提议的判法（等用户确认）：**
  - 「全部被拦」一次都没发生，并且 T2 + T3 的通过数不比开着自带搜索时低 1 个以上：做完整的第②层，取代 DuckDuckGo 那一档；
  - 不然先停，把数字拿给用户看。

## 不做

- 不注入伪装脚本，不伪造浏览器指纹，不自动去点或解人机验证（见第②层）。
- 不用用户登录过的浏览器资料夹搜索。
- 不把第④层默认打开。
- 不改 `web_extract`（打开某个网页读全文）。

  - 每家的门（第①层）：只在官方 host、按这一轮的模型选、本地模型不用。

- **在 Mac 上实测：**
  - 全新安装后后台装好浏览器；
  - 没装 node 的 Mac 上也能用；
  - 被拦以后按「打开窗口手动验证」，验证完再搜能过。

## 风险

- **搜索引擎的条款：** Google、Bing 的服务条款一般不允许自动查询。chrome-web-mcp 这样做，Arslan 是在用户自己的电脑上、按人的节奏、替用户搜。上线前核对各家条款，由用户决定接受到什么程度。
- **本地模型的对话会先去 Google**（今天只去 DuckDuckGo）。要不要加引擎设置、或本地对话默认 DuckDuckGo 打头，由用户定。
- **被拦率可能很高：** 第 0 步就是为了先知道这一点。
- **安装体积：** 完整 Chromium 比 headless shell 大，后台下载要在设置里写清楚大小。
- **第④层的条款**（见上表），**以及 Gemini 的条款**（不缓存、显示搜索建议）。
