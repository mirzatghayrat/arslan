## 目标

没有工具调用的回答，一边生成一边显示。今天的做法是先整段生成，过完一串检查，再用 `_reveal_streamed` 假打字放出来（0.1.62 计划 K-6）。

## 改哪些文件

- `server/orchestrator/tool_loop.py`
  - `_reveal_streamed`：定义在 `:1985`，调用点在 `:2043`、`:2165`、`:2639`，去掉；
  - 回答出门前的检查在 `:2563-2641`：空头承诺、拖延、协议文字、能力否认、任务验收。
- 只留一条硬规则：**绝不显示原始的工具调用 JSON。** 流式时按块检查，命中就停流，改走现有的处理。
- 其余检查改成生成后再追加更正。`promise_guard` 已经是这个形状（`server/orchestrator/arslan.py:878` 一带）。
- 修正误伤的词表：例如 `tool_loop.py:104-106` 的 `_CLAIMS_SEARCH_RE`，在只读了本地文件、没用过 `web_search` 的回答里也会命中「查到」。
- 守卫反弹不再计入「没有进展」（配合 K4 的停止策略）。
- `arslan/llm/stream_assembly.py` 与各供应商的 `chat_stream`：文本增量直接转成现有的 `stream_chunk` 帧。

## 不许碰

- **帧格式。** 更正只能用现有帧追加，不新增「替换」类帧。iPhone 已能接收逐段消息（`stream_chunk`），改帧格式就会影响 ①iOS。
- 守卫本身的判定逻辑。D6 要求先全部保留，再由跑分决定哪些只对弱模型开。

## 怎么做（要点）

1. 先写测试：用一个假的流式供应商量首字延迟，确认今天首字要等整段生成完。
2. 改成流式后，诚实类测试全部照旧通过。这些测试找 `promise_guard`、`capability_truth`、`tool_loop` 的现有测试文件。
3. 更正用一条追加的消息块，文字说明「更正：……」。

## 验收

- **测试：** 首字延迟接近模型首字；诚实类测试全过；原始工具 JSON 永远不显示。
- **M1（贴在 PR 里）：** 每题首字延迟、总时长、成功率不差于 K6 之后。
- **手动：** 用 Claude 时，没有工具调用的回答边生成边出现，iPhone 上也一样（§5.3 第 7 条）。

## 量级

产品代码约 −500 / +100 行。

## 风险与回退

- **风险：** DeepSeek 一类模型更容易谎称做完了。改成事后更正以后，用户会先看到错话，再看到更正。按 D6，由跑分决定哪些守卫只对弱模型保持拦截，这个开关做成按模型配置。
- **回退：** 设置项「回答完整生成后再显示」。
