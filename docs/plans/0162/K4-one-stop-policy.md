# K4 一个停止策略，聊天和后台同一套规矩

| 项 | 内容 |
|---|---|
| 道 | ②Main（Hands 聊天上限由 ③Hands 在 H3 里改） |
| 版本 | 0.1.62 |
| 分级 | 必须 |
| 依赖 | K3；H1（③Hands 先回答 5 步上限防什么） |
| 合并位置 | K 线第 4 个；H3 在它之后合 |
| 推动的门槛 | §5.2「预算」类的「等你」接近 0；§5.3 第 2 条；§5.1 T2 不再因预算出空回答 |
| 分支 | `claude/0162-k4-stop-policy` |
| 迁移号 | 无（每任务美元上限存设置键值） |

## 目标

一个回合不再被五六个上限夹住；提示词不再把多步骤的事推去后台（0.1.62 计划 K-3、D4）。

## 改哪些文件

- `arslan/execution_budget.py`
  - `:26-32`：今天聊天回合是 32 次请求 / 24 次工具 / 128k token / 600 秒。
  - `:91-98`：1.5 倍硬停。
  - 收成一个停止策略，只看三件事：步数上限、墙钟（保留「等卡时暂停」）、无进展检测。聊天的上限提到后台 standard 档。
- `server/orchestrator/tool_loop.py`
  - `:684`：`LIVE_FETCH_BUDGET = 25` 并入步数。
  - `:2276-2283`：强制收尾和无进展的判断随新策略改。
- token 计法改为以供应商返回的真实用量为准（当前上下文大小），不再每步累加整段历史：
  - `arslan/llm/adapter.py:131-151`；
  - `arslan/llm/usage_sink.py:26-33`。
- 两个估算器只留一个：
  - 删 `arslan/llm/usage_sink.py:174-179`，它只算汉字；
  - 统一用 `arslan/context_budget.py:4-6`，它算汉字、假名、谚文。
- `arslan/runtime_policy.py:71-108`：卡住检测。同一动作和同一结果出现 4 次、同一错误出现 3 次，就停。
- `server/orchestrator/arslan.py:1040-1046`：删掉 `start_background_work` 说明里的「Do NOT do such work inline in this turn」和「回一句话」类要求。后台变成「同样的工作，换个地方继续」，由用户或模型选择。
- 设置项：每任务美元上限，默认关。
- 网页：上下文环可点开，看各部分占比（系统、工具、记忆、历史、工具结果）。6 种语言的新文案按冲突协议加。

## 不许碰

- `server/registry/hands_tools.py:918-919` 的 `INLINE_ACTIONS`：这是 ③Hands 的文件，由 H3 改。
- 提示词的工作方法（K5）。

## 怎么做（要点）

1. 先用 M1 的 T2 复现「预算把回答截成空」，写成测试。
2. 新策略和旧策略在同一组测试上对比，确保后台任务行为不变。
3. 上下文环的明细，如果前端改动超过约 200 行，拆成 K4b，紧跟在 K4 后合。

## 验收

- **测试：**
  - 聊天与后台用同一组上限；
  - 卡住检测按 4 次 / 3 次触发；
  - 美元上限到了会明确停下并说明；
  - token 计法以真实用量为准。
- **M1（贴在 PR 里）：** T2 不再出空回答；全套不差于 K3 之后。
- **M2（装上后 7 天）：** 「预算」类的「等你」接近 0。

## 量级

产品代码约 −300 行（净减），另加前端的上下文环明细。

## 风险与回退

- **风险：** 放宽聊天上限后，某些回合跑太久、花太多钱。用墙钟、卡住检测和美元上限兜底；M1 里贴每题成本。
- **回退：** 停止策略的上限值可在设置里调回去；代码回退要整 PR revert。
