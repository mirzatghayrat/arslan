## 目标

一个回合不再被五六个上限夹住，但花费始终有上限；聊天和后台同一套规矩；提示词不再把多步骤的事推去后台（v0.1.63 计划 K-3、D4；更正 E9）。

今天的情况（`fb6d7230`）：

- 聊天回合：32 次请求 / 24 次工具 / 128k 计费 token / 600 秒（`arslan/execution_budget.py:25-35`），1.5 倍硬停（`:67`、`:92-98`）。后台 standard 档：120 / 80 / 600k / 1,800 秒（`:58-63`）。
- **token 早就按真实用量计（更正 E9）。** 用的是供应商返回的用量，缓存读按 0.1 折算（`arslan/llm/adapter.py:130-159` 的 `_account`；`arslan/llm/usage_weight.py:21-45`）。每次请求扣一次（`arslan/llm/usage_sink.py:26-35` → `execution_budget.py:334`）。每步重复计上的输入，就是真实会付的钱。
- **没有美元上限。** 回合的美元数只看输入、输出两个数（`arslan/llm/prices.py:63-95`；调用在 `server/orchestrator/arslan.py:567-568`）。DeepSeek 把缓存命中按全价算，偏高；Anthropic 漏了缓存读写，偏低。
- 网页读取每轮 25 次（`server/orchestrator/tool_loop.py:684`；判断在 `:2270-2271`）。
- 卡住检测：连续 4 次失败或 4 次重复结果就停（`arslan/runtime_policy.py:70-109`），不分是不是同一个错误。
- `start_background_work` 的说明写着「Do NOT do such work inline in this turn」和「reply in ONE short sentence」（`arslan.py:1041-1050`）。
- 两个 token 估算器：`usage_sink.py:174-179` 只认汉字；`arslan/context_budget.py:4-6` 认汉字、假名、谚文。

## 改哪些文件

### K4a 停止策略（`claude/0162-k4a-stop-policy`）

- `arslan/execution_budget.py`：收成一个停止策略，聊天和后台用同一组上限（聊天提到 standard 档）。停只看四件事：
  1. 步数上限；
  2. 墙钟，保留「等卡时暂停」（`paused()`，`:228-286`）；
  3. 无进展：同一动作和同一结果出现 4 次、同一错误出现 3 次（改 `runtime_policy.py:70-109`）；
  4. 花费：
     - **累计计费 token 上限保留**，跟着聊天上限一起放宽；
     - **每任务美元上限默认打开**（例如 $2，设置里可调）。
- 「当前上下文多大」只决定什么时候压缩（K2），**不用来停**。
- 美元按缓存分档计价：未命中、缓存读、缓存写、输出分开算。缓存字段同 `usage_weight.py:21-45`；价目表加缓存读、写两档。
  - 价格未知时（本地模型，或价目表里没有），美元上限不生效，只按计费 token 上限停，界面写明。
  - 顺带修两处计数偏差（写卡时发现，开工前再核）：`usage_weight` 把缓存写按 1 倍计，Anthropic 实际按约 1.25 倍（5 分钟）或 2 倍（1 小时）收；流式回答那条路（`arslan/llm/adapter.py:189-199`）记的是原始总数，没有缓存折扣。两条都要有测试。
- `tool_loop.py:2276-2283`：强制收尾和无进展的判断随新策略改。保留 K3 的「回合内工具表不变」。
- 到上限时，明确停下并说明是哪一条（步数、时间、无进展、token、美元）。
- 网页设置：加「每任务美元上限」一项。6 种语言的新文案按冲突协议加。

### K4b 统一规矩与提示词（`claude/0162-k4b-rules-prompt`）

- `arslan.py:1041-1050`：删掉「Do NOT do such work inline」和「回一句话」。后台变成「同样的工作，换个地方继续」，由用户或模型选。
- **长回合建议转后台：** 聊天回合跑过一定时长（例如 10 分钟），在两步之间出一条建议「可以转到后台继续」，不强制，每回合最多一次。
  - 原因：聊天回合一直占着回合锁（`server/ws/arslan.py:265-272`），崩溃后也不能像后台任务那样续跑。
- 网页读取并入步数：删 `LIVE_FETCH_BUDGET`（`tool_loop.py:684`）和 `fetch_budget` 收尾那几处（`:2270-2271`、`:2294-2295`、`:2306`）。
- 两个估算器只留 `context_budget.estimate_tokens`；删 `usage_sink.py:174-179`，调用方（`adapter.py:148`、`:201`）改过去。
- 网页：上下文环可点开，看各部分占比（系统、工具、记忆、历史、工具结果），用统一后的估算器。环在 `web/src/components/models/ConversationModelChip.tsx:31-38`、`:90`、`:123-124`。6 种语言的新文案按冲突协议加。

## 怎么做（要点）

1. **K4a 先写测试：** 用 M1 的 T2 复现「预算把回答截成空」。
2. 新旧策略在同一组测试上对比，确保后台任务的行为不变（后台本来就是 standard 档）。
3. 美元计价先写测试：同一份 Anthropic 用量，缓存读、写按各自价格算；同一份 DeepSeek 用量，命中部分不再按全价算。
4. **K4b 删提示词之后：** 用 M3 第 2 条（整理 PDF）看它不再要求转后台。
5. 代码注释写清留着的旧上限设置在哪个版本删（见「风险与回退」）。

## 验收

- **测试（K4a）：**
  - 聊天与后台用同一组上限；
  - 卡住检测按 4 次 / 3 次触发；
  - 计费 token 到上限会停；
  - 美元上限默认打开，到了会停并说明是哪一条；
  - 价格未知时只按 token 停；
  - 上下文大小不会触发停止。
- **测试（K4b）：** 提示词里没有那两句；网页读取不再单独计数；只剩一个估算器；长回合建议每回合最多出一次。
- **界面（审查 §5）：** 上下文环的数字和账单一致。在一道多步题上，PR 里贴对照：
  - 环显示的「上次输入」，等于供应商返回的「未命中 + 缓存读 + 缓存写」（K3 已改 `last_input`）；
  - 回合的美元数和供应商账单对得上，误差在 5% 以内。
- **M1（贴在 PR 里）：** T2 不再出空回答；全套不差于 K3 之后；贴每题成本。
- **M2（装上后 7 天）：** 「预算」类的「等你」接近 0。

## 风险与回退

- **风险：放宽聊天上限后，有的回合跑太久、花太多。** 墙钟、卡住检测、计费 token 上限、美元上限（默认开）四道兜底；M1 里贴每题成本。
- **风险：$2 对 Opus 一类贵模型偏紧。** 停下时说清是美元上限，设置里一步可调。
- **风险：长回合建议出得太频繁，打扰人。** 每回合最多一次，可以关掉。
- **回退：** 上限值在设置里调；代码回退两个 PR 可以分别 revert。
- **留着的旧路径与删除条件**（代码注释里同样写）：
  - 如果为了回退保留「聊天用旧上限」的设置：**v0.1.64 删**。条件：v0.1.63 装上后 7 天，M2 里「预算」类的「等你」接近 0，且没有用到这个回退。
  - `turn_budget()`、`job_budget()`（`execution_budget.py:83-98`）如果暂时作为新策略的别名保留：**v0.1.64 删**。
  - Hands 的 5 步上限不归 K4，由 ③Hands 在 H3 里处理。
