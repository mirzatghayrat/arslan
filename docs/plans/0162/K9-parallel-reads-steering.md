## 目标

- **只读工具并行：** 同一批里连续的只读调用同时跑，结果按原顺序记录。今天是逐个跑（`server/orchestrator/tool_loop.py:2388`）。
- **回合中插话：** 回合进行中发来的消息，在下一个工具边界送达，不再等整个回合结束。今天回合锁在时，新消息只会排队（`server/ws/arslan.py:340-342`）。还没开始的工具，给一个「已跳过」的结果，保证历史合法。

## 改哪些文件

- `server/orchestrator/tool_loop.py:2388`：批处理改成先分组，连续的只读调用用有上限的 `asyncio.gather` 并行，结果按原顺序回填；写入和需要审批的调用照旧串行。
- 只读的判断：复用 `server/services/task_service.py:37-45` 的 `_READ_TOOLS`，以及 MCP 的 `readOnlyHint`（已存库）。
- `server/ws/arslan.py`：排队机制（`:340-342`）改为在每批工具执行完后取出排队消息，作为一条 user 消息并入，界面显示「已插入」。
- 插话入口：窗口、iPhone、灵动岛、按住说话都走现有的消息路径。iPhone 的消息经 Bridge 到达时的格式不变。
- 网页：「已插入」标记。6 种语言的文案按冲突协议加。

## 不许碰

- **Bridge 帧格式**（`desktop/bridge/**`、`server/ws/bridge.py`、`spec/mobile-bridge/**`）。
- 「卡片等待时打字 = 拒绝 + 备注」的语义（`server/ws/arslan.py:335-339`）照旧保留。

## 怎么做（要点）

1. 先写测试：两个慢的只读工具，总用时约等于一个；中间夹一个写工具时，仍按顺序执行。
2. 插话测试：回合进行中发一条消息，下一次模型请求里就包含它；还没开始的工具得到「已跳过」的结果。
3. 并行有上限（例如 4），避免一次打开太多网页或文件。

## 验收

- 测试全过。
- **M1（贴在 PR 里）：** 读 3 个网页 / 文件的题，用时下降（领先路线的目标是 ≥40%）；成功率不降。
- **手动：** 任务进行中从 iPhone 改方向，它下一步就照做（§5.3 第 10 条）。

## 量级

产品代码约 +100 行。

## 风险与回退

- **风险：** 并行改变工具结果在历史里的出现时机。结果严格按原顺序记录，配对测试覆盖。
- **回退：** 设置项「工具串行」；插话可以单独关掉，回到排队。
