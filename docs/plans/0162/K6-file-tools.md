## 目标

读、找、改文件的三个工具达到主流 agent 的基本水平（0.1.62 计划 K-5）。

- **`read_file`**：输出带行号。今天它支持分段（`offset` / `limit`），但输出不带行号；分段的说明由 K5 补上。
- **`search_files`**：支持正则，并能按文件名 glob 找文件。今天它只做子串匹配（`server/registry/file_tools.py:230` 的 `if query in line`），工具本身在 `:183-235`。
- **`edit_file`**：加上 `replace_all`。

## 改哪些文件

- `server/registry/file_tools.py`：`read_file`、`search_files`（`:183-235`）、`edit_file`。
- `server/orchestrator/tool_loop.py:1357`：在 K5 补好的参数表上加新参数，包括 `pattern` 的写法、`glob`、`replace_all`。
- 测试：正则、glob、带行号的输出、`replace_all` 的替换次数、超长文件的分段。

## 不许碰

- 写入的符号链接保护（F4b 已做）；检查点（S3）。
- 工作区路径解析（`server/services/workspace_paths.py`），只能调用，不能改。

## 怎么做（要点）

1. 行号格式与 Claude Code 的 Read 工具一致：行号加制表符。说明里要写清楚，让模型知道改文件时不要把行号带进去。
2. 正则要设超时或长度上限，避免灾难性回溯；每个文件都按现有规则跳过凭据文件。

## 验收

- 测试全过。
- **M1（贴在 PR 里）：** 多文件精确修改题、5,000 行日志题达到 3/3，或不差于 K7 之后。
- **手动：** 让它改一个 1,000 行文本里的一处，它分段读、精确改，不整份重写（§5.3 第 5 条）。

## 量级

产品代码约 +120 行。

## 风险与回退

- **风险：** 行号进入模型的上下文后被原样写回文件。在 `edit_file` 里检测并拒绝以「行号 + 制表符」开头的 `old_string`，并给出提示。
- **回退：** 整 PR revert。没有数据迁移。
