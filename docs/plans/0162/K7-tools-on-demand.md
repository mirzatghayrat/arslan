## 目标

常驻工具只留核心几个。MCP 工具和 C3 降级的工具不再每轮全发，改成按需取用（吸收原 PR 9 的最小版本；领先路线 L2）。

近 30 天的本机数据：

- MCP 有 151 个工具，只调用了 18 次；
- 但每轮都要发 35 个工具，约 2.5 万字符。

## 和 K3 的约定：工具只追加、顺序固定

- **回合内工具表不变**（K3 卡已写）。常驻表的顺序由 K3 固定（按名排序）。
- **本回合取到的工具：** 不改工具表。通过一个固定的代理工具调用，例如 `use_tool`，参数是 `{name, arguments}`。
  - 完整参数表放在检索结果里给模型看；
  - 参数由 Arslan 自己校验（现有的 `_schema_problem`，`tool_loop.py:2411`），再按真实的工具名走正常的分发和审批。
- **从下一回合起：** 本对话用过的工具，以原生参数表追加在常驻表末尾。
  - 按首次使用的先后，不参与排序，不插队，不重排；
  - 本对话内一直保留，不撤（进程内记住，重启后重新检索即可）。
- **为什么这么定：** Anthropic 按「工具 → 系统 → 消息」拼前缀（`arslan/llm/providers/anthropic_provider.py:279-283` 的注释）。OpenAI 兼容端点一般也把工具放在前面（本卡未核）。
  - 工具表里任何一处变了，后面整段缓存（系统提示和历史）都失效。
  - 照上面做，回合内前缀只追加；只在「新用了一个工具」的下一回合开头失效一次。
  - 按需取用很少发生（近 30 天 MCP 只调用 18 次），这个代价可以接受。

## 改哪些文件

- `server/orchestrator/arslan.py` 的 `_arslan_tools`（`:982-1369`）
  - 常驻表只留核心工具。
  - MCP 那段（`:1339-1369`）不再逐个列出 MCP 工具，改由下面两个常驻工具取用。现在的 MCP 行按 `Tool.key` 排序（`:1355-1363`），检索结果沿用这个顺序。
- 新增两个常驻工具：
  - 检索工具，例如 `find_tools`：按名字和说明检索，返回名字、一句说明和完整参数表；
  - 代理工具 `use_tool`：见上面的约定。
  - 做法参考：Cursor 只列 MCP 名字、Codex 的直接 / 延迟 / 隐藏、Hermes 的 BM25 检索。
- `server/orchestrator/tool_loop.py`
  - `_dispatch_tool` 用 `resolve_tools()` 的结果判断工具在不在（`:1239`）。要分开两份：给模型看的表，和能调用的全集。按需的工具在全集里，否则会被当成「不可用」。
  - `_native_tool_schemas`（`:1713-1728`）照传入顺序出表，本身不排序。
  - 注意：装能力后会在回合中途重建工具表（`:2449-2453`）。这是现有行为，本卡不改；和 K3 的「回合内不变」怎么对齐，由 K3 定。
- 测试：在默认配置下，加上 3 个 MCP 服务器，量出渲染后工具 JSON 的字符数。

## 不许碰

- MCP 按标注审批（S1）；schema 规整（F3）。
- C3 已经决定的「哪些工具降级」，本卡只负责让它们能按需取到。
- `start_background_work` 在聊天里要一直接上（常驻）：K4b 的长回合提示只在它接上时出现（`tool_loop.py` 里 `long_turn_told` 那段，条件是 `"start_background_work" in wired_keys`）。要是改成按需，就同时把那个条件改成「不在后台任务里」，并改 `test_k4b_long_turn`（⓪Plan 审 #282 时提出）。

## 怎么做（要点）

1. 先写一个测量渲染后工具 JSON 字符数的测试，记下今天的数字。
2. 再写约定的断言测试：
   - 同一回合里，用 `use_tool` 调了按需的工具，前后各步的工具表逐字节相同；
   - 下一回合，原有部分逐字节相同，新工具只出现在末尾；
   - 现有的工具顺序测试（`tests/llm/test_tool_transport.py`）照旧通过。
3. 被降级的工具，用户在对话里点名时也要能用：模型通过检索找到它。
4. 「工具全部常驻」这个回退开关，代码注释写明删除条件（见下文）。

## 验收

- **测试：**
  - 默认配置加 3 个 MCP 服务器，每次请求的工具 JSON ≤ 约 12k 字符；
  - 按需的工具经 `use_tool` 能正常调用，参数错了会被拒并说明；审批照旧（S1）；
  - 上面的约定断言测试和缓存前缀断言测试都通过。
- **M1（贴在 PR 里）：** 全套不差于 K5 之后；贴每题工具 JSON 的字符数、`cache_read` 比例和成本对比。
- **手动：** 打开那个工具很多的 MCP 服务器，普通对话不失败，也不变慢（§5.3 第 4 条）。

## 量级

产品代码约 +200 / −100 行（原写 +150；加了代理工具和「下一回合起追加」）。

## 风险与回退

- **风险：** 模型找不到该用的工具。检索结果要带一句说明；M1 里观察「该用而没用」的情况。
- **风险：** 经代理调用，模型填参数可能不如原生准。M1 里看按需工具的参数错误率；下一回合起已经是原生参数表。
- **回退：** 设置项「工具全部常驻」，用于对比和回退。
- **留着的旧路径（§9）：** 「工具全部常驻」开关。**v0.1.64 删**，条件是 v0.1.63 的 M1 连续两轮「按需」不差于「全部常驻」。卡里和代码注释都这么写。
