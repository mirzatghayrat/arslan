# K7 工具表瘦身：MCP 和少用的工具按需取用

| 项 | 内容 |
|---|---|
| 道 | ②Main |
| 版本 | 0.1.62 |
| 分级 | 必须 |
| 依赖 | K5；C3（紧挨在 K7 之前合）；F3（schema 规整先在） |

| 推动的门槛 | 每次请求的工具 JSON ≤ 约 12k 字符（今天约 18k，外加 MCP 约 25k）；§5.3 第 4 条 |

| 迁移号 | 无 |

## 目标

常驻工具只留核心几个。MCP 工具和 C3 降级的工具不再每轮全发，改成按需取用（吸收原 PR 9 的最小版本；领先路线 L2）。

近 30 天的本机数据：

- MCP 有 151 个工具，只调用了 18 次；
- 但每轮都要发 35 个工具，约 2.5 万字符。

## 改哪些文件

- `server/orchestrator/arslan.py`
  - `_arslan_tools`（约 `:982-1369`）：常驻表只留核心工具。
  - MCP 那段（`:1340-1370`）改成只给一个检索工具。
- 新增一个检索工具，例如 `find_tools`：
  - 按名字和说明检索，返回名字加一句说明；
  - 模型第一次调用某个工具时，再把它的完整参数表加进本回合的工具列表。
  - 做法参考：Cursor 只列 MCP 名字、Codex 的直接 / 延迟 / 隐藏、Hermes 的 BM25 检索。
- `server/orchestrator/tool_loop.py`
  - 工具解析（约 `:1239`）；
  - `_native_tool_schemas`（`:1713`）：加载过的工具追加在常驻表之后，常驻表保持不变、按名排序，以免破坏 K3 的缓存前缀。
- 测试：在默认配置下，加上 3 个 MCP 服务器，量出渲染后工具 JSON 的字符数。

## 不许碰

- MCP 按标注审批（S1）；schema 规整（F3）。
- C3 已经决定的「哪些工具降级」，本卡只负责让它们能按需取到。

## 怎么做（要点）

1. 先写一个测量渲染后工具 JSON 字符数的测试，记下今天的数字。
2. 常驻表保持稳定，加载的工具只追加，不重排。
3. 被降级的工具，用户在对话里点名时也要能用：模型通过检索找到它。

## 验收

- **测试：** 默认配置加 3 个 MCP 服务器，每次请求的工具 JSON ≤ 约 12k 字符；加载后的工具能正常调用；缓存前缀断言测试照旧通过。
- **M1（贴在 PR 里）：** 全套不差于 K5 之后；贴每题工具 JSON 的字符数和成本对比。
- **手动：** 打开那个工具很多的 MCP 服务器，普通对话不失败，也不变慢（§5.3 第 4 条）。

## 量级

产品代码约 +150 / −100 行。

## 风险与回退

- **风险：** 模型找不到该用的工具。检索结果要带一句说明；M1 里观察「该用而没用」的情况。
- **回退：** 设置项「工具全部常驻」，用于对比和回退。
