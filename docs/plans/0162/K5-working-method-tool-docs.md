## 目标

提示词和工具说明帮模型把活干完，而不是劝它停（v0.1.63 计划 K-5；领先路线 L1）。

## 收尾清单（给用户看）

- **什么时候出：** 只在多步任务结束时出。
  - 「多步」= 本回合有 2 个或更多模型步骤调用过工具，只调 `update_plan` 的步骤不算（K5 计划 Q5）。
  - 只在主回合出：聊天和后台任务；delegate 的 worker 不出（它们要按 JSON 约定回答）。
  - 没核对到的写「未核对」（用回复的语言），不写「没查到」：后者会撞上 `_CLAIMS_SEARCH_RE`。
  - 在 `_run_native` 里数「带工具调用的步骤」，数到 2 才在状态块里加提示。
  - 普通聊天、只用了一步工具的请求，都不出清单，避免啰嗦。
- **格式：** 回答最后四行，用回复的语言，用大白话：
  - 做了什么；
  - 怎么核对的；
  - 哪些没核对到；
  - 还要注意什么。
- **放在哪：** 只放在状态块的提示里（`tool_loop.py:2359-2364`），不进系统提示。这样聊天回合的请求里根本没有它，测试能直接断言。

## 风险与回退

- **风险：** 提示词改动可能让某些题退步。领先路线 §0.2 提到：Meta-Harness 搜索中改提示词的候选全都退步。所以必须逐步消融，退步的那一步不合。
- **风险：** 清单里写「没查到」会撞上守卫词表的误伤：`_CLAIMS_SEARCH_RE`（`tool_loop.py:104-106`）里的 `查到了?` 也匹配「没查到」。K8 修词表之前，提示里让它写「未核对」，并加一条测试。
- **回退：** 按步骤拆成提交，单步可 revert。
- **留着的旧路径（§9）：** 只有 `edit_file` 的旧参数名 `old` / `new`。**v0.1.64 删**，卡里和代码注释都这么写。
