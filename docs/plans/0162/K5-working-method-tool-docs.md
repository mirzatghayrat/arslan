## 目标

提示词和工具说明帮模型把活干完，而不是劝它停（0.1.62 计划 K-5；领先路线 L1）。

## 改哪些文件

- `server/orchestrator/arslan.py` 的系统提示（`_ANSWER_STABLE_PREFIX` 一带）
  - 重写「How you work」：做完为止；先读再改；改完读回或跑一下核对；失败先读错误再换办法。
  - 收尾前过一遍完成核对清单。
- `server/orchestrator/tool_loop.py`
  - `:1676-1681`：「最多 1–2 次搜索」等网页规则，从系统提示挪进网页工具的说明。
  - `:2324-2333`：「最多六行对比」规则同样处理。
  - `:1357` `_NATIVE_PARAM_SCHEMAS`：给参数表为空的工具补上参数表，涉及 `edit_file`、`list_dir`、`search_files`、`whats_new`、`list_my_capabilities` 和 3 个定时任务工具。实际名单以 `:1688-1711` 为准，先核。
- `server/registry/file_tools.py`
  - `edit_file` 的参数改成 `old_string` / `new_string`，旧名 `old` / `new` 再兼容一版。
  - `read_file` 的说明写上它支持的 `offset` / `limit`。
- 工具说明与实际一致：`run_command` 的时限（F1 之后是 120 / 600 秒）。
- 首轮附一份环境快照：系统版本、可用的命令行工具、工作文件夹的顶层概况。每个对话缓存一次，放进 K3 的上下文块，不进系统提示。

## 不许碰

- 文件工具的新能力（K6）；工具按需加载（K7）。
- 守卫（K8）。

## 怎么做（要点）

1. 按领先路线 §6 第 6 条，一次只改一处、逐步看 M1：先环境快照，再完成清单，再参数表，再搬网页规则。每一步的 M1 结果都写进 PR 描述。
2. 加一个测试：每个给模型的工具都有非空参数表，确实无参数的工具除外。

## 验收

- 测试：参数表完整；`edit_file` 新旧参数名都能用；环境快照不进系统提示，缓存断言测试照旧通过。
- **M1（贴在 PR 里）：** 全套不差于 K4 之后；逐步的消融表。
- 能力否认类测试（`server/orchestrator/capability_truth.py` 相关）照旧通过；M1 轨迹里不再出现「不能写文件」。

## 量级

产品代码约 ±300 行，主要是提示词和说明文字。

## 风险与回退

- **风险：** 提示词改动可能让某些题退步。领先路线 §0.2 提到：Meta-Harness 搜索中改提示词的候选全都退步。所以必须逐步消融，退步的那一步不合。
- **回退：** 按步骤拆成提交，单步可 revert。
