- **T2 — not fixed (G3, research yield).** Three different failure paths:
  1. r1: three unreadable 51job pages + a browser timeout tripped the no-progress stop. The stop makes
     the next step text-only, so the table could not be saved; the synthesis fallback then wrote it
     **without links** — `_clean_findings` (tool_loop.py) drops search-result and page URLs. Two
     product bugs: a stop that cannot save the deliverable violates completion-first, and the
     fallback discards the one field the user asked for.
  2. r2: saved a 10-row table; 4 links matched, 3 pointed elsewhere, 2 were dead (410), 1 unverifiable.
  3. r3: handed the task to background work; ~35 tool calls, the fetch budget (25) was reached and
     the model kept calling `web_extract`, then the bench's $0.30 per-run cap stopped it before any
     save.
  Common factor: the job sites that matter are script-rendered, and **the browser has never worked
  inside the bench sandbox** (`BrowserUnavailable`; same in r5/r6), so Arslan works with search
  snippets and server-rendered pages only. Not a regression, but it caps T2 here.

  appears to leave tools out of the prompt when they cannot be called, so the forced step is a cache
  miss. Cost detail, not a failure cause.
