Principle (book ch. 2, ch. 4): rules in the system prompt are weak; **current, concrete facts at the end
of the context** and **specific alternatives at the moment of failure** are what change behaviour.

## 1. Design

### 1.1 Status bar (`<agent_status>`) — G2, G4, supports G1/G3

A short block rendered **at request time** after the newest message, never stored in the trajectory:

```
<agent_status>
Workspace: /Users/…/Arslan — you can create and edit files here (write_file, edit_file, run_command).
Saved this turn: report.md, jobs.csv          ← files written via write_file + new files seen in the workspace
Plan: [x] find sources  [>] collect 10 jobs (6/10)  [ ] save table   ← from update_plan, if used
Work so far: 9 tool calls (wrap-up at 24), 7 model calls.
<wrap-up / forced / compaction / research-scope notes that today are appended to the system prompt>
</agent_status>
```

- Only facts the host knows; never model-authored text except the plan items (which are the model's
  own words, marked as such). Lines are omitted when not applicable (no workspace → no write line).
- The system prompt becomes **byte-stable for the whole turn**: the seven `sys_now +=` notes move here.
  The status block changes every step but sits at the very end, so everything before it is a cached prefix.
- Native protocol: a separate trailing `user` message (DeepSeek keeps reasoning across user messages
  when tools are present — verified in the S10 probe). Legacy rendering: appended to the last user turn
  (some providers reject consecutive user turns). Gemini: same as legacy.
- Owned outputs: successful `write_file`/`edit_file` paths from the tool trace, plus files in the
  workspace whose mtime is after the turn started (covers `run_command` saves); capped at 10 names.

### 1.2 Plan tool (`update_plan`) — G3

`update_plan({items: [{text, status: pending|in_progress|done}]})` replaces the turn's plan; the plan
lives in run state (background jobs keep theirs) and is shown in the status bar. Description: use it for
tasks with several parts or a target count ("find 10 …"), keep counts in the item text. No executor side
effects; not offered to workers. Book data: fewer iterations and fewer forgotten sub-tasks.

### 1.3 Recovery hints at the point of failure — G1, G3

A small, explicit table maps known failure signatures to alternatives, appended to the tool result as
**trusted host text** (after the untrusted frame, like the MCP degrade hint):

| Signature (tool output / error) | Hint |
| --- | --- |
| `-1743`, `-10004`, "Not authorized to send Apple events", "privilege violation" | macOS refused AppleScript automation. Other routes: a Swift script using EventKit for Reminders/Calendar (`swift script.swift`, a different permission), a Shortcut (`mac_run_shortcut`), or ask the user to allow Automation for Arslan. |
| `command not found` | Check `command -v`; use an installed alternative or a short python3/swift script; installing shows the user first. |
| `Permission denied` / `Operation not permitted` on a path | Write inside the workspace (shown in the status bar). |
| web_extract: no extractable text / JS page | Try `browser_open` for script-rendered pages, or another source from the search results. |
| web_extract: 403/blocked/paywall | Use another source; do not retry this URL. |

`_STEER` stops saying "answer with what you have"; it says "try another source or browser_open; answer
with what you have only when other sources are exhausted, and say what is missing."

### 1.4 Capability-truth guard — G2

A deterministic final-answer check (like `_unverified_claim`): if the answer says it **cannot
write/save/create files** (zh/en patterns) while a write tool was offered and no write attempt this turn
failed with a permission error, the answer is bounced once: "You have write_file/edit_file/run_command
in <workspace>. Save the file now, or quote the exact error if a save failed." Same for "cannot access
the web" when web tools were offered. One bounce per turn (breaker), never on a forced step.

### 1.5 Tool descriptions — G1, G2

- `write_file`: drop "the user is asked for write permission once per session" when the workspace is
  Arslan's own folder (0.1.48: no prompt there); say "creates folders as needed".
- `run_command`: replace the `remindctl` example with the routes in 1.3; state it can write files.
- `start_background_work`: keep, but state that inline saving is fine for short tasks (the current text
  says "Do NOT do such work inline", which pushed some runs to hand off then end without saving).

### 1.6 Layered compression — G4 (second, measured)

At a compaction event (not every step, to keep the prefix stable): replace bodies of older tool results
and large old tool-call arguments (e.g. `write_file.content`) with receipts (`[read 12,345 chars from URL;
full text on disk at …]`) before evicting whole groups. Done only after 1.1–1.5 are measured.
