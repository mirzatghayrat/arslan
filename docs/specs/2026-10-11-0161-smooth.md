**The bar.** "Smooth" in this round means five things:
1. **Nothing asks inside the sandbox.** A card appears only when Arslan crosses a boundary:
   - writing outside the folders you allowed;
   - sending something off the Mac;
   - using another app;
   - changing how the Mac behaves;
   - money.

   A card can be answered once, for this conversation, or for good.
2. **Adding something is one card.** It can be a GitHub link, a package, a command, an MCP URL or a
   skill. After that one card its tools work in the same reply. Arslan never edits its own database
   or another agent's settings to get there.
3. **A broken tool says why.** It tells the user and the model in plain words, and repairs itself
   where it can.
4. **Skills are ordinary folders.** They are imported whole, the shared `~/.agents/skills` is read
   as it is, and their scripts run.
5. **The web works behind a proxy.** Web search and page reading work on this Mac's proxy.

**The common pattern.**
- The sandbox is the boundary, and cards appear only where it cannot hold.
- Consent is remembered at the right size.
- A reviewer is optional.
- Tools connect in the background and explain their failures.
- Skills are folders.

**Where Arslan differs.**
- Arslan ported Hermes' *unsandboxed* detector and kept it on top of its own sandbox, so commands
  are gated twice.
- Network: Codex and Claude Code control egress (Codex has it off; Claude Code uses a domain proxy).
  Arslan's sandbox leaves the network open. This spec keeps it open and keeps asking before
  *sending* (§A2). A domain proxy is the next step (§9).

## 2. Why Arslan asks so often, and why MCP and skills stick (code at `53d7bed2`)

### 2.1 Approvals

1. **It asks on text, not on the sandbox.** `terminal_policy` is "a pure function of the command
   text … not a sandbox" (`terminal_policy.py:23-25`).
   - Every Hermes pattern and Arslan rule shows a card even inside Seatbelt.
   - The only exception is a narrow script exemption (`terminal_policy.py:179-212`;
     `tool_loop.py:1078-1080`). That exemption trusts the *setting* even where Seatbelt cannot start.
2. **"Don't ask again" does not stick.**
   - The tick stores only the first matched rule (`ws/arslan.py:507-514`), but `standing_allows`
     needs every rule (`terminal_policy.py:166-171`). So `rm -rf build` (two rules) can never be
     silenced.
   - The per-window memory is the exact command text.
   - The Inbox shows the tick and ignores it (`AskForFrame.tsx:35`).
   - The card still points to "Settings › Advanced" (`en.json:1432`), which no longer exists.
3. **Background jobs never learn.** Job cards have no tick and use no conversation grant
   (`approvals.py:96-99, 288-292`).
   - Schedules ask on every call (`approvals.py:264-265`).
   - One unanswered card expires all the job's later cards (`approvals.py:238-248`).
   - Meanwhile the prompt sends multi-step work into jobs (`arslan.py:207-208`).
4. **The only writable folder is the working folder** (`command_sandbox.py:82-86`).
   - Anything else hits EPERM and then a "retry outside" card.
   - The outside grant is all-or-nothing for the rest of the conversation, held in memory
     (`command_sandbox.py:193-201`).
   - That broad grant is what let run 171 write Arslan's database.
5. **False positives.**
   - "malformed": Hermes strips quotes before parsing (`approval_detection.py:509-510, 973-976`),
     so ordinary `'\''` quoting looks unclosed.
   - `curl -f`/`-sSf`/`-D` read as "upload": the regex is case-insensitive (`terminal_policy.py:63`).
   - `ssh-keygen -l` reads as "remote-shell" (`:67`), and `crontab -l` as "login-items" (`:76`).
   - Text is read as a command:
     - a heredoc that writes a README containing `sudo` is **refused**;
     - `grep "rm -rf"` and a commit message mentioning it are carded.
6. **One rule for every app.** `osascript` is a single rule that is never remembered per app
   (`terminal_policy.py:57`). Hands keeps its own per-app grants, in memory (`hands_tools.py:32`;
   `hands_service.py:27`). Asking Notes four times was four cards.
7. **An expired card reads as a refusal.** In a chat window, an expired card is told to the model
   as "user declined" (`LAST_OUTCOME` is only set in `approvals.ask`). The timeout is 300 s
   everywhere (`approvals.py:31`).
8. **The judge cannot help yet.** It is shadow-only (`judgment.py:61-64`) and capped at 2 s
   (`judgment.py:32`).

### 2.2 MCP

1. **The model has no tool to add, check or repair a server.**
   - `suggest_connector` knows 10 catalog names (`catalog.py:22-81`).
   - For any other name it answers: "a skill, the terminal, a Shortcut or AppleScript may do it"
     (`tool_loop.py:1163-1166`).
   - The prompt calls the terminal "your general-purpose hand" (`arslan.py:200-202, 209-210`).
   - That is the road to run 171.
2. **Adding never connects, and nothing connects at start.**
   - `add_server` only inserts a row (`mcp_service.py:50-82`), and nothing connects at boot
     (`main.py:159-174`).
   - RECONNECT only drops a cache (`mcp_service.py:272-274`).
   - Both buttons always show (`McpServers.tsx:371-386`).
3. **Tight budgets, serialised.**
   - 30 s to connect, behind one global lock (`session.py:14, 20, 117-121`).
   - No read timeouts after that (`session.py:82`).
   - A first call from chat gets 20 s (`tool_loop.py:31`), and its timeout is not recorded.
4. **Failures lose their cause.** The server's stderr goes to the sidecar log (`session.py:81`);
   the user sees "TimeoutError (no message)" (`discovery.py:107`).
5. **State is stale and contradictory.**
   - It is described in four vocabularies, and old error lines stay under CONNECTED.
   - Tools of failing servers are still offered (`arslan.py:1313-1333`).
   - Tools that vanished upstream are never pruned (`discovery.py:135-146`).
   - `list_my_capabilities` shows no errors and points to a tab that is gone
     (`executors.py:311-357`).
6. **Two runtime worlds.**
   - Hand-added servers use the login-shell PATH, which misses `~/.zshrc` and nvm, and start in "/"
     (`spawn_env.py:41-86`; `session.py:73-80`).
   - Installed ones use pinned Node and uv (`capability_runtime.py:39-48`).
7. **Misrouted entry points.**
   - "Official MCP directory" opens the presets.
   - "Add as MCP" only posts, then says "added and locked" (`en.json:1206`) although host access is
     on.
   - No endpoint can edit a server.

### 2.3 Skills

1. **Arslan cannot run a skill's scripts.**
   - `run_python` is offered only to spawns (`seed_catalog.py:105-123`).
   - The scripts live in the data folder, which the command sandbox closes (`command_sandbox.py:88-101`).
2. **Imports keep little.**
   - Only `scripts/*.py` and `.md`/`.txt` references are kept, at most 10 of each
     (`skill_import.py:170-183, 278-310`).
   - A skill cannot be re-imported (`:273-275`).
   - At most 25 skills are listed per repository (`:36`, `:199`).
   - A `/tree/…/path` subpath in a link is ignored (`github_eval.py:17`).
3. **The license gate is a hard block.**
   - Only 8 SPDX ids are allowed, and `NOASSERTION` is refused.
   - A skill folder's unrecognised LICENSE overrides a permissive repo license
     (`skill_import.py:44-46, 76-129`).
4. **The index is weak.** At most 80 skills, in key order, with descriptions cut at 100 characters
   (`arslan.py:933-950`), and no search.
5. **Spawn-era leftovers.**
   - The tags "Usable", "Arslan only", ASSIGNABLE, FULL/PARTIAL/TEXT-ONLY and Health all describe
     spawns (`CapabilityCatalog.tsx`).
   - "Have Arslan write a method" needs a spawn (`SkillForge.tsx:437-450`).

## 3. The design in one picture

**One permission layer.** `permissions.decide(request, context)` serves every tool that can cross a
boundary: `run_command`, the file tools, Hands, osascript, Shortcuts, the browser, MCP calls,
`add_capability`, `schedule_task`.

**It answers in this order** and stops at the first step that decides:

1. **Floor**: never, in every mode. Examples: `sudo`, wiping disks, reading passwords out of the
   keychain, and any command that touches Arslan's own data, keys or database.
2. **Money**: always a card, in every mode.
3. **Full access**: allow. Adding a capability, money and another machine (§A7) still ask.
4. **Rule** ("Always …"): allow.
5. **Grant** ("for this task", or "for this conversation", which jobs started from the
   conversation inherit): allow.
6. **Approve for me**: the reviewer allows, denies or passes the decision to the user.
7. **Card**: the user decides once, for this conversation, or always.

**Every step that crosses a boundary writes one ledger row**, whoever decided (§A8).

**Who owns what.**
- I own the layer, the store, the ledger and the cards.
- ③Hands moves Hands onto it (§H).

## A. Permissions v2

### A1. Modes

The default for everyone is **Standard (sandbox first)**, as the user decided. The mode is set in
Settings → What Arslan may do. The composer's mode pill switches it for one conversation. Jobs and
schedules started from a conversation use that conversation's mode.

| | **Standard** (default) | **Approve for me** (optional) | **Full access** (optional) | **Careful** (only for a user who chose "ask for every command") |
|---|---|---|---|---|
| Commands inside the sandbox | run | run | run (wide profile, §A3) | card, unless a rule matches |
| Write outside your allowed folders | card (folder) | reviewer | run | as Standard |
| Leave the sandbox for another reason | card (prefix) | reviewer | run | as Standard |
| Send, publish, upload, mail, connect to another machine from a command (`ssh`, `scp`, `rsync host:`) | card | reviewer | run | as Standard |
| Recursive or forced delete, discard changes, drop data, kill -9 | card | reviewer | run | as Standard |
| Use another app (Hands, osascript `tell`, System Events) | card once per app: for this task, this conversation or always | reviewer (an approval holds for the task) | run | as Standard |
| A delete / send / submit step inside an app | card each time | reviewer | run | as Standard |
| Hands takes over the screen (up to 30 min) | card each time, unless "while I'm away" | as Standard (never the reviewer) | starts without a card; the glow, the 30-minute cap and the pause on your input stay | as Standard |
| Screenshot of the whole screen | card per conversation | reviewer | run | as Standard |
| Login items, launchd, `defaults write`, `crontab -e` | card each time | reviewer | run | as Standard |
| MCP tool marked destructive, or set to Ask | card | reviewer | run | as Standard |
| Change another agent's settings (Hermes, Codex, Claude, Cursor, OpenClaw, `~/.agents`) | card, once only | card (human) | run | as Standard |
| Add a capability (MCP server, skill, tool) | card | card (human) | card | as Standard |
| Money (pay, buy, transfer, checkout, order) | card each time | card (human) | **card** | as Standard |
| Another machine (`ssh_run`) | card each time | card (human) | card | as Standard |
| Floor (`sudo`, disks, keychain secrets, Arslan's own data/keys) | never | never | never | never |

**Notes on the table.**
- **Careful is today's `ask_all`.** It changes only commands; everything else is as in Standard, so
  Hands does not ask on every step.
  - It stays only for whoever chose it. Codex removed its ask-for-everything mode because it
    performed worse, so Careful is not offered to new users.
  - Migration: `shell_confirm_policy` `ask_risky` → Standard, `ask_all` → Careful.
- **Adding a capability always asks.** This keeps the supply-chain line the user set in 0.1.57:
  nothing goes from a result to installed without a person reading the named source
  (`tests/server/test_capability_supply_chain.py`).
- **Another machine always asks.** That is the P3b ruling ③ ("remote is HIGH, always"), which is
  unchanged.
- **Where Seatbelt cannot start** (for example, when Arslan runs inside another sandbox), Standard
  behaves like Careful for commands and says so once.

### A2. What asks in Standard

**Commands are sorted into categories.** `terminal_policy.classify(command)` returns every finding
with a category. The Hermes detector stays vendored and unedited (`approval_detection.py:1-4`).
Arslan maps each Hermes description to a category, and a guard test fails if a Hermes description
has no mapping.

| category | what | in Standard |
|---|---|---|
| **floor** | today's `_FORBID` + Hermes hardline (disks, fork bombs, shutdown, `sudo`, keychain secrets, macOS roots; except Hermes' malformed-grep finding, §A9) + **Arslan's data folder, keys and database in any form** (`Application Support/Arslan`, `config.data_dir()`, `~/.arslan*`; never the `~/Arslan` working folder) | never |
| **send** | Arslan's upload/mail/message/remote-shell/git-push/publish rules (fixed, §A9); plus `nc`/`ncat`/`socat`/`telnet`; plus scripts that *send* (see below) | card |
| **apps** | `osascript` that `tell`s an app (the app is parsed from the text and turned into a bundle id by ③Hands' `hands_service.app_identity`; the never-list applies); `shortcuts run`; `open -a Terminal`/`iTerm` with a script; `.command`/`.tool` files | card once per app (or Shortcut): for this task, this conversation or always |
| **screen** | `screencapture` (any form) | card per conversation |
| **system** | `launchctl load/bootstrap/enable/submit/kickstart`, `defaults write`, `crontab -e`/`-r`/`<file>`, `sfltool`, `tccutil`, `networksetup -set*`, `pmset`, `security add-*`/`delete-*` | card each time |
| **destructive** | recursive or forced delete (`rm -r/-R/-f/--force/--recursive`, `find … -delete`/`-exec rm`, `xargs rm`, `srm`); discarding work (`git reset --hard`, `git clean -f`, `git checkout -- …`, `git restore` without `--staged`, `git branch -D`, `git stash drop/clear`); SQL `DROP`/`TRUNCATE`/`DELETE` without `WHERE`; `kill -9`, `pkill`, `killall` | card |
| **opaque** | code that is fetched or decoded and then run: `curl … \| sh`, `bash <(curl …)`, `base64 -d … \| sh`, and scripts that `exec`/`eval` decoded or fetched text or load `marshal`/`pickle` data | card, once only |
| **local** | everything else: interpreters (`-c`/`-e`/heredoc), `bash -c`, `chmod +x && ./run`, installs into allowed folders, `.env`/`config.yaml` writes inside allowed folders, plain `rm file`, `trash`, Hermes' "malformed payload", reading the web (`curl URL`, `wget`, `git clone`, GET in scripts) | **runs inside the sandbox** |

**Hermes' descriptions map like this** (the full table lives in `terminal_policy`, checked by the
guard test):
- recursive delete, delete in a root path, mass delete (`xargs rm`, `find -exec rm`/`-delete`),
  destructive git, SQL drop/truncate/unscoped delete, process kills → **destructive**;
- force push → **send**;
- download or decoded text piped into a shell → **opaque**;
- writes to `/etc`, `~/.ssh`, shell start files, `~/.hermes/config.yaml|.env` → **system** or
  **other agent** (they are outside every allowed folder, so the sandbox stops them first);
- Docker/Podman daemon commands → **system** (the daemon runs outside the sandbox);
- interpreter `-c`/`-e`, interpreter heredocs, `bash -c`, `chmod +x` then run, `chmod 777` inside an
  allowed folder, package uninstalls, Hermes' own gateway lifecycle, malformed payloads → **local**.

**Why these categories.** The categories that ask are exactly what the sandbox cannot hold.
- Seatbelt contains *file writes*.
- It does not contain the network, Apple Events, launchd, preferences written through `cfprefsd`,
  or the screen.
- Deletion and discarding work are the one in-sandbox harm that cannot be undone. That is why Codex
  keeps a forced `rm` on its tiny dangerous list.

**Scripts are read for three things only:**
- **sending**: `requests.post|put|patch|delete`, `httpx.post…`, `urlopen(…, data=…)`, `http.client`
  `request("POST"…)`, `smtplib`, `ftplib`, `paramiko`, `socket` `connect`/`sendall`,
  `fetch(…, {method: 'POST'…})`, `XMLHttpRequest`, `WebSocket`;
- **other apps**: `osascript`, `NSAppleScript`, `appscript`, `ScriptingBridge`, `shortcuts run`;
- **hidden code**: `exec`/`eval` of decoded or fetched text, `marshal`/`pickle`.

Anything else a script does runs inside the sandbox; that includes reading the web, spawning
programs and importing modules. This replaces `_SCRIPT_REACH` (`terminal_policy.py:180-192`), which
asked for any mention of `urllib`, `re.compile(`, `base64`, the word "requests" or a backtick.

**Protected even with a click.**
- **Arslan's own folder** is a floor in the text and closed in *every* profile, the wide one
  included (§A3). Arslan changes its own settings only through its tools (`add_capability`,
  `mcp_status`, …).
- **Other agents' settings** are `~/.hermes`, `~/.codex`, `~/.claude`, `~/.claude.json`,
  `~/.cursor`, `~/.openclaw`, `~/.agents`, and `~/Library/Application Support/Claude`.
  - They are read-only in the sandbox (not in any allowed folder).
  - A write needs its own card, "Change Hermes' settings?", answered once each time. It never
    offers "this conversation" or "always", and it is never a folder grant.
  - Reading them stays free.
- **Shell start files and agent files** are `~/.zshrc`, `~/.bashrc`, `~/.zprofile`, `~/.profile`,
  `~/.gitconfig`, `~/.npmrc` and `~/Library/LaunchAgents`. Writing them is a **system** card.

### A3. Allowed folders, and leaving the sandbox

**Allowed folders.** These are where commands *and* the file tools may write:
- the working folder (today's only one);
- temp and caches (as today);
- the conversation's project folders;
- folders the user allowed, either for this conversation or always.

**Picking a folder is consent.** Picking a folder as the working folder or as a project folder in
Arslan's UI is the user saying "work here". It needs no extra card. The workspace-write card
(`tool_loop.py:1004-1017`) goes away, and the file tools write wherever commands may
(`file_tools.py:243-266`). A file tool aimed outside the allowed folders gets the same folder card
as a stopped command.

**When the sandbox stops a command (EPERM):**
1. Arslan reads the denied paths from the output ("… : Operation not permitted", Python's
   `PermissionError: … '<path>'`).
2. If the nearest existing folder is under the user's home and is not protected, not another
   agent's settings, not a system path and not `~` itself, the card is a **folder** card:
   - **"Let Arslan write in Downloads?"**
   - Choices: **Once** (this command) · **In this conversation** · **Always allow ~/Downloads** ·
     **No…**
   - On yes, the command runs again **inside the sandbox** with that folder added. It never runs
     outside the sandbox just because one folder was missing.
3. Otherwise the card is an **outside** card (below).

**When the model asks first.**
- The model may send `outside_sandbox: true` with a `why`, as today.
- It may also send `write_folders: ["~/Downloads"]` when a folder is all it needs; that gets a
  folder card.
- The prompt says: leave the sandbox only after it stopped a command, or when you know it must; a
  folder you need is `write_folders`, not leaving.

**The outside card.**
- **"Run outside the sandbox?"**, with the model's `why` as the question and the exact command
  below it.
- Choices: **Once** · **In this conversation, for `<prefix>`** · **Always for `<prefix>`** · **No…**
- The prefix:
  - comes from the model's optional `prefix_rule` (Codex), else from the command's first two words;
  - is offered only when the command is a plain chain of words joined by `&&`, `||`, `;` or `|`
    (as Codex parses it);
  - must cover every segment.
- **Banned prefixes** are never offered "this conversation" or "always". They are:
  - shells with `-c`/`-lc`;
  - `python*`, `node`, `ruby`, `perl`, `php`, `deno`, `bun`, `osascript`;
  - `env`, `sudo`, `rm`, `git`, `xargs`, `find`, `open`, `curl`, `wget`;
  - `npx`, `uvx`, `pipx run`;
  - `npm run`, `yarn run`, `pnpm run`, `make`.
- Examples that may be remembered: `brew install`, `npm install -g`, `ps`.

**Outside = the wide profile, not "no sandbox".**
- Today an outside run has no Seatbelt at all (`terminal_exec.py:99-102`).
- In 0.1.61 an outside run gets Seatbelt with writes allowed everywhere *except* the protected list
  (`command_sandbox.default_protected()`: Arslan's data and keys, `~/.ssh`, Keychains, Hands'
  folder). That list stays closed to reads and writes.
- So no click, and no mode, lets a command touch Arslan's database again.
- Where Seatbelt cannot start, an outside run is unsandboxed as today, and the floor rule on
  Arslan's folder still refuses the command text.

**The in-memory grant goes away.** The "rest of this conversation" outside grant
(`command_sandbox._granted`) is replaced by the stored, scoped grants (§A5). A broad "anything,
anywhere, for the rest of the conversation" is not offered any more.

### A4. The card

**One card shape for every kind.** It is shown in the chat window, a background job's conversation,
the Inbox, the island and the phone. Today's frames stay (`propose_run_command`, `propose_action`,
…) and gain optional fields, so the iPhone Bridge keeps working. New kinds use `propose_action` with
a new `kind`.

**What the card shows.**
- **Title:** one question in the user's language, e.g. "Use Notes in this conversation?". When the
  model gave a `why`, that line is the question.
- **Detail:** the exact command, element or arguments, folded after two lines.
- **Choices:** **Once** · **In this conversation** · **Always: `<literal scope>`** · **No…**
  - On an **app** card (and a Shortcut card), the first choice is **For this task** instead of Once.
    The task is the current chat turn or background job. Work in an app is 5–15 steps (look, click,
    type, look…), so one step per card would ask at every step. Risky and money steps still ask per
    step.
  - "No…" opens one optional line, "Tell Arslan what to do instead". The model receives that
    line. (Claude Code and Codex both pass the user's words back.)
  - Choices that do not apply are hidden:
    - "Always" for banned prefixes, deletes, risky steps, money, other agents' settings, system
      changes, whole-screen capture, opaque code, high-reach apps (System Events, Terminal, iTerm,
      Finder, System Settings, Script Editor) and new capabilities;
    - "In this conversation" for money, new capabilities, other agents' settings, system changes
      and opaque code.

**The same card everywhere.**
- **Background jobs** get the same choices as the chat window, and they use the grants of the
  conversation that started them.
- **The Inbox** honours every choice.
- **The island** answers Once (For this task) or No for folder, app (look and act, merged),
  screen, MCP tool, schedule, site and Shortcut cards. Everything else opens Arslan: money, send,
  delete or discard, a risky step in an app, a takeover, leaving the sandbox, system changes, other
  agents' settings, new capabilities, another machine. This is 0.1.55 decision 3 ("risky cards are answered in Arslan")
  extended to the new kinds, and it is enforced on the server, as today (`approvals.py:166-193,
  212-226`).
- **The phone** answers Once or No, as today: "a phone never grants always".
- **The Bridge** maps the new kinds to its six risk words in `FrameMapper.swift`, and shows the
  card's `title` instead of the kind's name:
  - money → `payment`, send → `send`, destructive → `delete`, outside → `install` (as today),
    everything else → `write`.
  - New capabilities never reach the phone (0.1.57: installing code wants the whole card).
  - This is a Mac-side change only; the iPhone app needs nothing.

**One card for identical requests.** If two requests in one conversation have the same kind and
target (parallel tool calls, a job and its parent), they share one card. The second waits for the
first one's answer.

**Waiting is not refusing.**
- A card stays open for **30 minutes**, not 5. That is OpenClaw's window; Hermes found 60 s "too
  tight" and settled on 5 minutes for phone latency.
- While it waits:
  - the turn shows "Waiting for you: <title>";
  - the island and Inbox show the card;
  - after 20 s, if Arslan's window is not in front, a macOS notification reads "Arslan needs your
    OK: <title>".
  - The turn keeps its 15 s heartbeat, so the window never calls it "Interrupted" (0.1.59).
- **If nobody answers**, the card closes as **expired**. The model is told:
  > Nobody answered the card for <title> in 30 minutes. This is NOT a refusal. Don't retry it in
  > this turn. Finish what you can and tell the user what is waiting.
  - The ledger says "expired". It never says "declined".
  - Hands stops saying "The user did not allow…" when a card only ran out.
- **A message typed while a card waits answers it.** It counts as "No", with the message as the
  note. Otherwise the message would wait behind the card for up to 30 minutes.

**Scheduled runs never wait.** A scheduled run has nobody to ask, so it uses the mode and the
"Always" rules of the conversation that created it. Anything else is refused at once. The Inbox
then lists it with **Always allow** for next time. (Hermes resolves unattended contexts from
policy, with deny as the default.)

**A job whose card ran out stops waiting.** Once one card in a background job expires, the person
is away: the job's later cards do not open and wait 30 minutes each. They are refused at once as
"waiting for you" and listed in the Inbox the same way, and the model finishes what it can. This
keeps today's rule (`approvals.py:238-248`) with the honest wording.

### A5. Rules, grants, and where they live

**Migration `_0067`** adds three tables:
- **`permission_rules`** ("Always"):
  - `kind`: `command_prefix` | `folder` | `app` | `shortcut` | `site` | `mcp_tool` | `mcp_server`
    | `legacy_rule`;
  - `target`: an argv prefix, a real path, a bundle id, a name, a host, or `server/tool`;
  - `label`: the literal scope the card showed;
  - `created_from`: a card's `call_id`, or "settings" / "migration";
  - `created_at`, `last_used_at`, `use_count`.
- **`permission_grants`** ("For this task" and "In this conversation"): `conversation_id`,
  `task_id` (the turn or job; empty for a conversation grant), `kind`, `target`, `created_at`,
  `call_id`.
  - A task grant is dropped when its turn or job ends.
  - Jobs started from the conversation look up their parent's conversation grants.
  - Conversation grants live as long as the conversation does, and they survive restarts and
    reloads.
- **`approval_events`**: the ledger (§A8).

**Migrated from today's stores.**
- `terminal_always_allow` → `legacy_rule` rows, still honoured. They can only widen what is
  allowed, and in Standard most are moot.
- The Hands "always" apps → `app` rows (③Hands, §H).
- The Hands per-app grants and looked-at sets, held in memory, → `permission_grants`.
- `command_sandbox._granted` → removed.

**Settings → What Arslan may do** lists everything, each item removable:
- the mode;
- **Allowed folders**;
- **Allowed apps** (shared by Hands and osascript);
- **Always rules** (commands, MCP tools, sites, Shortcuts);
- **Recent decisions** (the ledger, the last 200 rows, with a "stop allowing this" link on rows that
  came from a rule or grant).

Hermes rules show in words, not as raw descriptions.

### A6. Approve for me (optional, off by default)

- **Who reviews.** The reviewer runs on the model assigned to the "judgment" role in Settings →
  Models (`build_adapter(role="judgment")`, the one the memory judge uses today).
- **What it reviews.** Every card in the §A1 table marked "reviewer". It never reviews money, new
  capabilities, other agents' settings, another machine or a takeover. A takeover is about the
  user's screen, not about whether the request is safe.
- **An approved `app` request holds for the task**, like "For this task" on a card. A 10-step task
  in one app is one review, not ten.
- **What it sees.**
  - The user's last 6 messages in this conversation, which are trusted.
  - The conversation's folders.
  - The request: kind, target, exact command or tool with its arguments, or the app with the
    element's label.
  - The model's `why`, and the category.
- **What it never sees**: tool results, web or page text, or the assistant's prose.
  (Claude Code strips tool results and is "reasoning-blind by design".)
- **The policy**, as its prompt:
  - **Approve** when the action plainly serves what the user asked in this conversation and its
    effect is limited or reversible.
  - **Deny** when it reaches beyond the request: other people, credentials, mass deletion, sending
    the user's data somewhere they did not name, or changing other apps' settings.
  - **Ask the user** when unsure.
  - By risk: low or medium risk that serves the request → approve; high → approve only if the
    user's words ask for exactly this; critical → deny.
- **What it returns**: `{decision: approve|deny|ask, risk, reason ≤160 chars}`.
- **Timeout and errors.** It has 30 s (Hermes and OpenClaw use 30 s, Codex 90 s). A timeout, an
  error or an unparseable answer becomes the normal card.
- **What its answers mean.**
  - **Approve** means this once; nothing is stored (Hermes, OpenClaw).
  - **Deny** returns the reason to the model, with "find a safer way or ask the user". The user
    sees a line in the turn, "Reviewer stopped: <reason> · Run it anyway", which overrides it once.
- **The breaker.** 3 denials in a row, or 10 in the last 50 in a conversation, pause the reviewer
  for that conversation. Cards go to the user, with one line saying why (Codex, Claude Code).
- **Cost.** The ledger records each review's model, latency and tokens, and the Activity page shows
  its cost.
- **In Standard mode,** the shadow judgment continues with this new prompt and a 30 s budget. It
  runs after the card, never in the way, so the agreement can be measured on real cards.

**The confirmation.** Turning it on (in Settings, or from the composer pill for one conversation)
asks every time:

> It still asks before paying or buying, adding new tools, or working on another machine, and it

**The badge** stays visible while Full access is on:

### A8. The ledger

**Every decision that crosses a boundary writes a row of `approval_events`.** This includes silent
ones, decided by a rule, a grant, the mode or the reviewer. The columns:
- `created_at`, `conversation_id`, `job_id`, `run_id`;
- `kind`, `target`, `detail` (cut to 500 characters);
- `extra` (JSON, cut to 1 KB): for Hands, the app name, the element's role and label, and how Hands
  reached the app (background, borrowed front, visit, takeover);
- `mode`;
- `decided_by`: `floor` | `mode` | `rule` | `grant` | `reviewer` | `user` | `expired` | `policy` |
  `away` (a card refused at once because an earlier card in the same turn or job ran out; its
  `decision` stays `expired`, never `deny`, and it is listed in the Inbox like a policy refusal);
- `decision`: `allow` | `deny` | `expired`;
- `scope`: `once` | `task` | `conversation` | `always`;
- `rule_id` / `grant_id`;
- `reviewer` (verdict, risk, latency, model, tokens);
- `wait_ms`: how long the card was open.

Plain commands that just run inside the sandbox are not written.

**What it is for:**
- the Recent decisions list (§A5);
- the number this round is judged by, **cards per task**;
- ③Hands' missing Hands numbers.

Rows are kept for 90 days.

### A9. False positives fixed (each with a test from the measured cases)

**The "malformed payload" finding.**
- Re-read the *raw* text with `shlex` before accepting Hermes' malformed finding. Quoting that is
  valid in the shell is not malformed.
- In Standard, malformed-only is **local** anyway.
- Hermes' hardline "malformed" for grep (Hermes' own note: "118 of 125 hardline blocks in one week
  of real use, every one a benign grep") becomes local inside the sandbox, and asks where Seatbelt
  cannot start.

**Multi-rule commands.**
- A rule tick stores **all** of `ask_rules(command)`, not the first.
- In Standard, most multi-rule cases are local anyway.

**Arslan's own rules.**
- `curl`: the data flags are case-sensitive `-d`, `-F`, `-T`, `--data*`, `--form`, `--upload-file`
  or `--json`, or a POST/PUT/PATCH/DELETE method. `-f`, `-sSf` and `-D -` are reads.
- `ssh`, `scp`, `sftp` and `ftp` match as whole command words: `ssh-keygen` and `ssh-add` are not
  remote.
- `crontab -l` is a read; only `-e`, `-r` or `<file>` change it.

**Text is not a command.**
- Heredoc bodies are data for the program that receives them. They are scanned as shell only when
  that program is a shell (`bash`, `sh` or `zsh <<`).
- Quoted arguments are masked for the delete, install, sudo and SQL rules, unless they are the
  payload of `bash -c`/`sh -c`/`eval` (Hermes already exposes those).
- Cases fixed: `grep -n "rm -rf" build.sh`, `git commit -m "…rm -rf…"`, and a README heredoc that
  mentions `sudo` or `brew install`.

**Expired is not declined.** `LAST_OUTCOME` (or its successor in `permissions`) is set on every
path, chat included.

**The stale pointer.** The card's "Settings › Advanced" pointer becomes "Settings → What Arslan may
do"; `list_my_capabilities` stops pointing to "Capabilities → MCPS".

**The scheduler.** Its docstring says scheduled runs "cannot run a command" (`scheduler.py:479-486`);
that is corrected to §A4's rule.

### A10. What the model is told (prompt changes in `arslan.py`)

1. **The sandbox.**
   > Commands run in a sandbox that writes only to your allowed folders; inside it, just run them. If
   > the sandbox stops a command, Arslan shows the user a card: don't ask in chat. Leave the sandbox
   > only after it stopped a command or when you know it must; when all you need is a folder, pass
   > `write_folders` instead.
2. **Arslan's own capabilities.**
   > To add or repair Arslan's own capabilities, use `add_capability`, `mcp_status`,
   > `mcp_reconnect` and `mcp_remove`. Never read or change Arslan's own files or database with
   > commands, and never change another agent's settings (Hermes, Codex, Claude, Cursor, OpenClaw)
   > unless the user asked for that app by name.

   This replaces "the terminal is your general-purpose hand" as the answer to a missing capability.
3. **Other apps.**
   > To work in another app, prefer the desktop tools (Hands). osascript needs the same app
   > permission.
4. **Tool failures.**
   > When a tool fails, say what it said. For an MCP server, check `mcp_status` before anything
   > else.

### A11. `permissions.decide` (the shared interface; sent to ③Hands before the user's review)

```python
# server/services/permissions.py  (new; owned by ②Main)
Kind = Literal["command", "folder", "outside", "send", "destructive", "system", "screen", "opaque",
               "app", "app_risky", "money", "takeover", "shortcut", "site", "mcp_tool",
               "other_agent", "capability", "schedule", "remote"]

@dataclass(frozen=True)
class Request:
    kind: Kind
    target: str                 # the scope a grant or rule is stored under (bundle id, path, prefix, host, server/tool)
    title: str                  # the card's question, one line
    detail: str = ""            # what exactly: command, element label, arguments
    why: str = ""               # the model's one-line reason, if any
    always_label: str = ""      # the literal scope "Always" stores; "" hides "Always"
    conversation_ok: bool = True
    extra: dict = field(default_factory=dict)   # kind-specific: app name, server, risk words…

@dataclass(frozen=True)
class Context:
    conversation_id: str | None
    job_id: str | None = None
    run_id: int | None = None
    surface: Literal["chat", "job", "schedule", "phone", "none"] = "chat"
    user_request: str = ""      # the user's latest words (trusted), for the reviewer

@dataclass(frozen=True)
class Decision:
    allowed: bool
    by: Literal["floor", "mode", "rule", "grant", "reviewer", "user", "expired", "policy"]
    scope: Literal["once", "task", "conversation", "always"] | None = None
    note: str = ""              # the user's "tell Arslan instead", or the reviewer's reason
    model_text: str = ""        # what the tool result tells the model when not allowed

async def decide(req: Request, ctx: Context) -> Decision
async def decide_many(reqs: list[Request], ctx: Context) -> list[Decision]   # one card for several apps (DesktopAccess)
def would_ask(req: Request, ctx: Context) -> bool                           # no side effects
```

**Filling in the context.** When a caller leaves `Context.user_request` or `run_id` empty,
`decide()` fills them from the turn's trusted context (`personal_context`) and the run registry.
Hands' tools do not have the user's words.

**`decide_many`** (③Hands' semantics):
- Apps already allowed by a rule or grant are left off the card, and one answer covers every app
  shown.
- Decisions come back in input order, each with its own `by`.
- There are no per-app toggles in 0.1.61.
- If any app shown is high-reach, "Always" is hidden for the whole card.
- The card keeps each app's tier ("look only", "click and scroll only").

**How Hands maps onto it** (③Hands' proposal, adjusted):
- **Look and act** are one `app` grant per app, with target = bundle id.
  - "Once" on an app card is **For this task**.
  - "Always allow WeChat" becomes an `app` rule.
  - DesktopAccess becomes `decide_many`.
- **Risky steps and money are split** (③Hands owns the word lists):
  - pay, buy, purchase, order, checkout, transfer → `money`, which asks in every mode;
  - delete, remove, send, submit, sign, post, publish, confirm, risky keys (cmd+delete,
    cmd+return) and a Return that sends → `app_risky`, which asks each time and is never
    remembered.

  Both use target = bundle id, with the element's label in `detail`.
- **Takeover** asks each time in Standard unless "while I'm away" is on, never goes to the
  reviewer, and starts without a card in Full access. Its protections stay on in every mode (§A1).
- **App names become bundle ids** through ③Hands' `hands_service.app_identity(name)`:
  - running apps through Hands' `which_app`;
  - otherwise a LaunchServices lookup of the app bundle's Info.plist, which never launches the app.

  `terminal_policy`'s **apps** category uses it for `tell application "X"`. The never-list
  predicate stays `hands_service.never_touched`, extended to bundle ids; it is also checked for
  osascript (`MacAppleScriptExecutor` and the apps category).
- **Enforced inside Hands in every mode, never by cards:**
  - the never-list;
  - look-only browsers and click-only terminals;
  - password fields;
  - borrowing the front;
  - the takeover cap and pausing on user input.
- **A card waiting during an A18 visit** ends the visit after 15 s idle, so the user is back on
  their own desktop while the card is open.

## B. MCP v2

### B1. The life of a server

**One state, seen the same way by the UI and the model.** It replaces `status`, `health_status`,
the capability rows' on/off/setup/na and the install test result. The states:
- `off` (the user turned it off);
- `starting`;
- `ready`;
- `failed`, with a reason and the next retry time;
- `needs_auth`;
- `parked`, for a permanent error such as a missing command, 401/403, or a program that does not
  speak MCP.

Every start, call and probe updates the state with timestamps: `state_at`, `last_ok_at`.

**Starting.**
- At app start, enabled servers start in the background, at most 4 at a time, each with its own
  lock (the global lock goes, `session.py:20`).
- A chat turn never waits for them.
  - Tools of servers that are `ready` when the turn starts are offered.
  - Servers still starting get one line in the prompt: "still starting: rea (downloading)".
- **Budgets:**
  - first start after an add or update, or when the package is not cached: **120 s**;
  - later starts: 60 s;
  - `list_tools`: 30 s;
  - `call_tool`: 120 s. The MCP executor declares its own `timeout_s`; today the tool loop's 20 s
    applies (`tool_loop.py:31`).
- **Retries:**
  - first start: 3 attempts, 1 s / 2 s / 4 s apart;
  - after a failure: again at 30 s, doubling up to 10 minutes;
  - a dropped session: up to 5 reconnects;
  - a `parked` server probes itself every 300 s (Hermes).
  - RECONNECT and `mcp_reconnect` always start a **fresh** process.

**Errors with their cause.**
- Each server keeps the last 8 KB of its stderr.
- `last_error` = a classified line + the last 20 stderr lines. The server's own key values are
  replaced by `****`.
- A timeout is recorded as a timeout, with how long it took.

**Tools follow the server.**
- On every connect: new tools are added, changed ones updated, and vanished ones **removed**.
- A `tools/list_changed` notification re-lists them.
- MCP annotations are stored per tool (§B4).

**Not ready means not offered.**
- Tools of a server that is not `ready` are **withheld**. The prompt says which servers are
  unavailable and why, in one line each.
- A call to a server that stopped meanwhile returns its state and reason, not a raw exception. A
  startup failure no longer marks the task "needs reconciliation" (`task_service.py:308-317`),
  because the call never reached the server.

**Where it runs.**
- `npx`, `node`, `npm`, `uvx` and `uv` servers run on Arslan's pinned Node and uv
  (`capability_runtime.py` PINS, fetched on first use with progress).
- That ends the login-shell PATH and nvm problem (`spawn_env.py:41-86`). The user's PATH stays as a
  fallback.
- Each server gets its own working folder, `<data>/mcp/<id>/`, instead of "/".

### B2. Model tools (always offered to Arslan)

- **`add_capability {source, why}`** (§D): the one way to add an MCP server, skills or a command-line
  tool. One card. After approval it adds, starts and lists the tools, and returns the result in the
  same turn.
- **`mcp_status {name?}`** returns, per server:
  - the state, tool count, last error with its stderr tail, the last good time and the next retry;
  - **the fix**, in words and as a tool call ("run `mcp_reconnect rea`", "the user must sign in
    from Capabilities", "the key REA_TOKEN is missing");
  - servers found in other apps but not in Arslan (§B5).
- **`mcp_reconnect {name}`**: a fresh start, without a card. It is the user's own server.
- **`mcp_remove {name}`**: a card, "Remove rea?".
- **`list_my_capabilities`** gains each server's state, error and fix.

`suggest_connector` and `propose_capability` stay as thin aliases of `add_capability` for one
release, so that old prompts and memory notes keep working.

### B3. Adding a server: one card, with proof

1. **Resolving the source** (§D): `rea-agents` resolves to `npx -y rea-agents@6.4.0`. The version is
   pinned at add time; the user can update later.
2. **The card** shows:
   - what it is;
   - the exact command;
   - the pinned version and license;
   - "runs as you, outside the sandbox (like Claude Code, Codex and Hermes)" — or "sandboxed" for
     registry installs, as 0.1.57;
   - fields for the keys it needs, typed on the card and never in chat.
3. **Start arguments.** If the server does not answer MCP's `initialize` (the process exits, prints
   usage text, or closes the pipe), Arslan tries two things:
   - first, the start command found in the project's README: a JSON block with `mcpServers` or
     `command`/`args`;
   - then the usual flags, in order: `--mcp`, `--stdio`, `mcp`, `stdio`.

   The first that answers wins. The result says so: "rea started with `--mcp`". Only these flags
   are tried, and only inside an add the user approved.
4. **The result to the model**, in the same turn: "rea is ready: 14 tools: …" or "rea failed: <reason
   + stderr tail>; fix: …".
   - The card shows the same progress: Downloading… Starting… Found 14 tools.
   - If it fails, the row stays `failed` with the reason. It is never "registered" and silent.
5. **Editing.** `PATCH /api/v1/mcp/servers/{id}` changes command, args, keys or URL, then restarts.
   `add_capability` on an existing name is an edit, and its card shows the change.

### B4. Per-tool approvals

**Discovery stores the tool hints.** It keeps each tool's `annotations` (`readOnlyHint`,
`destructiveHint`, `openWorldHint`, `title`) in a new `tools.annotations` column; today they are
dropped (`discovery.py:139-155`).

**In Standard:**
- `readOnlyHint` → no card;
- `destructiveHint` → `mcp_tool` card (Once / In this conversation / Always for this tool / No);
- **money-like tools** → `money` card in every mode. A tool counts as money-like when its name or
  description matches pay, purchase, buy, checkout, transfer, charge, refund, payout, order or send
  money;
- other tools → allowed. Adding the server was the consent (today's rule, user ruling 2026-08-18;
  Hermes' default).

**Per tool,** the server's row lists its tools with **Allow / Ask / Off**. "Always" from a card
writes Allow. "Off" removes the tool from the model's list. This replaces the spawn-era tier and
wire controls.

### B5. Importing what you already set up elsewhere

**Sources**, read-only:
- Claude Desktop: `~/Library/Application Support/Claude/claude_desktop_config.json` → `mcpServers`;
- Claude Code: `~/.claude.json` → `mcpServers` (user scope);
- Cursor: `~/.cursor/mcp.json`;
- Codex: `~/.codex/config.toml` → `[mcp_servers.*]`;
- Hermes: `~/.hermes/config.yaml` → `mcp_servers`;
- OpenClaw: `~/.openclaw/openclaw.json` → `mcp.servers`.

**How it works.**
- The Capabilities page shows "Found in your other apps: rea (Hermes), …" with a checkbox each. The
  checkboxes start ticked for servers Arslan does not have yet.
- Importing copies the command, args, URL and headers. Keys are copied server-side and never shown
  to the model. The card says "copies 1 key (REA_TOKEN) from Hermes".
- Each imported server then starts as in §B3.
- The model sees the list through `mcp_status`. It can propose one with
  `add_capability {source: "import:hermes/rea"}`, which still shows one card.
- Arslan never writes those files.

### B6. Many tools: search on demand

**When there are many MCP tools,** they move behind two bridge tools, `mcp_find_tools {query}` and
`mcp_call {tool, arguments}`. "Many" means more than 30 tools, or their schemas taking more than 8%
of the model's context.
- `mcp_find_tools` returns up to 8 tools, each with its schema.
- The prompt lists each server in one line.
- Approvals, the ledger and the state checks still apply to the real tool behind the bridge.
  (Claude Code, Codex and Hermes all do this; Hermes turns it on whenever MCP tools exist.)

**It also keeps the tool list stable.** The tools array sits in front of the cached prompt prefix
(`arslan.py:1322-1328`). Today every server that comes or goes rewrites that list.

## C. Skills v2

### C1. Where skills come from

| source | where | default |
|---|---|---|
| bundled | `arslan/spawn/seeds/*/SKILL.md` (as today) | on |
| imported by Arslan | `<data>/skills/<key>/` (the whole folder, §C2) | on after import |
| shared | `~/.agents/skills/*/SKILL.md`: the cross-agent folder Codex and OpenClaw read; this Mac already has skills there | **on** |
| Claude Code | `~/.claude/skills/*/SKILL.md` | off; one switch turns the source on |
| Codex (old location) | `~/.codex/skills/*/SKILL.md` | off; one switch |

**Arslan only reads these folders, never writes them.** For each skill it keeps:
- its source;
- its on/off state;
- a hash of its text;
- a security-scan verdict.

**New and changed skills are picked up at the next turn**, by a cheap per-turn modification-time
check.

**The scan** follows Hermes' skills guard: patterns for exfiltration, prompt injection, destructive
commands, persistence and edits to agent settings. Verdicts:
- "caution": the skill stays on, with a note.
- "dangerous": the skill is off, with the reason. The user can turn it on after reading it.

**Frontmatter honoured:**
- `name` and `description`;
- `disable-model-invocation: true`: the skill is left out of the index and used only when the user
  names it.
- `allowed-tools`, `requires` and `metadata` are shown, not obeyed. Arslan's permissions decide.

### C2. Importing a skill is the whole folder

**What is copied.** The skill's whole folder: `SKILL.md`, `scripts/`, `references/`, `assets/` and
any other files.
- Limits: at most 20 MB and 2,000 files.
- File modes are kept, so scripts stay executable.
- The import is pinned to a commit with sha256 checksums, as 0.1.57's `capability_sources`.

**Re-import is an update.** It re-pins to the new commit and shows what changed, as the number of
files and the `SKILL.md` diff. The skill's on/off state is kept.

**Finding the skills.**
- A `/tree/<ref>/<path>` link is followed to that subpath.
- All `SKILL.md` files are listed through the repository archive, as `capability_search.library_index`
  already does. That ends the 25 cap and the per-skill API calls.

**Old imports move.** Old imports (`<data>/skill_scripts/<key>/`) move into the new layout on first
start. The two bundled seeds that carry `scripts/*.py` get them installed too. The `research` seed
stops pointing to a CLI that does not exist.

### C3. Running a skill's scripts

**Readable from the sandbox, never writable.**
- `<data>/skills/` is opened **for reading only**, after the protected rules. Seatbelt applies the
  last rule that matches; this was measured 2026-10-03 and 2026-10-10 (`command_sandbox.py` header).
- Writing there stays closed, so a skill cannot change itself.
- The rest of `<data>` stays closed.

**The model is told where the skill lives.**
- `read_skill` returns the skill's absolute folder and its file list.
- In the body, `${CLAUDE_SKILL_DIR}`, `${SKILL_DIR}` and `{baseDir}` are replaced with that folder.

**Scripts are ordinary commands** (as in Codex and Hermes).
- They run through `run_command`, inside the sandbox, without a card in Standard.
- Their outputs go to the working folder.
- Dependencies come through `uv run --with …` or a `.venv` in the working folder; uv's cache is
  writable.

**`run_python` stays a spawn tool.** Arslan does not get it.

### C4. Licenses: the text, your decision (the user's decision 4)

**A permissive license** (the 8 SPDX ids today) imports as now.

**Anything else** shows a step: "This skill's license is not one Arslan recognises. Read it and
decide."
- "Anything else" means a custom or unrecognised license, `NOASSERTION`, or no license file. With
  no file, the step says "No license file: by default the author keeps all rights."
- The step shows the full license text, with **Use it on this Mac only** / **Cancel**.

**After "Use it on this Mac only":**
- The skill is marked "Local use only, not redistributable".
- The text's sha256 and the time are recorded.
- It is never shared, exported or bundled.

**The gate stays on the server.**
- `import_skill(ref, path, *, license_ok: str | None = None)` imports a non-permissive skill only
  when `license_ok` equals the sha256 of the license text it fetched itself.
- A client cannot skip it.
- A text that changed between reading and importing fails.

**The supply-chain test changes with this.** `test_installing_a_skill_requires_naming_a_repository`
now expects `["ref", "path", "license_ok"]`. The rule it guards is unchanged: no query or search
result reaches the importer.

### C5. The index and `find_skill`

**A budget, not a cap.** The index has 2% of the model's context window, as in Codex: about 4,000
tokens at 200k.
- Descriptions may be up to 500 characters.
- Order: skills used recently in this conversation or pinned first, then those that best match the
  user's latest message (words in the name or description), then by name.
- Skills that don't fit are counted: "and 12 more: use `find_skill`".

**The tool.** `find_skill {query}` searches names, descriptions and bodies, and returns up to 8.

### C6. One status per skill, no spawn tags

**Each skill row shows:**
- its source;
- On / Off;
- "Has scripts" (they run);
- a license note ("Local use only") when there is one;
- a scan note when there is one.

**Removed:** Usable / All / Not implemented, "Arslan only", ASSIGNABLE, FULL / PARTIAL / TEXT-ONLY,
and Health (`CapabilityCatalog.tsx:23-27, 425-464`; `service.py:115-160, 209-317`).

### C7. Saving a skill from chat

**`save_skill {name, description, body, files?}`** puts a draft into `skill_candidates`, which
exists already. A proposal card offers **Save as a skill** / **Not now**, like memory proposals.

**The "Have Arslan write a method" button** starts a chat ("Write a skill for …") instead of opening
the Forge form. The Forge's evaluation step no longer needs a spawn.

## E. The web behind a proxy

**E1. `net_pin.pinned_request`.**
- **When a proxy carries the request**, our process never connects to the resolved address; the
  proxy resolves the name. The guard still refuses:
  - URLs whose host is a literal non-public IP;
  - `localhost`, `*.local`, `*.localhost`, `*.internal`;
  - names with any local answer that is non-public (`not is_global`, as today) — **unless every
    answer lies in the fake-IP range `198.18.0.0/15`**. Then the proxy decides, which is the
    module's documented delegation (`net_pin.py`, `_pinning_disabled_by_proxy`).
- **When no proxy is set but DNS is fake-IP** (TUN mode), answers in `198.18.0.0/15` are allowed and
  pinned as usual. Arslan knows DNS is fake-IP when a public canary name resolves into that range;
  this is checked once every 10 minutes. The TUN maps the address back to the name, and SNI keeps
  TLS checked against the real host.
- Everything else is unchanged: one resolution per hop, every answer validated, redirects re-checked.

**E2. The agent browser's tunnel** (`browser_proxy.py`, `PublicTunnel`/`validate_url`) uses the same
decision. When a system proxy is set, it forwards `CONNECT` to that proxy *by name*, instead of
dialling the fake address itself.

**E3. Errors say what happened.**
- `categorize()` names the guard's own refusal "blocked address (local network)", where today it
  says "unexpected error".
- Search providers pass the real cause through.

**E4. Tests** on a recorded table:
- fake-IP + proxy → allowed;
- fake-IP without proxy and with the canary → allowed;
- literal `10.x` / `127.x` / `::1` → refused;
- a name answering `192.168.x` → refused, proxy or not;
- `localhost` → refused.

`tests/server/test_pinning_is_the_same_on_both_paths.py` keeps both callers equal.

## 12. Decisions

### 12.1 The user's (2026-10-11, answered in chat)

1. **Default mode: 沙箱优先 (sandbox first).** Commands that stay inside the sandbox run without
   asking. Cards appear only at the boundary. This is the default for everyone (§A1, §A2).
2. **替我审批 (Approve for me): built this round as an optional mode, off by default** (§A6).
3. **完全访问 (Full access): offered, behind a confirmation and with a persistent badge.** Payments,
   transfers and purchases always ask (§A7).
4. **Skill licenses: show the license text and let the user decide.** The skill is then for local
   use only and marked not redistributable (§C4).

### 12.2 My calls inside those decisions (say if any should change)

1. **Recursive or forced deletes still ask in Standard**, even inside the sandbox. Codex keeps
   exactly this on its tiny dangerous list; Hermes asks too. A plain `rm file` runs.
2. **Adding a capability always shows one card, in every mode.** This is the 0.1.57 supply-chain
   line.
3. **The mode is switchable per conversation** from the composer pill, and Settings holds the
   default.
4. **The reviewer never decides** money, new capabilities, other agents' settings or another
   machine.
5. **Cards wait 30 minutes.** An expired card is "no answer", never "declined". A message typed
   while a card waits answers it "No", with that message as the note.
6. **Reading the web stays free** inside the sandbox. Sending is what asks (§A2). Egress control by
   domain comes later (§9).
7. **`~/.agents/skills` is on by default.** `~/.claude/skills` and `~/.codex/skills` are one switch
   away.
8. **On an app card, "Once" means "for this task"** (this chat turn or job), so a 10-step task in
   one app asks once. Risky and money steps still ask per step. (③Hands' review.)
9. **Under Full access, Hands may take over the screen without a card.** The glow, the 30-minute
   cap and the pause when you touch the keyboard or mouse stay. Under Approve for me a takeover
   still asks you; the reviewer never decides it. (③Hands' recommendation.)

## 13. 尚无证据、未声称已验 (no evidence yet, nothing claimed verified)

  rule relies on the "last rule wins" measurements of 2026-10-03 and 2026-10-10. It has not been
