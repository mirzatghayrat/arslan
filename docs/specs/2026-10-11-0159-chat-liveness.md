# 0.1.59 — a long answer is not "Interrupted", a second message waits its turn

Status: approved by the user 2026-10-11 ("先修"), after hitting it on 0.1.59-beta.3 on the real Mac.
Ships in 0.1.59 final (the release/0.1.59-beta line; Hands P2 stays in 0.1.60 — ③Hands agreed).

## 1. What happened (run 160, read from the user's database, read-only)

"Make a flowchart / architecture diagram": the turn read the architecture-diagram method, then the model
spent ~5 minutes writing one long `write_file` (15:06:05 → 15:10:54) and finished at 15:11:05 with
`~/Arslan/arslan-architecture.html`. The window showed:

1. **"Interrupted"** — nothing reached the window for 5 minutes; the window's watchdog calls 90 s of
   silence "interrupted" (`web/src/stores/arslanStore.ts:120`). The server was working.
2. **"Needs your check — This item changed elsewhere…"** — the user's follow-up ("what does Interrupted
   mean?") started a second turn while the first was running and was refused as a task conflict, shown
   with the generic edit-conflict text (`web/src/components/companion/errors.ts:33`). The message was lost.
3. **"Summoning specialist…"** — the live row cycles four timed phrases ("Summoning specialist…",
   "Dispatching tools…", …) whatever is happening (`WorkingPulse`); "specialist" is from before 0.1.44.
4. The model chip read "OpenRouter (Claude, Gemini and mo…" — the long provider name hid the model.

Under it, found by ③Hands with a socket trace: **during a turn nobody reads the window's socket** (the
turn runs inside the socket's own receive loop; only a pending card read it). Pongs go unread, uvicorn
closes the socket on its keepalive (~35 s, 1011), and a Hands card answered in the window is never read
(it expires after 300 s as "declined").

## 2. Changes

**A. A resident reader per socket** (`server/ws/arslan.py`). One task reads the socket for its whole life:
pings/pongs are drained; a card answer goes to `approvals.answer` at once (a stale `call_id` still gets
BUSY); a phone's late answer is dropped as before; everything else is queued for the loop. A turn no
longer blocks reading. A card waits on its own answer (or on the window going away — then #154's path
makes it shared). A disconnect ends the loop after the running turn, as before.

**B. One turn at a time per conversation, the next one waits.** A turn holds a per-conversation lock. A
message that arrives while another turn runs — on the same socket or another window's — is told
`queued`, waits, and runs right after (`dequeued` when it starts). No conflict, nothing lost. Background
jobs are not turns and are not affected ("talk while it works" stays).

**C. "Still working" heartbeats.** While a turn runs, every 15 s the server sends `working` (elapsed) to
every window on the conversation. Not journaled, never replayed. The window counts any frame as alive, so
"Interrupted" now means the connection really went silent, not that the model is slow.

**D. Honest live row.** The timed phrases go. Before any step: "Thinking…"; after 60 s with no new step:
"Still working — a long answer can take a few minutes"; the elapsed time stays. A queued message shows
"Arslan will read this as soon as it finishes the current reply".
When nothing at all arrives for 90 s (the connection, not the model), the marker says what happened and
what to do — "Lost touch with Arslan — it may still be working. Reopen this chat to check." — not a bare
"Interrupted". A message sent while a reply streams keeps that reply's timer.

**E. Plain words for a refused chat turn.** If a turn is still refused as a conflict (should not happen
after B), the chat says "Arslan was still busy with your last message, so this one did not start —
send it again", not the edit-conflict text.

**F. The model chip shows the short provider name** ("OpenRouter · anthropic/claude-sonnet-5"); the full
name stays in its tooltip and in the picker.

## 3. Tests (each must fail on today's code)

- A second message on another window during a turn → `queued`, then answered; no conflict; both answers
  saved. Same on the same window.
- Heartbeats arrive during a long turn (interval patched short) and are not in a reconnecting window's
  replay.
- A Hands card in a chat turn is answered by `confirm_action` on the same socket within seconds (③Hands'
  `test_hands_card_in_turn.py`).
- A stale card answer still gets BUSY; #154's window-gone tests still pass.
- Window: a `working` frame keeps the watchdog quiet past 90 s; queued/dequeued notice; the live row says
  "Thinking…" then "Still working…", never "specialist"; the chip label; the conflict text in chat.
