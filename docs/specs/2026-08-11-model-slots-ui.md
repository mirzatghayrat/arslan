## 1. 本轮裁决(用户 2026-08-11)

| # | 裁决 | 代价 / 理由 |
|---|---|---|
| ① | **另立「模型分工」分区**,不进「自动化」 | 见 §5 的 spec 偏离记录 |
| ② | embedding 槽**留在**「记忆与数据」,新分区放一行灰色引导 | 它绑着本地模型下载,拆走反而断上下文;但不放引导行,新分区自己就藏了一个看不见的槽 |

## 2. 设计

### 2.1 新分区「模型分工」

五个槽 + 一行指向 embedding 的灰色引导。进 `sectionRegistry`,分区从七个变八个。

### 2.2 🔴 空值文案分三种,统一写「跟随主模型」会有两处是假的

这是本轮最要紧的一节。亲核 `routing.py` 与四个消费点后,五个槽为空时的真实行为**不是同一件事**:

| 槽 | 空值时实际发生什么 | 文案 |
|---|---|---|
| **路由** | role=`router`,在 `JUDGMENT_ROLES` 里 ⇒ **永远主配置**,不参与漂移 | 「固定用主配置 (X)」 |
| **标题** | role=`summarize`,不在 JUDGMENT_ROLES ⇒ 会被路由 | 见下方分支 |
| **压缩** | role=`summarize` ⇒ 同上 | 同上 |
| **视觉** | role=`execute` ⇒ 同上 | 同上 **+「只在带图片的那一轮生效」** |
| **合成** | 🔴 **保持本轮对话正在用的模型**(`tool_loop.py:1046` 只在配置了才替换 `a`) | 「跟随本次对话正在用的模型」 |

可路由的三个槽(标题 / 压缩 / 视觉)按运行态分支:

```
被路由的真实条件 = (llm_strategy != "single") AND (配置数 >= 2)
  真  ⇒ 「由路由策略分配」
  假  ⇒ 「跟随主模型 (X)」
```

🔴 **两个条件缺一不可**:`routing.select` 在 `len(configs) < 2` 时也返回主配置
(`routing.py`:`if strategy == "single" or role in JUDGMENT_ROLES or len(configs) < 2`)。
只看策略会让「只有一个配置 + balanced 策略」这种常见组合显示成被路由,那是假的。

🔴 **「由路由策略分配」后面不带括号点名主配置**(用户 2026-08-11 修正自己的初版措辞):
路由选中的可能不是主配置,括号里点名主配置会再次暗示「主配置在干活」,
把 [[arslan-launch-gate]] 那轮堵上的「is_primary ≠ 实际会跑的那个」从措辞里放回来。

🔴 **合成那条写成「跟随主模型」就是界面上的假话** —— 与用户排除「显示名字但不特判 router」
那个选项的理由是同一条:一行界面上的假话,和一句描述没发生的事的注释是同一个病。

🔴 **视觉那句「只在带图片的那一轮生效」是必需的,不是补充说明**。
`tool_loop.py:58-69` 写明这个条件是设计的核心:没有它,设了视觉模型会**把每一轮都悄悄挪过去**
—— 正是本 spec 要消灭的静默换模型,却从防它的功能里钻出来。
用户不知道这条,就会以为设了没生效。

### 2.3 无配置时的空状态

一个 provider 配置都没有时:显示「尚未配置模型 → 去添加」并链到 Provider 分区。
**不显示算不出来的空括号**(用户硬要求)。

### 2.4 选项列表

照 `EmbeddingSettings.tsx:156-163` 的现成形状:空选项(= 未设置)+ 每个已保存的 provider 配置
(`${label || provider} (${model})`)。**不引入 embedding 那个 `local` 选项** —— 那是嵌入专有的。

## 3. 验收(mutation 为主)

| # | 判据 | mutation |
|---|---|---|
| 1 | 五个槽都在界面上,且都能改到对应设置键 | 删掉任一槽的 prop 传递 ⇒ 红 |
| 2 | 路由槽的文案与其它四个**不同** | 让它复用「跟随主模型」⇒ 红 |
| 3 | 合成槽的文案与其它四个**不同** | 让它复用「跟随主模型」⇒ 红 |
| 4 | 视觉槽文案含「图片」条件 | 删掉那句 ⇒ 红 |
| 5 | 策略 single ⇒「跟随主模型」;策略非 single 且配置≥2 ⇒「由路由策略分配」 | 把条件改成只看策略 ⇒ 红(单配置 + balanced 必须仍显示「跟随主模型」) |
| 6 | 「由路由策略分配」**不含**主配置名 | 加回括号 ⇒ 红(断言缺席) |
| 7 | 零配置 ⇒ 引导去 Provider 分区,无空括号 | 让它渲染空括号 ⇒ 红 |
| 8 | embedding 引导行存在且指向记忆与数据 | 删掉 ⇒ 红 |
| 9 | 六语齐、逐语言非空 | —— |

**判据 5 的形状要求**:必须有「单配置 + 非 single 策略」这个 fixture,
否则只看策略的错误实现会全绿。

## 4. 不做

- 不动后端(四个槽已实装且已接线;本轮纯装备面)。
- **不把 embedding 槽搬进新分区**(裁决 ②)。
- 不做按对话覆盖、不做运行时 A/B(原 spec §1「不做」已排除)。
- 不改 `JUDGMENT_ROLES`。🔴 原 spec §2.1 已警告:路由槽是**显式覆盖**允许,
  但**不许**因为加了槽就把 `router` 从 `JUDGMENT_ROLES` 拿掉 —— **这两件事看着像一件,不是一件。**

## 5. 🔴 对 `2026-08-07-per-task-model-assignment.md` 的两处修订(用户要求留痕)

**① 偏离 §2.1「设置面进自动化分区」** —— 改为另立「模型分工」分区。
理由:自动化分区的叙事是**自花钱警告**(自动进化 / 派发上限 / 整理层,均带消费提示),
而模型槽**不会自己花钱**,它只改变已经要发生的调用用哪个模型。
混进去会稀释那个警告,而那个分区当初正是为了把花钱的东西收拢在一处才建的。

**② §3② 那个「压缩盖一处还是两处」的开放裁决,实装已按 A 做了**
(只有 `memory.py:184` 接了 `compaction_config_id`,`ingest.py` 未接)。
这是实装替 spec 做的决定,补记为已裁决,不是仍开着。
