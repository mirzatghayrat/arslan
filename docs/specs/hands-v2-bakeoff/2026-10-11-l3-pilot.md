## What the pilot found

1. **`open -a` brings apps to the front.** With `desktop_open` unable to open a document, or to make a window for an
   app that is running without one, the model used `run_command "open -a …"`, which activates the app — against
   "never take the front". Fix (P2 follow-up): `desktop_open` takes a file, and makes a window for a running app
   with none, both with `open -g`; the tool description says so.
2. **P5: the delete was not found.** The model tried the toolbar's "More" menu, the Format popover, Escape, clicking
   rows, and probing the File menu; never Edit › Delete, ⌘⌫ or the context menu. Two Arslan behaviours made it worse:
   - **A repeated Escape was refused** ("This exact action already succeeded in this task. Do not repeat it."), so
     the "More" menu stayed open; an open menu also blocks Notes' Apple events until it closes (the runner's own
     read timed out because of it).
   - **A false risky card**: clicking the note's row asked as a risky action because the row's label includes the
     note's text ("a note for the delete task").
3. **Batches were rarely used** (only P4), so the with/without-batch comparison on P1 and P3 says nothing about
   batches; the wall-time differences are noise (P1's first run lost time to the missing window).
