# L3: Hands v2 with a real model — plan, tasks, cost (waits for the user's yes)

Spec 2026-10-08-0157 §8.1 L3 and gate G10, A17 item 4: a five-task pilot first, the full twenty after it. Nothing
here has run and nothing has been spent.

## What it shows

- **G10**: at least 18 of 20 tasks done, and no risky action without its card.
- **Whether the model uses what P2 built**: one card for several apps, batches, menus, borrowing the front for a
  pop-up, acting inline in a chat reply versus in the background, honest answers when an app is refused.
- **G8' wall time, end to end** (A17): each task's wall time and model turns; two pilot tasks also run with
  `desktop_batch` withheld.

## How it runs

- **Model**: the user's main model through `scripts/kernel_bench/meter.py`, the metering proxy from the kernel bench.
  Only the proxy holds the key; the user starts it in their own terminal (the key never passes through Claude's
  session). It refuses requests past a per-run cap and a total cap, priced at peak rates.
- **Arslan**: a test instance from the P2 branch (`scripts/kernel_bench/start_arslan.sh`, throwaway HOME and data
  dir), with the development Arslan Hands. Never the user's real data dir.
- **The apps are the user's real apps.** Test content only, made by the driver before each task:
  `~/Documents/Arslan L3/` (files) and a Notes folder `Arslan L3`. Nothing else is read or changed. The Notes the
  tasks make stay in that folder for the user to delete (the driver deletes nothing).
- **Cards**: the driver answers each card and records it. App and look cards: allow. Risky cards: allow only in a
  task that asks for that action on test content, otherwise deny. Every card is logged with its kind and target;
  a risky action without a card fails the run (G10).
- **Checking**: a checker per task reads the result itself — the file on disk, the note through a read-only
  AppleScript scoped to the `Arslan L3` folder, the fixture's state file — never the model's word. A claim of
  success that the checker contradicts fails the task.
- **The Mac**: borrowing the front takes it for about a second at a time and Notes may flash, so the user should
  be away from the keyboard for the run (pilot about 20 minutes). Stage Manager off.

## Cost

Measured before (kernel bench, DeepSeek v4-pro through the same proxy): $0.046 to $0.30 a task. A desktop task
here is about 15 model calls of about 20k input tokens (system prompt, tools, history, at most two screenshots) and
about 5k output tokens in all; at the proxy's peak prices ($1.32 per million uncached input, $0.044 cached, $3.96
output) and half the input cached, that is about $0.22 a task at peak and half that off-peak.

| Round | Runs | Estimate | Hard cap (the proxy refuses past it) |
| --- | --- | --- | --- |
| Pilot | 7 (five tasks + two without batches) | $0.35 to $1.75 | $2 total, $0.40 a run |
| Full | 20 | $1 to $5 | $5 total, $0.40 a run |

With another model the token counts stay and the price changes: about 0.3M input and 5k output tokens a task.

## Built before the pilot (no model cost)

- The driver answers and records cards (the bench driver only ever declined them), and withholds `desktop_batch`
  on request.
- Task setup and cleanup for the test content; a checker for each task; run against a scripted "model" first so the
  checkers are shown to pass a right result and fail a wrong one before any money is spent.
- Estimated half a day.

## What the user does

1. Says yes (or changes the tasks), and names the model.
2. Starts the proxy in their own terminal with their key (one command, given when the driver is ready).
3. Leaves the Mac alone for the pilot, about 20 minutes.
4. Afterwards, deletes the `Arslan L3` notes and folder (or tells Claude to leave them).
