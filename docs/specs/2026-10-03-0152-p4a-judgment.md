## 0. What the code does today (re-checked 2026-10-03)

- `personal_context.assemble` (`server/services/personal_context.py:267`) returns **nothing** for a cloud model
  unless the conversation has `cloud_memory_allowed`. That flag defaults to False in the table
  (`companion_models.py:25`), the API (`api/companion.py:149`) and the web (`App.tsx:418`). The v2 store is
  activated on every boot (`storage_boot.py:19`), so this gate applies on every machine.
- Facts noticed after a turn (`turn_facts` → `memory_compat.save_facts`, origin `extractor`) are always
  `proposed` + `local_only` (`arslan/companion/memory.py` `decide_write`). A cloud model only reads
  `cloud_allowed` entries (`personal_context.py:302`), so they never qualify, even with the flag on.
- Learning has the same gate (`learning_service.py:144`).
- The fast slot is `router_config_id`, falling back to role `router`. `turn_facts` already uses it.
- SQLite in the dev venv is 3.53.1, and its `trigram` tokenizer works for Chinese substrings (checked). The
  packaged Python's SQLite version still needs checking before release (trigram needs ≥ 3.34).

So for a DeepSeek user, what Arslan remembers almost never reaches the model.

## S1 — step 0: memory reaches the model (D1)

- New setting **"记住我，并用在对话里" / "Remember me and use it in conversations"**
  (`memory_in_conversations`, on by default). It lives in Settings → Brain and the Desktop section links to it.
- With it on, a cloud model is treated as `cloud_memory_allowed` for normal entries.
  - The per-conversation `no_memory`, temporary conversations and `no_learning` keep their meaning.
  - `allow_sensitive` stays per conversation and off by default.
  - With it off, behaviour is exactly 0.1.51.
- Facts noticed after a turn: a **normal** fact becomes `active` with `use_policy=cloud_allowed` and a new
  `confirmation_kind="auto_noticed"`, so it is visible, editable and deletable like any entry. A **sensitive**
  fact stays a proposal and is never sent to a cloud model before you accept it.
- **Poisoning guard, by construction**: the fact extractor now reads only the **user's own messages** (plus
  the facts already known), not Arslan's replies, which can carry web or file content. A fact can then only come
  from your words. Today it also reads Arslan's replies; this is narrowed on purpose.
- **Migration, no silent change** (0.1.42 rule: never fake a human review): existing non-sensitive pending
  proposals that came from the extractor are listed once in Brain as "Arslan noticed N things earlier". There
  are two buttons, "Use all" and "Review one by one". Nothing is changed until you click.
- Tests: the gate (cloud model with the setting on gets normal entries but not sensitive ones; off is
  unchanged; `no_memory` and temporary still empty); `decide_write` for `auto_noticed`; extractor input is
  user-only; the migration lists and changes nothing until accepted.

## S2 — the judgment layer skeleton (task C)

- `server/services/judgment/`, with a **registry of decision points**. Each one has:
  - a name and a question template;
  - the minimal state: named fields only, never page text;
  - an answer type (yes/no with probability, choice, or score);
  - a **mode** (`off` / `shadow` / `active`), a judge model (default: the fast slot), and a threshold;
  - a **2 s timeout** and a fallback: approvals ask as today, memory skips.
- **Ledger table `judgments`** (migration 0058): decision point, state hash, verdict, probability, latency,
  model, mode, created_at, plus an `outcome` filled in later (the user's real choice on the card, whether a lesson
  was followed). Activity gets a **"判断记录 / Judgments"** list.
- **Cost**: each call is recorded in `usage_ledger` with the new scope `judgment`. Daily cap setting
  `judgment_daily_usd` (default $0.20); above it every decision point falls back.
- **Offline replay**: `scripts/judgment_replay.py` re-asks recorded questions with another model and compares
  the verdicts, so a local model can be judged later without collecting new data.
- **First decision points in 0.1.52**:
  1. `tool.approval`, **shadow**. Every confirmation card still appears. In the background the judge is asked:
     "Did the user clearly ask for this, and does it stay inside the sandbox?" The answer is only recorded,
     together with the user's actual choice. Turning it on comes later, behind the task book's gate
     (≥100 cards, ≥99% approvals among "allow ≥0.9", zero high-probability allows on refused send/delete/install,
     ≥40% fewer cards), and only by the user in Settings. Sending, paying and writing outside the sandbox always ask.
  2. `memory.worth` / `memory.merge` / `memory.applied`, **active** from the start (they run after the answer,
     are reversible and visible). They feed S5. If the user undoes more than 15% in Brain, they tighten.
  3. `turn.completion`: registered and **off** (it gets a shadow trial on the bench later).
- Deterministic, no judge: **duplicate-line folding** in the long-output store (mu measured −51% characters on
  test logs). Repeated identical lines become "… (repeated N×)" in what the model sees; the full output stays on
  disk.

## S3 — episodic memory: `conversation_search`

- Migration 0058 also creates `arslan_messages_fts` (FTS5, `tokenize='trigram'`, external content on
  `arslan_messages`), with insert/update/delete triggers and a one-time backfill.
- Tool `conversation_search {query, since?, until?, limit?}` returns **original snippets** (no summaries), each
  with the conversation title, time and a link (`arslan://conversation/<id>#<message>`, which the web opens).
  - Temporary and `no_memory` conversations are excluded at query time.
  - Queries shorter than 3 characters fall back to `LIKE`.
  - Results are wrapped as data like any tool output.
- Tests: Chinese and English substrings; time range; exclusions; a 30-day-old message comes back with its link.

## S4 — core memory: always in view

- Two bounded sets rendered into the per-turn memory block (the system prompt's volatile suffix, after the
  byte-stable prefix, so the 0.1.50 cache holds):
  - **"关于你 / About you"**: active global facts and preferences, ≤ 1,500 characters, pinned first, then most
    recently confirmed.
  - **"Arslan 笔记 / Arslan's notes"**: a new memory kind `environment`, for facts about this Mac and setup.
    ≤ 2,500 characters.
- The block is snapshotted at turn start; writes during a turn apply from the next turn.
- Relevance-picked memory (`assemble`) keeps working for project/expert scopes and anything beyond the core.
- Tool `memory_note {action: add|replace|remove, set: about_you|notes, id?, text?}`:
  - It works by entry id, never by substring (Hermes' substring matching becomes unreliable after about 10 entries).
  - When a set is full it refuses with the current list, so the model replaces or removes something.
  - Every change is a normal memory revision: visible, undoable, with a source.
  - It goes through the same write rules (`decide_write`). The model's own writes to "About you" follow S1:
    normal content from the user's words is active; anything else is a proposal.
- Brain shows and edits both sets directly.

## S5 — lessons v1 (the first and most valuable layer)

- Table `lessons` (migration 0058) holds:
  - `situation`, `advice`, `polarity` (do/avoid), and `source` (user_correction | detour | machine_quirk);
  - an `evidence` ref (conversation/run) and `status` (active | proposed | stale | archived);
  - `pinned`, plus counters `recalled`, `followed`, `succeeded`, `failed`, and `last_used_at`.
- **Capture**, after the answer and off the reply path, using the S2 decision points:
  1. Was there a correction from the user, or a detour that ended in success? A detour is found from the turn's
     own trace: a tool failure with its error code or message, later a success by another route. These are host
     facts.
  2. `memory.worth`: is it worth keeping?
  3. `memory.merge`: is it a duplicate, more precise, or contradictory? Then write or merge.
- **Effect (D2)**: a lesson from the user's own words, or from a detour in a turn that read no external content
  (no web/browser reads, no files outside the workspace), takes effect at once and can be undone. Otherwise it is
  a proposal card "Arslan 想记住一个做法 / Arslan wants to remember a practice". Lessons never grant permissions:
  commands still go through `terminal_policy` and the sandbox.
- **Recall**: at turn start, FTS over lessons with the user message; the top ≤ 5 lessons (≤ 800 characters) go into
  the `<agent_status>` block, not the system prompt. `recalled` +1.
- After the turn, `memory.applied` decides whether each recalled lesson was followed, and whether that went well;
  this fills the counters. The curator that uses the counters is P4b.
- UI:
  - after a turn that learned something, one small line in chat: "学到了：… [撤销]";
  - Island overview: "+1 practice";
  - Brain → "学到的做法 / Learned practices": list, source, counts, undo/pin/delete;
  - Setting "学到的做法直接生效 / Learned practices take effect" (on, tiered as above).
