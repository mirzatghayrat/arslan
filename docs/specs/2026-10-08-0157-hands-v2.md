### 0.2 Limits of the design, not bugs

- **No eyes.** Hands is AX-tree only and never asks for Screen Recording (0.1.53 §2.4). Canvas, custom-drawn and
  web-in-app surfaces are invisible or opaque.
- **The engine is AX-only for good.** agent-desktop's maintainer declined background pixel input (PRs #227–229
  closed 2026-10-01). Measured limits on this Mac: Finder cannot rename in the background (0.1.53 amendment 13);
  only the current Space is seen (amendment 8); a headless shortcut can bring the app forward (amendment 6).
  Upstream main fixes Electron snapshots (#238) and the shortcut case, unreleased since 2026-09-23.
- **Slow and chatty.** One agent-desktop process per command; no batching, no "what changed", no menu tool.
- **Acting only in background jobs, one card per app per job** (`server/orchestrator/arslan.py:943-985`).
- **Text-only tool results.** `arslan/llm/trajectory.py` renders tool results as text (native `role:"tool"` for
  OpenAI-compatible providers; the legacy "TOOL RESULT for X" user message for Anthropic and Gemini). Images reach a
  model only when the user attaches one, and the vision slot applies only to such turns
  (`server/orchestrator/tool_loop.py:50-77`, ruling ②B).

### 0.4 cua-driver facts this spec relies on (read at `trycua/cua` `49e924c4`, 2026-10-08)

- **Licence, checked at the source.** Root `LICENSE.md` is MIT and covers every directory without its own LICENSE
  (`LICENSING.md`); `libs/cua-driver` has none, and every crate the driver builds from says `license = "MIT"` or
  takes the workspace's MIT. Not MIT:
  the optional perception extension (OmniParser icon detector, AGPL-3.0-only — never installed) and **Cua Spaces,
  `cua-spacesd` and the streaming crates (FSL-1.1-MIT, source-available)** — not used (§9). The driver links
  `libs/cua/crates/cua-telemetry` from outside its folder, so it builds only from the whole repository.
- **Churn.** 112 `cua-driver-rs-v*` tags; latest `v0.34.0` = `b0968e1b`. We pin.
- **Embedding.** In embedded mode the driver never shows a permission prompt and stays in its spawner's TCC
  responsibility chain: Accessibility and Screen Recording are the host's (`Skills/cua-driver/EMBEDDING.md`).
  Two host shapes: a daemon on a Unix socket plus an MCP proxy, or the **private worker**
  (`cua-driver __private-worker --generation <id>`, `crates/cua-driver/src/private_worker.rs`): one child, one
  JSON line per request on inherited stdin/stdout, operations `metadata, list, call, bind_session, close_session,
  sessions_list, shutdown`, and every answer carries `ActionCompletion` = `NotStarted | Completed | Unknown`.
- **The daemon socket checks only the user id** (`serve.rs:709-715`; only "trusted service sessions" check the parent
  pid): any process of the user could drive apps through it with the host's grants — the hole 0.1.53's peer check
  exists to close. Hence the private worker (§3.2).
- **Phones home by default.** Content-free PostHog telemetry (EU) with an installation id, on unless `DO_NOT_TRACK`
  or `CUA_DRIVER_RS_TELEMETRY_ENABLED=false` (`telemetry.rs`); a `check_for_update` tool and an update banner reach
  GitHub; an extension manager installs signed packages.
- **Results.** Every action returns `effect` ∈ `confirmed | partial | unverifiable | suspected_noop | refused`, a
  `route`, `delivery.mode`, `evidence` (value read back, window change) and optional escalation advice (`pixel,
  foreground, page, session`); "escalation belongs to the harness" (`docs/action-result-contract.md`).
  `verify_state` checks a postcondition: `satisfied | unsatisfied | unknown`, and `unknown` is never success.
- **What borrows the focus** (`Skills/cua-driver/MACOS.md`): element (AX) actions never do. A background pixel
  click goes through SkyLight to that process with "focus without raise": the target becomes active for event
  routing while its window stays where it is — the user's window loses key focus for the click. `invoke_menu`
  activates the target briefly (the menu bar belongs to the front app) and restores. Drags, modified clicks and
  surfaces that only take input in front need `delivery_mode:"foreground"`: front the window, act, restore; a
  foreground pixel click leaves the hardware pointer at the target.
- **Speed knobs** (EMBEDDING.md, cua's own numbers): after each action the driver watches for new windows for up
  to 1000 ms, which also holds a "give the front back" lease; a background AX click took 1153 ms by default, 325 ms
  at 200 ms, 78 ms at 0. Typing 185 characters took ~3650 ms at the default 8 ms key gap, ~980 ms at 2 ms.
- `prepare_desktop_environment` only does something on Linux; the experimental PiP window and `set_config` write
  `~/.cua-driver/config.json` under `$HOME`.

## 3. Engine: cua-driver inside Arslan Hands

### 3.1 Who holds what

```text
Arslan.app ─ arslan-server ─ run_command …        never hold Accessibility or Screen Recording
                 │ 0600 socket + per-launch token + code-signature peer check (0.1.53 §2.2)
Arslan Hands.app  (LaunchServices; its own responsible process; holds Accessibility + Screen Recording)
 ├─ hands/agent-desktop                 per command        (until it is removed)
 └─ hands/cua-driver __private-worker   one per Hands run  pipes only, no socket
```

Unchanged from 0.1.53: only Hands holds grants; it is never an ancestor of `run_command`; the backend reaches it
only through the checked socket. Both engine binaries sit **beside** the bundle, never inside it (0.1.53 amendment
1: a binary inside the bundle was lent the bundle's grant when run on its own). Hands checks each binary's sha256
against `Contents/Resources/<name>.sha256` (inside the sealed bundle) before every spawn.

### 3.2 The private worker, not the daemon

The daemon's socket admits any process of the user (§0.4); the private worker has no socket at all, only Hands'
pipes. It also reports `NotStarted / Completed / Unknown` per request, which is exactly what at-most-once needs.
(cua's third shape, the same-process SDK, would put the driver inside the backend, which must never hold grants.)
The price: it is cua's internal SDK channel ("not a CLI product surface"), so its protocol (version 1 today) is
pinned with the binary and covered by contract fixtures; a version change fails the build, not the user. Fallback
if the worker ever cannot do something we need: the daemon with its socket inside Hands' 0700 folder **and** a peer
check added in our fork — never the bare daemon.

### 3.3 Launch contract

Hands builds the worker's environment from nothing (no inheritance): `CUA_DRIVER_EMBEDDED=1`,
`CUA_DRIVER_HOST_BUNDLE_ID=<Hands' bundle id>`, permission mode `standard` (Arslan owns every ask; with browser tools
refused, `standard` has nothing left to ask), `DO_NOT_TRACK=1`, `CUA_DRIVER_RS_TELEMETRY_ENABLED=false`,
`HOME=~/Library/Application Support/Arslan Hands/cua-home` (cua's config, ids and logs stay inside Hands' folder,
and a user's own cua install cannot change Arslan's driver), `CUA_DRIVER_WINDOW_CHANGE_TIMEOUT_MS=300` (start
value; Hands' own give-back guard from 0.1.53 amendment 6 stays), `CUA_DRIVER_KEY_GAP_MS` left at 8 until the
harness shows a lower value reads back exactly, minimal `PATH`. No command-line or tool argument can change any of
these. Our fork also compiles out the telemetry sender, the update check and the extension installer (§3.6), so
"Arslan's hands never phone home" holds three ways and is measured (gate G9).

A new worker per Hands run (a fresh `--generation`); if it dies, Hands starts another, and the request in flight is
answered `unknown`, never replayed.

### 3.4 What Hands lets through (enforced in Hands; repeated in the backend for clear messages)

| cua tools | Allowed |
| --- | --- |
| `list_apps`, `list_windows`, `get_window_state`, `get_accessibility_tree`, `verify_state`, `zoom`, `get_screen_size`, `check_permissions`, `health_report` | reads; screenshots and trees only of windows of apps that may be looked at |
| `click`, `double_click`, `right_click`, `scroll`, `set_value`, `type_text`, `type_text_chars`, `press_key`, `hotkey` | acting, background delivery, always addressed to one pid (and window); never a global key |
| `invoke_menu`, foreground `delivery_mode`, `drag` | borrow (§6.3) or takeover (§6.4) only |
| `bring_to_front`, `move_cursor`, `set_window_frame` | takeover only |
| `launch_app` | `desktop_open` of an app the user granted; launched in the background |
| `browser_*`, `page`, `get_browser_state`, `get_desktop_state`, `get_cursor_position`, `check_for_update`, `install_ffmpeg`, `set_config`, `get_config`, `start/stop_recording`, `get_recording_state`, `replay_trajectory`, `kill_app`, `escalate_session`, `probe`, `runtime_only_probe`, `echo`, perception/extension tools, **any tool not named above** | never (web pages go through Arslan's own browser; never a whole-desktop screenshot) |

Kept from 0.1.53 §2.4: the never-list (password managers, System Settings, security dialogs, Notification Center,
Arslan and Arslan Hands), the tiers, no typing into secure fields (Hands reads the target's role/subrole first), a

allowed app; a coordinate click must come from the latest capture of that window (§4.6); keys never go anywhere
but the target pid.

### 3.5 One engine interface

Hands gets an `Engine` trait with two implementations (agent-desktop per command; cua private worker) under one
policy layer, so the backend never sees engine names. Every action answers in one shape: `outcome` (§5.3),
`evidence`, `route`, `mode_used` (`background | micro_borrow | borrow | takeover`), `front_restored`, `summary`.
The agent-desktop adapter fills it from `verified` and the front check (that is D7, generalised).

### 3.6 Maintenance

Same discipline as agent-desktop (0.1.53 §1 and amendment 14): **fork `trycua/cua` → `mirzatghayrat/cua`** (public;
**asked of the user before creating it** — the driver builds only from the whole repository); branch
`arslan/cua-driver-rs-v0.34.0` = upstream tag (or the latest tag on the day P1 starts) + one commit that vendors
every crate + one small commit that compiles out telemetry sending, the update check and the extension installer —
where removing a piece would reach deep into cua's code, that piece is left unreachable instead (Hands refuses its
tools, §3.4) and G9 proves the silence (`ARSLAN-FORK.md` lists exactly which).
`packaging/hands/cua-driver.pin` holds repository, branch, commit, upstream tag. `build_hands.sh` builds `cargo build --release --locked --offline -p cua-driver` from a clean fetch at the pin,
records the sha256, refuses a checkout whose `vendor/` holds git-ignored files; CI runs cargo-deny (licences: no
AGPL/FSL crate may appear) and `scripts/verify_vendored_checksums.py` on the pin; `THIRD_PARTY_NOTICES.md` gets
cua's MIT notice. Monthly sync; exit plan: if upstream breaks the worker protocol or goes quiet, we keep the fork.

### 3.7 Switching engines

A setting in `<data>/hands/settings.json` (`engine`), visible only in development builds. Default `agent-desktop`
through P1; the bake-off (§8.4) decides; on a pass, P2 makes `cua` the default and 0.1.58 removes agent-desktop.
**If cua fails the gates**, P2 is re-planned on agent-desktop at upstream main plus our own ScreenCaptureKit window
capture inside Hands, written down as an amendment here before any P2 code.

## 4. Seeing (look v2)

### 4.1 What a look returns

The window (title; the app's other windows by title), the focused element, **what changed since the last look of
this window** (added / removed / changed value), the interactive elements with refs and their position in the
screenshot's pixel frame (trimmed to the skeleton as today; `ref` opens a part), and **one screenshot of that
window**. Example of the text part:

```text
Notes — "Groceries" (other windows: "Ideas", "Work")
Focused: text area "Body" [e14]
Changed since your last look: + button "Done" [e31]; value of [e14] is now "milk, eggs"; − sheet "Share"
[e3] button "New Note" (812, 44)   [e14] text area "Body" (640, 380)   …  (41 of 212; open more with ref)
```

### 4.2 Screenshots

- Window only, through the engine (ScreenCaptureKit; works when the window is covered; other Spaces, minimized
  and full-screen windows are harness cases, §8.2). Long edge at most 1280 px; the scale is kept with the capture.
- Not taken when: Screen Recording is not allowed for Arslan Hands; the user turned screenshots off; the app is on
  the never-list or the user's "no screenshots" list. The look then says why, once per conversation, and works
  from the tree as today.
- Screen Recording is requested from Settings → Hands (a button that makes Hands call
  `CGRequestScreenCaptureAccess`), never in the middle of a job. macOS wants Hands relaunched afterwards: Hands quits
  when idle and the backend starts it again on the next request, as it does today.
- Screenshots are never written to disk. The trace records only that one was taken and its size; conversation
  history keeps the text part and a stub ("[screenshot of Notes · Groceries]").
- Cost: a 1280-px screenshot is about 1–2k input tokens on Claude-class models; §4.5 keeps it bounded.

### 4.3 Images in tool results

A tool result's content may be text plus image parts (`trajectory.py`). Rendering:
- legacy path (Anthropic, Gemini): the "TOOL RESULT for desktop_look" user message carries the image parts; the
  providers already translate image parts in user messages;
- native path (OpenAI-compatible): `role:"tool"` stays text; the images go in one user message placed right after
  that step's tool messages ("Screenshot for desktop_look (call <id>): Notes — Groceries").
Unit tests check the translated payload of each provider; nothing new is sent to a model in tests.

### 4.4 When the model cannot see

The order of `server/services/ocr_fallback.py` (decision ①A), unchanged: tier 1 the job's own model reads the
screenshot; tier 2 **only if that model refused it as an image** (`ocr_fallback.model_refused_the_image`, the narrow
matcher of `vision_errors.py`). Then the tool loop removes the images from this turn, puts
`ocr_fallback.read_locally` text (macOS Vision, nothing downloaded) in their place, repeats that model call once (a
model call, not an action) and remembers for this process that this model configuration refuses images, so later
looks go straight to tier 2. The vision slot is not used for Hands: ruling ②B applies it to turns that carry the
user's image, and swapping the model in the middle of a job would change the agent mid-task. No capability flag
is trusted (decision ②A).

### 4.5 Keeping it small

Only the last two screenshots of a turn or job stay images; older ones become their stub. Diffs (§4.1) and batches
(§5.6) cut the number of looks.

### 4.6 Look before acting

Hands keeps the latest look per window. An action's ref, and a coordinate click's capture, must come from that
look; anything older answers `look_first`. Coordinates are in the screenshot's pixel frame as the model saw it;
Hands converts with the capture's scale and refuses if the window moved or resized since.

## 5. Acting

### 5.1 The ladder

1. **Accessibility action** on the element (press, confirm, pick, set value) — background, no focus change.
2. **Events posted to that one process** (key events; pixel clicks via "focus without raise") — background; a
   pixel click is a *micro-borrow* (§6.2).
3. **Borrow** — menus, drags, modified clicks, surfaces that only take input in front (§6.3).
4. **Takeover** — long foreground work, with a card (§6.4).
5. **Refuse** with the reason (and, when the same task keeps needing 3–4, propose the workstation, §9).

Escalation is automatic only when nothing was delivered (`refused` with `route_unavailable` or
`delivery_failed`, or `NotStarted`), and from 2 to 3 only if the user's "borrow when needed" switch is on. After
`unverifiable` or `suspected_noop` something may have happened, so nothing escalates by itself: the model gets the
honest outcome, looks again, and may then ask for step 3 itself with `front: true` on that call (refused with the
reason when the borrow switch is off). Nothing ever escalates to takeover by itself.

### 5.2 Tools (model-facing)

Every acting call keeps `element` — what the model thinks it acts on, in words — shown next to the real label read
from the element on cards, the island and the trace.

### 5.3 Honest outcomes (one vocabulary for both engines)

| Outcome | Means | What the model is told |
| --- | --- | --- |
| `done` | delivered, with evidence (value read back, window change) | done, and the evidence |
| `sent_unconfirmed` | delivered, no proof either way | "look before the next step; do not repeat it blindly" |
| `no_effect` | delivered, nothing changed | "look: the element may be disabled, or need the front — after looking, `front: true` lets Arslan borrow it (if the user allows borrowing)" |
| `partly_done` | n of m delivered (typing) | how far it got; look first |
| `refused` | nothing delivered | the code and the hint |
| `unknown` | the reply was lost (§1 D1) | "this may have happened: look before anything else" |

Plus `mode_used`, `front_restored` and, when the user moved during a borrow, `yielded_to_user`. A `done` that the
fixture's ground truth contradicts is a lie; the gate is zero (G6).

### 5.4 Typing that cannot lose text

- `replace`: set the value, read it back; equal → `done`. Only if the field refused a value (nothing delivered):
  focus it and type to the pid, read back. Never type after a set that may have landed.
- `append`: the read must succeed (else `append_unreadable`); write old + new; read back.
- `submit`: confirm on that same field (the accessibility "confirm" action), else Return to the pid with that field
  verified focused, else `submit_unsure`. In apps where Return sends, submit is risky (asks, as today).
- Secure fields refused (as today). Over 2,000 characters: set-value only (typing would outlast the deadline); no
  clipboard. Chinese, emoji, punctuation and layout-dependent characters are harness cases.

### 5.5 Menus before shortcuts

`desktop_menu` reads the item from the app's menu bar (reading works in the background) and refuses missing,
disabled or ambiguous items. If the item has a keyboard shortcut, Hands sends it to the pid in the background; the
outcome goes back to the model as it is — a command that changes nothing visible (Bold, Save) can look like
`no_effect` while it worked, so Hands never runs it a second way by itself (§5.1). An item without a shortcut, or a
call with `front: true` after the model has looked again, goes through `invoke_menu` (a borrow). The tool
descriptions steer the model to in-window buttons first, then menus, then raw keys.

### 5.6 Batches

`desktop_batch` runs up to eight steps on one window with the same checks per step, stops at the first step that
is not `done`, asks for a risky step at that step, and ends with one look (diff + screenshot). One round trip
instead of nine.

### 5.7 Acting inside a chat turn

A chat turn may act when the conversation holds the app's grant: at most five acting calls, all in one app (a batch
counts its steps). Past that the tool answers `act_in_background` (today's code path) and the model starts
background work. Takeover only inside a background job.

## 6. Four ways to work, and how the user always knows

### 6.1 Overview

| Mode | When | The user sees | Guaranteed | Ends |
| --- | --- | --- | --- | --- |
| 后台 Background | ladder steps 1–2 (default) | Arslan's cursor at the target; the island line "Arslan · Notes · 新建备忘录"; Stop | front app, key window, pointer and window order unchanged (micro-borrow: §6.2) | each action |
| 借用 Borrow | step 3 | island "借用前台"; a short edge glow | waits for a typing pause; no key lost or misdirected; everything given back | each borrow |
| 接管 Takeover | step 4, after a card | steady edge glow; island timer, Esc and Stop | pauses within 0.2 s when the user touches anything | done, time up, Esc, Stop, lock |
| 工作机 Workstation | the user (or Arslan, proposing) sends a job there | the VM's screen in a window | nothing happens on the user's screen | the job |

### 6.2 Background and the micro-borrow

AX actions change nothing the user can see but Arslan's cursor. A background pixel click makes the target active
for a moment without raising it, so the user's window loses key focus for that click: Hands arms the key hold
(§6.3 step 4) around it, checks that the user's window is key again within 150 ms (and gives it back itself if
not), then replays any held keys. No glow: it is too short to see; the gate is zero keys lost or misdirected (G4).

### 6.3 Borrow — the algorithm (⚠ high effort: P2-3)

1. The step is borrow-class (§5.2) and "需要时借用前台" is on (default on).
2. **Wait for a typing pause**: no key from the user for 1.0 s. While waiting the island says "Arslan 等你停一下，
   要借用前台"; Arslan never interrupts typing; after 60 s the tool answers `waiting_for_pause` and the model may do
   other work.
3. Glow on (all displays) and the island line "借用前台 · Notes · 文件 › 新建".
4. **Key hold**: a Hands event tap holds every key event that Hands and its worker did not post, in order (no cap
   that drops; past 500 events the island asks the user to pause).
5. Note the user's front app, key window and pointer position.
6. Act (foreground delivery, `invoke_menu`, drag).
7. **Give back**: front app and key window (Hands re-activates them if cua's best effort missed), pointer moved back
   if it moved.
8. Check the give-back, then **replay the held keys** into the user's window through the normal event path (so
   input methods compose as usual), disarm, glow off.
9. The user moves or clicks the mouse during 3–8 → finish the current event, skip the rest, give back, replay,
   answer `yielded_to_user`.
10. Secure input is on (`IsSecureEventInputEnabled`, the user is typing a password) → no borrow; wait.

### 6.4 Takeover

- Started only by `desktop_takeover {why, minutes}` in a background job → card "Arslan 想接管屏幕约 N 分钟：<why>。
  期间请别动键盘鼠标，按 Esc 随时停。" [允许] [不允许]. The island may answer it.
- During: steady glow, island timer and Esc/Stop; foreground delivery allowed; screenshots stay window-only; a
  risky action still asks (the takeover pauses at its card).
- **Any input Hands did not post → no new event within 0.2 s**; the island offers 继续 / 我来 / 停止. 我来: the job
  waits (up to 30 min) until 继续. Esc = pause.
- Ends when the job is done, time is up (one tap on the island extends), Esc then 停止, Stop, or the screen locks.

### 6.5 When the user is away

Switch "我离开时可以借用和接管（风险操作仍等我）", default off. Away = no input for 180 s (the island's measure,
`desktop/src-tauri/src/island.rs:47`) and the screen unlocked. While away, borrows skip the typing pause and a
takeover starts without its card; risky actions still wait for the user; the first input pauses as in takeover.

### 6.6 Signals and where they are drawn

| Signal | Background | Micro-borrow | Borrow | Takeover | Drawn by |
| --- | --- | --- | --- | --- | --- |
| Arslan's cursor at the target | ✓ | ✓ | ✓ | real pointer | cua overlay (excluded from captures) |
| island line: app · element · mode | ✓ | ✓ | ✓ | ✓ + timer | island (Tauri) |
| island thumbnail of the window being worked on (the last screenshot) | ✓ | | | | island, if screenshots are on |
| edge glow | | | short | steady | Hands (new; click-through, every display, above full-screen apps; window captures never include it) |
| key hold | | ✓ | ✓ | input → pause | Hands |

Glow colour and the island lines are drawn in a mock first (P2-3), in Arslan's own look.

### 6.7 Locked screen, displays, Spaces

Screen locked → every Hands action waits (no locked-screen use). Glow on every display. Windows on other Spaces
and full-screen apps: whatever the harness proves cua can reach (agent-desktop could not, 0.1.53 amendment 8).

## 7. Asking the user

### 7.1 Unchanged

The never-list; tiers (browsers look only, terminals and editors look and click); risky actions — the real label
or key, every time, and the island cannot approve them (`approvals.island_may_answer`); the trace (typed text as
its length); Stop.

### 7.2 One card for several apps; "always"

`desktop_access {apps, why}` opens one card listing each app with what its tier allows; per app: 这次对话 /
总是允许 / 不允许. The island may answer it (allow = 这次对话 for every app listed; "always" is chosen only in
Arslan's own card). "Always" grants live in `<data>/hands/settings.json`
(`always: [{bundle_id, name, since}]`) and are listed in Settings → Hands with 移除; today's conversation grants
stay in memory. A job started from a conversation inherits that conversation's grants (today each job asks again).
The first `desktop_look` or act on an app without a grant still asks for that app alone, as today.

### 7.3 Risky, extended

Also risky, every time: a menu item whose label matches the risky words (Delete, Send, Empty Trash…, six
languages); a drag onto the Trash; a coordinate click whose element (Hands hit-tests the target app at that point)
has a risky label. A coordinate click with no readable label is an ordinary action; the card and trace say
"(x, y), no readable label".

### 7.4 Settings → Hands

Permissions: Accessibility, Screen Recording (for screenshots), and key hold if macOS wants a separate permission
for it (§12 Q2). Switches: Hands; screenshots (on); borrow when needed (on); while I'm away (off); cursor (on).
Lists: always-allowed apps; apps never touched (built-in + yours); apps never screenshotted (yours). Engine: dev
builds only.

## 8. Proof: harness, bake-off, gates, real-model run

### 8.1 Three layers

- **L1 engine harness** (`scripts/hands_harness/`, new): drives Hands directly over its socket (development build),
  engine `agent-desktop` or `cua`; no backend, no model.
- **L2 product harness**: `scripts/hands_smoke.py` grown — the real tool executors in a fake job, cards answered by
  the script and recorded.
- **L3 real-model run**: 20 real tasks with the user's main model. Paid: the task list and a cost estimate go to
  the user first; it runs only after their yes.

### 8.2 Fixtures

- `scripts/hands_fixture/HandsFixture.swift` grown: text field, text view, secure field, pop-up, checkbox, list,
  a slow button (label changes after 2 s), "Delete", a chat field where Return sends (counts sends), a canvas with no
  accessibility (custom-drawn buttons), menu items with and without shortcuts, a sheet — and an action log that is
  the ground truth for "done" and for double execution.
- **Typist**: the user's stand-in. A front window the harness types into at 8 characters a second (events it
  posts itself, so Hands counts them as the user's) and whose text must come out exact; it also moves the mouse for
  the borrow and takeover cases.
- Chromium: Google Chrome, if installed, with a throwaway profile on cua's HTML fixtures (vendored with their MIT
  notice; engine level only — Arslan's policy keeps browsers look-only). Electron: a minimal fixture built for
  development only, never shipped. A surface that is missing is reported as skipped, never as passed.
- Real apps, reversible steps only: Notes (a test folder), TextEdit (a temp file), Finder (look in a temp folder),
  Reminders and Calendar (a test list and calendar). What the run leaves behind is listed for the user to remove.
- About 60 cases per engine: reads, clicks, typing (incl. Chinese, emoji, punctuation, long text), menus, keys,
  pop-ups, scroll, slow UI and waits, other Space / minimized / full-screen, Chromium and Electron, canvas pixels,
  drags; and injected faults: a slow reply, a dropped connection after sending, a worker crash, a stale ref, a failed
  read before append, focus elsewhere before submit.

### 8.3 Oracles (an observer process samples every 20 ms)

O1 front app unchanged · O2 the user's key window unchanged (micro-borrow: back within 150 ms) · O3 hardware pointer
unchanged · O4 on-screen window order unchanged · O5 the typist's text exact and the target's text exact (nothing
leaks either way) · O6 the fixture log shows each requested action exactly once · O7 the reported outcome agrees
with the fixture's ground truth.

### 8.4 Bake-off (⚠ high effort: the decision)

Both engines (agent-desktop at 0.9.4 as shipped and at upstream main; cua at the pin), every case, three runs, one
sitting on this Mac with the user's usual apps open. The typist stands in for the user, so the Mac must be left
alone for the run (about an hour; asked of the user for a time). Today's numbers are measured first and recorded
before anything is called faster. Results (JSON + a table) and the decision go into an amendment to this spec.

### 8.5 Gates (cua becomes the default and 0.1.57 ships only when all hold)

| Gate | Requirement |
| --- | --- |
| G1 | No action runs twice (O6) under every injected fault |
| G2 | No text lost: append, replace and submit cases with injected read failures |
| G3 | Background: zero O1–O5 violations |
| G4 | Borrow and micro-borrow: zero keys lost or misdirected with the typist running; give-back 100 %; borrow p95 ≤ 1.5 s (drags excepted) |
| G5 | Takeover: glow on 100 % of the time; p95 ≤ 0.2 s from the user's input to the last Arslan event |
| G6 | Honest: zero `done` that O7 contradicts |
| G7 | Reach: cua ≥ agent-desktop on the case list, Electron included |
| G8 | Speed: L1 median look latency on the same windows, and the wall time of the L2 scripted tasks done with v2 tools (batches, diffs), each at most half of today's |
| G9 | Privacy: the worker opens zero network sockets for the whole run; writes nothing outside Hands' folder (anything else listed); screenshots only of allowed windows |
| G10 | L3: at least 18 of 20 tasks, zero risky actions without a card |

## 9. Arslan's workstation (0.1.58; outline — its addendum comes after a spike)

A macOS virtual machine on this Mac, made with **Lume** (MIT; Apple's Virtualization framework), running its own
Arslan Hands with cua-driver. Arslan sends a job there when it needs long foreground work or the user chooses
"在工作机上做": nothing moves on the user's screen. The VM's screen opens in a window for watching; "我来接手" means
the user clicks into it. Only `~/Arslan` is shared. The user signs in to accounts inside the VM themselves (Arslan

licence allows up to two additional macOS instances in virtual machines on a Mac already running macOS, including
for personal non-commercial use; the user reads it before we build. The spike measures: creation time, disk, idle
memory and CPU, the grants inside the VM (the user allows Hands once there), the channel from the host backend to
the VM's Hands (latency, how the peer check holds across it), and signing in to iCloud inside the VM.

### A2. third-hand and arc-cua, evaluated (2026-10-08, the user's request)

`shhivv/third-hand` (MIT, Swift, 331★, one author, created 2026-09-19) is a chat app that
proves TypeSafe's Jev decision model on computer use: ChatGPT (signed in with the user's plan)
plans a whole task as steps, Jev picks controls when labels are ambiguous, and screen labels and
values go to OpenAI and TypeSafe. **Not adopted** — it is an app, not an engine, it needs two
cloud services, and it types shell commands into terminals. Two UX ideas are noted for later:
the user choosing per task between "in the background" (⇧↩) and "on screen" (↩), and a hotkey
that opens a thread with the front app already tagged.

Its driver, **arc-driver** (`shhivv/arc-cua`, MIT, Python + PyObjC, 285★, one author, created
2026-09-20, release v0.1.0), is a real third engine candidate. Read in its source at
`6b353039`: the same private SkyLight calls as cua for per-process events and borrowed key focus;
a **private CGVirtualDisplay** to "park" minimized windows and hidden apps out of sight while they
take events; menu items pressed through accessibility in the background; and a **journal of
each app's structural changes** (windows, sheets, menus, focus) from accessibility
notifications: an action on a snapshot taken before a sheet opened is refused (`changed`) with a
fresh snapshot instead of landing under the sheet. Its own benchmark (one Mac, macOS 26.6.2,
against cua-driver 0.32.0 at cua's defaults, web tasks developed on the same suite) claims 4–32×
speed, 5/5 vs 0/5 on minimized windows, 10/10 vs 0/10 menu commands in hidden apps, and
cua-driver **pressing Submit under a sheet that opened after the look, 5/5**; cua-driver wins on
late sheets (0.3–0.8 s), Electron trees without relaunching the app (380 vs 13 elements in
Obsidian; arc needs `--force-renderer-accessibility`) and drag. Part of cua's latency there is
its default 1000 ms window watch, which §3.3 already sets to 300 ms (cua's own figure: 1153 →
325 ms).

Changes to this spec:
1. **§8.4 bake-off: three candidates** — cua-driver at the pin, agent-desktop, and arc-driver at
   a pinned commit through its MCP stdio server (L1 only; no packaging until it wins). Shipping a
   Python runtime inside Hands is a larger trust surface than one fixed binary (an interpreter
   that inherits Hands' grants; every file must be hash-checked), so arc-driver must win clearly
   to be chosen, and its virtual display must pass the "don't disturb" oracles (display
   arrangement, Spaces, the pointer never reaching it).
2. **§8.2 new cases, for every engine**: a sheet that opens 0.3, 0.8 and 1.5 s after a click;
   **acting on a look taken before a sheet opened** (must never land under it); a minimized
   window; a hidden app; a menu command in a hidden app; an Electron app's tree without
   relaunching it; a 2,000-row table and a 2,000-file Finder window.
3. **§4.6 look before acting, strengthened in Hands itself (engine-independent)**: Hands keeps,
   per app it acts on, a journal of structural changes from accessibility notifications
   (window created or closed, sheet, menu opened, focused window changed). An action whose look
   is older than the last structural change is refused with `changed` and a fresh look; value
   changes do not count, so several actions on one look still work.
4. **§5.5 menus**: try pressing the menu item through accessibility in the background first;
   the shortcut and `invoke_menu` (borrow) follow only if the harness shows the press does not
   work for that app.

### A4. P1-2 built and measured (2026-10-08)

### A5. P1-3: one outcome vocabulary for both engines (2026-10-09)

Hands now says `outcome` (§5.3: `done | sent_unconfirmed | no_effect | partly_done | refused`)
and `mode_used` (`background` until the borrow modes exist) on every action it ran, for either
engine (`desktop/hands/src/outcome.rs`): agent-desktop's `delivered_verified` is done, anything
else sent-unconfirmed; Cua's `confirmed / partial / suspected_noop / refused` map one to one and
`unverifiable` or any unknown word is sent-unconfirmed — never done. An action agent-desktop
reported as an error carries no outcome: its error code says what happened. The backend reads
Hands' word (`hands_contract.outcome`), treats a word it does not know as sent-unconfirmed,
falls back to the P0 reading for an older Hands, and tells the model each outcome in its own
words (`refused` is `ok: false`). Tests: Rust 57, Python (P0 + this) 22 in `test_hands_p0.py`;
5 mutations caught. The engine choice in the backend and the tools v2 mapping stay in P2.

### A6. P1-4: the L1 harness, and what its first runs showed (2026-10-09)

`scripts/hands_harness/` (`python -m scripts.hands_harness.run --hands-app …`): HarnessFixture
(a real app bundle; ground truth in a 50 ms state file and an event log; set-up commands
through a file), Typist (the user's stand-in, opt-in with `--typist`), an observer (front app

NSWorkspace needs a run loop; pointer; on-screen window order), the oracles O1–O7
(`oracles.py`, unit-tested), engine adapters for agent-desktop and Cua over the real Hands
socket, and 13 cases. Canvas pixels, drags, other Spaces, Electron and Chromium, and large
tables are still to add (P1-5).

**Found by the first runs and fixed in Hands at once:** Cua's window state carries the app's
menu bar including the system's Apple menu — Recent Items (the user's recent documents and
apps) and "Log Out <the user's name>". Hands now cuts the Apple menu out of every window state
it relays, drops the text tree (`tree_markdown`), and no longer allows `get_accessibility_tree`
until it is filtered the same way (Rust tests + a wiring mutation).
