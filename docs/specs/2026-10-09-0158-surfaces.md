## 1. Replies (P1)

**Header.** Avatar, "Arslan", time. The 主助手 badge goes everywhere (§0). Expert badges on old
expert messages stay — they are history.

**While working.** The live block stays where it is (under the streaming text, where the "…" is) but
loses its box: one line per step — family icon, plain words, ✓/✗, seconds — with Arslan's narration
(`note` frames) as muted sentences between steps. Consecutive reads/searches merge ("看了 4 个文件",
"搜了 3 次"), only the last 6 lines show ("前面还有 N 步"), and the pulse line + timer close it.

**When done — one footer row under the answer** (D1):

    ✓ 6 步 · 48 秒 ›        deepseek-v4-flash        ⧉   ⋯

- **The process chip** "✓ 6 步 · 48 秒" (or "⚠ 6 步，1 步没成 · 48 秒") toggles the process list
  *below the footer*, inside the reply. No steps → no chip. This is the Codex-CLI place, and what the
  user asked for: the live "…" area turns into this line; nothing sits above the answer.
- **The model name** (several: "A + B") opens a small popover: 调用模型 N 次 · 输入 X（每次调用都会
  重发上下文）· 输出 Y · 花费 ≈ $Z（unknown → no figure）· 用时. Tokens and cost leave the reply
  row (D3); the context ring by the composer (§6) shows how full the conversation is.
- **⧉ copy**, always (not only ≥ 240 chars). **⋯**: 查看全过程 (the replay), 下载 .md, 下载 .html.
- The latest reply shows the row always; older replies show chip and model faintly and copy/⋯ on hover
  or keyboard focus.
- Background-job result messages get the same row (they are Arslan messages with a run).

**The process list** (expanded): the steps in order, narration between them, merges expandable. Each
step opens to **plain details** (D2), never JSON:
- web_search: the query, N results, the top 5 links; web_extract: the page link, its title, how much
  was read.
- read_file / write_file / edit_file: a path chip (opens the reader, §2), new/changed, size; edit_file
  shows the replaced lines old → new (read-only).
- run_command: the command (copyable), exit code, the first 5 output lines + "+N 行"; run_python: the
  output head and the files it made.
- whats_new: "看了 Arslan 的更新说明（0.1.57）"; memory, project, capability and Hands tools in
  their own words; an MCP tool: "用了 Excel（read_data_from_excel）" — the server's display name —
  with its arguments as a key/value list and the first lines of its result.
- Raw input and output (JSON) appear only with **设置 › 通用 › 显示技术细节** on (new, default off),
  as a "原始数据" disclosure under each step — Claude Code's Verbose.

**Every built-in tool gets words in all six languages**; a guard test walks the registry and fails
when one has none, so "whats_new ok" cannot come back.

**After a reload it looks the same.** History rows gain, per Arslan message with a run: `process`
(step count, failed count, ms, models, usage) and `files` (§2). The expanded list is fetched when
opened: `GET /runs/{id}/process`, built from the stored RunSteps — which now include `note` steps.
One fixture rendered through the live path and through the reload path must give the same reply.

## 2. Files Arslan makes (P2)

**File cards under the answer.** Every file the turn produced — write_file/edit_file snapshots,
run_python outputs, deck and chart exports, the HTML deliverable — shows once (the last version of each
path) as a card: type icon, name, folder (`~/Arslan/…`), size; click = open in the reader; ⋯ = 用默认
应用打开 / 在访达中显示 / 复制路径. Up to three inline, then "还有 N 个文件 ›" (opens 文件 at this
turn). Charts, SVG and the deck card keep rendering inline as today. The HTML deliverable becomes a
card + reader instead of a 70vh iframe in the conversation.

**The reader** (in the right panel, §3), by type:

| Type | How |
| --- | --- |
| md | rendered (the chat's Markdown component), 源码 toggle |
| html | `sandbox=""` iframe (no scripts, no same-origin — the HX-2 rule), 源码 toggle; "在浏览器打开" runs it with scripts in the default browser, on purpose |
| pdf | WebKit's own viewer (blob URL); fallback: pages rendered by pypdfium2 (already a dependency) |
| png jpg gif webp svg | image, fit / 100%; SVG only as `<img>` |
| mp4 mov webm, mp3 m4a wav | native players (as today) |
| csv tsv xlsx | a table (sticky header, first 1000 rows; xlsx one tab per sheet) |
| txt log json code | monospace with line numbers, wrap toggle, JSON pretty-printed; no syntax colours this round |
| docx rtf | macOS `textutil` → HTML, shown like html |
| pptx key numbers pages and the rest | facts (size, pages if known) + 用默认应用打开 / 在访达中显示 |

Header: name · size · modified · path (click copies); actions 用默认应用打开, 在访达中显示, 复制路径,
**加进对话** (puts the path in the composer). Caps as today: 50 MB, text 100k chars + "打开完整文件".

**Clickable paths.** Absolute and `~/` paths in links and inline code become path chips. Inside the
readable roots — the workspace (`~/Arslan` or the chosen folder), project folders, Arslan's own
artifacts — a chip opens the reader; outside, it reveals in Finder (Arslan does not read it). A path
that does not exist stays plain text (one batched stat per message).

**Safety.** Reading resolves the path first and must stay inside a readable root (no symlink escape);
dot-files and dot-folders are not listed or read. File bytes go to the page by an authenticated fetch,
served as `application/octet-stream` + `nosniff` + attachment — user HTML is never served as a page
from Arslan's own origin.

**Output rules** (system prompt, brief §3, `_ANSWER_STABLE_PREFIX` `arslan.py:124`): things to paste or
run go in fenced code blocks (`bash` for commands, `text` for messages to send); name local files with
full paths; a long deliverable (report, table, more than about a screen) is written to a file in the
conversation's folder, with a 2–5 line summary and the path in the reply; before a tool call, one short
sentence on what it is about to do (shown in the process list, never in the answer).

## 5. Clearing a level by hand (P3)

- All checkpoints of the current level done → the button reads **过关：进入「{next}」** (primary).
  Otherwise it is a secondary **提前过关…** (D5).
- 提前过关… opens a sheet: "这一关还有 3 项没做完" + the list; ◉ **移到下一关「{next}」** (default) ○
  **不做了，从计划里删掉**; optional "为什么现在过关"; [过关] [先不过]. On the last level only 不做了
  is offered.
- Server: `POST /projects/{id}/advance` takes `{leftover: "move"|"drop", note?}`; with open checkpoints
  and no `leftover` it answers 409 `open_checkpoints` + the list. The event records the moved ids, the
  dropped rows and the note (as evidence `{kind: "user_note"}`), so **undo restores exactly**.
- After any hand clear: a toast "已进入「X」· 撤销", and 最近 lists hand clears with 撤销 too.
- Arslan's proposal card shows the open checkpoints when there are any; accepting asks the same
  question. Auto-advance (when the user turned it on) now fires only when no checkpoint is open;
  a condition read from what you said with checkpoints still open stays a proposal (a change:
  today it advances at once).

## 6. Models: every model of every provider, per conversation, per role (P4)

- **A model choice = (provider config, model id).** The config brings the key and endpoint; the model
  can be any model in that config's catalog.
- The catalog keeps more of what providers send: name, $/1M in and out, image input (看图), tools,
  reasoning, context — by the entry's shape, never by provider name (`model_catalog.py:178-200`).
- **One ModelPicker** for the composer and every role: a search box (fuzzy over name, id, provider);
  ★ 常用 on top (star any row); then per config its own model and "全部 N 个 ›". Each row: name, id,
  "128K", "$0.27 / $1.10 每百万", badges 工具 · 看图 · 免费. A row a role cannot use is disabled with the
  reason (the conversation needs tools; 看图 needs image input).
- **Composer**: the picker sits under *every* composer, also inside a conversation. A choice applies
  to this conversation from its next turn (stored with the conversation); the menu ends with **设为默认**
  — new conversations start with the default (D6). A ring next to it shows how full the context is
  (the last call's input against the model's context).
- **模型分工**: a first row **主模型** (the default), then the five slots — each with the same picker,
  stored as `*_config_id` (existing) + `*_model` (new; empty = the config's own model).
  `build_slot_adapter` and `build_synthesis_adapter` honour it.
- A turn's adapter: the conversation's choice if set and its config still exists; otherwise as today.
  The vision slot still takes over a turn with images. Nothing ever changes a model on its own.

## 14. As built (filled in per phase)

**P5 Activity** (`d31f5c26`):
- The box headings show how many rows are loaded and "往下还有" while more exist, not "20 / 312": no
  count endpoint was added; the list pages back by `before_id`.
- Hands rows get an icon per kind of call; the app's own icon is **not** shown (left out).
- Hands is one local trace file read whole (≤ 500 calls); its box reveals 20 more at a time on the
  client. Runs and judgments page on the server.
- A run's origin is read from records that already exist (Run.kind, the browser run name, the job
  result message, the turn's own phone message), so **no `runs.origin` column** and no migration.

**P3 Projects**:
- The sidebar groups at most 8 active projects (not done or dropped), ranked by their latest
  conversation. 最近 hides only the conversations of the projects shown, so nothing disappears from
  the sidebar. The list refreshes when you change sections, not on a timer.
- Accepting Arslan's proposal with checkpoints open asks the same sheet; the optional reason is not
  sent there (the proposal keeps Arslan's evidence).
- 14 older tests encoded the silent clear and now pass an explicit `leftover` or tick first. Their
  intent (streaks, undo, stale proposals, re-planning) is unchanged.

**P1 Replies**:
- Narration is kept on the tool call it came before (`RunStep.detail.narration`), not as a new
  step kind, so nothing else that reads RunSteps has to change. GET /runs/{id}/process lists it
  as its own line.
- An MCP step reads "用了外部能力 <tool name>", not the server's display name (left out).
- A failed web search or page read keeps its calm, specific line ("搜索被限流"…) instead of the
  past-tense words.
- The model popover shows the call count only for live turns (`stream_end.usage.calls`); a
  reloaded reply has no call count stored.
- ToolActivityCard and UsageChip are gone (their honesty tests moved to the popover).
- The usage popover and the ⋯ menu open downwards when the reply is near the top of the window.

**P2 Files, reader, workbench**:
- Readable roots = the read tools' roots (workspace, plus Desktop/Documents/Downloads when default
  read is on) + active project folders + Arslan's artifacts. Credential-shaped names
  (`is_secret_name`) are refused alongside dot-files.
- A delivered file opens its **snapshot** (what was written, checked by size and checksum by the
  download route). A path opens the file on disk. xlsx and Word through the server work for paths
  only; a snapshot of those shows its extracted text.
- The old WorkDock frame is gone from App. Its browser tabs live in 浏览器 (`embedded`); artifact
  tabs are replaced by the reader. The 当前任务 panel (ContextPanel) is removed.
- PDF: the WebKit viewer in a blob iframe, plus "用图片显示" (pypdfium2 pages, first 30) for path
  sources. Whether the packaged app's WKWebView shows the blob PDF is **not verified**.
- No syntax colours (no new dependency), as planned.

**P4 Models**:
- **Deviation**: a conversation's choice lives in its own table `conversation_models` (migration
  0065: conversation_id, config_id, model), not in new ConversationContext columns. A row exists
  only for a conversation that chose; "用默认" deletes it. GET/PUT/DELETE
  `/conversations/{id}/model`; PUT refuses an unknown config (404).
- A choice whose config was deleted, or one that fails to build, leaves the turn on the default
  (`tool_loop._adapter_for_turn` catches it): a broken choice never takes a turn down. The vision
  slot still takes image turns only.
- The search is word-by-word substring over id, name and provider (every word must match), not a
  true fuzzy match. Each provider shows its first 60 models; the search narrows the rest.
- ★ favourites are kept per window (localStorage), not synced.
- A model is disabled only when its provider *states* what it can do (`source == "api"`) and the
  role's need is missing; unknown capabilities never block.
- 设为默认: when the chosen model is not the config's own, the config's model is changed first,
  then the config becomes primary and the conversation goes back to following the default.
- The context ring uses `stream_end.usage.last_input` (the last call's input). A reloaded
  conversation shows no ring until its next turn: the value is not stored.
- Kept from the old model switcher: the provider's health dot on the chip (its failure reason as
  the tooltip), and the failure reason under that provider in the picker. ModelSwitcher is removed.
- The context size for the ring comes from the web's catalog fetch; the chat path still never
  imports `model_catalog`.
