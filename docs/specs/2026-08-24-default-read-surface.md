# Spec:默认可读(让素人装完就"能干事儿",而闸只留给真危险)

日期:2026-08-24 · 状态:**待用户批** · 触发:用户看 OpenBot 后——"现在给 arslan 太多限制了…读比如本地读取,我希望默认就能有;删卸这种威胁系统的要多次确认"。

## 0. 校准 + 现状亲核

用户的直觉**和已有裁决同向**:[[arslan-propose-vs-execute-bias]]「提议宁开、执行宁关」本就是定过的。问题是 **P1 当时把"读"也拴在 workspace 上**(裁决:零默认、显式选目录)——结果素人装完连"看看我文档"都做不到,文件工具压根不注册(`settings_service.workspace_dir` 空 ⇒ `_arslan_tools` 不挂 read/list/search)。这是"限制太多"的具体来源。

🔴 **但"默认可读"不能等于"全盘随便读",因为读也有两级危险**:
1. **读隐私 ≠ 删文件,但读了喂给 LLM 就出网了**:`~/.ssh`、钥匙串、cookie、`.env`——被读走比被删更糟。
2. 我们**已有对策雏形**:`workspace_paths.is_secret_name`(`.env*`/`*.key`/`*.pem`/`id_*`/`*.p12` 等)+ Search/Read 双层守卫(名字跳过 + `resolve_in_workspace` 容器判定,一处 mutation 保一层)。

## 1. 三环模型

| 环 | 范围 | 闸 |
|---|---|---|
| **绿环(默认开)** | `~/Desktop` `~/Documents` `~/Downloads` 的**只读**(list/read/search) | **零确认**——装完就能"看看我桌面" |
| **黄环(session 问一次)** | 绿环内的**写**;绿环**外**的读(其他目录) | 沿用 P1 的 session 授权卡 |
| **红环(逐条问 / 硬拒)** | 删除、覆盖、`~/.ssh`、`~/Library` 敏感区、拒读名单 | run_command 级逐条闸;拒读名单**永不放开** |

### 关键设计点
1. 🔴 **原假设「macOS 会弹原生授权框」经实测是错的(2026-08-31,本机 macOS 26.6.2,见 [[arslan-tcc-packaged-probe]])。** Arslan 那类 app(非沙箱+硬化+GUI 启动)读 Desktop/Documents/Downloads **零弹框、零 entitlement、直接放行**;同次测试里铁定 FDA 门控的 TCC.db/Safari 库 EPERM(证明 TCC 活着、测试没泄漏)。**这三个目录对这类 app 不是门控服务,没有任何 OS 级同意时刻。** ⇒ 工程上更简单(不碰 entitlement),安全上更吃重(macOS 不替我们问,同意与否 100% 落回环模型+拒读名单)。想要"素人也懂"的同意,只能自己造首启告知,或 opt-in 沙箱(大改另议)。
2. **拒读名单升级为穿透规则**:任何环里,`.env`/密钥/证书永不读,且**这条要有专门 mutation**(去掉它 → 能读到 `.env` → 测试红)。当前 `is_secret_name` 已是这个雏形,扩展它而非另造。
3. **绿环的读也留审计**(沿用 P3c 的 `ssh_audit` 同形状,新一张 `file_read_audit` 或复用):不是为了拦,是**素人的信任感来自"它做的事我看得见"**。这条是可选加分项,可后置。
4. **workspace 概念不删**:降级为"写作业目录"(黄环写的默认落点);绿环负责"到处看看"。

### 1.5 同意时刻(用户裁决 2026-08-31:自造,轻量)

实测证明 macOS 不提供文件夹授权框(§1.1),所以完全静默地默认可读——即便只读——对隐私敏感用户是「我没同意过」。**裁决:自己造一个同意时刻,但要轻,不做拦路向导。**

- **首启告知**:欢迎流里一行字——「Arslan 默认可以**读**你的桌面、文档、下载,用来帮你查找和总结;它不会改或删任何东西,除非你逐次批准。可在设置里关闭。」**不是模态弹窗、不阻断**,读随时可用;只是把边界讲在明处。
- **设置开关**:`default_read_enabled`(默认 **ON**——这是本 spec 的全部意义)。关掉 ⇒ 退回 P1 原行为(只有显式 `workspace_dir` 内可读)。开关旁一句说明三目录范围 + 拒读名单。
- 🔴 **红环不因这个同意时刻松动**:告知只覆盖「读」。删/覆盖/敏感区照样每次逐条确认——真正需要仪式感的是那一档,不是读。首启告知**绝不**能被读成「我一次性授权了它动我的文件」。
- **可发现性 = 信任**:关闭开关必须好找(不是埋三层)。素人的安全感来自「我知道它能看什么、也知道怎么关」,不是来自没有默认。

⚠️ 这行告知文案素人能否读懂、开关可发现性——**纯逻辑定不了,装后真机看**(见 §4)。

## 2. 为什么"读默认开"是安全的(逐条论证,评审必看)

1. **绿环是三个用户目录,不是全盘**:`~/.ssh`、`~/Library`、`/etc` 都在绿环外 ⇒ 想读它们要黄环显式授权。
2. **拒读名单穿透所有环** ⇒ 就算在 Desktop 放了个 `.env`,也读不到。
3. **只读**:绿环里一个字都改不了、删不了 ⇒ 最坏后果是"读到了某个它不该总结的文档",而非数据损失。这正是「提议宁开」该开的那一档。
4. **出网边界不变**:读到的内容进 LLM 才出网——这一点**语音 spec 和本 spec 共用**,且和现在打字读 workspace 完全同风险,不是新口子。
5. 🔴 **~~TCC 是真闸~~——经实测对三大目录不是**(见本节 1)。"默认开"就是真的默认能读、没有 OS 兜底。绿环之所以安全靠的是"只读+只三目录+拒读名单穿透",**不是**靠 macOS 会拦。

## 3. 验收判据(mutation 必红)

1. **核心行为变更**:`default_read_enabled` ON(默认)且 workspace 未设时,`list_dir`/`read_file`/`search_files` **仍然注册**且能读绿环三目录(**现状是不注册**——`_arslan_tools` 见 `workspace_dir` 空就不挂它们)。范围**限定绿环**。
   - **mutation**:把"空 workspace ⇒ 绿环可读"改回"空 ⇒ 不注册" ⇒ 一条"素人装完能读桌面"的行为测试必须红。
2. 绿环外目录(如 `~/.ssh`)的读 ⇒ 触发黄环授权,不是静默读。
3. 拒读名单命中(Desktop 里的 `.env`)⇒ 拒,且理由可读;去掉守卫 ⇒ 测试红。
4. 绿环内**写**(不是读)⇒ 仍走 session 授权卡(黄环),不因"默认可读"顺带放开。
5. 删除/覆盖 ⇒ 红环逐条确认,一个不少。
6. 绿环三目录是**推导**的(从一处常量),不是散落在多个执行器里手抄。
7. **同意时刻可关**:`default_read_enabled` OFF ⇒ 退回 P1 原行为(只有显式 `workspace_dir` 内可读)。mutation:让 OFF 不生效(仍读绿环)⇒ 测试红。
8. **红环不受同意时刻影响**:一个 `write_file`/删除动作在 `default_read_enabled` ON 时**照样**触发确认闸(回归钉,防"默认可读顺带放开了写")。

## 4. 尚无证据、未声称已验

- 本 spec 零代码。§0 现状为 2026-08-24 亲核 main `1b2af7c2`。
- 🟢 **TCC 已打包实证(2026-08-31,[[arslan-tcc-packaged-probe]]),结果与开工前假设相反**:非沙箱 GUI app 读三大目录直接放行、无框、无需 usage 串。正因如此才先测。🔴 **`fresh_install_check` 测不了这条**——它直接 exec 二进制,责任进程是终端会假绿;TCC 回归验证必须 `open` 真 GUI 启动。🔴 仍未验:首启"一句话告知"素人能否读懂 + 关闭开关可发现性。
- 三环里"绿环外的读走黄环"是否会让素人觉得啰嗦(vs 直接拒),需真机体感,不是纯逻辑能定。
- OpenBot / LiveTalking 的形态已核(见对话),**不引入任何一方的代码**。

## 5. 不做面

- **不把 agent 关进容器**(OpenBot 形态):Arslan 是"在你真电脑上受控做事",不是"给 agent 一台假电脑"。
- **不放开写/删的默认**:只有"读"进绿环。
- **多目录任意配置**:v1 绿环是固定三目录 + workspace,不做"用户自选任意目录进绿环"(那是黄环的事)。
- **不 opt-in 沙箱**:实测证明不需要沙箱就能读三目录;而 opt-in 沙箱会连带砍掉 sidecar 的一堆能力(网络出口、SSH 外联、任意路径),得失不成比例。同意时刻自造(§1.5),不靠沙箱换那个框。
- **`default_read_enabled` 默认 ON**:默认 OFF 等于本 spec 没做——素人装完还是读不了。开关是给隐私敏感用户的退路,不是给所有人的门槛。
