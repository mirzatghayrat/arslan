# 0.1.46 — settings layout, and no background spend on experts

Built on 0.1.45 (`42fdd358`), branch `claude/0146-settings-layout`.

## Layout

Owner: make Settings an inner-scrolling side list with small type that fits one
screen, and let only the right content scroll — not the whole page.

- Cause (read in code, seen in the running app): `SettingsScreen`'s outermost
  element was `overflow-y-auto`, so the nav and the content were one scrolling
  column; with 9 entries, a big brand header, an identity card and 14 px rows,
  the last System entries sat below the fold.
- Now: `SettingsScreen` fills the window (`overflow-hidden`); the shell is two
  columns; the nav is compact (12.5 px labels, tight rows, no brand header;
  version box and "back" at the bottom) and is its own scroller only as a
  fallback on very short windows; the content pane is the only scroller
  (`overflow-y-auto`, `overscroll-contain`) with a 160 ms slide-in keyed on the
  section (`prefers-reduced-motion`: none).
- Seen in Chrome against the isolated harness at 1280 and 900 wide: all nine
  entries fit; scrolling the long Advanced page leaves the nav and the
  auto-save footer fixed.

## Background spend

`evolution_watcher.trigger_spawn` now returns before any attempt while experts
are off. A user who had `evolution_auto` on would otherwise keep paying to
rewrite prompts nothing reads.

## Not done here, on purpose

Three settings are dead with experts off: spawn synthesis mode, auto-evolution
(+ max dispatches) and "learn per-spawn preferences". They are protected by the
"no control lost" contract tests and span five components and about ten tests,
so they are retired together with the expert code in step two, not hidden here.
