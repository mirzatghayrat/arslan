# 0.1.50 — Context that keeps the work on track

Design: `docs/specs/2026-10-02-0150-p2-context.md`. Measured on the kernel bench before shipping
(`docs/plans/2026-10-02-p2-s6-check.md`), deepseek-v4-pro.

## What was built

| Area | Files | What it does |
| --- | --- | --- |
| Status block | `server/orchestrator/agent_status.py`, `tool_loop.py` | Every working step ends with a short `<agent_status>` block of current facts: the writable folder, files saved this turn, the plan, work so far and the step's notes. The system prompt no longer changes mid-turn, so the provider's prompt cache holds. The block rides on the last message — never a new user message, which would make DeepSeek drop its in-turn reasoning. |
| Plan | `server/orchestrator/turn_plan.py` | `update_plan` keeps a checklist with counts ("6/10"); it is shown back every step and does not use the tool budget. |
| Recovery hints | `server/orchestrator/recovery_hints.py` | A failed step gets a concrete next route (AppleScript refused → Swift + EventKit or a Shortcut; page unreadable → another source or the browser). |
| Honest about abilities | `server/orchestrator/capability_truth.py`, tool descriptions | An answer that says "I can't save files" while it can is corrected once. `write_file` creates missing folders; saving in Arslan's own folder needs no permission and the tool says so. |
| Finishing a stopped run | `tool_loop.py`, `server/services/terminal_exec.py` | Repeated failure or a spent page-reading allowance ends research, not the deliverable: up to three steps to save, then an answer. While wrapping up, commands still run to process files already fetched — with the network blocked by macOS seatbelt. |
| Links that hold up | `server/orchestrator/link_check.py` | After a research turn saves a table, rows sharing a link and links never seen in that turn's results come back to the model to open, replace or mark unverified. Fallback answers keep each item's link. |
| Ending at the limit | `tool_loop.py` | A chat turn that reaches its hard work limit after doing real work ends with a closing message — what was saved, where, how to continue — instead of an error. |
| Activity | `web/src/components/UsageCard.tsx`, `ActivityView.tsx`, `Sidebar.tsx`, `server/api/usage.py` | Activity moves to where the "Local service · Online" line was (the connection shows only when it is not fine). The page leads with usage: runs, success rate, P95 time, tokens and cost, a time-taken heatmap and results on one time axis, and usage by model; then scheduled tasks, then recent work with status and duration. |

## Known gaps (next)

- A run that is already wrapping up with doubtful links does not always mark them unverified.
- `run_command` writes are not confined to the workspace yet (P3).
- Using pages the user is logged into: approved, design pending.

## Tests

Local full suite green (backend ~5,850, frontend 1,954). New suites cover the status block in real
request bodies (byte-stable system prompt, tail placement, prefix stability), the plan, recovery
hints, the capability guard, finish mode, offline commands (kernel-level on macOS), the link check,
the closing message and the Activity dashboard; each was mutation-checked.
