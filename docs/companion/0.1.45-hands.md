# 0.1.45 — hands: Arslan's browser and Mac automation

Built on 0.1.44 (`9d63e289`). Implementation by Claude on `claude/0145-hands`.
Goal from the re-plan (2026-09-30): let Arslan act, reusing what exists rather
than building from scratch. The browser reuses the managed `@playwright/mcp`
0.0.80 runtime Arslan already installs for previews.

## Design

- `server/services/agent_browser.py`: one headed Chromium with a persistent
  profile at `<data>/agent_browser/profile`, the public-only proxy (no
  loopback/LAN), downloads off, a fixed set of Playwright tools (navigate,
  snapshot, back, click, type, select option, press key). No evaluate / run
  code, cookies or storage, network routing, uploads or tracing.
- Probed in the real runtime: element arguments are `target` (not `ref`);
  navigation and actions reply with a snapshot file link, so every call is
  followed by an inline `browser_snapshot`. Unix socket paths are too long
  under the data dir; sockets use a short `/tmp` directory (the first real
  launch failed without it).
- `server/registry/hands_tools.py`: `browser_open/look/back`,
  `mac_list_shortcuts` are reads offered in any turn. `browser_click/type/
  select/press`, `mac_run_shortcut`, `mac_applescript` are offered only inside
  background jobs and ask through the job's cards (`approvals.ask`,
  `propose_action`): once per website / per Shortcut per job, every time for a
  script (shown in full). A field whose description names a password is never
  typed into. Approvals end with their job. Page text is returned as external
  (untrusted) content.
- Frontend: one `ActionApprovalCard` (six languages); the voice notice fires
  for it like other job cards.

## Evidence

- Real smoke in an isolated data dir: managed runtime set up; opened
  example.com and got inline element refs; a job click asked once for
  `https://example.com` and navigated to iana.org; typing into "Password" was
  refused; `shortcuts list` returned the owner's 12 Shortcuts (count only);
  `return 1 + 1` ran after asking.
- Offline tests: `tests/server/test_hands_0145.py` (11) + the job-end test;
  frontend `hands-card.test.tsx` (4). Mutation: 10 rules checked, all red
  after removing one redundant guard and adding the job-end test.

## No evidence yet, not claimed

- A real model driving the browser through a multi-step task.
- A real login flow (the owner signing in in the Arslan browser window).
- AppleScript against a real app with macOS Automation consent.
- Packaged app not yet built, signed or fresh-install checked for 0.1.45.
- Cost: no paid calls.
