# Jev / Laya：Arslan 效率调研，2026-09-24

## 结论与范围

值得跟进，但**不直接接入当前 0.1.40 正式版**。最有价值的不是换掉
主模型，而是把部分小范围、可回退的语义判断从生成模型中拆出来。
下一阶段优先评估本地 `laya-mlx`；Jev 可作为另行授权的云端对照。
这不是已经测得的提速，也不是采纳批准。

本轮仅查阅上游资料和 Arslan 源码，没有安装依赖、下载权重、创建
第三方账号、发送用户数据或调用新模型。现有主模型的独立
36 次 / US$5 验收预算不等于 Jev API 授权；新预算本轮仍为零调用。
本调研不增加 stable 发布门槛，不改原有十二个实际任务的验收标准。

用户后续方向：先交付正式版；未来可考虑一个显式的“Jev 加速模式”
开关。该开关是待验证的产品构想，不代表当前功能或已承诺的速度。
若实施，默认关闭，说明云端数据流/额外费用和适用任务；关闭或失败
恢复标准路径，保留主模型与权限确认。不使用通用“所有任务更快”
承诺，也不将它混同于主模型供应商的优先服务档位。

## 项目身份与证据

| 项目 | 实际是什么 | 对 Arslan 的意义 |
| --- | --- | --- |
| [Jev / TypeSafe](https://docs.typesafe.ai/introduction) | 托管的结构化决策模型；Choice、Score、Noul，不生成普通回答 | 可能承担分类、候选选择，不替代研究写作模型 |
| [Laya](https://github.com/NandhaKishorM/laya) | Convai Innovations 的独立开源模型/SDK，Apache-2.0；提供类似的决策接口 | “本地版 Jev”是功能类比，不是 Jev 权重、同一训练或质量等价 |

| [receptron/laya](https://github.com/receptron/laya) | TypeScript / ONNX 移植 | 备选，不因前端使用 TypeScript 就新增一条推理运行链 |

### Jev：便宜的判断，不是通用可靠性保证

[官方模型页](https://docs.typesafe.ai/models) 当前列出 `jev-1.13.0`，
每百万输入 token US$0.042，输出不计费；总请求上限 64k，
state 加最长单题另限 32k。英语是主要训练语言，非英语必须验证。
官方称请求不用于训练，但不能据此推断所有套餐默认零保留。
若后续使用，应固定版本而非移动的 `latest`，另审数据处理边界。

[官方限制页](https://docs.typesafe.ai/model-jaggedness/jev-1.13) 明确列出
数字、日期、复杂间接推理、无关长上下文和对抗输入的弱点。
因此不能用它裁决金额、恢复日期或授权条件。金额和日期仍由代码计算。
[confidence 文档](https://docs.typesafe.ai/confidence) 说明该数值由输出
概率分布推导；它不是对某次行动合法性或事实正确性的证明。

### Laya：本地运行有吸引力，但零样本和校准存在明显边界

[上游 README 的 Honest limits](https://github.com/NandhaKishorM/laya#honest-limits)
承认基础模型在 typed-decisions 上的零样本结果低于多数类基线，较好
成绩来自该基准训练集上的微调；不能据此宣称通用超越 Jev。
默认上下文只有英语 512、多语 1024 token，题目和选项也占空间。
上游还记录过度自信、标签/位置偏差；不能直接复制示例的置信度阈值。
这让它目前更适合待验证的窄任务，而不是全能本地大脑。

### MLX：要看整机成本，不只看热启动毫秒数

[移植基准](https://github.com/mizorewww/laya-mlx/blob/main/BENCHMARKS.md)
使用 M3 Max / 128 GiB，排除下载和模型加载。该表 FP16 单题短输入
P50 为英语 17.75 ms、多语 10.91 ms；README 中其他更快数字来自不同
测量，不能混为同一次基准。多语 FP16 权重约 614 MiB，单短题峰值
分配约 687.6 MiB。均是作者测量，不是用户这台 Mac 或 Arslan 的结果。
与上游输出一致也不等于答案正确。**不建议默认塞入 DMG或常驻全部模型。**

## 与现有 Arslan 的具体结合点

源码观察基线：本工作树 `8e795bdd`，不是 beta.6 已发布二进制的实测。

1. **首选实验：短请求的旁路意图判断。**
   `server/orchestrator/router.py:146` 当前汇总历史、摘要、事实和专家
   列表，再请求生成式路由。可以比较有限标签判断，但第一轮只记录
   实验输入/预测，不影响真实分派，不启动专家、不修改记忆。
   超长、语言不支持、指代依赖历史、模型未就绪一律弃权；不能静默截断。
2. **后续候选：已获准资料的相关性排序。**
   `server/services/personal_context.py` 已先筛选作用域、确认状态和
   有效性，再做检索与 token 限制。新模型只能处理这个筛选之后的
   候选；不能扩大访问集合、恢复被删除记忆或把未确认猜测变成事实。
   先比较排序，不让模型丢弃唯一证据或必要反例。
3. **低优先级：提示哪些引用值得复核。**
   可标记“可能不支持此结论”供检查，但来源的已读/未读/截断状态
   仍由实际读取记录决定。分类器不能把未读来源升级为“已验证”。

**不能把现有 router 直接换成一个 Choice 调用。** `RouterResult` 除
action 外还有 `task_brief`、`suggested_spawn`、`new_facts` 等生成字段；
`arslan.py` 会消费这些字段。少一次分类调用未必少一次主模型请求，
还可能引入额外调用和行为变化。必须先拆清职责、保护原有功能契约，
不能用分类准确率掩盖丢失的任务摘要或记忆确认。

禁止用途：权限放行、工具写入授权、自动发布、删除/确认记忆、批准
升级或恢复、覆盖已有确定性安全门。对网页注入文本的判断只能辅助，
不可作为唯一防线。可信 agent 的核心是可追溯证据和可执行边界，
不是模型给了一个很高的分数。

## 下一阶段的有限实验建议（尚未启动）

- 在 stable 交付之后，冻结一个独立小样本：六种现有路由意图各四例，
  共 24 个隔离合成样本，覆盖中英文、否定、指代和未知选项；加八个
  长输入/注入/不支持语言边界。它们不是当前十二案的替代物。
- 先比较现有路径、确定性规则和一个本地模型。开发集与盲测集分开，
  阈值只在开发集设置；保存所有失败，不做挑最好答案的多次重试。
  这只是可行性筛查，小样本通过不等于可以默认开启。
- 先核对生成字段和记忆行为不会丢失，再谈跳过现有路由调用。
  记录真实减少的请求数、总输入/输出、回退比例、整任务 P50/P95、
  冷启动、峰值内存和下载安装成本，而非只计分类器 forward 时间。
- 未知/不支持输入必须可弃权；模型缺失、超时、退出时原路径继续。
  模型仅在用户明确启用后下载，固定摘要、许可和来源，不后台更换。
- 任何权限越界、丢证据、丢生成字段或核心任务退化都否决启用。
  若省下的费用/等待不足以补偿内存、维护和回退成本，就不采纳。
  新云端对照、权重下载或模型训练需另行明确范围，不能挪用当前
  正式版验收的主模型预算。

**顺序不变：先把 0.1.40 的固定研究任务、原生交互和升级恢复验完，
再验证“同样的事更快、更便宜”。当前没有任何 Arslan 提速百分比。**
