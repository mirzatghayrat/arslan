# 0.1.44 — one Arslan; a failed read never stops a turn

Starting point `037f51f2` (0.1.43). Implementation by Claude on
`claude/0144-single-arslan`, per the owner's rulings (2026-09-29/30): remove
experts in two steps, keeping their methods as skills; budgets and guards
must not stand in the way of finishing.

## A. Unknown outcomes (field case)

Owner report: "Model error — An action may already have happened" after a web
read. Read-only query of the owner's local task journal: the uncertain actions
were `mcp_4__browser_take_screenshot` (twice, 2026-09-29) and `run_command`
(2026-09-26/27). Cause: only a fixed list of tools counted as reads; every
other tool (all MCP tools, every command) was an external write, a failed
external write became "uncertain", and the next model step aborted the turn.

- `task_service.effect_of`: MCP tools graded safe by their server (hand-graded
  table, then verb heuristic) and LOW-risk local commands are reads;
  `background_status` is a read; background start/stop are local writes.
  Unknown tools stay `external_write`.
- A local write our own tool refused cleanly (`ok:false`) is `failed`.
- The turn is no longer aborted: repeating the exact uncertain action is
  refused as a tool result; other work continues; the task ends
  `waiting_user / task_reconciliation_required` naming that action (the header
  task chip already offers "happened / did not happen").
- The flag was being cleared by a later success (masked before by the abort);
  now sticky.
- Chat card: task-status codes are titled "Needs your check", not "Model error".

## B. One Arslan (step one of two)

- `EXPERTS_ENABLED = False`: parked expert phases are cleared; router
  `route / suggest_create / suggest_update` become Arslan answering; @-mentions
  no longer force a handoff. The router call remains (it also extracts facts).
- Skills: the host had no `read_skill` at all (skills only reached experts).
  It now gets `read_skill` with an index of registered skills, when any exist.
- `/api/v1/experts/legacy`, `/experts/{id}/to-skill`: expert prompt → skill
  (`## Trigger` from domain, `## Method` = prompt), idempotent; an empty
  prompt is refused.
- Scheduler: fires always run as Arslan; migration 0056 sets `target=arslan`
  (`spawn_id` kept). Create API accepts no `spawn_id`.
- UI: no expert rows or picker in the sidebar, no expert bar, Capabilities
  "Former experts" converter, scheduled form without an expert field.
- Step two (a later version): delete the expert code and tests. Legacy expert
  tests run with the switch on until then; `@one_arslan` tests pin the default.
