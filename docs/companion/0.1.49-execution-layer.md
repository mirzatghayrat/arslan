# 0.1.49 — A steadier execution layer

Measured against Hermes on the same model before shipping
(`docs/plans/2026-10-02-arslan-vs-hermes.md`). Design: `docs/specs/2026-10-01-0149-p1-execution-layer.md`.

## What was built

| Area | Files | What it does |
| --- | --- | --- |
| Native tool protocol | `arslan/llm/trajectory.py`, `server/orchestrator/tool_loop.py`, `arslan/llm/providers/openai_provider.py`, `arslan/llm/adapter.py` | OpenAI-compatible models (DeepSeek, OpenAI, OpenRouter…) get real `tool_calls` / `role: tool` history with their reasoning passed back verbatim, instead of tool results disguised as user messages. Anthropic and Gemini keep their rendering. `ARSLAN_TOOL_PROTOCOL=legacy` rolls back. |
| Output budget and truncation | `arslan/llm/output_budget.py`, `tool_loop.py` | DeepSeek opens at 32k output tokens (thinking spends the same cap). A cut reply is re-sent at a higher cap, a cut answer is continued, a cut tool call is never executed. |
| Failure recovery | `server/orchestrator/model_call.py`, `server/orchestrator/llm_errors.py` | Rate limits and server errors back off (Retry-After honoured); balance/auth errors are not retried; a context overflow compacts once; errors always say what failed and what was tried. |
| Streaming watchdog | `arslan/llm/stream_assembly.py` | Long replies are streamed; a reply with no real progress for 90 s counts as stalled. |
| Tool mistakes | `tool_loop.py` | Malformed arguments are reported, never run as `{}`; arguments are checked against the tool's schema; unknown tools suggest the closest names; repeated no-progress steps are flagged to the model. |
| Long output | `server/services/tool_outputs.py`, `server/registry/file_tools.py` | Long results keep head and tail in context and the full text on disk; `read_file` pages by line. |
| Web search | `server/registry/search_providers.py`, `arslan/llm/deepseek_search.py` | Default search now uses the chat model's own search (DeepSeek built-in search, same key). DuckDuckGo had started answering with a human-verification page that read as "0 results". Blocked search is reported as blocked. |
| Chat turns finish | `arslan/execution_budget.py`, `task_service.py` | At the turn's limit Arslan stops researching and delivers what it has (1.5× is the hard stop), instead of ending with an empty reply. |
| Small fixes | `terminal_exec.py`, `managed_browser.py`, `tool_loop.py` | zsh here-documents work where /tmp is not writable; browser setup stages downloads in its own temp dir; DeepSeek's internal tool-call markup is never shown as an answer. |
| Kernel bench | `scripts/kernel_bench/` | Reproducible comparison against other agents (metering proxy with caps, sandbox, checkers for six tasks). |

## Measured (deepseek-v4-pro, 3 runs per task)

| Task | Arslan | Hermes |
| --- | --- | --- |
| Apple financial table (T3) | 3/3, cheaper | 3/3 |
| Organise Downloads (T5) | 3/3 | 3/3, cheaper |
| Reminders (T1) | 1/3 | 3/3 |
| Job table (T2) | 1/3 | 1/3 |

0.1.48 scored 0/2 on T5 in the October 1 sample.

## Known gaps (next: 0.1.50)

- When one route is blocked (AppleScript refused), Arslan does not reliably try another (EventKit).
- It sometimes says it cannot write a file when it can.
- Using pages the user is logged into: approved, design pending.

(golden model inputs recorded on the previous code), the native wire format, failure
injection, stream assembly, tool errors, long output, search fallback and turn budgets;
each was mutation-checked.
