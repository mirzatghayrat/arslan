## Decisions worth knowing

- **Reads run, outward and destructive actions ask, a few things never run.**
  Same shape as the frontier agents; the terminal is on by default because
  without it every command-line skill is dead text.
- **The default posture flipped, so the UI had to follow it.** The settings
  adapter read an unset switch as OFF and an unset policy as ask_all while the
  backend treats them as ON / ask_risky; a fresh install showed the terminal
  switched off while it worked. The composer's one-line posture hint now
  appears for the non-default "ask for every command".
- **Example experts are no longer seeded.** Every install used to get six, and
  the new "Former experts" tab would have listed them for people who never had
  experts; the tab lists only experts the user made.
- **Replies are spoken only during a voice conversation.** The separate
  read-aloud switch is gone.

- New backend: one loop and fact capture, default folder, terminal policy and
  executor, browser auto-setup, workspace API, terminal-rules API.
- New frontend: Activity, context panel, terminal rules panel, adapter
  defaults, old expert messages without actions, i18n namespace collision guard.
- Retargeted, not deleted: fact provenance and the memory recap event now go
  through `turn_facts`; tests that only stubbed the router to "answer" keep
  their assertions.
- Deleted: tests of removed expert behaviour (routing, staffing, rosters,
  verdicts, refinement, expert sockets, command sandbox).
- Mutation checks (change reverted from a copy, then re-run green): adapter
  defaults ×2, i18n collision guard, old-expert-message test, fact
  provenance, recap event, former-experts filter, workspace API ×4 and the
  terminal policy/executor mutants from the earlier commits. All killed.
- Real browser (throwaway HOME and data dir): Activity (empty states, Open
  Activity link from Automation), context panel with a real file in
  `~/Arslan`, Advanced › Terminal (switch on, "ask only for risky", seeded
  rules listed, **Ask again** removes the rule in the backend), Capabilities
  with Connections as a tab, a fresh install with no "Former experts".

Full runs (local, CI environment variables):
- Frontend: 1944 passed / 0 failed; `tsc` clean.
- Backend: 5580 passed, 2 failed, 68 skipped (`ARSLAN_SECRET_KEY=ci-secret`,
  empty token, temp data dir). Both failures passed alone and depended on an
  earlier test's database: under 0.1.48 a harmless command and a write into
  Arslan's own folder no longer ask, so whether they saw a card depended on
  ambient settings. Both now pin their precondition; those two files then ran
  15 passed / 0 failed. The full backend suite after that fix runs in CI only.
- CI (PR run 36802936259) then failed 9 executor tests on Linux: no `/bin/zsh`
  there. The shell is now zsh where it exists (always on macOS) and `/bin/sh`
  otherwise; the executor tests also pass forced onto `/bin/sh`. The same
  failure exposed a real bug: `argv` without a `command` joined to `'' status`
  and ran; an empty command now reaches the floor (mutation-checked).
- Rust: unchanged this round.
