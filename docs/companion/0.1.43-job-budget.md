# 0.1.43 — background jobs put completion first

Starting point `dad2ca39` (main after 0.1.42). Implementation by Claude on
`claude/0143-job-budget`, after the owner's field report (a research job ended
"stuck" with `task_budget_exhausted` and nothing delivered) and ruling:
budgets must not stand in the way of finishing; they only guard runaways.

## Cause

- W08 (2026-09-14) made execution budgets hard: reaching a limit raises
  `BudgetExceeded` and the task pauses as `task_budget_exhausted`.
- 0.1.42 ran background jobs on the per-turn default (32 requests, 24 tool
  calls, 128k tokens, 10 min). Research routinely exceeds 24 tool calls.
- In the native loop, running out of tool calls already forced one text-only
  answer, but also set `task_budget_exhausted`; running out of model requests,
  tokens or time ended the job with no answer at all.

## Change (background jobs only; chat turns unchanged)

- `arslan/execution_budget.py`: `JOB_TIERS` (lean / standard / ample),
  `job_budget(tier)` = hard limits 1.5× over a soft `Budget.soft`;
  `soft_reached()`; soft limits persist in the snapshot (`soft_limits`, only
  when present) so recovery keeps them.
- `tool_loop.run_native`: past the soft limit, `wrap_up` — only `write_file`
  / `edit_file` are offered, other calls are refused with `wrap_up`, and the
  system prompt asks for the complete deliverable from what is at hand. No
  pause reason is set; completion checks decide the outcome.
- Hard limit: unchanged W08 behaviour. The job's card and one message name
  the limit, used/limit and next steps (counts only, no tool output quoted).
  New outcome `out_of_budget`.
- Setting `background_job_budget` (default `standard`), Settings → Advanced.
  A backend test pins the tier numbers shown on the page to `JOB_TIERS`.
- Cards map pause codes to words; unreached criteria are `not_reached`.
- `background_status` / `task_progress` descriptions steer progress questions.
