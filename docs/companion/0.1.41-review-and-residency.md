## A. Source review → after-save advice

- The 0.1.40 pre-save gate (blocked writes, stopped tasks with
  `research_review_unavailable`) is removed, not switched on. The critique now
  runs only after `write_file` succeeded; its outcome never reaches the writing
  model, never triggers a revision and never changes the task result or its
  stop/pause reason.
- Prompt narrowed to absence and cross-document comparison claims.
- Critique requests: thinking explicitly disabled on official DeepSeek,
  temperature 0, output ≤ 2048. Only official DeepSeek and Anthropic providers
  are eligible (`supports_bounded_critique`); others are skipped and recorded.
- `research_review.affordable` skips the critique when it would leave the task
  without one more request, a 16k-token reserve or 90 s.
- The note is stored beside the immutable artifact snapshot
  (`artifacts/_reviews/<filename>.json`), bound to its sha256, served by
  `GET /api/v1/runs/{id}/artifacts/{filename}/review` and shown in the artifact
  preview with a "model advice, not a fact check" disclaimer.
  **Deviation from the brief:** no DB migration and no "stale" flag — a rewrite
  is a new snapshot, so an old note can never attach to new bytes.
- Setting `research_review_enabled`, default off, fail-closed when unreadable.

Tests: `tests/server/test_research_review_after_save.py` (16),
`web/src/__tests__/artifact-review-notes.test.tsx` (7). Mutations (setting
ignored, budget check removed, thinking re-enabled, fail-open setting, review
errors propagating, review leaking into the trace, no snapshot hash check; and
on the frontend: no hash binding, any URL scheme linked, default on, no
disclaimer) each turned a test red; restored, all green.

## B. Resident shell

- `desktop/src-tauri/src/resident.rs`: closing the MAIN window hides it
  (pure `close_action`); launch/recovery windows still close. Dock click and the
  menu-bar "Open Arslan" show it. Explicit quits are unchanged (existing
  `RunEvent` handler; sidecar stdin lifeline). Menu-bar item via tauri
  `tray-icon` (already in `Cargo.lock`), status line from the backend.
- Backend `desktop_status` + `GET /api/v1/desktop/status` (loopback, existing
  token): counts of work in flight and of sent confirmation cards, and a ring
  of events (turn finished, approval needed, scheduled finished/paused). No
  message text; a conversation "title" is the first user message, so only
  scheduled-task names are included. Access log for this path muted.
- One IOKit `PreventUserIdleSystemSleep` assertion while work is in flight and
  `keep_awake_enabled` (default on); dropped after 3 failed polls.
- UNUserNotificationCenter through objc2 dynamic classes (`block2` added as a
  direct dependency; no new crate in the lock). Only while the window is hidden
  or unfocused; click opens the window and an existing, non-archived
  conversation. Unbundled dev binaries skip notifications.
- Settings → Desktop (new section; both switches default on and spend nothing).

Tests: Rust `resident::tests` (9; 89 total with 1 pre-existing ignored),
`tests/server/test_desktop_status.py` (7), `web/src/__tests__/resident-desktop.test.tsx` (5).
Mutations: every-window-hides, keep-awake ignored, focus ignored, restart
events dropped, history replayed on first poll, cancelled turns notifying,
non-200 responses parsed; backend: no approval event, working count leaking on
error, keep-awake default off, cancel reported as error, no pause event — each
red, restored green. One Rust mutation first survived and exposed a real
defect: after a backend restart its events (ids from 1) would have been
filtered by the old cursor and silently dropped; fixed and re-tested.
