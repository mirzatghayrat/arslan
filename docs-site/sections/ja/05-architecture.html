05 / システムアーキテクチャUI、実行、権限は、それぞれ何を担うのか

分かりやすく説明すると、React はユーザーの作業画面、Tauri は macOS とつなぐシェル、Python は仕事を調整するエンジンです。モデルが判断し、ツールが実際に動作し、データベースとディスクが過程と結果を保存します。これらの役割は一つのデスクトップ製品にまとまっていますが、同じプロセスで動くわけではありません。

図 1 · 現在のアーキテクチャ。テキストで表すと、UI ↔ ローカルサービス → 統一 Agent ループ ↔ モデル、実行ループ → ツール → システム／ファイルとなり、状態は SQLite とディスクに保存されます。iPhone は CloudKit を通じて Mac Bridge と通信し、Mac の公開インターネット向け API に直接接続するわけではありません。

この層構造を選んだ理由

境界得られること必要になること
React ↔ ローカルサービスチャット、設定、グラフなどの UI と実行ロジックを分離でき、モデルのストリームやツールイベントをリアルタイムで表示できますプロトコル、再接続、ストリーミング状態、認証の管理が必要です。ページが開いていることだけでは、タスクの稼働を判断できません
Tauri ↔ Python sidecarPython のモデル連携と文書処理のエコシステムを維持しながら、通常の Mac アプリとしてインストールできます複数言語のパッケージング、動的依存関係、ポートの検出、プロセスの終了、署名を管理する必要があります
モデル ↔ ツール実行器モデルはアクションを提案し、決定論的なコードが検証、許可、実行、記録を担います不正な引数、未知のツール、途切れた応答、繰り返す失敗、キャンセルへの対応が必要です
Hands の独立 helper独立したプロセスが Accessibility 権限を持ち、アプリ単位と操作単位のルールを適用しますコード署名、プロセスの識別、システム権限、アプリごとの差異が、追加の保守負担になります
Mac ↔ iPhoneMac の電源が入り、ネットワークに接続され、スリープしていなければ、離れた場所から依頼、結果の確認、対応する承認処理を行えますMac が利用できない間、メッセージは iCloud で待機します。再試行、順序の乱れ、復旧、最終状態の整合性への対応も必要です

起動時にプロセスを接続する仕組み

  1. Tauri が実行ファイル化された Python sidecar を起動し、サービスの準備ができるまで起動画面を表示します。
  2. sidecar はローカルポート 47317へのバインドを優先し、競合時には一時ポートを使います。その後、標準出力で ARSLAN_PORT を返してハンドシェイクします。
  3. デスクトップシェルがポートを受け取ると、システム WebView に、ローカルサービスが提供する React ページを読み込ませます。固定ポートを優先することで、WebKit origin と UI のローカルストレージを安定させます。サーバー側の会話ディレクトリにより、ポートが変わっても履歴を再び見つけられます。
  4. UI は HTTP でリソースを管理し、WebSocket でテキストストリーム、ツール状態、承認、タスクの進捗を受け取ります。ローカル接続でも token と接続元の検証は必要です。
  5. シェルは、ライフサイクルを連動させるために標準入力パイプを保持します。親プロセスの終了で EOF が生じると、sidecar は後処理をして終了できます。出力パイプも継続的に読み取り、ブロックや、接続断後に孤児プロセスが残ることを防ぐ必要があります。

これらの仕組みにより、ウィンドウ、サービス、データベースのライフサイクルを整合させます。HTTP health の成功だけでは、WebSocket、添付ファイル、静的リソース、ネイティブ helper がすべて使えるとは確認できません。リリース時の受け入れ確認では、それぞれ個別に検査します。

旧設計と新設計：再利用を保ち、専門家への振り分けを終了する

過去の仕組み

複数の専門家／Meta-Agent

ユーザー → 前段の Router → Spawn を選択／作成 → 専門家が実行 → 集約。専門家のプロンプトは、ホールドアウト評価と人手による Promote の対象にできました。ユーザーには、専門家の役割、装備、一覧、進化の理解が求められました。

0.1.55 の主要経路

One Arslan／統一ループ

ユーザー → 共通の Agent loop → 必要に応じて Skill を読み込み、ツールを呼び出す → 結果を出力。通常の事実は回答後に抽出します。既存の専門家は Skill に変換でき、履歴も保持しますが、専門家へのルーティングは主要な実行経路ではなくなっています。

「統一ループ」は「すべて逐次実行」や「委任しない」という意味ではありません。コードには、制約付きの読み取り専用 worker が残っています。これは、独立した人格、装備、進化、ルーティングを持つ初期の専門家システムとは異なります。
