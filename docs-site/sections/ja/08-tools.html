08 / ツール、Skill、拡張機能機能を再利用し、実行の境界を保つ

Arslan は、「何ができるか」と「どう行うか」を分けて構成しています。ツールは実際の操作、Skill は手順と参考資料、MCP は外部機能との接続を担い、プラグインのマニフェストがそれらを組み合わせます。モデルが受け取るのは、そのターンで利用できる機能の集合です。ソースのレジストリにツールが存在しても、既定で有効であることや、実行が許可済みであることを意味しません。

四つの概念の関係

構成要素提供するもの代わりにはならないもの
Tool検索、ファイルの読み取り、コマンド実行など、名前、引数の契約、実行器を持つ操作ツールの説明は、引数の検証、権限の判断、実際の返却値の代わりにはなりません
SkillSKILL.md に記載された作業手順と、任意のスクリプトや参考資料Skill 自体がシステム権限を得るわけではなく、別途学習されたモデルでもありません
MCPstdio または HTTP を通じて外部ツールを検出し、呼び出すプロトコル共通のインターフェースはサービスの信頼性を保証しません。接続、ツールの公開、許可は引き続きアプリが管理します
Plugin manifestarslan.plugin.json が、MCP の起動方法、secret スロット、関連する Skills を宣言しますマニフェストのインストールや解析だけで、記載されたサーバーが自由に実行されるわけではありません

宣言から実行までに行う検査

機能を検出する組み込みレジストリ、設定済み MCP、Skill 索引
選別して提供する文脈、設定、権限に応じて今回の schema を提供
要求を解析するツール名、JSON 引数、完全性を検証
実行し、結果を返す実際の許可後に実行器を呼び、結果と失敗を記録

組み込みツールは登録済みの実行器が処理し、 mcp_ で始まる呼び出しは MCP プロキシに渡されます。ツール結果は統一ループへ戻り、モデルはそれをもとに引数を補い、代替手段を選び、またはタスクを終えます。モデルがすでに Skill を読んでいても、ファイル、コマンド、アプリの操作は、それぞれの権限検査を通る必要があります。

0.1.63 以降、リクエストはすべてのツールを載せるわけではありません。載せるのは、日常的に使うツールの常駐セット（ウェブ検索とページの読み取り、ファイルの読み取り・書き込み・編集、ターミナル、計画、バックグラウンド作業、記憶、read_skill、機能の一覧、Hands のデスクトップツール）と、二つの検索役です。find_tools は、このターンで呼び出せるが提示されていないツールを順位付けし、use_tool はそのうち一つを本来の名前で呼び出します。引数はそのツール自身のパラメーターに照らして検査され、直接呼び出した場合と同じ承認、トレース、受領記録が適用されます。MCP ツール、attach_file、ブラウザーツールは、この方法で利用します。必要に応じて使ったツールは、次のターンからその会話の一覧に加わります（会話ごとに最大 12 件、メモリ上に保持されるため、再起動後はモデルが改めて探します）。find_tools が返す MCP サーバーのテキストは、指示ではなく外部のデータとして包まれます。

モデルが続けて複数の読み取りを求めた場合は、最大 4 件を同時に実行します。対象は、ウェブ検索とページの読み取り、read_skill、ファイルの読み取りや一覧表示など、そしてサーバー側が読み取り専用と示している MCP ツール（一つのグループにつきサーバーごとに 1 件）です。各呼び出しは引き続き返信の順序ですべての関門を通り、各結果はそれを求めた呼び出しと対応付けられたままです。読み取りではないものは、その位置で単独で実行されます。

Skill は必要に応じて読み込みます。索引が利用できる手順をモデルに示し、read_skill が登録済みの SkillPack または許可された参考資料のパスから本文を取得します。これにより、手順のライブラリを増やしながら、各ターンのコンテキスト量を抑えられます。Arslan は独自の Skill を二つ同梱しています。デザインされた HTML レポートと、Skill を作る Skill です。0.1.63 以降、専門家時代の初期データ、あらかじめ用意された MCP コネクターの一覧、モデルのコネクター提案ツールはなくなりました（新しい MCP サーバーの検索は、後述の find_capability を通ります）。また、廃止された名前でインポートした Skill が削除されることもなくなりました。

0.1.55 以降、Capabilities ページでは Arslan にできることをスイッチとして一覧表示し、それぞれがオン、オフ、あと一歩で使える、この環境では使えない、のいずれかであるかを理由とともに示します。オフにした機能はモデルにまったく提示されず、read_skill もオフの Skill の読み込みを拒否します。各行は、そのターンでどのツールを渡すかを決めるのと同じゲートから読み取るため、ツールが欠けているのに行が「オン」と表示されることはありません。whats_new ツールは、「どのバージョンか、何が変わったか」という質問に、モデルの記憶ではなく、アプリに同梱されたリリースノートから答えます。

拡張サービスは、新たな信頼境界になる

ローカルの stdio MCP は通常、独立したプロセスの起動を伴い、HTTP MCP はリモートサービスへ接続する場合があります。Arslan は、接続、主アシスタントからの利用可否、ツールの公開、認証情報の保存と表示をそれぞれ管理します。プラグインのマニフェストで宣言する HTTP MCP サービスの URL は、HTTPS が必須です。secret スロットはパラメーターの形式を宣言し、実際の認証情報をマニフェストに埋め込みません。設定済みの環境値は暗号化して保存し、読み出して表示するときはマスクします。

0.1.61 以降、ユーザーがオンにした MCP サーバーはすべて、Arslan を開いたときにバックグラウンドで起動します。同時に起動するのは最大 4 つで、チャットがその完了を待つことはありません。各サーバーには、「機能」ページとモデルの両方が読む一つの状態があり、モデルに提供されるのは今すぐ使える状態のサーバーだけです。それ以外のサーバーへの呼び出しには、その状態と理由が返され、キーとトークンはマスクされます。初回の起動には 120 秒が与えられます。失敗したサーバーは 30 秒後に再試行され、その後は間隔が広がります（最長でも 10 分に 1 回）。

0.1.62 以降、Arslan は MCP ツールのパラメーター説明を、Anthropic、OpenAI 互換プロバイダー、Gemini が受け付ける形に整え直してから送ります。組み込みツールは書かれたまま送られます。それでもプロバイダーが特定のツールを拒否した場合、そのツールは返信の残りの間は除外され、返信は続きます（拒否がツールを特定しない場合や、2 つ目のツールが拒否された場合は、その返信ではすべての MCP ツールが除外されます）。

0.1.63 以降、MCP の呼び出しは、サーバーがそのツールの動作をどう示しているかに応じて確認を求めます。サーバーが読み取り専用と示しているツールは、カードなしで実行されます。破壊的と示しているものは、毎回、今回のみとして確認を求めます。それ以外は、今回のみ、またはその会話について確認を求め、「Always」は選べません。引数が長すぎてカードに全文を表示できない呼び出しは、切り詰めずに拒否されます。これらの印はサーバー自身の申告であり、Arslan が検証するものではありません。確認できる相手がいない場合（定期実行）は、読み取り専用のツールだけが実行されます。

これらの制約は、意図しない露出や誤実行の機会を減らしますが、実際の MCP サービスは、与えられたリソースにアクセスし得ます。ツールの出所、必要な権限、リモートへ送られるデータ、操作の副作用は、いずれも拡張機能として説明すべき事項です。

育つ能力：探す、尋ねる、インストールする、スキャンする、テストする

0.1.57 以降、ある手順に Arslan のできないことが必要になると、find_capability が公式の MCP Registry、GitHub、審査済みのスキルライブラリをまとめて検索します。propose_capability が名前を挙げられるのは、この会話で提示された候補だけです。カードはモデルの言葉からではなく、その検索結果からサーバー側で組み立てます。内容は、追加される機能、入手元、プロジェクト自身のライセンスファイルから読み取ったライセンス、実行方法、使用できるフォルダー、必要なキーです。承認できるのは、尋ねた Arslan のウィンドウだけです。バックグラウンドジョブや、尋ねる相手のいないターンでは、見つけた候補を Capabilities ページの「Arslan found」に記録するにとどめます。

承認後は、バージョンを固定し、無効の状態でインストールします。ハッシュ付きのロック、公開されたチェックサム、またはコミットで固定し、Arslan 自身の固定された uv または Node を使います。インストール中にパッケージのコードは実行しません（wheel のみ、npm はインストールスクリプトなし）。スキャンは既知の危険なパターンを探します。たとえば、スキルに隠された指示、さらにコードを取得して実行するコード、macOS がプログラムを起動する場所への書き込みです。重大な検出があれば、再び削除します。スキャンでは安全を証明できません。そのため、サーバーはその後、専用のサンドボックス内で動作します（第 09 章）。有効にする前に、起動して少なくとも 1 つのツールを一覧に出せなければなりません。ツールループはツール一覧を読み直すので、失敗した手順を同じ返信の中でやり直せます。GitHub から取り込んだスキルは、1 つのコミットに固定し、ファイルごとにチェックサムを持ちます。その本文は外部のコンテンツとして読み、権限を与えることはできません。

ファイルはファイルとして返る：ワークベンチのリーダー

0.1.58 以降、ターンの中で書き出されたファイルは返信の下にカードとして表示され、返信に含まれるパスは Arslan 内またはファイルブラウザーで開けます。ワークベンチのリーダーが読み取れるのは、Arslan 自身の読み取りツールが読める場所に限られます。つまり、ワークスペース、既定の読み取りが有効な場合の Desktop、Documents、Downloads、アクティブなプロジェクトのフォルダー、Arslan 自身の出力です。シンボリックリンクは先に解決し、隠しファイルや認証情報のような名前のファイルは一覧にも表示せず、読み取りもしません。ファイルのバイト列は nosniff 付きの添付として送り、HTML は空の sandbox 属性を持つ iframe 内に表示するため、そのスクリプトは実行できません。

0.1.63 以降、スクリーンショット、グラフ、エクスポート、文書などのファイルを求めると、attach_file がそれを回答に添付します。ウィンドウにはファイルカードが表示され、ペアリングした iPhone にはファイルそのものが届きます。これはリーダーが読める場所を読むだけなので専用のカードは出ず、同じルールが適用されます。隠しファイルや認証情報のような名前は対象外で、読み取り可能なフォルダーの外へ出るリンクも対象外です。また、Arslan 自身のデータ、キーチェーン、SSH 鍵の配下にあるもの、20 MB を超えるファイル、1 回の実行で保持できる数を超えるファイルも添付しません。

Hands v2：一つのウィンドウの画像、バッチ、前面の借用、画面の引き継ぎ

Hands は引き続き、ウィンドウをアクセシビリティツリーとして読み取ります。0.1.60 以降は、読み取りのたびに、その一つのウィンドウの JPEG を添付することもできます。画面全体を撮ることはありません。画像はメモリ上にだけ保持してモデルにのみ送り、ディスク、トレース、UI には書き出しません。モデルが画像を受け付けない場合は、代わりに macOS Vision がローカルで文字を読み取ります。この機能は設定 → Hands でオフにでき、指定したアプリではテキストだけに限定することもできます。一つのアプリでの複数の手順は最大 8 件のバッチとしてまとめて実行し、アプリが前面にないときでもメニュー項目を直接選び、アプリはバックグラウンドで開きます。0.1.62 までは、チャットの返信で行える操作は最大 5 件で、すべて一つのアプリ内に限られていました。0.1.63 以降、チャットの返信に Hands 独自の上限はなく、バックグラウンドジョブと同じく実行自体の上限の中で操作します。スケジュール実行は Mac 上で一切操作できません。承認する人がいないためです。

ポップアップメニューのように、アプリが前面にないと動かない操作もあります。その場合 Hands は、キー入力が 1 秒途切れるのを待ってから、すべてのディスプレイの縁が青く光る間、約 1 秒だけ前面を借ります。その間に押されたキーは保持しておき、ユーザーのアプリが前面に戻ったときに再送します。アプリのウィンドウが別のデスクトップにある場合、Hands は同じルールのもとでそこへ移動し、作業が終わったとき、操作のないまま 15 秒が経ったとき、またはユーザーが最初に入力したときに戻ります。より長い作業では、バックグラウンドジョブが最大 30 分間、画面の引き継ぎを求めることができます。キーボードやマウスの入力があると、ユーザーが続行するまで一時停止します。「While I'm away」は既定でオフです。オンにすると、入力のないまま 3 分が経った後、カードなしで引き継ぎを始めることがあります。前面の借用はオフにでき、その場合 Hands は代わりに操作を断ります。

検索とウェブの読み取り

0.1.63 以降、web_search は、そのターンが動いているモデル自身の検索を最初に使います。Anthropic 自身の API 上の Claude の会話では Anthropic のウェブ検索、DeepSeek のモデルでは DeepSeek の検索です。ローカルモデルでの会話が、検索クエリをプロバイダー自身の検索へ送ることはありません。設定で選んだ Tavily またはセルフホストの SearXNG は、唯一の検索になるか、モデル自身の検索の次のバックアップになります。意図的な選択がない場合は、ベストエフォートの DuckDuckGo のスクレイピングが最後に来ます。検索サービスが Arslan を拒否したときは、結果に検索がブロックされ何も検索されなかったと示され、「結果なし」とは表示されません。

ページの読み取りとブラウザーでは、外向きの通信のガードが維持されます。ローカル名、実際のプライベートアドレス、制御文字を含むホストは拒否されます。0.1.61 以降、プロキシや VPN が DNS に偽のアドレス（198.18.0.0/15）で応答する Mac では、https のポート 443 で要求された名前のうち、すべてのアドレスがそのブロックにあるものは通され、そのような名前への通常の http や別のポートは拒否されます。そのような名前では、リクエストが実際にどこへ行くかをプロキシが決めます。引き続き有効なのは TLS であり、実際の名前に対して検証されます。

並列調査を残している理由

統一 Agent ループには、制限付きの一時的な読み取り専用 workers が残っています。v0.1.63 では一度に最大 4 件、同時に最大 2 件を実行できます。ツールは検索と Web ページ抽出に限られ、ファイルや個人の記憶へ書き込まず、再帰的に workers を増やすこともできません。主アシスタントが結果を確認して統合します。

この委任は、互いに独立した資料調査を分割するのに適しています。初期の恒久的な専門家の分身とはライフサイクルが異なり、ユーザーが先に専門家チームを選んだり管理したりする必要はありません。また、すべてのメッセージを別の「専門家」に強制的に振り分けるものでもありません。並列化するかどうかは、タスクを有効に分割できるかと、追加の呼び出し費用によって判断します。

バックグラウンド、定期実行、heartbeat

バックグラウンド job は、時間のかかる実行を現在のチャットから切り離し、同じモデル、ツール、受け入れ確認のロジックを再利用します。定期タスクは「いつ開始するか」を永続化します。heartbeat はチェックリストを定期的に確認する用途の一つで、既定では無効であり、確認と提案を担当します。定刻に起動したからといって、提案が承認済みの書き込みやコマンドになるわけではありません。0.1.63 以降、定期実行はすべて、確認できる相手のいない通常の Arslan のターンです。このバージョンでは、以前に何を許可していたかにかかわらず、ターミナルコマンドを一切実行せず、書き込みは Arslan 自身のフォルダーにだけ行い、Mac を操作せず、サーバーが読み取り専用と示している MCP ツールだけを実行します。それ以上が必要な手順は拒否され、Inbox に一覧されます。

チャットの返信とバックグラウンドタスクは、タスクごとのドル上限で止まります（既定でオン、$2。上限の約 3 分の 2 で締めくくりに入ります。価格が分かっているモデルだけが計上されます）。上限は設定で変更できます。長い作業のために、チャットの返信がバックグラウンドへ押し出されることはなくなりました。バックグラウンドの作業は、ユーザーまたはモデルが選んだときに、同じ作業を別の場所で行うものです。

現在のスケジューリングはローカルサービスが担い、重複実行のスキップ、失敗時の一時停止、再起動時の整理などを処理します。逃した実行回は一つずつ補完せず、同じタスクの前回分が終わっていないときは次の回を重ねて開始しません。個人向けデスクトップアプリに適した動作である一方、常時オンラインのサーバーとは実行条件が異なります。
