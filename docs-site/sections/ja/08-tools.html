08 / ツール、Skill、拡張機能機能を再利用し、実行の境界を保つ

Arslan は、「何ができるか」と「どう行うか」を分けて構成しています。ツールは実際の操作、Skill は手順と参考資料、MCP は外部機能との接続を担い、プラグインのマニフェストがそれらを組み合わせます。モデルが受け取るのは、そのターンで利用できる機能の集合です。ソースのレジストリにツールが存在しても、既定で有効であることや、実行が許可済みであることを意味しません。

四つの概念の関係

構成要素提供するもの代わりにはならないもの
Tool検索、ファイルの読み取り、コマンド実行など、名前、引数の契約、実行器を持つ操作ツールの説明は、引数の検証、権限の判断、実際の返却値の代わりにはなりません
SkillSKILL.md に記載された作業手順と、任意のスクリプトや参考資料Skill 自体がシステム権限を得るわけではなく、別途学習されたモデルでもありません
MCPstdio または HTTP を通じて外部ツールを検出し、呼び出すプロトコル共通のインターフェースはサービスの信頼性を保証しません。接続、ツールの公開、許可は引き続きアプリが管理します
Plugin manifestarslan.plugin.json が、MCP の起動方法、secret スロット、関連する Skills を宣言しますマニフェストのインストールや解析だけで、記載されたサーバーが自由に実行されるわけではありません

宣言から実行までに行う検査

機能を検出する組み込みレジストリ、設定済み MCP、Skill 索引
選別して提供する文脈、設定、権限に応じて今回の schema を提供
要求を解析するツール名、JSON 引数、完全性を検証
実行し、結果を返す実際の許可後に実行器を呼び、結果と失敗を記録

組み込みツールは登録済みの実行器が処理し、 mcp_ で始まる呼び出しは MCP プロキシに渡されます。ツール結果は統一ループへ戻り、モデルはそれをもとに引数を補い、代替手段を選び、またはタスクを終えます。モデルがすでに Skill を読んでいても、ファイル、コマンド、アプリの操作は、それぞれの権限検査を通る必要があります。

Skill は必要に応じて読み込みます。索引が利用できる手順をモデルに示し、read_skill が登録済みの SkillPack または許可された参考資料のパスから本文を取得します。これにより、手順のライブラリを増やしながら、各ターンのコンテキスト量を抑えられます。過去の専門家を Skill に移行することも、「手順と資料を残し、実行の入口を簡素化する」という方向に沿っています。

0.1.55 以降、Capabilities ページでは Arslan にできることをスイッチとして一覧表示し、それぞれがオン、オフ、あと一歩で使える、この環境では使えない、のいずれかであるかを理由とともに示します。オフにした機能はモデルにまったく提示されず、read_skill もオフの Skill の読み込みを拒否します。各行は、そのターンでどのツールを渡すかを決めるのと同じゲートから読み取るため、ツールが欠けているのに行が「オン」と表示されることはありません。whats_new ツールは、「どのバージョンか、何が変わったか」という質問に、モデルの記憶ではなく、アプリに同梱されたリリースノートから答えます。

拡張サービスは、新たな信頼境界になる

ローカルの stdio MCP は通常、独立したプロセスの起動を伴い、HTTP MCP はリモートサービスへ接続する場合があります。Arslan は、接続、主アシスタントからの利用可否、ツールの公開、認証情報の保存と表示をそれぞれ管理します。プラグインのマニフェストで宣言する HTTP MCP サービスの URL は、HTTPS が必須です。secret スロットはパラメーターの形式を宣言し、実際の認証情報をマニフェストに埋め込みません。設定済みの環境値は暗号化して保存し、読み出して表示するときはマスクします。

これらの制約は、意図しない露出や誤実行の機会を減らしますが、実際の MCP サービスは、与えられたリソースにアクセスし得ます。ツールの出所、必要な権限、リモートへ送られるデータ、操作の副作用は、いずれも拡張機能として説明すべき事項です。

育つ能力：探す、尋ねる、インストールする、スキャンする、テストする

0.1.57 以降、ある手順に Arslan のできないことが必要になると、find_capability が公式の MCP Registry、GitHub、審査済みのスキルライブラリをまとめて検索します。propose_capability が名前を挙げられるのは、この会話で提示された候補だけです。カードはモデルの言葉からではなく、その検索結果からサーバー側で組み立てます。内容は、追加される機能、入手元、プロジェクト自身のライセンスファイルから読み取ったライセンス、実行方法、使用できるフォルダー、必要なキーです。承認できるのは、尋ねた Arslan のウィンドウだけです。バックグラウンドジョブや、尋ねる相手のいないターンでは、見つけた候補を Capabilities ページの「Arslan found」に記録するにとどめます。

承認後は、バージョンを固定し、無効の状態でインストールします。ハッシュ付きのロック、公開されたチェックサム、またはコミットで固定し、Arslan 自身の固定された uv または Node を使います。インストール中にパッケージのコードは実行しません（wheel のみ、npm はインストールスクリプトなし）。スキャンは既知の危険なパターンを探します。たとえば、スキルに隠された指示、さらにコードを取得して実行するコード、macOS がプログラムを起動する場所への書き込みです。重大な検出があれば、再び削除します。スキャンでは安全を証明できません。そのため、サーバーはその後、専用のサンドボックス内で動作します（第 09 章）。有効にする前に、起動して少なくとも 1 つのツールを一覧に出せなければなりません。ツールループはツール一覧を読み直すので、失敗した手順を同じ返信の中でやり直せます。GitHub から取り込んだスキルは、1 つのコミットに固定し、ファイルごとにチェックサムを持ちます。その本文は外部のコンテンツとして読み、権限を与えることはできません。

並列調査を残している理由

統一 Agent ループには、制限付きの一時的な読み取り専用 workers が残っています。v0.1.57 では一度に最大 4 件、同時に最大 2 件を実行できます。ツールは検索と Web ページ抽出に限られ、ファイルや個人の記憶へ書き込まず、再帰的に workers を増やすこともできません。主アシスタントが結果を確認して統合します。

この委任は、互いに独立した資料調査を分割するのに適しています。初期の恒久的な専門家の分身とはライフサイクルが異なり、ユーザーが先に専門家チームを選んだり管理したりする必要はありません。また、すべてのメッセージを別の「専門家」に強制的に振り分けるものでもありません。並列化するかどうかは、タスクを有効に分割できるかと、追加の呼び出し費用によって判断します。

バックグラウンド、定期実行、heartbeat

バックグラウンド job は、時間のかかる実行を現在のチャットから切り離し、同じモデル、ツール、受け入れ確認のロジックを再利用します。定期タスクは「いつ開始するか」を永続化します。heartbeat はチェックリストを定期的に確認する用途の一つで、既定では無効であり、確認と提案を担当します。定刻に起動したからといって、提案が承認済みの書き込みやコマンドになるわけではありません。

現在のスケジューリングはローカルサービスが担い、重複実行のスキップ、失敗時の一時停止、再起動時の整理などを処理します。逃した実行回は一つずつ補完せず、同じタスクの前回分が終わっていないときは次の回を重ねて開始しません。個人向けデスクトップアプリに適した動作である一方、常時オンラインのサーバーとは実行条件が異なります。
