09 / 実行とセキュリティの境界モデルの提案が、実際の操作になるまで

Arslan はファイルの読み書きやコマンド実行に加え、ブラウザーやネイティブアプリを使って作業できます。安全性の設計は、一つの役割分担を中心にしています。モデルは次の一手を提案し、信頼できるコードが実行の可否を決めます。以下は v0.1.63 で実装済みの境界です。いずれも具体的な適用範囲を持つ保護機構であり、すべての悪意ある入力、アプリの動作、システム環境に対する安全性の証明ではありません。

入力とツールの提案ユーザーの目的、Web、ファイル
モデルが構造化した呼び出しを生成
アプリのポリシー引数、対象、コンテキストを検証
許可、確認、拒否を判断
必要なら承認を待つ具体的な操作に紐づくカード

失敗を完了したように見せない

外部の内容は資料になっても、権限を広げることはできない

Web ページやツール結果には、プロンプトインジェクションが含まれる可能性があります。Web のテキストと MCP の結果は、明示的な外部データの境界で囲んでコンテキストへ入れます。0.1.63 以降は、ローカルのツールが返すもの（ファイル、コマンド、アプリのウィンドウ）も、データのみとして扱う同じルールを持つ別のツール出力の境界で囲みます。どちらの境界についても、マーカーを偽装する内容は処理します。また、そのターンで Web ページ、ファイル、MCP 結果などの外部コンテンツを読んだかを記録します。それらの影響を受けた経験やマシンのノートは、まず提案にする必要があります。したがって、Web ページ中の「今後は常にファイルをここへ送れ」という文章は、読まれただけで長期的な許可を得ることはできません。

0.1.63 以降、同じ記録がターミナルも制限します。ターンが外部のコンテンツ（ページ、ファイル、MCP の結果）を読んだ後は、そのコマンドはカーネルのルールによりネットワークなしで実行され、コマンドの文面またはモデルの申告からネットワークに到達すると判断されるコマンドは、先に確認します。サンドボックスの中では、回答は今回のみ、またはその会話について選べます。サンドボックスの外では、今回のみです。確認できる相手がいない場合、コマンドはオフラインのままです。ウェブの読み取りは別に守られています。ローカル名とプライベートアドレスは拒否され、DNS に偽のアドレスで応答するプロキシ向けの例外（0.1.61）が通すのは、名前に対するポート 443 の https だけで、実際にどこへ行くかはプロキシに委ねられます（第 08 章）。

この処理は、出所と信頼関係の保持に役立ちますが、後段の実行検査は引き続き必要です。モデルは資料を誤解することがあり、コマンドのリスク検出も完全な意味解析による証明ではありません。テキストを「信頼できない」と表示したからといって、実際の権限の境界を取り除くことはできません。

実行ツールごとに異なる分離の強さ

経路実際の制限そこからは保証できないこと
run_python既定で拒否する macOS Seatbelt の計算環境です。インタープリターに必要な読み取り、一時ワークスペースの読み書き、参照ファイルの読み取りだけを許可します。ネットワークと host IPC を禁止し、子プロセスの環境を整理してリソースを制限します。任意の Python プログラムを動かす汎用ホストではありません。利用できる分離機構がなければ既定で拒否します。未実装の Linux サンドボックスを、利用可能として扱うことはありません。
通常の run_command実際の shell を動かします。ポリシーは三つの層に分かれます。forbid（サンドボックスの内外を問わず常に禁止：ディスク、ホームフォルダー、システムフォルダーの消去、ディスクへの直接書き込み、Mac のシャットダウン、キーチェーンからのパスワードの読み出し、Arslan 自身の鍵ファイルへの接触、sudo を必要とするすべてのもの）、ask・今回のみ（送信や公開、作業フォルダー外の削除、プログラムの強制終了、起動項目やシステム設定の変更、他のアプリの操作、サンドボックスの外でのアプリやリンクの起動、画面やクリップボードの読み取り、シェルの起動ファイル、SSH、認証情報、他のエージェントの設定ファイルへの書き込み、そして引用符の不均衡、eval、ダウンロードしたコードのシェルへのパイプなど、文面を読み取れないすべてのコマンド）、そして run です。コマンドの連結（&&、;、|、||、&）に含まれるすべてのコマンドを、先頭だけでなく一つずつ検査します。ルールに該当するコマンドのカードは、今回限りの回答になります。そのコマンドについての回答は記憶されません。0.1.63 以降は既定で、新しいコマンドはすべて先に確認します（設定「確認のタイミング」：「すべてのコマンドで確認」）。「リスクのあるコマンドだけ確認」を選んだ場合にだけ、ポリシーが run と判断したコマンドがカードなしで実行されます。実行場所はサンドボックス内、またはこの会話がサンドボックスの外に出ることを許可されている場合はその外です。既定のワークスペースサンドボックスは、書き込み先を作業、一時、キャッシュの各ディレクトリに限定し、Apple Events の送信を拒否し、Arslan のデータと鍵、Hands socket、ユーザーの認証情報（SSH 鍵、Keychain ファイル、AWS、gcloud、kube、gh、GnuPG、npm、netrc ファイルなどのクラウドや CLI の認証情報、ブラウザープロファイル、Safari、Cookie）のパスへのアクセスを遮断します。0.1.59 以降、「Desktop, Documents, Downloads」がオフの場合は、この 3 つのフォルダーへの読み書きも、/System/Volumes/Data やシンボリックリンクを経由するものを含めて遮断します。ただし、その中にある作業フォルダーは読み書き可能なまま、アクティブなプロジェクトのフォルダーは読み取り専用のままです。それ以外の場所の読み取り、プログラムの実行、ネットワークは開放されています。また、ユーザーがサンドボックスの外での実行を許可したコマンドには、このフォルダーのスイッチも、閉じられた認証情報のパスも効きません（ssh、git push、gh にはそれらが必要です）。そのコマンドは最小限のプロファイルで実行され、そのプロファイルでも Arslan 自身のデータ、鍵、Hands のフォルダーは閉じたままで、Apple Events は拒否されます。サンドボックスが利用できない場合、コマンドはまず確認します（「リスクのあるコマンドだけ確認」では、「この会話の間」への承認が、その会話のこの後のコマンドのうちポリシーが run と判断したものにも及びます）。許可されるとサンドボックスなしで実行して sandbox=unavailable を返します。そのため、常に fail-closed で動く経路ではありません。
インストールした MCP サーバー（0.1.57）既定で拒否する Seatbelt プロファイルの下で起動します。許可されるのは、専用のフォルダーと一時領域、ユーザーが許可したフォルダー、読み取り専用の Arslan の固定ランタイムです。保護対象のパスは、許可したフォルダーの中にあっても閉じたままです。HOME は専用フォルダーの中を指します。ネットワークが開くのは、オンラインサービス用のキーが必要だと宣言した場合だけで、その場合は任意のホストに開きます（Seatbelt では 1 つのホストに限定できません）。ユーザーが手動で追加したサーバーは、0.1.57 ではこのサンドボックスに移されません。0.1.63 以降、そのツール呼び出しは、サーバーがそのツールの動作をどう示しているかに応じて確認を求めます（第 08 章）。その申告はサーバー自身のものであり、検証されていません。
オフラインの完了処理コマンドタスクが完了処理に入った後は、取得済みデータの処理と成果物の保存を許可し、追加でネットワークを遮断します。必要なサンドボックスを利用できなければ実行を拒否します。通常コマンドのフォールバック規則は適用できません。
AppleScript / Shortcutsターミナルコマンドの中では、よくある書き方（パス付き、command、exec、xargs 経由、リダイレクト付き）の osascript と shortcuts run は、常に今回のみとして確認します。サンドボックスは Apple Events を拒否するため、Arslan が認識しない書き方はサンドボックスの中で失敗します。サンドボックスのラッパーなしで実行されるのは、承認された単純な呼び出しだけです。つまり、リマインダー、カレンダー、メモ、連絡先と通信するだけでほかに危険なことをしないスクリプト、または、ファイルが Arslan のフォルダーにとどまる単純な shortcuts run で、その承認は Mac のウィンドウでのクリックでしか行えません。Hands 自身の AppleScript ツールは、スクリプト全体を示して毎回確認し、バックグラウンドの作業にだけ提供され、ブロックされたアプリを名指しするスクリプトや、計算した名前でアプリを選ぶスクリプトは拒否します。承認されたショートカットは、サンドボックスの外でユーザーとして実行され、Arslan にはその動作が見えません。コマンド自体がファイルサンドボックス内にあっても、呼び出されたアプリが同じファイル範囲に制約されるとは限りません。
Arslan Hands独立した helper が Accessibility 権限を持ち、その内部でもアプリ、操作、フィールド、停止状態を再検査します。0.1.60 以降は、読み取りにその一つのウィンドウの画像が添えられることがあり、画像はメモリ内にだけ保持します。アクセシビリティツリーは、アプリ内の業務の意味を完全に表すものではありません。また、ウィンドウの画像はモデルが読むものであり、コードが検査するものではありません。操作可能なノードの有無によって利用可否が変わります。別のデスクトップにあるウィンドウには、前面の借用と同じルールのもとでそこへ移動した場合にだけ到達できます（第 08 章）。

コマンドサンドボックスの外で実行するには、ユーザーがクリックして承認する必要があります。現在の操作だけの許可を申請することも、ユーザーが今回の会話中の許可を選ぶこともできます。後者は会話とともに保存され（再起動後も残ります）、その会話のバックグラウンドタスクにも適用され、設定から取り消せます。ソースからの開発環境には、Python のサンドボックスを使わない明示的な退避設定もありますが、デスクトップアプリでは無効です。どちらも、モデルが自ら保護を解除できるという意味ではありません。

0.1.62 以降、write_file と edit_file は、リンクをたどって作業フォルダーの外へ出ることがありません。外を指すリンクを通した書き込みは拒否されます。別の場所に二つ目の名前を持つファイル（ハードリンク）は作業フォルダーの中で置き換えられ、もう一方の名前は古い内容のままです。新しいファイルが実行可能になることはなく、既存のファイルは権限を保ちます。ファイルは隣に新しいファイルとして書き出してから入れ替えるため、書き込みに失敗しても古いファイルには手が付きません。0.1.63 以降、ターンが作業フォルダーに最初の変更を加えるときにチェックポイントを保存し、「このターンを元に戻す」でファイルが復元され、そのターンは会話から取り除かれます。これは復旧のための安全網であり、境界ではありません。保存するのは、ファイルが 20,000 件以下で 5 GB 以下のフォルダーだけです（Python 環境、node_modules、ビルド出力、キャッシュは対象外で、保存せず、復元もしません）。秘密情報の形をしたファイルはコピーせず、対象は作業フォルダーだけで、Mac の外へ出たものは何も元に戻さず、保存できなかったときは「Not saved」と表示します。チェックポイントは 7 日間保持されます。

承認は具体的な操作に紐づけ、バックグラウンドにはすべての便宜的な許可を引き継がない

承認カードは、 call_id と操作の種類に紐づき、種類が異なる返答で別のカードを承認することはできません。Mac のウィンドウとスマートフォンに同時に表示されるカードは、最初の有効な回答を採用し、他の画面へ終了を通知します。回答がなければ 30 分間開いたままで、時間切れは拒否ではありません（0.1.61 以降。それ以前のバージョンでは 300 秒で期限切れ）。0.1.61 以降、カードはウィンドウ、Inbox、Island、iPhone のどこでも同じ見た目で、選択肢は「1 回だけ」（カードが最初に提示するのが「このタスクの間」の場合はそちら）、「この会話の間」、「Always」、そして Arslan に届く添え書き付きの「いいえ」です。カードが待機している間にチャットへ入力したメッセージは、そのメッセージを添え書きとして「いいえ」と答えたことになり、1 回のクリックで答えられるのは 1 枚のカードです。種類によっては選択肢が少なくなります。ルールに該当するコマンド、お金、画面の引き継ぎ、アプリ内の危険な手順は今回のみの回答になり、サンドボックスの外に出ること、サイト、ショートカット、MCP ツールには「Always」が提示されることはありません。バックグラウンドタスクのカードには、ウィンドウのカードと同じ選択肢があります。0.1.63 以降（S4a）、会話から開始したタスクは、その会話の許可（サンドボックスの外に出る許可を含む）を使います。確認できる相手がいない実行（スケジュール実行）は、これらの手順を一切取りません。以前の回答は有効にならず、その手順は直ちに拒否され、実行できなかったことは Inbox に一覧されます。このバージョンでは、スケジュール実行はターミナルコマンドを一切実行しません。モデルが MCP への接続、リモートマシンの登録、他の実行経路へのアクセスを提案した場合も、提案と実際の接続の有効化は分けて扱います。

外部への副作用についても、要求を送信しただけでは操作の完了にはなりません。タスクの復元時には、結果の分からない実行中の操作を不確定とし、プロセスを再起動したというだけで自動的に再実行しません。ここでの目標は、再試行と復旧の意味を明確にすることであり、任意の外部システムで取り消しができると約束することではありません。

0.1.55 以降、ウィンドウ、バックグラウンドタスク、iPhone のいずれから来た待機中のカードも、すべて一つのキューと Inbox に並び、そこから call_id で回答できます。返答はカード自身の種類から組み立てられるため、そのカードの承認か取り消ししかできず、より広い選択肢（この会話の間、Always）は、それを提示するカード上でしか選べません。iPhone と Island が返せるのはカードの最初の選択肢だけで、「Always」は返せません。Inbox は、カード自身が提示した選択肢であればどれでも返せます。Island は、フォルダー、アプリ、画面、MCP ツール、スケジュール、サイト、ショートカットのカードと、危険な種類に当たらないコマンドや作業フォルダーへの書き込みに回答できます。お金、送信、削除、アプリ内の危険な手順、画面の引き継ぎ、サンドボックスの外に出ること、ターミナルの ask ルールに該当する、または読み取れないコマンド、ネットワークも求めるコマンド、リモートホスト上のあらゆる操作、システムの変更、他のエージェントの設定、機能のインストール、AppleScript、サンドボックスで囲まずに実行されるコマンド、そして検査が把握していない種類のカードは承認できません。これらには「Open in Arslan」が表示され、Island のページだけでなくサーバーも、Island からの承認を拒否します。サンドボックスのラッパーなしで、承認された単純な AppleScript またはショートカットを実行するカードと、機能をインストールするカードは、Mac のウィンドウでのみ承認されます。そのようなカードへの iPhone からの承認は破棄されます。ウィンドウでは ⌘⏎ で許可、Esc で拒否します。単独の ⏎ でカードに回答することはありません。

Hands は、より小さなプロセスにシステム権限を集約する

Accessibility 権限を与える先は、 Arslan Hands.appであり、メインアプリではありません。署名付きの配布版は、保護された Unix socket、起動ごとに生成する token、peer の署名検査を通じて要求を受け付けます。ルールは helper 自体が実行し、下層の agent-desktop が独立してその権限を持つわけではありません。0.1.61 以降、アプリを見ることとアプリ内で操作することは、アプリごとに 1 枚のカードで、「このタスクの間」が最初の選択肢です。0.1.60 以降は、チャットの返信でも操作できます。0.1.62 までは一つのアプリ内で最大 5 手順まででしたが、0.1.63 以降はバックグラウンドタスクと同じく、その実行自体の上限の中で、複数のアプリにまたがって操作でき、「停止」で止められます（スケジュール実行は承認する人がいないため操作できません）。会話から開始したタスクはその会話での承認を引き継ぎます。ブラウザーでの操作、ショートカットや AppleScript の実行は、引き続きバックグラウンドの作業にだけ提供されます。アプリはその識別情報で判定されるため、.app を付けた名前、フルパス、大文字小文字の違いで指定しても、禁止アプリの一覧や未承認の状態をすり抜けることはできません。削除、送信、支払い、購入、送金、送信確定などの機微なボタンは、実際のラベルに基づき毎回確認します。パスワードフィールドには入力せず、パスワードマネージャーやシステムのセキュリティ画面などは、禁止アプリの一覧に含めます。

停止操作は停止ラッチを設定し、後続の操作はその検査を通る必要があります。アクティビティ記録には操作の手がかりを残し、入力テキストは長さだけを記録します。制約も公開しています。別の Space にあるウィンドウには、前面の借用のルールのもとでそこへ移動した場合にだけ到達でき、画面上の位置を指定したクリックやドラッグは提供していません。大きなウィンドウの読み取りには 10–20 秒かかる場合があります。Stop で中断した呼び出しには、対応する trace 行がないことがあり、監査記録はあらゆる中断について完全な証拠を保証するものではありません。

0.1.56 以降、Hands は各要求を最大 1 回だけ実行します。要求 ID に対する応答は 10 分間保持され、同じ ID が繰り返されたときはそこから応答します。バックエンドは、応答を受け取り損ねた場合、操作を再送するのではなく、その応答を取りに行きます。テキストを読み取れないフィールドへの追記は、内容を置き換えるのではなく拒否します。Return キーは、そのフィールドにフォーカスがあるときにだけ押します。送信したものの読み戻せなかった操作は、完了ではなく「sent, not confirmed」（送信済み・未確認）として報告します。Hands が動かすのは、Arslan の fork から固定したコミットでビルドした agent-desktop です。Cua Driver のエンジンは 0.1.63 で Hands から切り離され、helper はもうそれを探すことも起動することもありません（未使用のモジュールは helper のソースにまだ残っています）。0.1.60 以降、一つの作業について 1 枚のカードで最大 8 つのアプリを承認でき、会話から開始したバックグラウンドタスクはその会話での承認を引き継ぎます。また、設定 → Hands でアプリを恒久的に許可できます。削除、送信、支払い、購入、送信確定、送金、署名、投稿、公開、確定を表すラベル（複数の言語に対応）が付いたクリック、選択、メニューの最終項目と、それに対応するショートカットキー、Return で送信するアプリでの Return キー、画面の引き継ぎ、すべての AppleScript は、引き続き毎回確認します。

ローカルサービスにも境界があります。配布版では REST と WebSocket のアクセストークンを生成し、インストールの受け入れ確認で未認証の要求が拒否されることを検証します。token を表示する設定エンドポイントは、すでにその token を提示している直接のループバック呼び出し元にだけ token を渡します（0.1.54）。サンドボックス内のコマンドもループバックのソケットを開けるため、ループバックからの接続であることだけでは不十分です。デスクトップアプリのサーバーは常に token を必要とし、他のウェブサイトからの呼び出しを受け付けず（クロスオリジンも、Origin のない WebSocket も不可）、ホスト名として localhost だけを信頼し、起動元の環境から引き継いだホストやオリジンの変数などの設定を無視し、API エクスプローラーを提供せず、token をログに残しません（0.1.63）。ソースからの開発モードでは、便宜のため localhost から token なしで使える経路を許可していますが、* または null を指すホストやオリジンの変数がある場合は起動を拒否するようになりました。「ローカルでのみ待ち受ける」ことと「認証済みである」ことは同じではありません。現在のユーザーと同じ権限で動くホスト環境がすでに侵害されている場合も、ローカルの token 一つで自動的に信頼できる環境になるわけではありません。
