10 / iPhone と Mac Bridge依頼と確認はスマートフォンで、実行は Mac で

モバイル連携により、ペアリング済みの iPhone から Mac のタスクを確認し、作業を依頼し、承認に回答し、結果を読むことができます。実行するのは引き続き Mac 上の Arslan です。スマートフォンは別のクラウド Agent サービスではなく、Mac の HTTP インターフェースを直接公開したり呼び出したりすることもありません。本章は、Mac v0.1.63 の公開プロトコルとソースコードを基準にしています。Mac Bridge は以前のリリースに含まれており、公開リリースノートでは iPhone App は引き続き公開予定とされています。そのため、本書では App Store での公開や、本番環境における一連の経路の受け入れ確認が完了したとは述べません。0.1.60 以降の変更には、登場する箇所にバージョンを付けています。0.1.61 のリリースノートには、Mac 側が Arslan for iPhone 1.0 に対応すると書かれていますが、これは引き続き App Store での公開予定として説明されています。

CloudKit はメールボックスであり、デバイスの本人性はプロトコルで確認する

v1 は、同じ Apple ID の CloudKit 非公開データベースを使います。Mac は電源が入り、オンラインで、実行可能な状態である必要があります。そうでなければメッセージは処理待ちとなり、スマートフォンから電源の切れた Mac を動かすことはできません。LAN 内の Bonjour は今後の方向性であり、この版の代替直結経路ではありません。Mac helper は、アプリに伴って動く独立した ArslanBridge.appで、stdin 経由でローカル API token を受け取ってバックエンドに接続します。スマートフォンはこの token を持たず、モデルの API key も受け取りません。

エンベロープのクラウド側で見える索引フィールドには、送信元・送信先のデバイス、シーケンス番号、大まかな kind、通知フラグ、時刻があります。実際のメッセージ種別、本文、ファイル内容は、アプリ層の暗号文に含まれます。したがって、「エンドツーエンド暗号化」は、ペアリングされたデバイス間のメッセージ保護を指します。メタデータが存在しないことや、バックエンドのモデル呼び出しがユーザー設定の AI サービスを一切経由しないことを意味しません。

QR コードの読み取りは、ペアリングの始まりにすぎない

QR コードには、一回限りの pairing_id、Mac の署名用・鍵交換用の公開鍵、32 バイトのペアリング鍵、固定のコンテナ識別子、有効期限が含まれます。有効期間は最大 600 秒です。スマートフォンは、期限切れ、誤ったコンテナ、制約に合わない内容を拒否し、QR コード内の Mac 公開鍵を固定します。その後、自身の識別用・鍵交換用の鍵を生成し、暗号化されたペアリング要求を送ります。Mac は要求を検証した後もユーザーに提示し、Mac 上でのクリックによって承認または拒否を決めます。

同じ要求の再試行には同じ決定を返し、二度目の許可を生じさせないようにします。承認後はデバイスの識別情報を使って通信し、ペアリングコードは使用済みになります。Mac からスマートフォンの登録を取り消すこともできます。同じ iPhone が再びペアリングするときは以前の ID を伝え、Mac はそれらの古い項目を 2 件並存させずに削除します。スマートフォンを削除すると、Mac がそのスマートフォン宛てに iCloud に残していたメッセージも削除されます。起動時にも Mac は、ペアリングが解除されたスマートフォンを待ち続けている記録を消去します。設定 › 接続 › iPhone では、各スマートフォンは Mac がそこから認証済みのメッセージを初めて読み取るまで Connecting… と表示され、その後は Connected と最終接続時刻が表示されます。各デバイスの秘密鍵は、それぞれの Keychain に保存します。信頼の根拠は、一回限りのペアリング情報とユーザー確認の組み合わせであり、「同じ iCloud アカウントだから、どのメッセージも信頼できる」というものではありません。0.1.60 以降、iPhone 側でペアリングを解除すると、Mac は、設定 › 削除 を実行したときと同じようにそのスマートフォンの登録を消し、以後そこから届くものを無視して、一覧を更新します。

メッセージの内容、出所、コンテキストを同時に検証する

新しいメッセージごとに一時的な X25519 鍵で共有秘密を確立し、HKDF-SHA256 で 32 バイトの鍵を導出します。ChaCha20-Poly1305 で認証付き暗号化を行い、さらに Ed25519 で署名します。ヘッダーには長さで区切る UTF-8 フィールドを使い、言語間の JSON の並び順の違いが検証に影響しないようにします。ヘッダーフィールドは署名と AEAD 認証の両方に結び付けます。これは CryptoKit の暗号プリミティブを使ったアプリケーションプロトコルであり、Signal の Double Ratchet は実装していません。一時鍵を使うことだけをもって、あらゆる状況での前方秘匿性を主張することもできません。

受信時の順序は明確です。形式と受信者を確認し、署名を検証してから復号します。その後、平文とヘッダーの一致を確かめ、ファイルがある場合は添付も検証します。どの段階で失敗しても、業務上の処理が部分的に反映されてはいけません。ファイルの上限は 20 MiB で、暗号文のダイジェスト、認証タグ、平文のサイズとダイジェストがすべて一致して初めて、キャッシュやプレビューが可能になります。

スマートフォンの承認は、Mac の許可と実行経路を再利用する

スマートフォンには具体的な action、target、risk を表示します。承認には端末内の生体認証が必要ですが、拒否には不要です。回答を送信した後も、Mac からの approval.resultを待ちます。Mac はカードがまだ有効かを確認し、元の confirm / cancel 操作へ対応付けます。スマートフォンからコマンドに「常に許可」を与えることはありません。音声入力は確認待ちのテキストを作れますが、承認の代わりにはなりません。

0.1.61 以降、承認カードはどこでも一つです（チャットウィンドウ、Inbox、Island、iPhone）。スマートフォンには、カードのタイトルから取ったカード自身の質問と、承認が何を対象とするかが表示されます。回答できるのは 1 回だけ、またはそれがカードの最初の選択肢である場合は「このタスクの間」（アプリ、サイト、ショートカットのカードでは、見出しの末尾が「(for this task)」になります）で、「この会話の間」と「Always」は選べません。Mac 上でのカードの待機時間は 30 分です（0.1.61 より前は 5 分）。時間切れは expired として報告され、Arslan はこれを拒否ではなく、誰も回答しなかったものとして扱います。新しい機能のインストールを求めるカードは、スマートフォンには届きません。Mac が先に回答した場合（ウィンドウ、Inbox、Island のいずれか）、スマートフォンの approval.result には answered_on_mac が含まれます。

バージョンの境界：v0.1.54 以降、Mac は faceid または touchid マーカー（iPhone SE では Touch ID）が付いている場合にのみ回答を承認として扱い、そのことを capabilities でスマートフォンに伝えます。それ以外のマーカーはすべて拒否として扱います。0.1.54 より前は、Touch ID による承認はキャンセルとして扱われていました。プロトコル内の high_risk_mac_only は、この版では false に固定されており、ユーザーが設定できるスイッチではありません。共有プロトコルとテストベクトルは相互運用や異常系を検証できますが、最終配布パッケージ、実際の iCloud、プッシュ通知、デバイス認証を含むエンドツーエンドの受け入れ確認の代わりにはなりません。

ファイル、ライブ会話、スマートフォンからの進路変更

これらは追加のプロトコルタイプです（プロトコル文書の 5.7 節）。対応していない Mac は unknown_type を返し、Mac が新しいイベントを送るのは、hello の capabilities でそれを求めたスマートフォンだけです。

  • スマートフォンからのファイル（0.1.61）。Arslan for iPhone から送られたファイルや写真（20 MiB まで、1 メッセージにつき最大 10 件）は、通常のアセットと同じく検査され、Mac の作業フォルダーの Inbox/iPhone に、日付ごとのフォルダーで保存されます。Arslan はメッセージと一緒にそれを読み、画像はモデルへ画像として渡せます。メッセージのファイルがすべて 120 秒以内に届かない場合、そのメッセージは実行されず、スマートフォンは再送できます。
  • ライブ会話（0.1.61）。Mac は、最新の 20 件の会話と、実行中のタスクがある会話を連携させたままにするため、スマートフォンはそれらを一覧し、Arslan の作業中に回答、進捗、カードを追えます。スマートフォンから会話を削除できます（Remote 会話は削除されません）。1 通のメッセージに収まらないほど長い履歴は、最も古いメッセージから削られ、切り詰めたことが示されます。
  • 書かれるそばから届く回答（0.1.63）。これを求めたスマートフォンには、返信がそこまでの全文を持つ partial イベントとして届きます。頻度は 1 秒に 1 回まで、100 KB までで、最終メッセージがそれらを置き換えます。Mac で入力した言葉は、Mac からのものとして印を付けてスマートフォンに表示され、スマートフォンを鳴らすことはありません。
  • 進路変更（0.1.63）。返信の実行中に送ったメッセージは、終わるのを待たず、次のステップでその返信に届きます。iPhone、Mac のウィンドウ、押している間だけの音声入力のいずれでも同じです。返信が最終回答を書いている間は残りのステップがないため、メッセージはその直後に実行されます。0.1.63 の既知の制限：返信中に Mac のウィンドウで追加したメッセージは、iPhone には次の返信からしか表示されず、iPhone は自分のメッセージが追加された後も「Queued behind the current turn」と表示し続けます。
  • スマートフォンへのファイル（0.1.63）。ファイル（スクリーンショット、グラフ、エクスポート、文書）を求めると、Arslan はそれを回答に添付します。Mac のウィンドウにはファイルカードが表示され、iPhone にはファイルそのものが届きます。上限は 20 MiB です。
