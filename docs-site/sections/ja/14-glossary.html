14 / 用語集用語を具体的な実装に結び付ける

用語は、異なる仕組みを区別するために使います。以下では簡潔な定義とともに、各概念が Arslan の実装でどう使われるかを示します。過去の仕組みは、その旨を明記しています。

AI とコンテキスト

用語わかりやすい説明Arslan での使い方
LLM言語を理解し、生成する大規模なモデルユーザーが設定したプロバイダーから提供される。Arslan はアプリと実行システムを担う
Agent結果を見て次の手順を決める実行プロセスモデルを呼び出し、ツールを実行し、結果を見て継続または終了する
Orchestrator複数の機能を組み合わせる調整役モデル、コンテキスト、ツール、権限、タスク状態を調整する
Tool callingモデルが構造化された形式でツールを要求することツール名と JSON 引数を検証してから実行する
Native tool protocolプロバイダーが正式に定義したツールメッセージ形式を使うことtool call ID、結果、推論の継続を正しく対応させる
Trajectoryモデルとツールのやり取りを構造化して記録した軌跡OpenAI 互換経路では native history を使用し、他の Provider はそれぞれの経路を維持する
Context windowモデルが一回の呼び出しで参照できる情報の範囲すべての履歴、記憶、長い出力全文を無制限に詰め込むことはできない
Compaction古いコンテキストを長さに上限のある要約へ圧縮することリクエストの大きさを抑え、直近の内容を残す。元の会話を削除することではない
RAG関連資料を先に探し、その後モデルに回答させること取り込んだ知識から関連部分を検索し、出典を添える
FTS5SQLite の全文検索語句の一致を探すのが得意で、ベクトルがなくても資料を検索できる
Embedding文章の意味を数値ベクトルに変換すること表現が異なっても意味の近い内容を見つけるために使う
Cosine similarityベクトルの方向がどれだけ近いかを比べること意味検索で使う類似度の計算方法の一つ
RRF複数の検索結果を順位に基づいて統合することFTS とベクトルの順位を統合し、単位の異なるスコアを直接混ぜない
Skill再利用できる「やり方」の説明SKILL.md と任意のスクリプトや参照資料で構成される。別のモデルではない
MCPAgent と外部ツールをつなぐ標準インターフェースstdio または HTTP で外部機能に接続する。承認の制御は引き続きアプリが担う
BYOKユーザーが自分のモデル API キーを持ち込むことユーザーがプロバイダーを選び、対応するモデル呼び出し費用を負担する
Prompt injectionWeb ページやツールの内容を、Agent への新しい指示に見せかけること外部の内容はデータとして扱う。外部の影響を受けた未確認の経験は通常、提案に回すが、完全な耐性の証明ではない
Learned practice訂正や成功した代替手段から記録する方法「このマシンでは AppleScript が使えないので EventKit を試す」など。モデルの重みは変更しない
Shadow mode判断だけを記録し、実際の動作にはまだ反映させない方式判断層が承認の推奨を記録できるが、実際のカードはユーザーのクリックを待つ
Held-out evaluationプロンプトの調整に使っていない課題を残して評価すること初期のエキスパート進化に関する過去の設計で、現在の各会話ターンの固定手順ではない

ソフトウェア構造、状態、信頼性

用語わかりやすい説明Arslan での使い方
SPA一つの Web アプリ内で画面や状態を切り替える構成React の作業画面に必要な静的リソースをローカルサービスが配信する
Sidecarメインアプリと一緒に起動する補助プロセスTauri と並行して動く Python のローカルバックエンド
IPC同じコンピューター上のプロセス間通信パイプや Unix socket を使う。すべてのモジュールがクラウド経由で通信するわけではない
REST / HTTP一回のリクエストでリソースを取得または変更する方式設定、履歴、タスク、ファイル管理の API
WebSocket双方向接続を維持して情報を継続的に送る方式応答ストリーム、ツール状態、承認、進捗のイベント
Async I/OI/O の待機中にイベントループを明け渡し、他のタスクを進める仕組みPython asyncio、非同期 API、データベースアクセス。CPU 処理が無制限に並列化されるわけではない
Schema / Contract入力、出力、許される状態についての明確な取り決めPydantic、ツール引数、タスクの受け入れ契約
State machine有限個の状態で処理の進行位置を表す仕組みqueued、running、waiting_user、verifying、succeeded など
Checkpoint進行位置、実施済みの内容、残作業の記録参照、証拠、予算を使ってタスクを再開する。結果不明の副作用を無条件に再実行しない
Attemptタスクの一回の実行試行再開時は新しい試行を作り、古い非同期結果が新しい状態を上書きしないようにする
Optimistic concurrency書き込む前に、データが先ほど読んだ版のままか確かめる方法row version と attempt ID により、古い結果がキャンセルや更新を上書きするのを防ぐ
Idempotency同じ要求を繰り返しても、意図せず操作が重複しない性質メッセージ／タスク ID で重複を防ぐ。外部への影響が不明な場合は、別途確認が必要
ACK受信側が「このパケットを受け取った」と伝えることタスクの成功や承認の適用を意味するものではない
Single-flight前の実行が終わるまで、同じ処理を重ねて開始しない方式予約タスクの重複実行が積み重なるのを防ぐ
Backoff失敗後、再試行の間隔を徐々に広げることレート制限やサービスエラーでは待機し、Retry-After を尊重する。認証エラーをむやみに再試行しない
WALSQLite が先にログを書き、読み書きの共存を改善する方式ローカルデータの永続化に使用するが、同時書き込みには引き続き制約がある
Migration古いデータベース構造を新しい構造へ安全に更新すること明示的なバージョン付き runner、更新前のバックアップ、未知の schema の拒否
Provenance情報がどこから来たかという来歴文書の出典、記憶の出典、実際の実行軌跡
Observability問題が起きたときに、何が起きたかを把握できる性質Run/Step、Activity、usage、エラー、成果物を関連付ける

OS、セキュリティ、配布

用語わかりやすい説明Arslan での使い方
Sandbox / SeatbeltOS がプロセスのアクセス可能なリソースを制限する仕組み計算サンドボックスとコマンドサンドボックスではルールが異なり、ネットワークとフォールバックの動作を分けて説明する
Fail-closed保護層が利用できなければ実行を拒否する方式標準の Python サンドボックスとオフラインでの終了経路に適用される。通常の全コマンドに一般化してはいけない
Accessibility treeOS が公開するウィンドウ、ボタン、テキストなどの構造Hands がコントロールを読み取り、特定するために使う。スクリーンショットの画素認識には依存しない
TCCmacOS のプライバシー権限管理の仕組みアクセシビリティ、マイク、Apple Events などは、アプリ内のスイッチだけで許可されるものではない
SSRFサービスを誘導し、本来アクセスすべきでない内部アドレスに接続させる攻撃Web 抽出や外部 URL では、接続先、リダイレクト、ネットワークの境界を検証する必要がある
AEAD内容の機密性と完全性を同時に保護する暗号方式Bridge は ChaCha20-Poly1305 を使用し、改ざんされると検証が失敗する
Key agreement / Signature前者は暗号用の材料を共有し、後者は送信者の身元を検証するX25519 と Ed25519 は役割が異なり、混同してはいけない
Replay protection攻撃者が古いメッセージを再送して、再び効果を生じさせるのを防ぐこと署名、宛先、シーケンス番号のスライディングウィンドウ、永続的な重複排除を組み合わせる
CI / CDビルド、検査、配布の手順を自動化すること成功した CI が公開予定の SHA と一致する必要があり、最終成果物も検査する
Contract test境界の両側が同じプロトコルに従っているかを検証するテストPython/Rust、Mac/iPhone で正常系・異常系のベクトルを共有する
Mutation testing保護ロジックを意図的に壊し、テストで検出できるか調べる方法特定のアサーションが違いを検出できることを示す。単なるユニットテストの別名ではない
Code signingソフトウェアの出所と、成果物が変更されていないことを検証する仕組みApp と内蔵 helper の両方に正しい署名が必要
Notarization / StapleApple が配布パッケージを審査し、チケットをパッケージに添付する手順署名とは別の処理で、結果は Gatekeeper でも確認する必要がある
Fresh-install acceptance開発環境も過去のデータもない、新しいユーザーを再現する検証実際のインストールパッケージの認証、WebSocket、リソース、helper を確認する

現在のシステムは、主にローカルの階層型モノリスと独立した helper で構成されています。SQLite とプロセス内の非同期スケジューリングは、個人向けデスクトップ製品のインストールと運用に適しています。関連する用語は、この規模の配置を前提に理解してください。
