15 / FAQWhat is easiest to mix up when using and understanding Arslan

How is Arslan different from chatting with a model on its website?

Beyond the model, Arslan provides local files, tools, task state, memory, permissions and desktop integration. The model judges and generates; the app turns tool requests into controlled execution and records the results. Its value depends on whether the whole process gets a specific task done.

Was it built by one person with AI?

Yes. The author builds and iterates on Arslan alone with AI-assisted development — vibe coding. The product uses open-source frameworks, third-party components and external models, whose sources and licences are recorded in the project documents.

Does everything stay on my Mac?

Data is primarily stored, and execution orchestrated, on your Mac. When you use a cloud model, search, a remote MCP server or similar, the relevant requests go to that service. Memory also has its own cloud-use permission and sensitivity rules; local-first does not mean always offline.

Can I switch models, or use a local one?

You can configure a supported provider or a compatible endpoint, including an OpenAI-compatible local server. An endpoint connecting only proves the transport works; tool calling, images, reasoning continuation and context length still depend on that model and its adapter path.

Early docs mention many expert personas — why is there only one Arslan now?

The product converged. 0.1.44 stopped creating and dispatching experts, 0.1.46 turned off the old automatic evolution loop, and 0.1.48 removed the front router. Old methods can be converted into Skills, historical data stays compatible, and constrained read-only workers are still used for independent research.

Are memory, the knowledge base and chat history the same thing?

No. Chat history records conversations, and the working context picks recent content plus a summary; personal memory keeps preferences, facts and rules with their sources and permissions; knowledge retrieval finds relevant passages in imported material. The three differ in how they are stored, recalled and deleted.

Does "learning" train the model, or let it give itself more permissions?

No. Learning today records reusable methods and recalls them in later tasks; it does not change foundation-model weights or execution permissions. The records show practices can be captured, recalled and followed; a general speed-up or cost saving still needs more controlled experiments.

Do all commands run in an offline sandbox?

No. The default Python compute sandbox denies the network; the ordinary terminal's workspace sandbox usually keeps network access and has its own fallback behaviour. Tool permissions, command policy, system permissions and sandboxes are different layers; the security chapter has the details.

What happens to a task when I close the chat window?

Connections and tasks are managed separately, and a background job can run while the app's service keeps running; closing the window is not the same as quitting the process. If the service exits or the Mac sleeps, the task cannot keep relying on local execution. After a restart, interruptions are checked from the records, and the task resumes explicitly along a supported path.

Does resuming automatically re-run every earlier action?

No. Resuming checks the steps already taken and their external effects, and unknown side effects are checked first. Task attempts, action states, checkpoints and version constraints help stop old results overwriting new state, but they cannot guarantee exactly-once execution for every external system.

Can Hands operate any Mac app?

Compatibility depends on the Accessibility structure the app exposes, system permissions and Arslan's action rules. Being able to read a control does not mean every business operation can be completed safely. Sensitive buttons and keys trigger finer-grained confirmation, and some apps or controls may still not be supported.

Can the iPhone get work done while the Mac is off?

On the Mac Bridge path the Mac still does the work; when it is unavailable, messages wait in iCloud. v0.1.53 shipped the Mac side of Bridge, which does not mean the iPhone app is on the App Store. The phone showing a message as received does not mean the task is done either.

If all tests pass, can any real task be done?

Each test only covers its own conditions: unit tests check local logic, protocol tests check boundary consistency, installer acceptance checks the artifact, and real-task comparisons check results for a given model and task. Models, web pages, system permissions and external apps can all change the outcome.

Why is the version still 0.1.x?

The project is still in pre-v1 continuous iteration. More than fifty version numbers reflect that history; judge maturity by specific capabilities, failure handling, test coverage and release status. The full version appendix in this document keeps those distinctions.
