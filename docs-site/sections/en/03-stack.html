Why the Python core stays

Python handles model adapters, document processing, the agent loop and task services, where an existing ecosystem and the current implementation can be reused directly; Tauri and Rust handle windows, process lifecycle and native integration. A public architecture decision records the choice to keep this core. Moving it to another language would change tools, data migration, packaging and test boundaries all at once — "more native" alone is not a measure of the gain.

The structure is layered logically but deployed mainly as one local service. Internal Python modules are not separate remote microservices, and nothing needs Redis, Celery or Kubernetes to run. Hands, Bridge, MCP servers and terminal subprocesses form process boundaries where they need separate permissions or a separate runtime.
