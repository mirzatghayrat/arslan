01 / OverviewConnecting plain language to real work

Arslan is an open-source, Mac-first, local-first personal AI assistant for getting work done. You describe what you want done; Arslan assembles the context, calls a model, uses tools, records what it did, and delivers an answer or a file you can check. Chat, memory, file handling, the terminal, the web, some native Mac apps and background work all sit behind one entry point.

The author builds and iterates on it alone, with AI assistance — what is often called vibe coding. This document goes from the product's goals down to the actual code boundaries: why it is designed this way, how it runs, and how it changed from the first prototype to v0.1.55.

Understand the task

From this turn's request, recent conversation, the personal memory it is allowed to use and relevant material, work out what information and tools the next step needs.

Act and observe

The model proposes a structured action, code validates its arguments and permissions, the tool returns a real result, and the model decides whether to continue, change approach or wrap up.

Deliver a result you can check

Files, tool returns, task state and sources are the evidence for the result. You can watch progress, handle approvals, stop a task, or carry on from what is already recorded.

What "local-first" actually means

Local-first describes where data is primarily stored and where work runs: the desktop interface, the local service, the database, the workspace and the Mac tools run mainly on your machine. You configure the model. With a cloud model, the conversation, excerpts of material and any memory you allowed for that use are sent to that model provider. A compatible local model endpoint can also be connected, but tool calling and vision still depend on the model and how the service implements them.

So Arslan's architecture has to answer two questions at once: which machine the work happens on, and what is sent to which model endpoint. Local persistence, permission for cloud use of memory and tool permissions do different jobs; one "local" switch cannot describe them.
