02 / Independent and open sourceOne person, with AI, turning an app into a system

Arslan is a project I built on my own with AI-assisted development — what is often called vibe coding. From the first prototype to every later version, I have driven it on my own.

"Independent" here means the author drives the project as a whole, with AI as a collaborator in the implementation. Arslan also stands on open-source frameworks, system APIs, external models and third-party components. How it was built, who is responsible for it and where its components come from are separate questions; what follows is about the design and implementation that actually shipped.

From generating code to maintaining a usable product

Code that runs is a small part of a product. A desktop app also has to settle how its service starts, how the window connects, how an old database is upgraded, how things are cleaned up when a process is killed, who holds system permissions, and whether the installer works on a machine with no development environment. An agent adds more uncertainty: models time out, tool arguments get truncated, pages are read incompletely, and a run may need the user's approval halfway through.

These problems pushed Arslan's iteration in four directions: explicit contracts for inputs and state, observable tool results to check what was actually done, permission boundaries around real side effects, and tests plus release acceptance to check that a change holds. AI assistance speeds up implementation and debugging, but the delivered product rests on these constraints together.

Willing to delete early assumptions

Early on, capabilities were organised around expert personas; later it converged on a single Arslan. Tools and methods could be reused, while the user's entry point and the main execution path were redesigned around real problems.

Keeping evidence of what did not improve

Adding a review layer, learned practices or parallelism does not automatically make tasks go better. The project recorded a failed review layer, research tasks that lagged behind, and learning that did not speed things up — each a concrete direction for the next round.

App and runtimeArslan organises the interface, model adapters, the single loop, task state, memory, tool permissions and desktop delivery into an installable personal app.
