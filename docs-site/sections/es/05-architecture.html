05 / Arquitectura del sistemaResponsabilidades de la interfaz, la ejecución y los permisos

Una explicación sencilla: React es el entorno de trabajo que ve el usuario; Tauri, el contenedor que conecta con macOS; Python, el motor que coordina el trabajo; el modelo aporta criterio; las herramientas producen acciones reales; y la base de datos y el disco conservan el proceso y los resultados. Estas funciones se integran en un mismo producto de escritorio, pero no pertenecen a un único proceso.

Figura 1 · Arquitectura actual. Lectura textual: entorno de trabajo ↔ servicio local → bucle unificado del agente ↔ modelo; bucle de ejecución → herramientas → sistema/archivos; el estado se guarda en SQLite y en disco. El iPhone se comunica con Mac Bridge mediante CloudKit; no se conecta directamente a una API pública del Mac.

Cómo se conectan los procesos al arrancar

  1. Tauri inicia el sidecar Python empaquetado y muestra una pantalla de arranque hasta que el servicio está listo.
  2. El sidecar intenta primero usar el puerto local 47317; si está ocupado, utiliza un puerto efímero y comunica por la salida estándar el handshake ARSLAN_PORT.
  3. Cuando recibe el puerto, el contenedor de escritorio hace que el WebView del sistema cargue la página React servida localmente. Priorizar un puerto fijo ayuda a mantener estables el origen de WebKit y el almacenamiento local de la interfaz; el catálogo de sesiones del servidor permite recuperar el historial aunque cambie el puerto.
  4. La interfaz gestiona recursos mediante HTTP y recibe por WebSocket el texto en streaming, los estados de herramientas, las aprobaciones y el progreso de las tareas. La conexión local también requiere token y comprobación de origen.
  5. El contenedor mantiene abierto el canal de entrada estándar como vínculo de ciclo de vida. Si la salida del proceso padre produce EOF, el sidecar puede limpiar y cerrarse. La salida también debe consumirse de forma continua para evitar bloqueos o procesos huérfanos tras perder la conexión.

Estos detalles mantienen coordinados los ciclos de vida de ventanas, servicio y base de datos. Una respuesta correcta del endpoint HTTP de salud no demuestra que WebSocket, adjuntos, recursos estáticos y helpers nativos estén disponibles; cada uno debe comprobarse durante la aceptación de la versión.

Arquitectura anterior y actual: reutilizar capacidades y retirar la coordinación de expertos

Histórica

Múltiples expertos / Meta-Agent

Usuario → Router previo → Seleccionar/crear Spawn → Ejecución por un experto → Síntesis. Los prompts de expertos podían someterse a evaluación con datos reservados y a Promote manual. El producto exigía comprender identidades, equipamiento, catálogo y evolución de expertos.

Ruta principal de 0.1.54

One Arslan / Bucle unificado

Usuario → Un mismo bucle de agente → Cargar skills y llamar herramientas según sea necesario → Resultado. Los hechos comunes se extraen después de responder. Los antiguos expertos pueden convertirse en skills y conservar su historial, pero su enrutamiento deja de ser la vía principal de ejecución.

Un «bucle unificado» no significa que todo sea secuencial ni que nunca se delegue. El código conserva workers de solo lectura con restricciones. No equivalen al antiguo sistema de expertos con personalidad, equipamiento, evolución y enrutamiento propios.
