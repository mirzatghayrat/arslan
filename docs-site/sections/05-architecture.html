05 / 系统架构界面、执行和权限，各自负责什么

一句通俗解释：React 是用户看到的工作台，Tauri 是连接 macOS 的外壳，Python 是协调工作的引擎，模型提供判断，工具产生实际动作，数据库和磁盘保存过程与结果。这些职责组合在同一个桌面产品里，但不属于同一个进程。

图 1 · 当前架构。纯文本读法：工作台 ↔ 本地服务 → 统一 Agent 循环 ↔ 模型；执行循环 → 工具 → 系统／文件；状态落 SQLite 和磁盘。iPhone 通过 CloudKit 与 Mac Bridge 通信，不是直接连接 Mac 的公网 API。

为什么选这种分层

边界获得什么需要付出什么
React ↔ 本地服务聊天、设置、图谱等界面与执行逻辑分离；模型流和工具事件可实时展示要维护协议、断线重连、流式状态和认证，不能以页面仍打开判断任务仍活着
Tauri ↔ Python sidecar保留 Python 的模型与文档生态，同时提供普通 Mac 安装体验多语言打包、动态依赖、端口发现、进程退出和签名都要管
模型 ↔ 工具执行器模型负责提出动作；确定性代码负责校验、授权、执行和记录必须处理畸形参数、未知工具、截断响应、重复失败和取消
Hands 独立 helperAccessibility 权限由独立进程持有，并有应用级和动作级规则代码签名、进程身份、系统权限和应用差异成为额外维护成本
Mac ↔ iPhoneMac 开机、联网且唤醒时，离开电脑后仍能发起请求、查看结果、处理支持的审批Mac 不可用时消息在 iCloud 等待；还需处理重试、乱序、恢复与终态一致性

一次启动怎样把这些进程接起来

  1. Tauri 启动冻结后的 Python sidecar，在服务就绪前显示启动界面。
  2. sidecar 优先绑定本地端口 47317，冲突时使用临时端口，再通过标准输出返回 ARSLAN_PORT 握手。
  3. 桌面壳收到端口后，让系统 WebView 加载本地服务提供的 React 页面。优先固定端口有助于保持 WebKit origin 与本地界面存储稳定；服务端会话目录支持端口变化后重新找到历史。
  4. 界面通过 HTTP 管理资源，通过 WebSocket 接收文本流、工具状态、审批与任务进度。本地连接仍需要 token 和来源检查。
  5. 壳保留标准输入管道作为生命周期联系；父进程退出造成 EOF 时，sidecar 可以清理退出。输出管道也需要持续消费，避免阻塞或失去连接后留下孤儿进程。

这些细节共同保证窗口、服务和数据库生命周期保持一致。只检查 HTTP health 返回成功，无法证明 WebSocket、附件、静态资源和原生 helper 都已可用；它们在发布验收中还需要分别检查。

旧架构与新架构：保留复用，退役专家调度

历史

多专家／Meta-Agent

用户 → 前置 Router → 选择／创建 Spawn → 专家执行 → 汇总；专家提示词可进入留出评测和人工 Promote。产品需要用户理解专家身份、装备、名册和演进。

0.1.53 主路径

One Arslan／统一循环

用户 → 同一个 Agent loop → 按需加载 Skill 和调用工具 → 输出结果；普通事实在回答后提取。旧专家可转成 Skill，保留历史记录，但不再把专家路由作为主执行路径。

“统一循环”不等于“一切串行”或“永远不委派”。代码仍有受约束的只读 worker 能力；它不等于早期那套有独立人格、装备、演进与路由的专家产品系统。
