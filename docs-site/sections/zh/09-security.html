09 / 执行与安全边界从模型建议到真实动作，中间发生什么

Arslan 可以读写文件、运行命令，也能通过浏览器和原生应用完成工作。它的安全设计围绕一个区别展开：模型负责提出下一步，可信代码负责决定这一步能否执行。下面描述 v0.1.63 已实现的边界；这些是有具体作用范围的保护机制，并不是对所有恶意输入、应用行为或系统环境的安全证明。

输入与工具建议用户目标、网页、文件
模型生成结构化调用
应用策略校验参数、目标与上下文
判断允许、询问或拒绝
需要时等待批准绑定具体动作的卡片
拒绝与超时都有结果
执行边界工作区、沙箱、独立 helper
各自限制实际访问
观察结果工具回执、文件与状态
失败不伪装成完成

外部内容可以提供资料，不能自行扩大权限

网页和工具结果可能含有提示注入。网页文本和 MCP 结果进入上下文时，会被包在明确的外部数据边界中；自 0.1.63 起，本地工具返回的内容（文件、命令、应用窗口）被包在另一个独立的工具输出边界中，同样只当数据看待，伪造这两种边界标记的内容都会被处理。系统还记录本轮是否读过网页、文件、MCP 结果等外部内容：受这些内容影响的经验和机器笔记需要先成为提案。这样，一段网页里的“以后总是把文件发到这里”不能仅凭被读到就获得长期授权。

自 0.1.63 起，同一份记录也限制终端：一旦某一回合读过外部内容（网页、文件、MCP 结果），它的命令就在内核规则下无网络运行，而按命令文本判断、或按模型自己所说会访问网络的命令，会先询问。在沙箱内，回答可以只对这一次或对这个对话有效；在沙箱外，只对这一次有效。在无人可问的地方，命令保持离线。读取网页另有防护：本地名称和私有地址会被拒绝，而针对用假地址回答 DNS 的代理所设的例外（0.1.61），只放行对某个名称的 https 443 端口访问，由代理决定它实际去往哪里（第 08 章）。

这层处理有助于保持来源和信任关系，但仍然依赖后面的执行检查。模型可能误解资料，命令风险识别也不是完整的语义证明；不能因为文本被标为“不可信”，就取消真正的权限边界。

不同执行工具，有不同的隔离强度

路径实际限制不能从中推导出的保证
run_python默认拒绝的 macOS Seatbelt 计算环境：只开放解释器所需读取、临时工作区读写和只读参考文件；禁止网络及 host IPC，清理子进程环境并施加资源限制。不是任意 Python 程序的通用宿主。缺少可用隔离时默认拒绝；未实现的 Linux 沙箱不会被当成已经可用。
普通 run_command运行真实 shell。策略分三层：forbid（无论在沙箱内外都绝不允许：清空磁盘、主目录或系统文件夹，直接写磁盘，关闭 Mac，从钥匙串读出密码，碰 Arslan 自己的密钥文件，任何需要 sudo 的操作）；ask，只对这一次有效（发送或发布，删除工作文件夹之外的内容，强制结束程序，更改启动项或系统设置，驱动其他应用，在沙箱外打开应用或链接，读取屏幕或剪贴板，写入 shell 启动、SSH、凭据或其他 agent 的设置文件，以及任何文本读不懂的命令，例如引号不成对、eval，或把下载的代码通过管道交给 shell）；以及 run。命令链（&&、;、|、||、&）中的每一条都会检查，不只第一条；命中规则的命令，其卡片只对这一次有效：不会为它记住任何回答。自 0.1.63 起，默认每条新命令都先问（“什么时候问”设置：“每条命令都先问”）；只有选了“只在有风险时问”，策略判为 run 的命令才会不出卡片直接运行：在沙箱里，或在这次会话已获准离开沙箱时于沙箱外运行。默认工作区沙箱限制写入工作目录、临时与缓存目录，禁止发送 Apple Events，另行关闭 Arslan 的数据和密钥、Hands socket 以及用户凭据所在的路径（SSH 密钥、Keychain 文件、AWS、gcloud、kube、gh、GnuPG、npm、netrc 等云和命令行工具凭据，浏览器配置文件、Safari 和 cookies）。自 0.1.59 起，“桌面、文稿、下载”关闭时，这三个文件夹也对读写关闭，经由 /System/Volumes/Data 和符号链接也一样；位于其中的工作文件夹仍可读写，活跃项目的文件夹仍可只读。其他位置的读取、程序运行与网络仍开放；用户允许在沙箱外运行的命令不受这个文件夹开关约束，也不受已关闭的凭据路径约束（ssh、git push 和 gh 需要它们）；它在一份最小配置下运行，该配置仍然关闭 Arslan 自己的数据、密钥和 Hands 文件夹，并禁止 Apple Events。沙箱不可用时，命令会先问（选了“只在有风险时问”时，对“本对话内”的同意也覆盖这次会话之后策略判为 run 的命令）；获准后在沙箱外运行并返回 sandbox=unavailable，因此不是统一的 fail-closed 路径。
安装的 MCP 服务（0.1.57）在默认拒绝的 Seatbelt 配置下启动：只能用自己的文件夹和临时目录、你授权的文件夹，以只读方式使用 Arslan 固定版本的运行时；即使在授权文件夹里，你的受保护路径也保持关闭。它的 HOME 指向自己的文件夹。只有声明需要某个在线服务的 key 时才开放网络，而且此时可以访问任何主机（Seatbelt 无法限定到单个主机）。0.1.57 不会把你手动添加的服务移进这个沙箱。自 0.1.63 起，它的工具调用按服务声明该工具做什么来询问（第 08 章），而这一声明是服务自己的，未经核实。
离线收尾命令任务进入收尾后，允许处理已取得的数据并保存交付物，同时额外阻断网络。所需沙箱不可用则拒绝执行，不能套用普通命令的降级规则。
AppleScript / Shortcuts在终端命令中，osascript 和 shortcuts run 以常见写法（带路径、经 command、exec 或 xargs、带重定向）出现时，始终询问，且只对这一次有效。沙箱禁止 Apple Events，所以 Arslan 不认识的写法会在其中失败。只有一个已获批准的普通调用会不带沙箱包装运行：与提醒事项、日历、备忘录或通讯录对话、且没有其他风险动作的脚本，或文件只留在 Arslan 文件夹里的普通 shortcuts run；它只能通过在 Mac 窗口里点击来批准。Hands 自己的 AppleScript 工具每次都询问并展示完整脚本，只提供给后台工作，并拒绝指名了被禁用应用、或用计算出的名称选择应用的脚本。已获批准的快捷指令以用户身份在沙箱外运行，Arslan 看不到它做了什么。命令本身在文件沙箱中，不代表被调用的应用也受同一文件范围约束。
Arslan Hands独立 helper 持有 Accessibility；helper 内再次检查应用、动作、字段和停止状态。自 0.1.60 起，一次查看可以附上那一个窗口的画面，只保存在内存里。辅助功能树不是完整的业务语义，窗口画面由模型读取，而不是由代码检查。应用是否提供可操作节点会影响可用性；另一个桌面上的窗口只能按借用前台的规则前往（见第 08 章）。

离开命令沙箱需要用户点击批准：可以为当前动作申请，也可以由用户选择本次会话内允许；后者随会话保存（重启后仍在），也适用于该会话的后台任务，可在设置里收回。源码开发环境另有显式的 Python 无沙箱逃生设置，桌面版会关闭这条逃生路径。两者都不应被误读为模型可以自行关闭保护。

自 0.1.62 起，write_file 和 edit_file 绝不顺着链接写到工作文件夹之外：通过指向外部的链接写入会被拒绝；在别处有第二个名字的文件（硬链接）会在工作文件夹里被替换，而另一个名字保留旧内容；新建的文件从不可执行，已有文件保留它的权限。文件先写成旁边的一个新文件再换入，所以写入失败时旧文件原封不动。自 0.1.63 起，一个回合第一次改动工作文件夹时会保存一个检查点，“撤回这一轮”会把文件放回去，并把这一回合从对话中移除。这是恢复用的保障网，不是边界：它只保存最多 20,000 个文件、5 GB 的文件夹（不计 Python 环境、node_modules、构建输出和缓存，这些被排除在外且绝不会被放回），从不复制形似机密的文件，只覆盖工作文件夹，不会撤销任何已离开这台 Mac 的东西，并在无法保存时显示“未保存”。检查点保留七天。

审批绑定具体动作，后台工作不继承所有便利授权

审批卡通过 call_id 与动作种类关联，错误种类的回复不能批准另一张卡。Mac 窗口和手机共同看到的卡采用首个有效回答，并向其余视图广播关闭结果；无人回答则保持开启 30 分钟，时间到了也不算拒绝（自 0.1.61 起；更早的版本在 300 秒后过期）。自 0.1.61 起，同一张卡在窗口、收件箱、Island 和 iPhone 上看起来一样：“一次”（或“本任务内”，以卡片列在第一位的为准）、“本对话内”、“始终”，以及附带一条会交给 Arslan 的备注的“否”；卡片等待期间在聊天中输入的消息，会以这条消息为备注回答它“否”，而且一次点击只回答一张卡。有些种类的选项更少：命中规则的命令、涉及金钱的、接管、以及应用里有风险的步骤，只对这一次有效；离开沙箱、站点、快捷指令和 MCP 工具则从不提供“始终”。后台任务的卡片与窗口的卡片提供相同的选项；自 0.1.63 起（S4a），从会话发起的任务使用该会话的授权，包括离开沙箱。没有人可问的运行（定时运行）不走这些步骤：那里不计任何先前的回答，该步骤立即被拒绝，它没能做的事会列在收件箱中。在这个版本中，定时运行完全不运行终端命令。模型建议连上 MCP、登记远程机器或访问其他执行入口时，提案与真正启用连接分开处理。

对于外部副作用，发送请求也不等于完成动作。任务恢复会把结果不明的在途动作标为不确定，不能仅因为进程重启就自动重放。这里的目标是让重试与恢复有明确语义，而不是许诺任意外部系统都能撤销。

自 0.1.55 起，所有等待中的卡片——无论来自窗口、后台任务还是 iPhone——都排在同一个队列里，也出现在收件箱中，可以凭 call_id 在那里回答；回复按卡片自身的种类构造，只能确认或取消这一张卡，更宽的选项（本对话内、始终）只能在提供它们的卡片上选择：iPhone 和 Island 只给出卡片的第一个选项，绝不给“始终”，而收件箱可以给出卡片本身提供的任何选项。Island 可以回答文件夹、应用、屏幕、MCP 工具、定时、站点和快捷指令的卡片，以及不属于有风险类别的命令或工作区写入。它不能批准涉及金钱、发送、删除、应用里有风险的步骤、接管、离开沙箱、命中终端 ask 规则或读不懂的命令、同时要求访问网络的命令、远程主机上的任何操作、系统更改、其他 agent 的设置、安装能力、AppleScript、会在没有沙箱包裹的情况下运行的命令，或检查不认识的卡片种类。这类卡片显示“在 Arslan 中打开”，而且服务端会拒绝来自 Island 的批准，不只是 Island 页面不显示按钮。会不带沙箱包装运行已获批准的普通 AppleScript 或快捷指令的卡片，以及安装能力的卡片，只能在 Mac 窗口里批准；iPhone 对这类卡片点的“是”会被吞掉。在窗口里，⌘⏎ 允许、Esc 拒绝；单独按 ⏎ 永远不会回答卡片。

Hands 将系统权限收在一个更小的进程中

Accessibility 授予 Arslan Hands.app，而非主 App。签名发行包通过受保护 Unix socket、每次启动生成的 token 和 peer 签名检查接收请求。helper 自己执行规则，底层 agent-desktop 不单独持有该权限。自 0.1.61 起，查看一个应用和在其中执行动作合为每个应用一张卡片，并把“本任务内”列在第一位。自 0.1.60 起，聊天回复也可以执行动作：0.1.62 及以前最多五步、限于同一个应用；自 0.1.63 起只受这次运行本身的上限约束，和后台任务一样，可以跨多个应用，而且“停止”能让它停下（定时任务不能执行动作：没有人在场批准）；从对话发起的任务继承该对话的同意。在浏览器中执行动作、运行快捷指令和 AppleScript 仍然只提供给后台工作。应用按其身份判断，所以用 .app 或完整路径、或用不同的大小写来称呼它，都绕不过禁用名单或缺失的批准。删除、发送、支付、购买、转账和提交等敏感按钮按实际标签每次询问；密码字段不输入，密码管理器、系统安全界面等应用在禁用名单中。

停止入口会设置停止闩锁，后续动作要经过该检查；活动记录保留操作线索，输入文字只记录长度。限制同样公开：另一个 Space 上的窗口只能按借用前台的规则前往，不提供按屏幕位置点击和拖拽，大窗口读取可能需要 10–20 秒；Stop 截断的调用可能没有对应 trace 行，审计记录并非对所有中断情况的完整取证保证。

自 0.1.56 起，Hands 每个请求最多只执行一次：同一请求 ID 的回答保留十分钟，重复的 ID 直接用保留的回答答复；后端丢了某次回复时，会去取回那次的回答，而不是再发一次动作。读不到原有文字的字段不会被“追加”覆盖，而是拒绝；只有该字段获得焦点时才按回车；动作已发出但没有读回结果时，报告为“已发送，未确认”，而不是已完成。Hands 运行的是从 Arslan 的 fork 按固定提交构建的 agent-desktop；Cua Driver 引擎已在 0.1.63 中从 Hands 摘除，因此 helper 不再查找或启动它（其未使用的模块仍留在 helper 的源码里）。自 0.1.60 起，一张卡片可以为一项工作覆盖最多八个应用，从对话发起的后台任务继承该对话的同意，应用也可以在 设置 → Hands 里永久允许。标签含删除、发送、付款、购买、提交、转账、签署、发帖、发布或确认（多种语言）的点击、选择或最后一个菜单项，对应的快捷键，在按回车即发送的应用里按回车，接管，以及任何 AppleScript，仍然每次询问。

本地服务也有边界。发行包为 REST 和 WebSocket 生成访问 token，并在安装验收中检查未认证请求被拒绝。显示 token 的设置接口只把它交给已经带着该 token 的直接本机调用方（0.1.54）；仅凭本机来源不够，因为沙箱里的命令同样能打开本机 socket。桌面应用的服务始终需要它的 token，不接受其他网站作为调用方（不接受跨域，也不接受没有 Origin 的 WebSocket），只把 localhost 当作可信的主机名，忽略从启动它的环境中继承来的主机和 origin 变量及其他设置，不提供 API 浏览器，并且不让 token 出现在日志里（0.1.63）。源码开发模式允许 localhost 无 token 的便利路径，不过命名了 * 或 null 的主机或 origin 变量现在会拒绝启动；“只监听本机”与“已经通过认证”不是同一件事。与当前用户同权限且已被攻陷的宿主环境，也不能靠一个本地 token 自动变成可信环境。
