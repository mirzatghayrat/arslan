04 / 项目如何走到今天从生成专家，到一个能持续工作的 Arslan

Arslan 由作者以 AI 辅助的 vibe coding 方式持续独立开发。它的演进过程既有新能力，也有收回的设计：有些功能需要补齐运行条件，有些复杂度则需要删除。理解这些变化，比把所有历史功能并列在一张清单上，更能说明今天的架构。

这是一条有证据边界的时间线。早期日期取自保留的 Git 提交，正式版本日期取自公开 Release，并统一换算为北京时间。最早提交、开源准备、仓库变为公开和首次发布不是同一个时间点；现有记录不能确定仓库转为 Public 的准确日期；当前的公开仓库建立于 2026 年 7 月 26 日。

六月：先建立“通过对话生成 Agent”的闭环

2026 年 6 月 7 日最早保留的提交从数据模型开始。当时的方向是 Meta-Agent：让不熟悉技术的用户通过对话创建领域专家，再由这些专家完成任务。随后出现模型适配器、工具注册表、需求对话状态机、模板、Spawn Manager 和 CLI。6 月 8 日，FastAPI、异步数据库、认证、WebSocket 与 React 界面接起来，原型有了可交互、可保存和可恢复连接的入口。

随着工具开始真正运行，系统需要知道“执行过什么”，也需要给回答提供资料。6 月 23 日加入 Runs、Steps、Evaluations，以及文档分块和 SQLite FTS5；6 月 27 日接入 MCP 的 stdio 与 HTTP 传输。这些变化把项目从生成一段专家提示词，推进到管理一次完整执行：调用模型、运行工具、保存过程、检索资料，再把结果交回用户。

最早数据模型；Runs 数据模型；FTS5 知识索引；MCP HTTP 传输。

七月：把记忆和交付变成工程问题

7 月 5 日，Second Brain 加入 embedding 与按作用域过滤的混合检索，结合全文搜索、向量相似度和 RRF 排序融合。随后补上事实来源、有效状态、替代与撤销、整理提案和使用记录。记忆由此不只是聊天摘要：资料是否相关、是否仍有效、属于哪个范围，都要影响它能否进入模型上下文。

把更多历史放进上下文会带来新的取舍：检索范围过大可能混入无关资料，旧事实可能覆盖新事实，外部文本也可能影响长期行为。因此七月的实现开始给事实补来源和时序，区分自动追加、需要审阅的修改与敏感内容，并让整理结果进入提案收件箱。后续记忆功能沿着这些约束继续演进，用户能看见、纠正和撤回，成为比“记住更多”更明确的工程目标。

这一阶段也开始处理长期维护。7 月 14 日，数据库迁移切换到自有版本化 runner，移除 Alembic 依赖。7 月 10 日改用 Apache-2.0 许可证，并加入 NOTICE 与 SECURITY.md；7 月 25 日出现明确的开源准备提交；到 7 月 27 日，v0.1.0 作为首个桌面安装版发布，Tauri 外壳与冻结的 Python 后端一起交付，签名、公证、更新和首次安装检查进入发布链路。

真实安装环境随即暴露了开发测试看不到的缺口：v0.1.0–0.1.6 的安装包缺少 WebSocket 运行依赖，健康接口正常，聊天却无法建立连接。0.1.7 修复依赖层与 PyInstaller 隐式导入，并把真实握手加入安装验收。这个故障解释了为什么“后端启动了”必须进一步验证为“用户的整条路径可用”。

混合检索；版本化迁移；开源准备；安装包 WebSocket 故障复盘。

八月：能力可接入，还要让用户看懂

0.1.20 把凭据状态区分为未配置、可解密和不可解密，稳定盐与密钥迁移；搜索增加来源与错误说明，模型开始按任务分工。随后，MCP OAuth、OpenRouter 登录、首次引导、扩展清单、本地工作区读写、定时任务与 SSH 逐步加入。扩展能力变多后，系统也必须准确说明：当前连接能否调用工具、装备是否生效、哪次动作需要授权。

本地执行能力也开始分层。工作区读取与写入分开，写入需要相应授权；定时任务有自己的调度许可；SSH 可以记住机器，但每次远程执行仍需要确认。工具清单由此同时描述能力和使用条件。对用户而言，“已经连接”与“这次可以执行”是不同状态，界面与模型上下文都需要表达这个区别。

0.1.23 的 turn journal 让切换对话后正在生成的回答仍能接回来；安装版找到 npx 的修复则再次说明，桌面应用拿到的环境与终端不同。八月的主线不只是接更多服务，而是把连接、状态和授权变成用户能理解的操作。

九月：从一次回答，走向可追溯的工作

0.1.38 集中补可靠性：默认拒绝的 Python 执行沙箱、独立计算运行时、持久化 Runs、产物、检查点和共享执行预算。0.1.40 的预览与稳定化继续推进项目记忆、文档来源、任务延续和迁移前备份，同时保留跨语言、多文档比较的已知失败。来源可点击，只说明资料能被找到，并不能证明模型的结论正确。

更早一些，8 月 31 日到 9 月 3 日，语音从朗读（0.1.32）、按住说话（0.1.36）推进到半双工对话（0.1.37），同时修复麦克风权限与语言选择。与此同时，0.1.40 的研究验收没有把跨语言比较失败改写成成功；0.1.41 的来源审阅在校准不理想后保持默认关闭。这些记录限定了“系统做过检查”的含义，也让下一步改进可以围绕真实失败展开。

0.1.41 让关闭窗口变为留在菜单栏继续工作；0.1.42 把长任务放到后台，用户可以继续聊天；0.1.43 再区分预算软限与硬停：到达软限先利用已有材料收尾，避免研究做到一半却没有交付物。任务逐渐拥有独立于界面的生命周期，但这不意味着任意外部动作都能在崩溃后安全自动重放。

九月末到十月：收敛为一条执行循环

早期设计把专家作为长期存在的角色，用户和系统都需要处理选择、邀请与路由。0.1.44 停止创建和调度专家，旧专家的方法可以转为 Skill；0.1.46 停止已无消费路径的专家后台演化；0.1.48 移除前置 router，每条消息直接进入 Agent 循环。发布说明指出，某些“我不能做”的固定回答来自路由判断，而不是实际能力。这次收敛把工具选择放回拥有真实工具和状态的执行过程。

收敛后，改进集中到共同的执行层：0.1.49 完善原生工具协议、截断与失败恢复；0.1.50 增加当前工作状态、计划与替代路线；0.1.51 增加命令沙箱和 Island；0.1.52 让用户记忆与 learned practices 进入后续工作。这里的“学习”是保存和使用可管理的经验，不是更新基础模型权重。

0.1.53 进一步通过独立 Hands helper 读取辅助功能树、操作 Mac 应用，并纳入 Mac 侧 iPhone Bridge。0.1.54 为 iPhone App 补齐这一 Mac 侧（Touch ID 审批、一台手机一个条目、移除手机后清理），并补上终端闸门的四处缺口，每一处都只会多问、不会少问。0.1.55 让所有需要你回答的卡片统一样式、排进同一个队列：可以在收件箱里回答，不涉及风险的步骤也可以直接在 Island 里回答。0.1.56 把项目分成两层：一块看板放所有项目，每个项目有自己的关卡和检查点，Arslan 只凭能说出来源的证据打勾。0.1.57 让能力自己长：某一步需要 Arslan 还不会的事时，它会去找合适的服务或 Skill，问你，固定版本并在沙箱里安装，测试通过后重试那一步。旧的专家编排已经属于历史，辅助功能操作也不能外推为所有应用都可靠可控。当前版本仍以可见的状态、明确的权限和可检查的结果，约束模型能够实际完成的工作。

可靠性基础；稳定研究助手的范围；后台工作；统一 Agent 循环；Hands 与 Bridge。
