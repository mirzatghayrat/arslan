08 / 工具、Skill 与扩展让能力可复用，也让执行有边界

Arslan 把“能够做什么”和“知道怎样做”分开组织。工具负责实际动作，Skill 保存方法和参考，MCP 连接外部能力，插件清单把这些资源组合起来。模型拿到的是本轮可用的能力集合；某个工具存在于源码注册表中，并不代表它默认启用或已经获得执行许可。

四个概念怎样配合

组成提供什么不能替代什么
Tool有名称、参数约定与执行器的动作，例如搜索、读文件或运行命令工具描述不能替代参数校验、权限判定和实际返回值
SkillSKILL.md 中的工作方法，以及可选脚本和参考材料它本身不获得系统权限，也不是单独训练的模型
MCP通过 stdio 或 HTTP 发现、调用外部工具的协议统一接口不保证服务可信；连接、暴露与授权仍由应用控制
Plugin manifestarslan.plugin.json 声明 MCP 启动方式、secret 槽位及关联 Skills安装和解析清单不等于立即运行其中的任意服务器

从声明到执行，中间有哪些检查

发现能力内建注册表、已配置 MCP、Skill 索引
筛选与提供根据上下文、配置与权限提供本轮 schema
解析请求校验工具名、JSON 参数和完整性
执行与回流实际授权后调用执行器，记录结果和失败

内建工具由注册执行器承接，带 mcp_ 前缀的调用进入 MCP 代理。工具结果回到统一循环，模型可以据此补充参数、选择替代方法或结束任务。即使模型已经读过一份 Skill，文件、命令和应用操作仍要通过各自权限边界。

自 0.1.63 起，一次请求不再携带所有工具。它携带一组常驻的日常工具（网页搜索与页面读取、文件读取／写入／编辑、终端、计划、后台工作、记忆、read_skill、能力清单，以及 Hands 的桌面工具），外加两个查找器：find_tools 对这一回合可以调用、但没有展示给模型的工具排序，use_tool 则按真实名称调用其中一个，因此参数按该工具自己的参数校验，所受的审批、追踪和回执与直接调用相同。MCP 工具、attach_file 和浏览器工具都通过这种方式使用。按需使用过的工具，从下一回合起加入该对话的列表（每个对话最多 12 个，保存在内存里，所以重启后模型要重新查找）。find_tools 返回的来自 MCP 服务的文字，会被包装成外部数据，绝不当作指令。

当模型连续请求多个读取时，最多四个同时运行：网页搜索和页面读取、read_skill、文件读取和列目录等，以及其服务标记为只读的 MCP 工具（一组中每个服务一个）。每个调用仍按这条回复的顺序通过所有闸门，每个结果仍与发出请求的那次调用配对；任何不是读取的调用则在原位置单独运行。

Skill 采用按需读取：索引告诉模型有什么方法，read_skill 再从已注册的 SkillPack 或允许的参考路径取出正文。这样可以让方法库增长，同时控制每轮上下文体积。Arslan 自带两个 Skill：一份设计过的 HTML 报告，和 Skill 创建器。自 0.1.63 起，专家时代的种子、预设的 MCP 连接器清单以及模型的连接器建议工具都已移除（寻找新的 MCP 服务改由下文的 find_capability 完成），而你以已退役名称导入的 Skill 也不再被删除。

自 0.1.55 起，“能力”页把 Arslan 能做的事列成开关：每一项是开、关、差一步，或在此处不可用，并写明原因。关闭就意味着根本不提供给模型，read_skill 也会拒绝读取已关闭的 Skill。各行状态读自决定每轮可用工具的同一组闸门，因此不会出现显示“开”而工具其实缺失的情况。新增的 whats_new 工具用随应用发布的版本说明回答“你是哪个版本、改了什么”，而不是凭模型记忆。

扩展服务是新的信任边界

本地 stdio MCP 通常意味着启动一个独立进程，HTTP MCP 则可能连接远端服务。Arslan 需要分别管理连接、主助手是否可用、工具是否暴露，以及凭证怎样保存和展示。插件清单中声明的 HTTP MCP 服务 URL 必须使用 HTTPS；secret 槽位声明参数形状，不在清单中内嵌真实凭证。已配置环境值会加密保存，读取显示时掩码处理。

自 0.1.61 起，你开启的每个 MCP 服务都会在 Arslan 打开时于后台启动，一次最多四个，聊天从不等待其中任何一个。每个服务只有一个状态，“能力”页和模型都读取它，模型只会看到此刻已就绪的服务；对其他服务的调用，会得到它的状态和原因作为回答，其中的 key 和 token 已被掩码。首次启动有 120 秒；失败的服务在 30 秒后重试，之后间隔变长（最长每 10 分钟一次）。

自 0.1.62 起，Arslan 在发送之前，会把 MCP 工具的参数描述重塑为 Anthropic、OpenAI-compatible 提供商和 Gemini 都接受的形式；内建工具按原样发送。如果某个提供商仍然拒绝其中一个，该工具在这条回复剩余的部分被排除在外，回复继续进行（如果拒绝没有指明工具，或第二个工具被拒绝，则这条回复排除所有 MCP 工具）。

自 0.1.63 起，对 MCP 调用的询问方式取决于服务声明该工具做什么：服务标记为只读的工具无需卡片即可运行；标记为破坏性的工具每次都要询问，且只对这一次有效；其他工具会询问，可以只对这一次或对这个对话生效，绝不提供“始终”。参数太长、卡片无法完整显示的调用会被拒绝，而不是被截断。这些标记是服务自己的声明，Arslan 不核实。在无人可问的地方（定时运行），只运行只读工具。

这些约束降低了意外暴露和误执行的机会，但实际 MCP 服务仍可能访问它获得的资源。工具来源、所需权限、发送到远端的数据和操作副作用，都属于扩展能力需要解释的部分。

能力自己长：找、问、装、扫、测

自 0.1.57 起，某一步需要 Arslan 还做不到的事时，find_capability 会同时搜索官方 MCP Registry、GitHub 和经过审核的 Skill 库。propose_capability 只能提名本次对话里已经展示过的候选，卡片由服务端根据那次搜索结果生成，而不是照搬模型的话：要添加什么、来自哪里、许可证（从项目自己的许可证文件读取）、怎样运行、可以使用哪些文件夹、需要什么 key。只有发起询问的那个 Arslan 窗口能批准；后台任务或无人可问的一轮，只把找到的结果记到“能力”页的“Arslan 找到的”里。

批准后，它以固定版本、默认关闭的状态安装：带哈希的锁文件、发布方给出的校验和或某个提交，运行在 Arslan 自己固定版本的 uv 或 Node 上；安装过程中不执行任何包代码（Python 只装预编译 wheel，npm 不跑安装脚本）。扫描会查找已知的危险写法——Skill 里藏着的指令、下载并运行更多代码的代码、写入 macOS 启动程序位置的操作——发现高危项就会把它移除；扫描无法证明任何东西安全，所以服务之后在自己的沙箱里运行（见第 09 章）。它必须能启动并列出至少一个工具才会被启用，工具循环随后重新读取工具列表，失败的那一步可以在同一次回复里重试。从 GitHub 导入的 Skill 固定到某个提交，每个文件都有校验和，其文字按外部内容读取，不能授予权限。

文件以文件的形式返回：工作台阅读器

自 0.1.58 起，一轮中写出的文件会在回复下方显示为卡片，回复里的路径可以在 Arslan 或文件浏览器中打开。工作台里的阅读器只读取 Arslan 自己的读取工具能读的位置：工作区，默认读取开启时的桌面、文稿和下载，活跃项目的文件夹，以及 Arslan 自己的产出。符号链接先解析；隐藏文件和形似凭据的文件名从不列出也不读取；文件内容以附件形式加 nosniff 发送；HTML 显示在 sandbox 为空的 iframe 里，其中的脚本无法运行。

自 0.1.63 起，当你要一个文件（截图、图表、导出文件或文档）时，attach_file 会把它附在回答上：窗口中是一张文件卡片，配对的 iPhone 上则是文件本身。它不需要自己的卡片，因为它只读取阅读器可以读的位置，适用同样的规则：不含隐藏或形似凭据的文件名，没有指向可读文件夹之外的链接。它也绝不会取 Arslan 自己的数据、钥匙串或 SSH 密钥下的任何内容，不取超过 20 MB 的文件，也不取超过一次运行所能容纳的文件数。

Hands v2：单个窗口的画面、批量、借用前台、接管

Hands 仍然以辅助功能树读取窗口。自 0.1.60 起，每次查看还可以附上那一个窗口的 JPEG 画面——从不截整个屏幕——只保存在内存里，只发送给模型；不会写入磁盘、运行记录或界面。模型不能接收图片时，改由 macOS Vision 在本地读出文字。可以在 设置 → Hands 里关闭，或对你列出的应用只读文字。同一个应用里的几个步骤作为一批执行，最多八步；菜单项即使在应用不在前台时也能直接选择；应用在后台打开。0.1.62 及以前，聊天回复里最多执行五个动作，且都在同一个应用里；自 0.1.63 起，聊天回复没有 Hands 自己的上限，和后台任务一样只受这次运行的上限约束。定时任务在 Mac 上完全不能执行动作：没有人在场批准。

有些操作只有应用在前台才能完成，比如弹出菜单。这时 Hands 会等你打字停顿一秒，借用前台约一秒，期间所有显示器的边缘亮起蓝光，你这时按下的键先被保留，等你的应用回到前台后再补上。如果应用的窗口在另一个桌面上，Hands 会按同样的规则去那里，在工作结束、15 秒没有动作或你第一次输入时回来。较长的工作可以由后台任务请求接管屏幕，最多 30 分钟；任何键盘或鼠标输入都会让它暂停，直到你让它继续。“我离开时”默认关闭；打开后，三分钟没有输入，接管可以不经卡片开始。借用前台可以关闭，关闭后 Hands 会拒绝而不是借用。

搜索与读取网页

自 0.1.63 起，web_search 首先使用这一回合所跑的模型自己的搜索：Anthropic 自己 API 上的 Claude 对话用 Anthropic 自己的网页搜索，DeepSeek 模型用 DeepSeek 的搜索。使用本地模型的对话绝不会把查询发给提供商自己的搜索。在设置中选择的 Tavily 或自托管 SearXNG，要么是唯一的搜索，要么是模型自己的搜索之后的备用；没有明确选择时，尽力而为的 DuckDuckGo 抓取排在最后。当某个搜索服务拒绝 Arslan 时，结果会说明搜索被拦截、什么也没有搜到，绝不会说“没有结果”。

页面读取和浏览器保留对外访问的防护：本地名称、真实的私有地址以及含控制字符的主机会被拒绝。自 0.1.61 起，在代理或 VPN 用假地址（198.18.0.0/15）回答 DNS 的 Mac 上，通过 https 在 443 端口请求、且所有地址都落在该段内的名称会被放行，而对这类名称使用普通 http 或其他端口则被拒绝。对这样的名称，由代理决定请求实际去往哪里；仍然有效的是 TLS，它按真实名称校验。

并行研究为何仍然存在

统一 Agent 循环保留了受限的临时只读 workers。v0.1.63 中，一批最多 4 项，最多同时运行 2 个；工具限定为搜索与网页提取，不写入文件和个人记忆，也不能递归创建更多 workers。主助手负责检查并综合它们的结果。

这类委派适合拆开互相独立的资料查询。它与早期永久专家分身的生命周期不同：没有要求用户先挑选或管理一个专家团队，也没有把每条消息强制路由给另一位“专家”。是否使用并行，仍应取决于任务是否能有效拆分以及额外调用成本。

后台、定时与 heartbeat

后台 job 将耗时执行与当前聊天分开，复用同一套模型、工具和验收逻辑。定时任务把“何时开始”持久化；heartbeat 是定期检查清单的一种使用方式，默认关闭，负责检查与提出建议。定时触发不会把建议变成已批准的写入或命令。自 0.1.63 起，每次定时运行都是一个没有人可问的普通 Arslan 回合：在这个版本中，它完全不运行终端命令，无论此前允许过什么；只在 Arslan 自己的文件夹里写入，不能在 Mac 上执行动作，只运行其服务标记为只读的 MCP 工具；需要更多权限的步骤会被拒绝，并列在收件箱中。

聊天回复和后台任务都会在每个任务的美元上限处停止（默认开启，为 $2；达到其大约三分之二时开始收尾；只有已知价格的模型才计入），可在设置中更改。聊天回复不再因为工作耗时长而被推到后台：后台工作是在你或模型选择时，把同样的工作换到别处去做。

当前调度由本地服务实现，包含重叠跳过、失败暂停和重启清理等处理。错过的周期不会逐一补跑；同一个任务上一轮未完成时，不叠加启动下一轮。这些行为适合个人桌面应用，也意味着它的运行条件与持续在线的服务器不同。
