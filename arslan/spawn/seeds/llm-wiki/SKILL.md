## Trigger

当用户要「把这些材料整理成知识库 / wiki / Zettelkasten / 互链笔记」或要在既有笔记体系上增改查时激活。产出物是一组 markdown 笔记的**文本内容**(在回复里逐篇给出,标明文件名),用户存入 Obsidian/Logseq 等工具即可成库;这是纯文本工件方法,不涉及运行任何软件。

## 决策规则

- **一概念一笔记**:每篇笔记只承载一个概念/实体/主张;一篇笔记里讲了两件事就拆成两篇再互链。判据:标题能否用一个名词短语无歧义地概括全文——不能就说明该拆。
- **标题即 ID,起了就别改**:笔记标题是全库引用它的主键,用稳定、无歧义的名词短语(「Transformer 注意力机制」而非「关于那个注意力的笔记」);后续宁可新建别名小节,不轻易改标题——改标题等于打断所有入链。
- **首次提及即 [[链接]]**:一篇笔记里第一次出现另一个概念,就地写成 `[[概念标题]]`;同一篇内的后续重复提及不再链。链接密度是知识库的价值所在,漏链的概念等于不存在。
- **悬空链接立 stub**:写作中链到了尚不存在的笔记,当轮就补一篇 stub——只含标题、一句话定义、`#stub` 标记;绝不留死链。stub 是待办清单,不是垃圾。
- **必须有 index/MOC 笔记**:每个库(或主题域)有一篇 Map of Content 入口笔记,按主题分组列出关键笔记链接 + 一行说明;新增笔记时同步更新 MOC。没有入口的笔记库是仓库不是知识库。
- **合并优先于新建**:添加新内容前先检查已有笔记——同一概念换了说法(缩写/中英文/同义词)必须归并进已有笔记而非另开一篇;发现两篇笔记实为一个概念时,合并内容、保留一个标题、在被并者位置留一行"已并入 [[存留标题]]"。重复是知识库的头号腐烂源。
- **每条断言可溯源**:笔记中的事实性断言要跟来源——用户提供的材料标注出处(文档名/章节),来自 web_search 的标注 URL;无来源的推断明确标 `(推断)`。别人(包括未来的用户自己)要能验证每一句话是从哪来的。
- **笔记体自律**:正文用短段落 + 列表,先一句话定义、再展开、末尾放「相关笔记」链接列表;单篇 ≤ 300 词左右,超了考虑拆分;不写"如上所述"这类依赖阅读顺序的措辞——每篇笔记都应可独立阅读。
- **交付格式**:每篇笔记以 `### 文件名.md` 开头、下接完整 markdown 内容,逐篇给出;批量交付时最后附变更清单(新建/修改/合并了哪些篇)。
