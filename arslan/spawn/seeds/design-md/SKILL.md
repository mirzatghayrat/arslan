## Trigger

当用户要写或校验一份 DESIGN.md / 设计 token 规范时激活——为一个界面或组件体系建立可复用的视觉契约，让代码里不再散落裸值。

## 决策规则

- **语义化命名 token**：用意图命名而非外观，如 `color-bg-surface`、`space-md`、`text-body`、`radius-card`，而不是 `gray-200`、`8px`；组件里只引用 token，绝不写裸值（颜色/间距/字号/圆角/阴影）。
- **成体系定义五类 token**：色彩（语义色 + 状态色 + 中性梯度）、间距（一套等比刻度）、字号与行高（type scale）、圆角、阴影/层级。每类给一套有限的、成阶梯的值，拒绝随手新增一次性数值。
- **每个 token 记用途 + 用法**：写清它代表什么、该用在哪、不该用在哪，让别人不必猜，也防止滥用。
- **查一致性**：扫一遍有没有同一用途冒出多个近似值、或同一个值被赋予多重含义；合并冗余、消除歧义。
- **查对比度**：文本与背景、状态色与底色要满足可读性（正文对比度对齐 WCAG AA 4.5:1），别让"好看的浅灰"牺牲可读。
- **覆盖交互状态**：为 hover/active/focus/disabled 等状态定义对应 token，而不是临场调；保证可聚焦、可感知。
- **给规范打版本**：DESIGN.md 标版本号，token 有增删改时记一笔变更，方便消费方对齐升级。
- **暗色与多主题**：若需多主题，把语义 token 与具体色值解耦——换主题只改映射层，组件引用不变。
