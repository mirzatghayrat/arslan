## Trigger

当用户要「找论文 / arXiv 上的相关工作 / 某方向的最新研究 / 查证某篇论文是否存在」时激活。这不是一个独立工具,而是叠在通用 web_search / web_extract 之上的方法纪律——查询怎么构造、结果怎么分诊、引用怎么保持诚实。

## 决策规则

- **查询构造分层收窄**:第一轮用 `site:arxiv.org` + 核心术语;命中太散就加精确短语引号(如 `"chain of thought"`)、作者姓氏 + 年份、或 arXiv 分类码(cs.CL、cs.LG、stat.ML 等)逐步收窄;一次只加一个约束,能看出是哪个约束起了作用。
- **术语要用领域行话**:检索词用论文标题/摘要会用的表述而非用户口语(用户说"让模型自己检查答案"→ 检索 "self-verification" / "self-consistency");第一轮结果里出现的规范术语,回填进第二轮查询。
- **按摘要分诊,不按标题**:标题党在学术界同样存在;对候选论文用 web_extract 抓 arXiv abstract 页(`arxiv.org/abs/<id>`),读摘要判断相关性再决定深入;摘要页抓不到就基于搜索摘录判断并注明信息有限。
- **只引真实见到的论文**:引用的每一篇论文——标题、作者、arXiv ID(如 2303.08774)——都必须出现在本次搜索/抓取结果里;**绝不凭记忆补全 ID、作者列表或年份**,记忆里的"著名论文"也要搜到确认后才引。编造一个 arXiv ID 比说"没找到"恶劣一百倍。
- **区分证据等级并明示**:报告里分清三档——「已读摘要」(抓取过 abs 页)、「仅见搜索摘录」(只看到搜索结果片段)、「被别的来源提及」(转引,未直接见到);每篇论文标注其等级,转引的明说"未直接核实"。
- **PDF 抓取失败就明说**:web_extract 对 arXiv PDF 经常拿不到正文;失败时直接说"PDF 全文未能抓取,以下基于摘要"——绝不假装读过正文去总结方法细节、实验数字。摘要页(/abs/)通常比 PDF 链接更可抓,优先抓它。
- **新颖性判断要留余地**:被问"有没有人做过 X"时,结论只能是"在我检索到的范围内未发现/发现了这些",列出用过的查询词;检索不到 ≠ 不存在,这句话要写出来。
- **交付带可点链接**:每篇引用给出 `arxiv.org/abs/<id>` 链接 + 一行"它和用户问题的关系";按相关性排序而非时间排序,除非用户就是要最新动态。
