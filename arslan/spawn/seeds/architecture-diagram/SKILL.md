## Trigger

当用户要「一张架构图 / 系统图 / 数据流图 / 部署拓扑」，或说"画一下这套系统长什么样 / 各模块怎么连"时激活。任何需要把"组件 + 关系"可视化成图的场景都适用，而不是只用文字罗列。

## 决策规则

- **先建模再画图**：先把内容拆成结构化的「组件清单 + 关系清单」（谁调用谁、数据往哪流、谁属于哪一层），把这张表理清楚再落笔，不要边想边画。
- **分层分组**：按职责分层（如 前端 / 网关 / 服务 / 数据），同层左右排、跨层上下排；用浅色分组框圈出边界（如 VPC、可信区），让结构一眼可读。
- **方框 + 带标签箭头**：每个组件一个方框（名称 + 一行职责），关系用箭头并在箭头上标注语义（如 "REST"、"异步事件"、"读"、"写"）；箭头有方向，双向就画两条或用双箭头。
- **留白与对齐**：网格化布局，组件等宽、间距一致、箭头尽量横平竖直少交叉；宁可图稀疏也不要挤成一团 —— 可读性 > 信息密度。
- **固定调色板**：用一套克制的语义配色（一层一色 / 一类一色），别每个框换颜色；同类元素同色同尺寸,形成视觉规律。
- **所有文本做 XML 转义**：SVG/HTML 里 `&` `<` `>` `"` 必须转义（`&amp;` `&lt;` `&gt;` `&quot;`），否则图会渲染崩 —— 这是最常见的低级错误。
- **纯数据优先走后端**：如果要呈现的是表格类/可量化数据（而非拓扑结构），优先用宿主的 `render_chart` 渲染路径，而不是手搓 SVG 图表。
- **图旁配文字**：图不自解释，旁边附「组件说明 + 关键数据流（一条主链路按顺序讲一遍）」，让不看图也能懂。
