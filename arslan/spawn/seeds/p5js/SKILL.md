## Trigger

当用户要「p5.js sketch / 生成艺术 / creative coding / 交互动画草图」时激活。产出物是一份完整可运行的 p5.js 源码,用户粘贴进 editor.p5js.org(或本地 p5 环境)即可看到效果。你自己不能执行或截图这段代码,所以整套方法围绕"静态推理就能保证正确"来设计。

## 决策规则

- **单文件自包含**:一个 sketch 就是一段完整代码——`setup()` 建画布定基调,`draw()` 负责每帧;不引外部库、不加载图片/字体/音频等外部资产(`loadImage` 等一律不用),粘贴即跑,零依赖。
- **随机必须播种**:任何用到 `random()`/`noise()` 的 sketch,`setup()` 第一行就 `randomSeed(SEED)` + `noiseSeed(SEED)`,SEED 是顶部命名常量——用户和你看到的才是同一幅画面,"换个感觉"只需改一个数。
- **可调参数全部提成顶部常量**:粒子数量、色相范围、速度、画布尺寸等一律 `const PARTICLE_COUNT = 200;` 式命名常量并附一行注释说明效果,集中放文件顶部;魔法数字散在 draw() 里的 sketch 没法调。
- **注释里写出预期视觉行为**:文件头一段注释描述"运行后应该看到什么"(如"深蓝底上 200 个粒子沿 noise 场缓慢流动,拖尾渐隐");关键代码块注释写意图。这既是给用户的说明书,也是你静态自查的对照标准。
- **复杂度以可推理为上限**:你不能运行代码,所以只写自己能在脑内逐帧走通的逻辑——单一视觉主题、一两种机制(如 noise 场 + 拖尾),避免多系统耦合、递归深度不明、状态机复杂的设计;拿不准正确性的花哨效果,换成拿得准的朴素效果。
- **交卷前静态自查一遍**:逐项核对——所有变量已声明、`createCanvas` 在 setup 里、坐标/角度单位一致(`angleMode` 明确)、颜色模式(`colorMode(HSB)` 等)在使用前设置、数组循环边界正确、没有每帧泄漏(如在 draw 里无限 push 不清理)。
- **性能有底线**:draw() 每帧的工作量心算一下数量级——粒子 ≤ 数百、避免每帧嵌套 O(n²) 碰撞检测(必须要就限制 n 或降频);拖尾用半透明矩形覆盖(`background(0, 20)` 技法)而不是存历史帧。
- **交付诚实**:明确说这是源码、你无法执行或截图验证,请用户粘贴到 editor.p5js.org 运行;若效果与注释描述不符,请用户回报现象(报错信息/看到了什么),再据此修——不假装"已确认运行正常"。
